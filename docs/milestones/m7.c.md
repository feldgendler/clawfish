# M7.C — SEE capture futility / delta pruning

**Status:** ◐ EXPLORED & SHELVED 2026-06-18 — two SPRT variants vs `M7.B.2` both failed (v1 flat ≈−1.7 Elo, v2 clear regression −49 with a 60+0.6 collapse). **No ship; production HEAD stays `M6.J` + `M7.B.2`.** Code retained on branch `m7c-see-capture-futility` (not merged). ADR-0042. **Closes M7.** Same outcome class as M7.A's ordering split: for this engine SEE's Elo is fully captured by the *qsearch* prune (M7.B/M7.B.2).

## What landed

The **negamax-side complement of FFP** and the **second production consumer** of the M7.A SEE evaluator (after M7.B's qsearch prune). At a frontier node — reusing FFP's exact node gate `ffp_static_eval` (`ply>0 && !is_pv && depth∈[1,FFP_MAX_DEPTH] && |alpha|<MATE_IN_MAX_PLY && !in_check`) — a **non-promotion capture** (`mv.is_capture() && !mv.is_promotion()`) is skipped when an optimistic material-plus-margin ceiling can't reach alpha. Two layers (the Stockfish MVV-first / SEE-second pattern):

- **(a) MVV delta-prune** — `static_eval + victim + margin ≤ alpha`. `victim` is the max material a non-promo capture can net (`see ≤ victim` unconditionally — the swap-list only subtracts recaptures), so this is a **sound optimistic ceiling**; returns BEFORE any `see()` call.
- **(b) SEE refinement** — for materially-losing captures (`victim < attacker`) only: `static_eval + see(mv) + margin ≤ alpha`. Catches even RxR-defended trades in lost positions that (a) misses. Winning/equal captures (`victim ≥ attacker`) are never SEE-pruned in v1 (perf: bounds `see()` to the `qsearch_see_pruneable` fast-out class; conservatism: the likeliest saving tactics).

On a fire: floor `best` + provenance downgrade (`best_is_full_depth_after_score(.., move_is_full_depth=false)`, the FFP §7 accounting verbatim) + `continue`. `CFP_MARGIN_D1 = 150` (D2/D3 = 300/500 forward-compat, inert at `FFP_MAX_DEPTH = 1`). **No root-depth ramp** — alpha-relative futility is self-regulating in TC (research §4), the opposite of M7.B's alpha-independent threshold that needed the M7.B.2 ramp.

New code: 3 constants, `capture_futility_margin` + `cfp_pruned_bound` helpers, the move-loop block (after the FFP quiet skip), `cfp_firings`/`cfp_pruned_moves` test counters + accessors.

## Lessons

- **Alpha-relative futility is the TC-safe form of SEE pruning — and that was the only thing that worked.** Where M7.B's alpha-*independent* `see < 0` threshold regressed at the slowest TC (and needed the M7.B.2 depth ramp), v1's alpha-relative gate self-regulated and showed **no 60+0.6 regression** (the design's central claim, vindicated). The moment v2 broadened (b) to capture-side-material-agnostic pruning, the alpha-relative protection was *insufficient* — pruning winning captures in *statically* lost positions reintroduced the slow-TC collapse, because "statically lost" ≠ "actually lost" once the engine searches deep enough to find the winning-capture refutation.
- **SEE's Elo for this engine is concentrated entirely in the qsearch prune.** Across M7: ordering-by-SEE (M7.A) flat, negamax-frontier capture-futility (M7.C) flat-to-negative; only qsearch SEE-pruning (M7.B/M7.B.2) converted (+92–124). The negamax move loop's ordering (MVV-LVA + TT + killer + history) and existing prunes (RFP/NMP/FFP/LMR) already extract the available signal at internal nodes; SEE adds value only at the qsearch horizon where there is no other pruning.
- **A new pruning feature shifts the regimes its predecessors' tests rely on.** The FFP provenance-downgrade test was built on a *searched* losing capture; CFP now prunes that capture, so the test's alpha had to move into the window where CFP prunes via branch (b) (low bound) rather than branch (a) (high bound) — otherwise the CFP contribution, not the FFP one, became the node max. Same-subsystem feature additions need a pass over the existing tests' constructed regimes.
- **Stop a conclusive SPRT early.** v2 seed 1's CI fully negative (−49 [−72,−26]) with a 60+0.6 collapse is a one-seed clear-regression no-ship; seed 2 was stopped at 28 games (the M5.G item-6 precedent) — a 2-seed confirm is for guarding against false-positive *ships*, not for re-confirming a clear regression.
- **cargo-mutants TIMEOUT ≠ MISSED.** A comparator flip that makes the search misbehave can hang a slow same-binary test past the per-mutant timeout before the fast unit-test failure is collected; manual apply-test-revert on the mutant confirms it's caught.
