# M5.D — Frontier futility pruning (retrospective)

Fourth M5 sub-phase. Adds **frontier futility pruning (FFP)** as a per-quiet-move skip inside the negamax move loop at shallow depth (`depth ≤ FFP_MAX_DEPTH = 2`): before recursing into a quiet move, if `static_eval + margin(depth) ≤ alpha`, skip it. The pruned move contributes its proved fail-soft upper bound `static_eval + margin` to the node's running `best`, routed through `best_is_full_depth_after_score` with `move_is_full_depth = false` to downgrade the full-depth flag (load-bearing TT-store correctness — ADR-0026 §7).

## What landed

- FFP constants and compile-time invariant in [`src/search.rs`](../../src/search.rs):
  - `FFP_MAX_DEPTH = 2`
  - `FFP_MARGIN_D1 = 100`
  - `FFP_MARGIN_D2 = 150`
  - `FFP_MARGIN_D3 = 250` (defined but inactive at v1)
  - `const _: () = assert!(FFP_MAX_DEPTH < LMR_MIN_DEPTH)` — production tripwire pinning FFP/LMR depth disjointness
- Pure helpers (mirroring the M5.A `null_move_reduction` / M5.B `reverse_futility_margin` / M5.C `late_move_reduction` precedent):
  - `frontier_futility_margin(depth: u32) -> i32`
  - `ffp_pruned_bound(static_eval: i32, depth: u32, alpha: i32) -> Option<i32>` — single helper combining gate test + bound calculation, saturating arithmetic on the inside; closes the overflow asymmetry that two separate bool/i32 helpers would create
- Node-level gate computed once before the move loop, with the lazy STM-relative `static_eval` latched into `ffp_static_eval: Option<i32>` whose `Some/None` IS the eligibility signal (no separate bool to keep in sync).
- Move-loop integration: per-quiet FFP block lands BEFORE the LMR decision; on FFP fire, contributes `pruned_bound` to `best` via `best_is_full_depth_after_score(..., false)` (the load-bearing provenance downgrade), then `continue`s past the LMR/recurse/quiets_searched/history-update plumbing.
- Test-only instrumentation: `ffp_firings: u32` counter and `ffp_skipped_moves: Vec<Move>` move list (gated by `lmr_trace_root_ply` so FFP and LMR share one trace root).

## Implementation highlights

- **Provenance downgrade is the load-bearing correctness commitment.** Without routing the FFP bound through `best_is_full_depth_after_score(..., move_is_full_depth = false)`, the engine could store an inflated Upper TT entry from coarse static-comparison evidence in the mixed case (capture full-depth-witnesses `best` at score < alpha, then FFP overwrites with a larger pruned bound still ≤ alpha). The plan-review and test-suite-review loops both flagged variants of this issue and converged on the M5.C-precedent fix; the test `negamax_ffp_contribution_downgrades_best_is_full_depth` pins the mixed-case suppression with an anti-vacuous sister.
- **Fixture design for the downgrade test required two iterations.** Pass-1 fixture used a winning capture (Q wins pawn cleanly), so `capture_score > pruned_bound` and the downgrade arm was bypassed — the test passed vacuously. Pass-2 fixture (`4k3/3p4/8/8/3Q4/8/8/6K1 w - - 0 1`) uses a Q-for-P trade where the only legal capture is Qxd7 (defended by Ke8) → recapture loses Q for P → capture_score ≈ −900 cp, pruned_bound ≈ +1000 cp → ~1900 cp gap, structurally guaranteeing the downgrade arm fires. Three runtime invariants assert the regime: `n_captures ≥ 1 && n_quiets ≥ 1`, `captures.len() == 1`, and `returned_score == pruned_bound_d1`.
- **Single-helper `ffp_pruned_bound` design**. Returning `Option<i32>` instead of separate bool/i32 helpers eliminates the saturation-overflow asymmetry that two helpers would create: the gate must use `saturating_add` to defend against `i32::MAX + margin` overflow under unit-test edge cases, and the call-site contribution must reuse the same saturated value or the overflow re-emerges. The single helper computes the bound once and threads it through.
- **Compile-time invariant placement.** `const _: () = assert!(FFP_MAX_DEPTH < LMR_MIN_DEPTH)` lives adjacent to the FFP constants in production code (not in the test surface), mirroring ADR-0025 §3's `LMR_HIGH_HISTORY_THRESHOLD <= MAX_HISTORY` precedent. A future tuning that violates the invariant must remove the assert in the same patch that updates ADR-0026 §6 — friction is appropriate for a load-bearing correctness commitment.
- **No disturbed pre-existing test pins.** M5.A/B/C tests use `depth ≥ 3` fixtures; FFP fires only at `depth ≤ 2`. The pruning ranges don't overlap on the firings counters. The only pin movement is E50 (M5.C depth-4 bench-determinism) downgraded to determinism-only at landing; new E51 carries the M5.D depth-4 value pin (`117768`).
- **Test-suite review loop caught a subtle illegal-position issue.** My initial in-check sister fixture re-used the M5.B RFP test's no-check FEN (`7k/8/7n/8/3Q4/8/5PPP/6K1`), which is actually an illegal position (Black king in check at White's turn — Q d4 attacks h8). RFP's test escaped this because RFP returns early without running the move loop. FFP's move loop runs at the no-check arm and tries to capture the black king (Qxh8) — legal-direct movegen emits this from an illegal position. Fixed by switching to the standard middlegame fixture for the no-check arm and a clean Bd5/Kh1 in-check fixture.

## Outcome and follow-up

The M5.D mixed-TC SPRT did not validate a positive strength delta over M5.C at the v1 parameters (`FFP_MAX_DEPTH = 2`, margin table 100/150/250). The per-TC breakdown is strongly bimodal:

- **Fast TC**: clear positive (10+0.1: 56.5%; 20+0.2: 68.3%).
- **Slow TC**: clear negative (40+0.4: 30.2%; 60+0.6: 40.6%).

Aggregate is inconclusive — neither H1 nor H0 crossed at 400 games — but the bimodal pattern is too strong to be coincidence within the per-bucket noise envelope. The most credible interpretation: depth-2 ("extended futility") FFP is too aggressive at deep search, where its tactical-blindness risk grows faster than its node-savings benefit. Heinz 1998's original frontier-FP formulation was depth-1 only; depth-2 was the same paper's extension and is the riskier choice.

**Recommended follow-up (not part of the M5.D landing commit)**: re-SPRT with `FFP_MAX_DEPTH = 1` (frontier-only). If positive across all TC buckets, land as M5.D-v2 and create `baseline/m5d-ffp` then. Other lower-priority candidates: tighter `FFP_MARGIN_D2 = 100`, gives-check exemption.

**Tagging decision**: `baseline/m5d-ffp` is NOT created at the M5.D landing commit. Future phases (M5.E and beyond) use `baseline/m5c-lmr` as the strength-validation reference until a future FFP retune validates a positive delta.

## Workflow

- **Plan-review loop**: 3 passes (must-fix + should-fix at pass 1; minor cleanup at pass 2; converged at pass 3 with "no further substantive issues"). The pass-1 must-fix on the provenance downgrade was the architecturally load-bearing finding; the rest were tightening / consistency.
- **Test-suite review loop**: 3 passes (must-fix on the downgrade-test fixture at pass 2 — the pass-1 fix wasn't enough; converged at pass 3 with "no further substantive issues" + one stale-comment nit cleaned up).
- **Final review loop**: 1 pass, converged with three documentation nits (stale E50 docstring fixed; architecture-doc paragraph order acknowledged; bench-number cross-doc agreement verified).
- **Mutation-testing**: ran in-diff against `0f9bd88..HEAD` (M5.D landing diff). 38 mutants enumerated. Initial pass: **1 missed** — `replace > with >= in AlphaBetaMover::negamax` at the `if pruned_bound > best { best = pruned_bound; }` site. The mutant is **equivalent**: when `pruned_bound == best`, both branches leave `best` unchanged (assignment of equal value is a no-op). **Closure**: replaced the conditional with `best = best.max(pruned_bound)` — removes the `>` operator entirely, kills the mutant by structural elimination. Re-run after the fix: **36 caught + 2 unviable + 0 missed = 100% effective catch rate**. The 2 unviable mutants are `&& → ||` in the `if quiet_move && let Some(...) && let Some(...)` chain, which cannot compile (let-chains require `&&` syntactically).
