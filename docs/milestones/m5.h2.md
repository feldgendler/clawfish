# M5.H2 — Staged movegen lazy quiet sort (REJECTED)

**Status**: Rejected per plan §13 outcome 4. M5.H milestone closes at H1.

**Dates**: 2026-05-10 (plan + first three implementation variants + first SPRT) → 2026-05-11 (v3 + v4 variants + descope decision).

**Final disposition**: Production code reverted to `baseline/m5h1-stager-refactor` (M5.H1 v2 thin-wrapper). M5.H2 v4 working code preserved in `git stash` for archival. ADR-0030 §11 + `docs/research/m5-staged-movegen-allocation.md` document the failure analysis. M5.H3 (typed lazy generation) is no longer scheduled.

---

## Summary

M5.H2 attempted to capture the literature-documented +5–15 Elo signal from lazy quiet sorting (research §15.6: "history scores at sort time reflect updates from searching captures and killers at the same node"). The H2 design defers the quiet sort from construction-time to first-Stage::Quiets-entry, so the sort sees post-captures-search history scores.

Four implementation variants were tried; all failed SPRT against the M5.H1 v2 thin-wrapper baseline.

| Variant | Approach | Key result |
|---|---|---|
| v1/v2 | 3-Vec + lazy (Stage enum + per-stage Vecs) | 277-game SPRT: 47.8% score, Δ Elo ≈ −15 logistic; **bimodal per-TC** (20+0.2: −95 decisive; 40+0.4: +65 decisive) |
| v3 | 1-Vec in-place + lazy (skip TT/killers in iteration) | Sustained-load 1.53× FASTER; 32-game SPRT trajectory ≈ 37% score, **same bimodal shape** → regression is algorithmic, not allocation-driven |
| v4 | v3 + depth-gating at `LAZY_QUIET_SORT_MIN_DEPTH=6` | Sustained-load **0.38× — 2.8× SLOWER** (eager sort fires at every shallow node); failed §12 step 5 abort criterion before SPRT |

## What worked

- **Plan + test surface**: ~600 LOC plan, 1495 tests including H1/H2 proptests at 2048 cases each. Plan-review converged in 3 passes; test-suite review converged in 4 passes. **The algorithmic correctness of every variant was verified** — the H2-P1 proptest (yield-equivalence to `order_moves` under constant history) passed for all four variants.
- **v3 allocation refactor**: single-Vec in-place partition matched M5.G / H1-v2 baseline's 1-alloc-per-node profile. Sustained-load 1.53× faster than baseline. **The literature signal at 40+0.4 (+65 Elo) confirmed the algorithm IS sound at deep depth.**
- **Independent research**: chess-researcher agent surveyed allocation patterns (CPW, TalkChess) and confirmed the bimodal TC pattern's qualitative explanation. Findings preserved at `docs/research/m5-staged-movegen-allocation.md`.
- **Sustained-load gate (plan §12 step 5)**: caught v4's 2.8× slowdown before burning SPRT wallclock. The §12 abort criterion (`ratio < 0.95 → STOP`) worked as intended.
- **CI fmt drift caught**: an unrelated rustfmt drift in the M5.H1 commit was diagnosed and the pre-commit hook was updated to match CI's `cargo fmt --all -- --check` form. Hook update kept in the working tree.

## What didn't work

- **The algorithm itself, at clawfish's strength + TC profile.** At slow TC (40+0.4, depth 14–18), the lazy quiet sort produces the expected +Elo signal. At fast TC (10+0.1, 20+0.2, depth 8–12), the post-captures-search history is too sparse and noisy to outperform pre-search history, producing −Elo regression. Aggregate over a 4-bucket uniform mix: net negative.
- **Each cost-mitigation attempt traded one cost for another.** v3 fixed allocation cost (1.53× speedup) but kept the algorithmic regression at fast TC. v4 fixed the algorithmic regression at fast TC (eager-sort at depth < 6) but introduced a structural speed regression (eager sort firing at every shallow node). No design point reconciled both.
- **The +5–15 Elo literature prediction** was unduly optimistic for an engine at clawfish's strength range and TC profile. The chess-researcher findings noted that the prediction assumes engines reach depth 14+ consistently; clawfish's time-bound reach is depth 8–12 at typical TCs.

## Lessons (for future feature attempts)

1. **Sustained-load NPS gate is necessary but not sufficient for landing.** v3 passed it convincingly (1.53× speedup) and still failed SPRT. Future features that have a per-depth ordering quality component should ALSO measure per-depth tactical-suite performance (e.g., WAC + STS) before SPRT, to disambiguate "fast but worse" from "slow but better."
2. **Algorithmic-correctness proptests don't validate Elo.** Both H1-P1 and H2-P1 verified yield-sequence equivalence (2048 cases each) yet the production behavior under mutating history doesn't produce the predicted Elo gain. Future proptests should ALSO assert "the algorithm's claimed Elo property" where possible — e.g., a proptest that mutates history mid-iteration and verifies the post-mutation order differs from the pre-mutation order in the expected direction.
3. **Bimodal SPRT patterns reflect depth-conditional algorithms.** The naive expectation "average over mixed TC will reflect average Elo" was wrong: the +65 at one bucket and −95 at another don't average to −15; they signal a depth-conditional algorithm where the average summary obscures the structural problem. Future SPRT analysis should include per-TC breakdowns as a first-class check.
4. **Depth-gating to dodge a TC-fragile algorithm is non-trivial.** v4 demonstrated that the "obvious" workaround (eager at shallow, lazy at deep) introduces its own costs. Future depth-gating attempts should benchmark the cost-of-eager-at-shallow before committing to the design.
5. **Time investment**: ~12 hours across plan, test-writing, four implementation variants, two SPRT pulses, partial mutation campaign, sustained-load campaign, two SPRT failures. **Result**: descope. The investment was substantial but the negative result is high-confidence — multiple structural attempts failed in the same direction. Future agents should treat the M5.H2 rejection as a hard data point against re-attempting lazy quiet sort without addressing the root cause (clawfish's depth-12-ceiling at typical TCs).

## Decision

**Per plan §13 outcome 4: descope. Land documentation-only commit recording the rejection.** M5.H milestone closes at H1 (the architectural refactor).

**M5.H2 is DEFERRED, not abandoned.** Scheduled for revisit when typical-TC search reaches depth ≥ 14 (a precondition for the literature signal's signal-to-noise ratio). See `docs/tuning-backlog.md` §"M5.H2 lazy quiet sort — REVISIT" for the 3-gate precondition checklist:

1. Typical-TC depth reach ≥ 14 at 20+0.2 (currently 10–12).
2. History table accumulation ≥ 4000 nonzero entries per game (instrumented measurement required).
3. No higher-leverage feature pending.

**Recommended revisit approach**: recover v4 from stash (`git stash list | grep m5h2-v4`), re-tune the `LAZY_QUIET_SORT_MIN_DEPTH` threshold via SPRT campaign (sweep over [4, 6, 8, 10, 14]), and consider selection-sort-on-quiet-sub-slice as an orthogonal alternative not tried in v1-v4 (research §3.2). Hard rejection criterion if revisit shows the same bimodal pattern at depth ≥ 14 reach.

**Next phase**: M6 (eval improvements). Per-theme STS validation available via `src/bin/epd-suite.rs`; M5.H1 baseline at HEAD is 8822/15000 (58.9%) total credit, with weakest themes "King Activity" (42.3%) and "AKPC" (46.2%) — natural empirical anchors for the first M6 sub-phases. **M6's depth gains will be the next opportunity to re-check the M5.H2 revisit preconditions.**
