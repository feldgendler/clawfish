# M5.B — Reverse futility pruning (retrospective)

Second M5 sub-phase. Adds RFP (reverse futility pruning, also called static null-move pruning or beta pruning) to the negamax prologue at new step 8, between the TT probe (step 7) and the M5.A NMP block (step 9).

## What landed

- **Constants** `RFP_MAX_DEPTH: u32 = 6` and `RFP_MARGIN_PER_DEPTH: i32 = 100` in `src/search.rs`, immediately after the existing `NMP_DEPTH_DIVISOR` block. Both `pub(crate)` so test-module call sites can reference them without `super::`.
- **`reverse_futility_margin(depth: u32) -> i32`** helper in `src/search.rs`, next to `null_move_reduction`. Returns `RFP_MARGIN_PER_DEPTH * depth as i32`. Pure function; extracted as a named helper so mutations on the formula constants are directly unit-testable (M3.D `negate_window` / M5.A `null_move_reduction` precedent).
- **RFP block (new step 8)** in `negamax` (~25 LOC). Gate: `ply > 0 && !is_pv && !in_check(pos) && depth <= RFP_MAX_DEPTH && beta.abs() < MATE_IN_MAX_PLY`. Inside the gate, `static_eval` is read lazily (sign-flipped by STM, identical pattern to M5.A's NMP block); on `static_eval - margin >= beta`, returns `static_eval - margin` (fail-soft proved lower bound). No TT store on cutoff (research §6 / §7: the proof is depth-specific to the margin and would be incorrect to use at a different probe depth). ADR-0024.
- **NMP block (step 9)**: byte-identical to M5.A. ADR-0023 unchanged.
- **Step renumbering**: TT probe = 7, RFP = 8 (new), NMP = 9 (was 8), movegen = 10, terminal = 11, order = 12, recurse = 13, TT store = 14.
- **`#[cfg(test)] rfp_firings: u32`** counter on `AlphaBetaMover` + `pub(super) fn rfp_firings_for_test()` accessor, mirroring M5.A's `nmp_firings` pattern. Increment site is inside the RFP cutoff branch, before the `return`.
- **E49** `bench_signature_deterministic_across_two_runs_with_rfp` integration test. Mirrors E48's shape: two consecutive `bench 4` runs in the same engine session emit identical node counts. Pinned to 137,174 nodes at depth 4.
- **ADR-0024** records the formula, gate set, max-depth, fail-soft return value, no-TT-store policy, lazy-dup design choice, and RFP-before-NMP ordering decision.

## Implementation highlights

- **Single coder slice** (Sonnet). M5.B's negamax-body change is materially smaller than M5.A's — no signature change, no novel invariant introduction, no call-site migration. Plan §8 identified one Sonnet slice as sufficient and correct.
- **Lazy-dup design confirmed correct**. RFP and NMP each read `static_eval` independently inside their own gates. The M5.A NMP block is byte-identical to its M5.A form. M5.B's SPRT signal vs `M5.A` is a clean RFP-only attribution with no NMP-side behavior change. ADR-0023 unchanged.
- **`nmp_firings` empirical pin held at K=34**. The plan §5.4 flagged this as a likely drift item; in practice the RFP fixture choices at depth=1 and depth=6 (root-fires-before-movegen) don't share node paths with the K=34 pin's test fixture.
- **No existing-test re-pins required**. M5.A's 971 lib + 12 uci-integration tests all pass under M5.B without modification.

## Fixture course-corrections

The most significant implementation challenge was **descendant contamination of the `rfp_firings` counter**.

The `rfp_firings` counter counts firings across the ENTIRE search tree rooted at the `negamax_for_test` call, not just the root frame. Tests at the originally-planned depth=4 (or depth=3) allowed children to recurse into negamax, where descendants could fire RFP if their gate conditions were satisfied. A global counter cannot distinguish root firings from descendant firings.

**Fix for PV / in-check / ply-zero / mate-beta gate-skip tests**: Changed depth=4 (or 3) → **depth=1**. At depth=1, children dispatch to qsearch (depth=0), not negamax. No descendant negamax calls → no descendant RFP firings → counter isolated to the root frame. Beta updated correspondingly from `reverse_futility_margin(4)` to `reverse_futility_margin(1)`.

**Fix for `negamax_skips_rfp_at_depth_above_max`**: The depth-above-max test requires asserting `rfp_firings == 0` at depth=7 and `rfp_firings == 1` at depth=6. Cannot use depth=1 to test this boundary (1 ≤ 6 for both). A single-beta approach was impossible: for the d=6 root to fire RFP, need `beta ≤ static_eval - 600`; for d=7 descendants to produce zero firings, need `beta > 850` (empirically confirmed via beta sweep). These constraints are mutually exclusive.

**Two-beta resolution**: use two separate betas, leveraging the fact that RFP fires at **step 8, before movegen at step 10**. When the root fires RFP at depth=6 with `beta = static_eval - 601`, it returns immediately before generating any moves — literally zero children are explored — so `rfp_firings == 1` exactly with no contamination risk. For depth=7 with `beta = 950`, the root's gate fails (`7 > 6`) and the entire search tree for a K+Q vs K position produces zero firings (empirically confirmed: no descendant at any depth satisfies `eval - margin*d >= 950` after captures alter the static eval).

The `<= → <` mutation on the depth gate is killed by the `rfp_firings_d6 == 1` assertion alone (under the mutation, `6 < 6 = false` → root doesn't fire → count = 0 ≠ 1). The d=7 assertion contributes documentation value.

## Mutation-survivor analysis

Joint M4.B+M4.C+M4.D+M5.A+M5.B campaign (748 mutants: 669 caught, 31 missed, 33 unviable, 15 timeouts — 89.4% catch rate). M5.B-specific survivors from this campaign:

### 1. `replace < with <= in AlphaBetaMover::negamax` — RFP `beta.abs() < MATE_IN_MAX_PLY` boundary

**Classification: Structurally undetectable — expected survivor per plan §10.**

Mutating `<` to `<=` would cause RFP to fire when `beta.abs() == MATE_IN_MAX_PLY = 29936` exactly. No chess fixture can produce a beta of ±29936 — that value corresponds to mate-in-64 moves, an unreachable position in normal search. Documented as an anticipated survivor in the plan and in `docs/mutants-backlog.md` §"Edge cases" before the campaign ran. `exclude_re` rule added to `.cargo/mutants.toml`. The `negamax_skips_rfp_when_mate_beta` sister-fixture test covers the reachable regime: beta = `MATE_IN_MAX_PLY + 100` (larger than the boundary) vs beta = `MATE_IN_MAX_PLY - 100` (smaller) — both sides correctly discriminated.

**Also covers the M5.A NMP `>= → >` mate-cap boundary**: the same `replace < with <= in AlphaBetaMover::negamax` rule name in `.cargo/mutants.toml` applies to both mutations since they appear in the same function. See `docs/milestones/m5.a.md` §"Mutation-survivor analysis" item 3.

The 30 other survivors (from ELOH harness SearchClock, draw-score CLI validation, SPRT alpha/beta CLI, colour-parity adjudication, pentanomial CI, write_match_pgn separator logic, driver whole-fn replacements, and the M4.B+C+D+M5.A surface) are documented in the respective milestone retrospectives.
