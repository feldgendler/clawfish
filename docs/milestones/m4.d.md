# M4.D — Aspiration windows (retrospective)

Fourth and final M4 phase. Wraps M3.E's iterative-deepening outer loop with two-tier asymmetric aspiration windows. Closes M4.

## What landed

- **`aspiration_window(prior_score, depth) -> (i32, i32)`** in `src/search.rs`. Returns `(-INF, INF)` for `depth < ASPIRATION_MIN_DEPTH = 6` or `prior_score == None`; else `(prior - HALF_WIDTH, prior + HALF_WIDTH)` with `HALF_WIDTH = 50` cp. **No mate-score skip** — per research §7.2 + §10, the asymmetric widening handles mate scores correctly via the second-tier full-window path. **Threshold=6, not 4**: the plan initially specified threshold=4 (literature default); empirical fast-TC SPRT at tc=10+0.1 showed a 22-Elo regression with threshold=4. Threshold=6 produced +65.92 Elo (LOS 100%) on the same baseline. See SPRT log for the full curve.
- **`widen_after_fail(returned, prev_alpha, prev_beta) -> (i32, i32)`** in `src/search.rs`. On fail-high (`returned >= prev_beta`): `(returned, INF)`. On fail-low (`returned <= prev_alpha`): `(-INF, returned)`. The proved fail-soft bound is preserved on the unfailed side; only the failing side widens to `±INF`. Matches CPW / Beowulf / TalkChess literature consensus exactly.
- **`extract_bestmove_or_tt_fallback(pv, tt, root_key) -> Option<Move>`** in `src/search.rs`. Returns `pv[0][0]` when populated; falls back to the root TT entry's `best_move` field when PV is empty (the rare fail-high empty-PV edge case where true value equals the proved bound exactly). The fallback works because ADR-0018 §7's best-move-on-overwrite preservation rule keeps the failed-try's cutter in the TT slot even after the re-search overwrites with `bound=Upper, best_move=0`.
- **`Search::go`'s ID outer loop body restructured** around an inner aspiration loop (search.rs ~lines 422–540). Up to two negamax calls per iteration (first try + at most one re-search). Per-iteration `clear_killers` runs once at the top of each ID iteration (M4.B inter-iteration policy preserved). Per-try resets clear `aborted` / `root_score` / `pv.lengths[..]` but NOT killers (cross-try ordering hints preserved per research §12.7). `tries >= 2` cap enforces the "two-tier" rule; window-contained returns short-circuit the re-search.
- **`Move::from_bits(bits: u16) -> Move`** added to `src/mov.rs` as `pub(crate) const fn`. Required by `extract_bestmove_or_tt_fallback` to decode TT-stored bestmove bits back into a `Move`. Caller-contract docstring spells out the valid-flag-nibble invariant.
- **`info string aspiration_re_search depth=N alpha=A beta=B`** test-instrumentation line emitted via `info_sink` on each re-search (plan §3.8). Cost is bounded (one allocation per fail, ~0–1 per ID iteration). Tests parse via the existing `RefCell<Vec<String>>` pattern.

- **Helper-extraction discipline maintained**. Three new helpers (`aspiration_window`, `widen_after_fail`, `extract_bestmove_or_tt_fallback`) follow the M3.D `negate_window` / M3.E `aborted_fallback_result` / M3.F `compute_bench_nps` precedent: direct unit-testability for mutation-test surface; pure functions with deterministic output; AS24a–d cover the empty-PV TT-fallback's four branches with synthetic `PvTable` + synthetic `TranspositionTable`.
- **Plan-review converged in 3 passes** (pass 1: 1 must-fix + 6 should-fix; pass 2: 2 must-fix + 4 should-fix; pass 3: `no further substantive issues`). Notable v1→v2 design changes driven by reviewer + research:
  - Re-search window form reverted from `(L-1, +INF)` to `(L, +INF)` (literature consensus).
  - Mate-score skip dropped (research §7.2).
  - Stop-flag check between tries dropped (research §12.4).
  - Empty-PV recovery via TT-fallback helper (replaces `failed_root_move` snapshot field).
  - `Move::from_bits` constructor added when pass-2 reviewer noticed the API gap.
- **Final-review converged in 2 passes** (pass 1: 2 should-fix + 3 nits; pass 2: `no further substantive issues`). AS23 weak-pin acknowledged and surfaced as anticipated-possibly-surviving for the joint mutation campaign; ADR-0018 §11 stale "M4.D = PVS" text corrected at landing; `Move::from_bits` invariant docstring added.

## SPRT result

Mixed-TC campaign vs `baseline/alpha-beta-tt-killer-history` ran 2026-04-30 20:44 → 23:20 local (2 h 35 m wallclock) using ELOH.D's `--tc-sample` 4-bucket uniform mix `10+0.1:1,20+0.2:1,40+0.4:1,60+0.6:1` and seed `0xC1ABF15AE10DD001`. 400 games / 200 pairs at concurrency 4 (`taskpolicy -c utility` on both engines), frozen-K mode, threshold adjudication matching `scripts/sprt.sh sprt` defaults.

**Result: 138-90-172 (score 56.00%), Δ Elo +41.89, pentanomial 95% CI [+18.18, +65.61], `Ptnml(0-2) = [5, 40, 78, 56, 21]`.** CI excludes zero by 18 Elo on the lower side; verdict significantly positive at p < 0.001.

Per-TC point estimates: 10+0.1 +59.5 (118 games), 20+0.2 +30.1 (104), 40+0.4 +74.5 (90), 60+0.6 +0.0 (88). The 60+0.6 bucket is individually neutral but with 95% CI of ±73 Elo — consistent with anywhere from −72 to +72 Elo at that sample size, so does not refute slow-TC strength. Cross-validates run 3 of `bench/sprt/2026-04-30-m4.d-vs-history.md` (fast-TC-only +65.92 ± 26.52 Elo) within ~1σ at the 10+0.1 bucket.

Sampler chi-squared check: χ² = 2.92 / 3 d.o.f., p ≈ 0.40 — consistent with uniform.

## Notes for future maintainers

- **Width-tune campaigns** (±25, ±75, ±100 vs ±50) are plan §12 follow-ups; ~10 hours each unattended; document outcomes in `bench/m4.md`'s M4.D section. If a non-±50 width clearly wins under mixed-TC SPRT, ship a separate "M4.D width tune" commit replacing the constant.
- **Adaptive width** (W as function of depth or PV stability) is M5+ scope per plan §1; the fixed-width M4.D mixed-TC curve is the reference baseline that adaptive variants will be measured against.
- **Third aspiration tier** is M5 scope per plan §1 + roadmap §M5; the two-tier cap (`tries >= 2 { break; }`) sits at the aspiration-loop's exit point and can be relaxed by adding an intermediate `widen_after_fail` step. The body restructure of M4.D anticipates this — the loop is already a `loop {}` with explicit breaks, not a hardcoded 2-iteration `for`.
- **PVS at M5** will replace the synthetic `is_pv: bool` parameter (introduced in M4.A) with the window-based `beta - alpha == 1` predicate. M4.D's first-try window has `beta - alpha = 100`, far from PVS's zero-window — so `is_pv` continues to govern PV/non-PV at M4.D. ADR-0018 §11's text was corrected at M4.D landing to clarify this.
