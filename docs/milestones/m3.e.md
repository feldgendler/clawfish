# M3.E — Iterative deepening + time management

Status: complete (2026-04-29). Wraps M3.C/M3.D's negamax + qsearch in an iterative-deepening (ID) outer loop driven by `compute_caps`'s soft + hard wallclock caps. Adds a `MoveOverhead` UCI option (default 50 ms) for latency hedging and a prior-iteration root-PV ordering hint. **ADR-0017** codifies the time-management formulas + ID discipline.

`go depth 8` from startpos: 72.45M nodes (cumulative across iterations 1–8) / wallclock ~17s contended ≈ 4.34 Mnps; uncontested re-measure pending. Iteration-8 alone visits ~63.2M nodes (vs M3.D's 84.7M single-pass at the same depth — qsearch + ID prior-PV hint together drop iteration-8 nodes by ~25%). Bestmove `e2e4` with PV `e2e4 e7e5 b1c3 b8c6 g1f3 g8f6 d2d4 f8d6` (Italian-style opening). 749 lib + 8 integration tests passing in BOTH debug and release.

## What landed

**Time management — `compute_caps` pure function**:

- `pub(crate) fn compute_caps(&SearchLimits, Color, u64) -> TimeCaps` in `src/search.rs`. Returns `(soft, hard)` `Duration`s; `Duration::MAX` means "no cap".
- Formula tree per ADR-0017 §1: non-time limits (`infinite`/`ponder`/`depth`/`nodes`/`mate`) → `(MAX, MAX)`; `movetime` → `soft = hard = max(1, mt - mo)`; clock-based with sudden-death `denom = 20`, classical-TC `denom = movestogo`, `movestogo=0` defensively folds to 1; increment-only TC (`rem = 0, inc > 0`) → no forfeit clamp; very-low-time (`rem = 0, inc = 0`) → `(1ms, 1ms)`.
- 26 unit tests pinning the formula to research §9's test table verbatim, plus 4 priority-vs-clock tests pinning that non-time flags trump a simultaneously-set clock.

**ID outer loop in `Search::go`**:

- Per-iteration reset (`aborted`, `root_score`, `pv.lengths[..]`); per-go reset adds `prior_root_move = None` and `history`/`nodes` clear. `nodes` is **NOT** reset between iterations (cumulative `info nodes` semantic + cross-iteration `go nodes <N>` budget). `prior_root_move` is **NOT** reset between iterations (set after each completed iteration so the next sees the prior best as the ordering hint).
- Mid-iteration abort (hard cap fires via `should_abort` at the 4096-cadence): partial PV/score discarded; `last_complete` snapshot from the prior iteration becomes the reported result.
- Inter-iteration checks (between iterations only): `if depth >= max_depth { break; }`, `if ctx.stop.load(Relaxed) { break; }` (load-bearing — closes the per-iteration `aborted` reset gap), `if soft_deadline elapsed { break; }`.
- Iteration 1 unconditionally allowed to start (soft check is at end-of-iteration). Pinned by `id_completes_iteration_1_unconditionally_even_if_soft_already_past`.
- Final fallback when `last_complete = None` (iteration 1 aborted before any root improvement): extracted into `aborted_fallback_result(&PvTable, Option<i32>) -> (u32, Option<Move>, i32)` named helper. Same precedent as M3.D's `negate_window` extraction — the inline call site is structurally unreachable at M3.E scope (iter-1 from any chess position visits < 4096 nodes, below the cancellation cadence), so the mutations on the inline expression are uncatchable. Extracting into a helper makes them directly unit-testable with synthetic `PvTable` fixtures.

**Root prior-PV ordering hint**:

- New `prior_root_move: Option<Move>` field on `AlphaBetaMover`. Consumed by `negamax` at `ply == 0` ONLY: after the existing MVV-LVA sort, prepend the prior move via `remove(idx) + insert(0)` to preserve relative MVV-LVA order of the rest. The `idx != 0` guard skips the no-op case. The `position()` lookup gracefully handles the case where the prior move is no longer in the current movelist (e.g., position changed via `position startpos` since the prior `go`).
- Verified by node-count differential test: hint-set vs. no-hint at depth 3 from startpos must produce different node counts (proves the reorder code executes; deleting the reorder block makes both runs go through MVV-LVA only).

**`MoveOverhead` UCI option**:

- `option name MoveOverhead type spin default 50 min 0 max 5000` emitted between `Random_Seed` and `uciok`.
- `Engine::move_overhead: u64` field, default 50, valid range `[0, MAX_MOVE_OVERHEAD = 5000]`.
- `handle_setoption` arm follows `Random_Seed` arm and precedes the unknown-option fallback. Strict u64 parse + range check; `info_string_debug` on rejection (silent if debug off).
- 16 unit tests + 1 integration test (E41 — `setoption MoveOverhead 500 + go movetime 1000` lands bestmove in [400ms, 1200ms]).

**`SearchContext` extension**:

- One additive field: `pub soft_deadline: Option<Instant>`. Polled by ID outer loop between iterations; `should_abort` semantics unchanged (hard-cap path).

### Final mutation gap — engine.rs:225 `+` → `-` on `now + caps.hard`

This survivor remained after the targeted-test pass. The mutation flips `now + caps.hard` to `now - caps.hard`, putting the deadline in the past. Rationale for non-catch:

- Iteration 1 from startpos (~20 nodes) and most non-pathological positions complete WELL below the 4096-node cancellation cadence, so the in-iteration `should_abort` check never fires inside iteration 1.
- The inter-iteration check `if depth >= max_depth { break; }` has higher priority than the soft check; with `depth = Some(N)` set, the loop exits on `depth` cap before the soft check runs.
- For `wtime/btime` tests without an explicit `depth` cap, `max_depth_from_limits` returns 63, so the loop iterates until either a hard cap fires (now-deadline mutation: fires at the 4096-cadence inside iteration 2+, but only when iter 2+ visits 4096+ nodes) or a soft cap fires.

The new test `handle_go_with_wtime_btime_reaches_at_least_depth_2` catches the SOFT-deadline `+` → `-` mutation (engine.rs:226) by asserting ≥ 2 info lines. The HARD-deadline mutation (engine.rs:225) requires the harder fixture: a position where iter 2 alone reaches 4096+ nodes within the engine's natural depth-2 search time. Deferred to M4 — the TT will materially change iteration-1/iteration-2 node counts, and a calibrated test fixture there will incidentally close this.

### Test-driver pattern: wait for `bestmove` before sending `quit`

The race the integration tests hit under M3.E is structural. With the inter-iteration `stop` check (load-bearing per ADR-0017 §2), sending `quit` while the worker is still mid-search flips `stop=true` between iterations, causing the ID loop to break after iteration 1 instead of running to the requested depth. The fix that landed: the new `wait_for_line_starting_with` helper in `tests/uci_integration.rs` polls `mpsc::recv_timeout` until the `bestmove` line appears, then proceeds with `quit`. Pattern mirrors fastchess's UCI-driver protocol.

### `aborted_fallback_result` extraction — same playbook as M3.D's `negate_window`

A naive impl puts `let bm = (self.pv.lengths[0] > 0).then(|| self.pv.moves[0][0])` inline in `Search::go`. Cargo-mutants flagged 3 mutations on the `> 0` operator that no chess fixture could kill — iteration 1 from any position visits well below the 4096-cancellation cadence, so the fallback path that consumes this expression is structurally unreachable from a chess test. Following the M3.D `negate_window` precedent: extract the fallback into a named helper (`aborted_fallback_result`), which makes the helper's body directly unit-testable with synthetic `PvTable` fixtures (4 new tests — empty PV / populated PV / `root_score = None` / `root_score = Some` / and a combined "distinguishes pv.lengths zero from one" test that catches all three mutations independently).

### M3.D `mutants.toml` over-filter avoided

Initial impulse was to add an `exclude_re` rule for `replace > with X in <impl Search for AlphaBetaMover>::go`. That regex would have over-filtered: the iteration-completion path inside `Search::go` ALSO has a `pv.lengths[0] > 0` expression (line 328), where the same mutation IS catchable. Excluding the function-level pattern would silently disable that test surface too. The structural extraction sidesteps the over-filter cleanly and carries a documentation cost (one named helper, one unit test set) that the regex would have hidden.
