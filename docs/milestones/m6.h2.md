# M6.H2 — Corpus lanes (flat build-ready lanes; build→finalize)

**Landed 2026-05-23. Data-infra refactor; data-quality + reproducibility +
crash-safety gate, NOT SPRT — no Elo claim. Production HEAD remains `M6.F`
(bench `1213649` / d4 `90591` byte-for-byte; no `evaluate`/search touch).**
ADR-0035 §12 / ADR-0036 §7; supersedes the M6.G build-era split-at-generation
design.

## What landed

A refactor unifying the four corpus `Source` lanes (`SelfPlayOnBook`,
`SelfPlayOffBook`, `Ccrl`, `LichessOpen`) so each is an INDEPENDENT generator
that produces one FLAT list of build-ready labelled positions inline. The
build-era `corpus build` (which did the cross-game dedup → cap → split → merge
transform) is replaced by the thin `corpus finalize` (manifest / stats / digest
/ re-run.sh, no record transformation); the transform moves inline per lane.

## The four-lane design

- **One dir per lane, one flat `lane.bin`.** Each lane lives in its own
  `--out <dir>` and produces `lane.bin` (the CRC-framed per-game-block
  `store.rs` format) + `manifest.json` + `filter_spec.txt` + `corpus_stats.txt`.
  Self-play / fetch / `ingest-pgn` all write `lane.bin` (was `shard.bin` /
  `pgn-shard.bin`). The lanes are never co-located; each lane's `game_id` space
  is private, so resume / dedup reads exactly one file.
- **Inline pipeline at generation, shared `LaneCommitter`.** All four lanes
  apply the same per-position pipeline (opening-skip `OPENING_SKIP_PLIES=8` →
  drop in-check → `|static_eval| ≤ HIGH_SCORE_CP=600` → `is_quiet` with
  `QUIET_MARGIN_CP=30`) then route the surviving quiet-certified records through
  `pipeline::LaneCommitter` (per-lane FEN dedup → per-game reservoir cap
  `PER_GAME_CAP=10` → exact target truncation → CRC-block append). Fetch uses
  `LaneCommitter::resume` (its own single scan); self-play's consumer uses
  `from_parts` (constructed from the consumer's existing scan — no second read).
  The order matches the pre-M6.H2 consumer byte-for-byte (dedup first, cap among
  survivors, exact target).
- **`ingest-pgn` made build-ready.** The local-file PGN path constructs a
  one-shot `LaneCommitter` + its own `QSearcher` and applies the SAME inline
  pipeline as fetch — closing the build-era gap where ingested PGN was never
  per-position filtered.

## The no-split / no-cross-dedup decisions

- **No train/val split at generation.** The split moves to M6.I, which reads
  the four flat lane dirs and owns the inter-lane MIX + the train/val split.
  `src/corpus/split.rs` deleted; `CorpusRecord::dedup_key` removed (per-lane
  dedup is first-seen-by-arrival, deterministic from the deterministic arrival
  stream — self-play strict `game_id`+ply order, fetch stream order + ply order).
- **No cross-lane dedup.** The same FEN may appear in up to four lanes, possibly
  with CONFLICTING labels — explicitly accepted. The M6.I mixer reconciles
  (per-source reweighting). ADR-0003's audit is per-lane (each lane's labels are
  original game outcomes) → still passes per lane. Pinned by
  `tests/corpus_lanes.rs` (`same_fen_admitted_in_multiple_lanes_with_conflicting_labels`,
  `no_cross_lane_dedup`).
- **Usable-count target.** `--target` (fetch) / `--cap-positions` (self-play)
  count USABLE positions (post quiet-filter → dedup → cap); the committer's exact
  truncation lands the lane on the target exactly (no overshoot). Per-lane target
  2M usable → 8M total.

## The build→finalize change

- `cmd_build` (+ `emit_records_per_game` + the build-era `write_rerun_script`)
  removed. `corpus finalize --in <lane-dir>` recomputes `corpus_sha256` over the
  already-build-ready `lane.bin`, writes/updates the manifest + filter_spec +
  stats, and writes a per-lane `re-run.sh`. NO record transformation.
- `write_rerun_script` is lane-type-aware (reads the manifest): a self-play lane
  emits `selfplay … --cap-seed … --cap-positions … && finalize && quality-gate`;
  a fetch lane emits `fetch --url <source_url> … && finalize && quality-gate`.
- **Manifest schema v1→v2.** Drop `validation_fraction` / `val_fraction` /
  train-val positions; rename `split_seed`→`cap_seed`; `total_positions` = usable
  positions in `lane.bin`; add `source_url` / `target_usable`. The reader
  tolerates schema-v1 (accepts `split_seed` as `cap_seed`, ignores
  `validation_fraction`); lanes are regenerated, not migrated.

## The gate must-PASS-set change

The three must-PASS checks change from {ADR-0003 label-provenance audit,
reproducibility-rerun, **held-out-split integrity**} to {ADR-0003 audit,
reproducibility-rerun, **per-lane dedup-integrity**}. The held-out check is gone
with the split. `check_dedup_integrity` asserts over `lane.bin`: zero exact-FEN
dups (`unique_fens == total_records`) AND ≤ `PER_GAME_CAP` records per game — the
load-bearing defense that every committed lane went through the `LaneCommitter`.
The gate is now FIVE checks (the recorded `dedup_ratios` check was folded into
the must-PASS dedup-integrity check). `check_reproducibility_rerun` digests
`lane.bin` only (no train‖val concat). `store.rs` is untouched, so crash-safety
(byte-0-restart, torn-tail discard, skip-re-seen) is byte-for-byte preserved.

## Reproducibility class (unchanged from ADR-0035 §8)

- Self-play lanes: byte-identical across fresh re-runs AND across worker-count K
  (deterministic from `seed` + `cap_seed` + the knobs). Pinned by
  `tests/corpus_reproducibility.rs` (`rerun_byte_identical`,
  `rerun_byte_identical_across_k` over K∈{1,4,10}, both with the `finalize` step
  wired in) + `tests/corpus_per_game_file.rs`.
- Fetch lanes: a *fresh uninterrupted* fetch from the pinned `source_url` is
  byte-identical; a *resumed* fetch is content/label-equivalent (same FEN+label
  multiset) but its `game_id` provenance tags are path-dependent — the
  pre-existing ADR-0035 §8 "weaker / re-derivable" external-source tier, NOT a
  regression from dropping `dedup_key`.

- **clippy / fmt:** clean — `clippy --all-targets -D warnings` under both default
  and `--features corpus-fetch`; `fmt --check` clean.
- **llvm-cov** (scoped to the new modules' unit tests): `pipeline.rs` **99.64%
  region / 100% line / 100% fn**; `quality_gate.rs` 94% region / 89% line;
  `manifest.rs` 84% region / 85% line (the v1-compat reader paths are additionally
  covered by integration tests). (A full instrumented `--lib` run shows pre-existing
  timing-sensitive corpus tests failing under instrumentation slowdown; all pass
  un-instrumented — `pipeline.rs` has no timing logic.)
- **cargo mutants** on `pipeline.rs` over its unit tests: 30 mutants →
  **17 caught / 7 missed / 6 unviable**. All 7 missed are in `cap_dedup_survivors`
  (the reservoir sampler, copied verbatim from the pre-M6.H2 consumer) + one
  truncation boundary, and are equivalent / spec-immaterial: `144:38 >→>=`
  (`truncate(room)` at `len==room` is a no-op), `184:17 ||→&&` (the `cap==0` path
  is unused — `PER_GAME_CAP=10` — and yields empty either way), and `194 ×4` /
  `195:14` (change *which* subset the reservoir samples; the contract is "≤cap +
  deterministic", both preserved, and lanes are regenerated so there is no
  byte-vs-historical obligation). Matches the documented M6.H reservoir-survivor
  precedent. Confirmed by the blind final review.
- **bench:** `1213649` / d4 `90591` **byte-for-byte** (the engine `evaluate`/search
  is untouched — a free confirmation that the refactor is eval-neutral).
- **Review loops:** plan (2 passes → approved), test-suite (converged after the
  must-fix empty-post-dedup (c)-gap + should-fixes), final (2 passes → approved,
