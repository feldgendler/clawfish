# M4.C — History heuristic

Status: complete (2026-04-30). Third M4 phase. Adds a butterfly-indexed history table (`[side][from][to]` i16, 16 KiB) updated with `+= depth*depth` bonus on quiet-move beta cutoff and matching `-= depth*depth` malus on quiets searched-but-failed at the same node. Layered into M4.B's `negamax_move_order_score` as the score for non-killer quiets in `[-MAX_HISTORY, MAX_HISTORY] = [-16384, 16384]`. ADR-0019 codifies the design.

**Provenance and rebase.** M4.C was developed on parallel branch `m4.c-history-heuristic` (off M4.A) while M4.B was on its own branch. Both have since merged: M4.B at `1771e57` (rebased onto `33a0d0d`), M4.C at the current branch tip (rebased onto `874a215` post-M4.B-follow-up). At rebase, the score-tier scheme was reworked: M4.B's original `KILLER0_SCORE = 200` and `KILLER1_SCORE = 100` (chosen to fit between 0 and the smallest MVV-LVA capture score, with M4.C history projected to land in `[0, 99]`) were bumped to `100_001` / `100_000`, and the comparator's non-quiet branch gained `+ CAPTURE_OFFSET` (= 1_000_000), so that history could use the literature-standard `MAX_HISTORY = 16384` from CPW + MadChess. Compile-time `_SCORE_TIER_INVARIANTS` const-assert in `src/search.rs` pins the relative ordering. Mutation testing prepared but not run (joint M4.B+M4.C overnight campaign tracked in [`docs/mutants-backlog.md`](../mutants-backlog.md)); SPRT runs as the merge gate.

`bench` from production binary at default depth 7: **`bench: 17650332 nodes <NPS> nps`**. Down from M4.B's 22,237,579 nodes — **20.6% node reduction** from history-aware non-killer-quiet ordering composing on top of killers + TT. NPS unchanged.

## What landed

**`src/history.rs` — new module:**

- `pub(crate) const MAX_HISTORY: i16 = 16384;` — saturation cap.
- `pub(crate) struct HistoryTable { entries: [[[i16; 64]; 64]; 2] }` — 16 KiB, `[side][from][to]` butterfly + side dim.
- `impl HistoryTable` with `new`, `clear` (memset via `*self = Self::new()`), `score`, `update` (clamp on add).
- `impl Default for HistoryTable`.
- 12 unit tests (H1–H12) pinning new/clear/score/update including positive/negative clamp boundaries (H5/H6/H7), side-independence (H9), square-independence (H10), 16-KiB layout (H11), and `Send + Sync` (H12).

**`src/search.rs` — score-tier rework + negamax integration:**

- `AlphaBetaMover.history_table: HistoryTable` field added; initialized in `new()`.
- `Search::reset()` body extended additively — M3.B `self.history.clear()` + M4.B `clear_killers(&mut self.killers)` + new M4.C `self.history_table.clear()`.
- **Score-tier rework** (M4.B-merged constants bumped at rebase):
  - `CAPTURE_OFFSET = 1_000_000` — added to non-quiet branch of `negamax_move_order_score` (M4.B comparator).
  - `KILLER0_SCORE = 100_001` (was 200), `KILLER1_SCORE = 100_000` (was 100).
  - `MAX_HISTORY = 16384` (literature standard, restored from the parallel branch's design).
  - `_SCORE_TIER_INVARIANTS` compile-time const-assert pins `CAPTURE_OFFSET > KILLER0_SCORE > KILLER1_SCORE > MAX_HISTORY > -MAX_HISTORY`.
- M4.B's `negamax_move_order_score` and `order_moves` extended with a `&HistoryTable` parameter; the "other quiet" branch (which previously returned `0`) now returns `history_table.score(side, from, to) as i32`.
- Stack-local `quiets_searched: MoveList` accumulator added before the move loop. Quiets that complete recursion without producing a beta cutoff are pushed onto it (with a `debug_assert!(mv.from_square() != mv.to_square())` sentinel guard).
- On quiet-move beta cutoff: M4.B's `update_killers(...)` runs as before, and M4.C now also applies `+depth*depth` to the cutter via `history_table.update(side, from, to, +bonus)` and `-depth*depth` to every prior quiet in `quiets_searched`. The `let side = pos.side_to_move()` read happens at the cutoff site, AFTER the make/unmake balance — the load-bearing comment documents why this point is correct (mover's color, NOT recomputed inside the malus loop).
- `#[cfg(test)] pub(super) fn ordered_moves_for_test(&self, pos)` accessor added; returns the post-comparator sorted move list (without TT-bubble) for HS9/HS12 unit-level tests.
- 16 new M4.C tests (HS1–HS12 + HS3b + HS3c + HS4b + HS8b) pinning the bonus/malus dispatch, capture-exclusion, abort/TT-cutoff/rep/MDP-collapse early-exit history-untouched discipline, side-to-move invariant at root and non-root, saturation clamp integration. M4.B's S22 (`negamax_move_order_score_returns_mvv_lva_plus_offset_for_capture_even_if_matches_killer`) and S23 (`killer_scores_strictly_below_capture_path_output_and_above_max_history`) updated at rebase to reflect the new score-tier scheme. M4.B's S22b updated to acknowledge that "non-killer quiet returns 0" is the empty-history case (full discrimination tested by HS9 + HS12).
- M4.C's `Move::is_quiet` method dropped at rebase (M4.B already lands `is_quiet` as a free function in `src/search.rs`); call sites use the M4.B free function consistently.

## Plumbing / process highlights

**Plan-review converged in 3 passes** (1 pass-1 fired all 3 must-fix items; pass 2 cleared them and 4 of 7 should-fix items; pass 3 cleared the rest with no must-fix remaining → terminated per workflow.md pass-cap rule).

**Test-suite review converged in 2 passes** (pass 1: 1 must-fix on HS5 fixture, 3 should-fix; pass 2: 1 should-fix residual on HS4b's empirical assertion, accepted; verdict `no further substantive issues`).

**Coder slicing was disrupted by an Opus usage-limit hit** mid-test-writing for Slice C. The agent had completed ~95% of the work (test surface + skeleton wiring) before failing; the orchestrator picked up the remaining 5% (the rewritten HS5 fixture, HS4b new test, and HS1 strengthening) directly. The impl phase ran on a Sonnet coder and completed cleanly — the plan was prescriptive enough.

**Test-fixture regressions surfaced post-impl:**
- HS5 originally used `4k3/8/8/8/3b4/8/8/3QK3 w - - 0 1` with `(-INF, INF)` window — no cutoff fired anywhere; test-suite review caught it. Replaced with `4k3/4n3/8/8/8/8/4Q3/4K3 w - - 0 1` (Q+K vs N+K) at window (0, 1): Qxe7+ → Kxe7 returns 0 (insufficient-material short-circuit on K-vs-K) so capture doesn't cut; quiets preserve queen → +688 cp → cut.
- HS6 originally used `depth=2` with `(-INF, INF)` — at non-root sub-nodes the window narrows from the root's full window, and quiet cutoffs DID fire there, updating history. The test was changed to `depth=1` so children = `depth=0` = qsearch (no history update path).
- One pre-existing test (`alphabeta_partial_completion_under_abort_returns_partial_pv_and_score`) had an empirical `assert_ne!(score_cp, Some(0))` that no longer held: history-aware ordering changed the depth-3 startpos best-line score to exactly 0. Relaxed to `assert!(score_cp.is_some())` — the load-bearing assertion is on bestmove being populated, which separately verifies the abort-fallback path returned real data.

**Bench-signature node reduction post-rebase: 20.6% vs M4.B end** (`22,237,579 → 17,650,332`). The marginal gain on top of killers is smaller than the parallel-branch's 51.8% drop vs M4.A (which compared history-alone to no-history-no-killers); SPRT-at-merge measures the empirical Elo.

**Score-tier rebase rework.** The parallel-branch design used `MAX_HISTORY = 16384` (literature standard) with no killer constraints (M4.B was on a separate branch). On rebase, M4.B's already-merged `KILLER0_SCORE = 200, KILLER1_SCORE = 100` initially forced the rebase agent into `MAX_HISTORY = 99` to fit history below killer1. User flagged this in chat (provenance: M4.B's research §6 noted these constants were "arbitrary; can be tuned later"; the `[0, 99]` projection had propagated forward via M4.B's CLAUDE.md update). On user direction, the rebase reworked the score-tier scheme to restore the literature-standard `MAX_HISTORY = 16384`: M4.B's killer constants bumped to `100_001 / 100_000`, and `negamax_move_order_score`'s non-quiet branch added `+ CAPTURE_OFFSET = 1_000_000`. Compile-time `_SCORE_TIER_INVARIANTS` const-assert pins the four-tunable ordering; runtime tests S22 (capture-path-output) + S23 (capture-above-killer-via-CAPTURE-OFFSET) updated.

**Per-game-state lifecycle** carries cleanly: `Engine::reset_for_new_game()` → `Search::reset()` → all three of `self.history.clear()` (M3.B game-history Vec), `clear_killers(&mut self.killers)` (M4.B), `self.history_table.clear()` (M4.C). E46 + the existing M4.A/M4.B-era reset tests all stay green.

**Mutation testing deferred** per user instruction. Joint M4.B+M4.C diff range is documented in [`docs/mutants-backlog.md`](../mutants-backlog.md); survivor triage lands as a follow-up commit on main once the campaign returns.
