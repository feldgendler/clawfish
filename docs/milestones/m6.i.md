# M6.I — Texel tuning harness

**Landed 2026-05-24. Harness lands INERT — `src/texel/` + `src/bin/texel-tune.rs`
are a standalone consumer; `evaluate` byte-identical to `M6.F` (bench `1213649`
/ d4 `90591` byte-for-byte). No SPRT for the harness landing.** The *tuned
weights* ship as a separate diff gated by a mixed-TC SPRT vs `M6.F` per the
verdict ladder — **the operator-run landing step** (the M6.G corpus-materialization
precedent; a ~10h mixed-TC match cannot run in an interactive session). ADR-0037.

## What landed

The single joint-Texel tuning harness for the cumulative M6.B–F deferred-term
weight surface (**~193 linear-core weights**), consuming the four frozen
M6.H2 corpus lanes against game-result labels.

- `src/texel/` library (7 modules: `mod`/`layout`/`params`/`features`/`dataset`/`loss`/`optimizer`/`mixture`).
- `src/bin/texel-tune` CLI (`cache`/`kfit`/`tune`/`mixture`/`apply`/`crosscheck`/`sensitivity`).
- Additive read-only `pub(crate)` feature accessors in `eval/{mobility,king_safety,tier1,pawns}.rs` (share detection with the unchanged scoring functions; `evaluate` untouched ⇒ bench byte-identical).
- `tests/texel_resume.rs` (crash-safe resume integration).
- `bench/m6-params.json` (the tuned vector + K + mixture + sensitivity table + lane sha256s + stopping constants).

## Design (ADR-0037)

- **Frozen reference frame** (Arm A; the tuning-backlog "PST co-tuning" Arm B is deferred): material, 12 PSTs, bishop-pair, mop-up, `EG_SCALE_DEN`, `FIFTY_MOVE_TAPER_FROM`, `PASSED_KDIST_CAP`. Freezing the base pins the K·score gauge.
- **Two scorers** to defeat the shipped-weights cross-check tautology: a parameterized `reference_score_white(pos, &EvalParams)` oracle (validated `== static_eval_white` at shipped weights) + a fast cached linear model `model_score_white` (validated `== reference` at *arbitrary* weights — the tuned regime).
- **Feature model**: per-position `FeatureVec { base_mg, base_eg, mop_up, phase, raw-count coeffs }`; the model mirrors `evaluate_core`'s **single** blend division (two summed f64s ÷ 24 once, not per-term) + mop-up after scale.
- **Optimizer**: full-batch Adam on the closed-form gradient over a disk feature cache; classic coordinate-descent as a cross-check.
- **K** fit once (golden-section) on init weights, frozen; refit per mixture candidate.
- **Init = shipped weights; ridge toward shipped** (NOT literature) + monotonicity smoothing on the monotone tables ⇒ low-signal terms stay near zero rather than shipping un-validated literature values.
- **King-safety: shield + open/semi-open-file ARE tuned** (linear, fire in quiet positions; they moved). Only the **attacker-count S-curve table + the 4 per-kind attacker multipliers are EXCLUDED.** The **primary** reason is structural, not corpus signal: the table is indexed by `units = Σ multiplier_kind · attackers`, and the multipliers ship at **zero** (M6.E inert) ⇒ `units ≡ 0` ⇒ only `KING_SAFETY_TABLE[0]` is ever reachable ⇒ the table is dead by construction. Making the index live needs non-zero multipliers, which either (a) make the index a function of tunable params ⇒ non-linear ⇒ breaks the linear core, or (b) frozen at literature ⇒ the `reference_score_white` oracle diverges from the shipped `static_eval_white` (zero multipliers) ⇒ breaks the faithfulness cross-check. It's the same class as the multiplicative endgame-scale (handled by a separate outer sweep). The **secondary** reason is corpus signal: the quiet filter preferentially removes the sharp king-attack positions (a tactical attack has a large static−qsearch gap) so the high-danger end of the S-curve is under-observed (the Blunder mobility-degeneracy lesson; research §3). Tuning the S-curve properly = a non-linear freeze-and-sweep over the multipliers + accepting under-observation — deferred to a follow-up (a documented partial-obligation, ADR-0037 §3).
- **Endgame-scale** (the one non-linearity): linear core runs at identity scale; the 3 scale numerators are a coarse outer coordinate sweep via the reference scorer. The inner-weights-not-re-optimized-under-swept-scale is a stated two-stage approximation.
- **Mixture meta-optimization** is an optional secondary `texel-tune mixture` subcommand (research rates source-mix second-order); the default `tune` runs a fixed mix and reports per-source held-out loss for operator escalation.
- **Write-back**: `texel-tune apply` rewrites marker-delimited (`TEXEL-TUNABLE-BEGIN/END`) const regions in `eval/data.rs` (structural, idempotent; handles the two non-contiguous `scale` regions).

## Operational robustness (R1/R3/R6/R7)

- **R1** atomic checkpoint (temp → fsync → rename); **R3** resume bit-identical (checkpoint carries {w, best_w, Adam m/v, iter, k, rng, patience, val_hist}). **Load-bearing finding:** the checkpoint uses a binary `f64::to_bits` + CRC encoding — `serde_json`'s shortest-decimal float serialization is NOT bit-exact (1-ULP drift on some f64), which would have silently broken R3.
- **R6** features cached to a disk file, streamed in bounded chunks per epoch (peak heap doesn't scale with corpus size).
- **R7** parallel feature extraction (`std::thread::scope`, deterministic output order); graceful on SIGINT, safe on SIGKILL via R1.
- **Stopping**: held-out plateau (patience-5, restore-best) ∧ integer-quantization floor ∧ max-iter backstop. Never on training loss.

## The full tune run (in-session, on the materialized 8M-position corpus)

The operator had materialized the full corpus (4 lanes × 2.0M = 8.0M positions,
~560 MB). Feature-cache build: **5.3 s** (parallel extraction → 1.3 GB cache,
per-source [2M,2M,2M,2M]). Tune: full-batch Adam, val-fraction 0.2 (game-level
split), patience 5 / eval-every 10 / max-iter 1000, seed 20260524. Result (36 min):

- **K = 0.0057**, **held-out val_loss = 0.1427** (well below the 0.25 constant-0.5
  baseline ⇒ real predictive signal; K≈0.0057 is sane for centipawn-scale scores —
  the literature's "K<0.1 ⇒ bug" is pawn-scale, ≈0.001 in centipawns).
- **Weights recovered cleanly** (`bench/m6-params.json`): N/B/R/Q mobility from zero
  to **monotonic curves** (the monotonicity regularizer worked); outposts ~[7,17,20];
  rook open 29/16 > semi 18/5; passed-pawn EG rank bonus increasing; shield + open-file
  (open king-file −42). **King-safety S-curve table + attacker multipliers stayed all-zero**
  (correctly excluded). **Scale numerators = 64 (identity)** — the optional outer scale
  sweep was not run on the default `tune` path. **Mix = uniform** (the `mixture`
  subcommand is optional/secondary). Sensitivity: all endpoint gradients ~1e-6 (converged).
- **Diagnostic:** the run hit the max-iter cap rather than early-stopping (val improved
  by sub-noise amounts and the integer-quantization-floor didn't latch within 1000 iters);
  the result is a converged vector (tiny gradients). A future run can lower max-iter or
  tighten the val-plateau tolerance — a hyperparameter note, not a correctness issue.
- **Apply pipeline validated end-to-end:** `texel-tune apply` → rebuild produced a LIVE
  engine (bench **1411314** ≠ 1213649, proving the tuned weights take effect + the codegen
  emits valid Rust); reverting restored bench **1213649** (data.rs differs from HEAD by
  only the 18 comment-marker lines — zero const-value change). The committed harness ships
  INERT; the tuned `bench/m6-params.json` is committed for the operator to `apply` + SPRT.

## Operator landing step (the verdict ladder)

The land/revert decision is operator-gated by a mixed-TC SPRT vs `M6.F`:

1. **H1-accept** (CI lower ≥ 5): `texel-tune apply` the tuned params, rebuild, tag `M6.I` at the tuned build.
2. **Small-but-not-regression** (mean ≥ 5 ∧ CI lower > −10): ship tuned, retrospective notes inconclusive SPRT.
3. **Marginal-positive** (mean ≥ 0 ∧ CI lower > −10): ship tuned with caveat.
4. **Regression / wide-CI negative**: revert — M6 ships at `M6.F` (deferred terms stay zeroed; no literature values written), `M6.I` tag at `M6.F`'s commit.

Re-run: `bench/corpus/*/re-run.sh` materializes the corpus; `bench/m6-params.json`'s re-run reproduces the tuned vector; `scripts/sprt.sh sprt M6.F` runs the gate.

## Lessons

- **The cross-check tautology** (caught in plan review): validating a feature model only at shipped weights — where every deferred term is zeroed — proves nothing about the tuned regime. The two-scorer design (reference oracle + fast model validated against it at arbitrary weights) is the fix.
- **f64 single- vs per-term blend division** is numerically identical (division distributes); the truncation-order concern is real only against the *integer* engine eval, validated by the model-vs-reference rounding check, not a same-precision self-comparison.
- **King-safety's attacker S-curve is excluded for a *structural* reason, not "no signal"** — the table index is a frozen-to-zero function of the (inert M6.E) multipliers, so the table is unreachable; making it live needs a non-linear outer sweep + a baseline change. (The quiet-corpus under-observation of the high-danger range is a real but *secondary* reason.) Shield + open-file king-safety, being linear and present in quiet positions, ARE tuned. The earlier "untunable on a quiet corpus" framing was imprecise — corrected here and in ADR-0037 §3.
- **Float serialization is not bit-exact** — R3 reproducibility needs a binary `to_bits` checkpoint, not JSON.
