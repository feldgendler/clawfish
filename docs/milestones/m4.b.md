# M4.B — Killer moves

Status: complete (2026-04-29 commit; rebased onto main + SPRT-validated 2026-04-30). Second M4 phase. Adds two killer slots per ply, updated on quiet-move beta cutoffs and folded into negamax move ordering between captures/promos and remaining quiets. Builds on M4.A (TT + TT-move-first ordering); does not touch qsearch.

## What landed

**`src/search.rs` — additions:**

- `pub(crate) struct AlphaBetaMover` gains `killers: [[Move; 2]; MAX_PLY]`. `Move` is `repr(transparent)` over `u16`, so the table is exactly 256 bytes (fits in L1; matches research §8's recommended shape with no `Option<Move>` 2× memory penalty). Sentinel = `Move::default()` (`bits() == 0`); never collides with a real move because movegen never produces `from == to`.
- Free helpers (all `pub(crate)` and directly unit-testable, M3.D `negate_window` precedent):
  - `is_quiet(mv: Move) -> bool` — `matches!(mv.flag(), Quiet | DoublePush | KingCastle | QueenCastle)`.
  - `update_killers(killers, ply, mv)` — shift-on-distinct: if `mv == killers[ply][0]` no-op, else shift slot-0 to slot-1 and write `mv` to slot-0.
  - `negamax_move_order_score(mv, pos, killer0, killer1) -> i32` — wraps `mvv_lva_score`; non-quiet returns capture/promo score; quiet matching killer0 returns `KILLER0_SCORE`, killer1 returns `KILLER1_SCORE`, otherwise 0.
  - `order_moves(moves_vec, pos, killer0, killer1, tt_move)` — pure function: sort by `negamax_move_order_score` descending, then promote TT move to index 0 if found (idx != 0 guard). Replaces M4.A's inline step-10 body.
  - `clear_killers(killers)` — single-line zero-fill; named helper so all three call sites (per-go reset, per-iteration reset, `Search::reset`) lower through one mutation surface.
- Constants `KILLER0_SCORE = 200`, `KILLER1_SCORE = 100`. Pinned by S23 against the runtime-computed `mvv_lva_score(QxP, _) = 287` (under our `victim × 16 − attacker` formula at search.rs:861).
- `negamax` step 10 (move ordering) replaced inline body with `order_moves(...)` call.
- `negamax` step 11 (cutoff branch) gains `if is_quiet(mv) { update_killers(...); }` inside the `alpha >= beta` arm before the `break`.
- `Search::go` per-go reset and per-iteration reset both call `clear_killers(&mut self.killers)` at the end of their respective blocks.
- `Search::reset` calls `clear_killers(&mut self.killers)` after `self.history.clear()`.
- `#[cfg(test)] killers_for_test` and `set_killers_for_test` accessors mirror `pv_root_for_test` / `set_tt_for_test`.
- 23 unit + integration tests (S14–S29 with sub-IDs S22b, S24b–f, S25b) covering: flag-arm coverage of `is_quiet`, all four `update_killers` shift cases, `negamax_move_order_score` per-arm, `KILLER0_SCORE` boundary discipline against runtime-computed `mvv_lva_score(QxP)`, `order_moves` TT-promotion + idx-0-no-op + zero/absent-tt + killer-above-quiet-below-capture + TT-killer overlap single-occurrence + stale-killer-bits-no-op, integration `negamax_records_quiet_killer_on_beta_cutoff` (scans all plies; panics with diagnostic if no killer fires) + `negamax_does_not_record_capture_on_beta_cutoff`, `negamax_killer_observed_in_ordering_at_sibling_node` (two-run differential at depth=3 with `killers[2][0]` pre-set), `clear_killers_zeroes_pre_populated_table`, `search_reset_clears_killers`, `search_go_clears_killers_at_per_go_entry`.

**Two test surface shifts caused by killer ordering** (documented as M3.A-calibration-log pattern: M4.B's qualitative ordering shift breaks existing tests relying on M3-era search shape; adjusting fixtures, not implementation, is the right call):

- `alphabeta_partial_completion_under_abort_returns_partial_pv_and_score` (M3.E test): killer ordering shifted the depth-3 startpos negamax-return snapshot. The test's "score must NOT be 0 (abort sentinel)" assertion couldn't distinguish "real 0 from symmetric startpos" from "abort-contamination 0". Fixture switched to Kiwipete (asymmetric position; genuine eval reliably non-zero).
- S26 (`negamax_killer_observed_in_ordering_at_sibling_node`): initially picked the lexicographically-last quiet from white-to-move startpos's legal-move list and stored it at `killers[1][0]`, but ply=1 is black to move at depth-3 from startpos — a white move's bits never matched any of the 20 ply-1 sibling positions' legal moves; the killer was silently ignored, node-count differential = 0. Corrected: pre-set `killers[2][0]` (white-to-move at ply=2). Side-to-move discipline now documented in the test's doc-comment.

**Implementation slice (Sonnet) hit org-wide monthly limit mid-task.** The agent completed steps 1–6 (helpers filled, negamax step 10 + step 11 rewired, lifecycle resets wired) but did not reach step 7 (remove `#[ignore]` markers) or step 8–10 (verification + bench). **Helper extractions follow M3.D `negate_window` + M3.E `aborted_fallback_result` precedent.** Each new helper is a named free function unit-testable in isolation with synthetic inputs, so cargo-mutants can target the helper's body rather than indistinguishable inline literals at multiple call sites. The plan §8 mutation-prep table enumerates ~12 catchable surface points covering all five helpers + the negamax deltas + the lifecycle resets.

**`Move::default()` sentinel discipline mirrors the TT's `u16 == 0` discipline.** No `Option<Move>` wrapper needed because movegen never produces `a1→a1` moves. 256 bytes for the killer table fits comfortably in L1.

**Bench determinism preserved.** `Search::go` per-go and per-iteration `clear_killers` calls + `Engine::reset_for_new_game` (per-bench-position via `handle_bench`) ensure killers do not leak across bench positions. The bench signature is reproducible across invocations.

## Lessons learned

_(populated post-final-review and SPRT.)_

Already captured:

- **Side-to-move discipline in killer-table tests.** When pre-populating `killers[ply][0]` for ordering tests, the chosen move must be legal at the side-to-move at that ply. White-side moves stored at black-to-move plies are silently ignored (legality-by-non-match invariant — by design). Pinned by S26 + S24f.
- **M3-era tests relying on symmetric-startpos eval scores need refresh under M4-era ordering.** Killer ordering changes which iteration's snapshot becomes the partial-completion fallback; symmetric-startpos legitimate evals can be exactly 0, defeating regression checks framed as "score != 0". Asymmetric-position fixtures (Kiwipete) are durable.
- **Implementation-slice agent can hit usage limits mid-task.** Orchestrator picked up the work directly, finished the remaining steps (un-ignoring tests, fixing two test breakages, capturing bench). The plan's prescriptive structure made this hand-off seamless.
