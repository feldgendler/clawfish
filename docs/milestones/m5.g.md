# M5.G — Singular extensions (retrospective)

Seventh M5 sub-phase. Adds **per-node singular-extension verification** at non-PV interior nodes whose TT-Lower entry has sufficient depth: search the TT move at `depth + 1` when verification confirms it dominates every alternative. Composes against the now-stable post-M5.F TT.

ADR: [`docs/decisions/0029-singular-extensions.md`](../decisions/0029-singular-extensions.md). Plan: [`docs/plans/m5.g.md`](../plans/m5.g.md). Research: [`docs/research/m5-singular-extensions.md`](../research/m5-singular-extensions.md).

## What landed

Three new constants — **`SE_MIN_DEPTH = 6`** (v2 retune, Xiphos default; v1's literature default = 8 SPRT-failed and was retuned), `SE_MARGIN_PER_DEPTH = 1` (Xiphos / Ethereal default), `SE_TT_DEPTH_DELTA = 3` — plus the compile-time invariant `const _: () = assert!(FFP_MAX_DEPTH < SE_MIN_DEPTH)` clustered with the existing `FFP_MAX_DEPTH < LMR_MIN_DEPTH` invariant.

Three pure helpers, per the M3.D `negate_window` / M5.C `late_move_reduction` / M5.D `ffp_pruned_bound` precedent:

1. **`singular_beta(tt_score, depth) -> i32`** — `(tt_score − depth · 1).max(−(MATE − 1))`. Saturating subtraction; the floor is defense-in-depth (clause 8 of the eligibility predicate makes the underflow case unreachable in production).
2. **`verification_depth(depth) -> u32`** — `(depth − 1) / 2`. Caller's `depth >= SE_MIN_DEPTH` is the only protection against `u32` underflow at `depth == 0`; debug-asserted.
3. **`singular_extension_eligible(...)` (9 conditions)** — re-entrancy guard (`excluded_move.is_none()`); root exclusion (`ply > 0`); non-PV (`!is_pv`); not-in-check (`!in_check_flag`); depth gate (`depth >= SE_MIN_DEPTH`); Lower bound (clause 6); TT depth fresh (`tt_depth >= depth − 3`); mate-score guard (`tt_score.abs() < MATE_IN_MAX_PLY`); non-zero TT move (clause 9). All clauses pure-function-testable. Marked `#[allow(clippy::too_many_arguments)]` per ADR-0029 §4.

Six production-side modifications in `negamax`:

1. **`excluded_move: Option<Move>` parameter** added to `negamax` and `negamax_for_test` after `allow_null`. ~70 existing call sites mechanically pass `None`. The verification call passes `Some(moves_vec[0])`.
2. **`TtProbeSnapshot` struct** captures `(tt_move, bound, depth, score)` (ply-adjusted) at step-7's probe; held in `Option<TtProbeSnapshot>` for use at step 12.5.
3. **Three `excluded_move.is_none()` TT-side-effect guards**:
   - **Step-7 cutoff branch** (`src/search.rs:1388`). Load-bearing — without this guard, the verification frame's same-zobrist Lower-bound TT entry self-cuts on `tt_score >= beta_verif = singular_beta = tt_score − depth_parent` (always true for `depth_parent >= 0`), defeating SE entirely.
   - **Step-9 NMP TT-store** (`src/search.rs:1498`).
   - **Step-14 main TT-store** (`src/search.rs:1816`).
4. **Move-loop excluded-move skip**: `if Some(mv) == excluded_move { continue; }` as the first statement of the loop body, before `child_is_pv` / `quiet_index` / FFP / LMR work.
5. **Per-iteration extension**: `let move_extension: u32 = if i == 0 { tt_move_extension } else { 0 };`. Non-LMR `search_child` argument changes from `depth - 1` to `depth - 1 + move_extension`. LMR and FFP branches untouched (depth-disjoint via the new compile-time invariant; per-iteration disjoint via `i == 0` vs `i >= 1`).
6. **SE block at step 12.5**: between move ordering and the move loop. On verification fail-low (`verif_score < singular_beta`), `tt_move_extension = 1` and the `#[cfg(test)] se_extensions` counter increments. The verification call passes `is_pv = false`, `allow_null = true`, `excluded_move = Some(moves_vec[0])`, `(s_beta − 1, s_beta)` null window. **Lazy `in_check(pos)`**: only evaluated as the predicate's 4th argument when both the let-Some on the snapshot and `moves_vec[0].bits() == snapshot.tt_move` short-circuit-pass — frames without a TT hit, or where the TT move was demoted by ordering, never pay the in_check cost.

New surface:
- `pub(crate) fn singular_beta`, `pub(crate) fn verification_depth`, `pub(crate) fn singular_extension_eligible` helpers.
- `TtProbeSnapshot` struct (private to `negamax`).
- `excluded_move: Option<Move>` parameter on `negamax` / `negamax_for_test`.
- `#[cfg(test)] se_extensions: u32` counter + `se_extensions_for_test()` accessor.
- `#[cfg(test)] se_tt_move_search_depth: Option<u32>` recorder + `se_tt_move_search_depth_for_test()` accessor (records the depth at which the TT-move's child was actually searched when SE fires).
- `#[cfg(test)] set_aborted_for_test(bool)` test helper.
- 41 new tests across `src/search.rs::tests` (22 helper-level + 2 property tests + 17 integration).

No changes to `src/mov.rs`, `src/position.rs`, `src/eval.rs`, `src/movegen/`, `src/tt.rs`, or any other file outside `src/search.rs`.

## Implementation highlights

- **Plan-review took 5 passes to converge.** Each prior pass surfaced new must-fix doc-consistency items as the design itself was refined. The most consequential: pass-2's discovery that the verification frame's step-7 TT cutoff fires every time on the same-zobrist Lower entry, defeating SE entirely if not suppressed. The plan v1 had misread research §5.2 as covering this case; v3 corrected with the load-bearing `excluded_move.is_none()` guard, and v4–v5 cleaned up consequent doc consistency.

- **Test-suite review took 2 passes to converge.** Pass 1 found 4 must-fix coverage gaps: `>= 1` instead of `== 1` (allowing the `tt_move_extension = 1 → 2` mutant to survive), missing integration tests (`_sets_extension_when_verification_fails_low`, `_skips_extension_when_verification_fails_high`, `_extension_increments_child_depth_by_one`, `_does_not_extend_non_tt_moves`, `_extension_does_not_double`), a tautology test (`_skips_extension_at_singular_beta_exactly` only computed `singular_beta` arithmetic without invoking negamax), and a conditional abort assertion (`_aborts_during_verification_propagate_correctly` was effectively a no-panic smoke test). All four addressed in pass 2; loop converged with 2 should-fix items + 2 nits surfaced for awareness (boundary `verif_score == s_beta` test, vacuous-pass concern on the fail-high test).

- **Final review took 2 passes to converge.** Pass 1 flagged the `in_check_se` eager read at every non-leaf frame as a should-fix (real perf concern at low depths where SE never fires). Resolution: lazy via Rust let-chain `&&` short-circuit on the snapshot-presence and TT-move-match clauses; `in_check(pos)` becomes a function-argument evaluated only after the cheap clauses pass. Pass 1 also flagged the deferred-mutants plan as under-specified (recorded in `docs/tuning-backlog.md`), and the `_does_not_extend_non_tt_moves` test name as misaligned with content (renamed to `negamax_se_below_min_depth_does_not_record_extension_depth`). Pass 2 verified all three; verdict `no further substantive issues`.

- **Bench signature unchanged** because `SE_MIN_DEPTH = 8 > BENCH_DEFAULT_DEPTH = 4`. SE is invisible at the bench corpus's depth. Empirical signal from the deeper SPRT tournament + STS at 1000ms/move is where the +Elo and +tactical-credit show.

- **96.7% mutation catch (58/60 viable)** is below M5.F's 100% but above the 95% target. Both missed mutants are at the same expression (`s_beta - 1`) and reduce to one underlying gap (no boundary-engineering test). Documented as a coherent follow-up campaign rather than a regression vs M5.F.

## Lessons learned

1. **Plan-review loops past pass 3 are sometimes necessary.** Workflow says the cap is pass 3 "when no must-fix items remain" — but for M5.G the design itself was being refined across passes (the verification-frame TT cutoff issue surfaced at pass 2 was a real bug in the planned design, not a doc inconsistency). The loop ran 5 passes; the 4th–5th passes were doc-cleanup convergence. Each pass cost ~1–2 min of wallclock + ~5K tokens of review context. Acceptable cost for a load-bearing design discovery.

2. **The chess-coder follow-up loop for must-fix items works well.** Pass 1 found 4 gaps; pass 2 verified them addressed in one round-trip. The orchestrator's role was to relay the reviewer's concerns concretely (action list with #1, #2, ..., not just "fix what the reviewer said") and to anticipate which fixes were genuinely structural vs which were one-line edits.

3. **Lazy-dup on `in_check` matters even at SE's high depth gate.** SE_MIN_DEPTH = 8 means SE itself fires at deep nodes — but the SE block's eligibility check runs at every non-leaf frame, regardless of depth, before failing on the depth gate. The eager `in_check(pos)` read at every non-leaf frame would have been a subtle NPS regression invisible at the bench corpus (depth 4, no SE) but visible at SPRT depths. Final-reviewer pass 1 caught this; the let-chain short-circuit on the cheap snapshot-presence + TT-move-match clauses captures the dominant savings.

4. **Mutation-testing's two missed mutants reduced to one gap.** The `s_beta - 1` → `+` and `s_beta - 1` → `/` mutants both miss the same exact-equality boundary case (`verif_score == s_beta`). One boundary test catches both (and the `<` → `<=` mutant from test-suite review). Future SE work that adds the boundary test will close the gap retroactively.

5. **STS picks up tactical signal that bench can't.** STS +214 credit (well above ±68 noise) is a robust positive tactical signal even though bench is unchanged. The STS suite runs at 1000ms/move per position, reaching depths well above SE_MIN_DEPTH on most positions; bench at depth 4 is too shallow to see SE.
