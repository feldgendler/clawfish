# M6.D — Piece mobility (retrospective)

Fourth M6 sub-phase. Lands the **piece-mobility evaluation infrastructure**
(N/B/R/Q pseudolegal-attack count ∩ mobility area, per-kind MG/EG tables,
computed live in `evaluate_core`, never cached) **shipped score-neutral** —

to the M6.I joint-Texel reshape. The Stockfish-HCE literature defaults

transfers here" confirmation, M6.B→M6.C→M6.D). M6.D lands behaviorally
inert vs `M6.C` (bench `1213649` byte-for-byte).

## Lessons learned

- **"Co-calibrated-elsewhere ≠ transfers here" is now a three-phase law
  (M6.B→C→D).** The Stockfish-HCE mobility set is a *single coherent
  Texel run* (the strongest possible "coherent source"), yet it
  catastrophically over-magnitudes (−131 all-four; even the best single
  kind {N} ≈flat-negative) on our PeSTO PSTs. No coherent-source cross-engine
  weight transfer onto a different eval baseline is safe to ship raw — the
  shape, not just the scale, is baseline-specific.
- **The over-magnitude offender was the raw EG *magnitude*, not the
  predicted PST double-count.** Research §8 / the secondary-gate per-theme
  deltas pointed at knight/bishop (PST overlap); the per-kind screen showed
  the *sliders* (huge `ROOK_EG`/`QUEEN_EG`) dominate and `{N}` (tiny
  `KNIGHT_EG`) is ≈harmless. A per-theme STS prior is directionally useful
  but the per-kind SPRT screen is the ground truth — run it.
- **The co-scale probe can *invert* the rescue hypothesis.** ×0.5 made it
  *worse* (−220 vs −131), not better — a sharper scale-invariant signal
  than M6.C's plateau/migration. A global multiplier on a wrong-shaped term
  is not merely non-rescuing; it can actively degrade. Decisively converts
  M6.I's mobility brief to "reshape (re-derive per-kind tables against our
  PeSTO PSTs), do not rescale."
- **The progressive-send vs raw-pipe E39 trap.** The completed-depth-3
  startpos move is `d2d4` via the test harness (waits for `bestmove`) but a
  raw `…go depth 3\nquit` pipe returns `e2e4` — the M3.E inter-iteration
  early-abort artifact. Always derive depth-pinned fixtures via the
  wait-for-bestmove harness, never a raw pipe (documented in-test so it is
  not "corrected" to the pipe value).
- **An eval-magnitude screen surfaces latent equivalent-mutant tests.** The
  M6.D screen's eval reshuffle exposed that `negamax_passes_allow_null_false`
  pinned a *provably non-discriminating* firing count (an equivalent mutant
  that was inert even at M6.C). The reachability-witness redesign is a
  strict strengthening that the score-neutral floor *keeps* (eval-
  independent), not reverts — the M6.C keep-the-collateral-correctness-fix
  precedent. Likely other hand-built search fixtures share latent
  non-discrimination (a tooling-backlog candidate, alongside the M6.C
  opponent-not-in-check audit).
- **Score-neutral landing keeps the milestone moving (M6.B/M6.C, third
  time).** M6.D lands the infrastructure (term math, mobility-area semantic,
  the boundary discipline, the test surface) inert; M6.E builds on the
  attack-bitboard reads; M6.I joint-Texel reshapes the mobility weight set
  jointly with the M6.B ISO/DBL/BWD + CONN rescale and the M6.C passed-pawn
  reshape. No Elo lost (inert vs `M6.C`); the cost was ~the screen-SPRT
  compute that produced a precise, documented per-kind M6.I brief instead
  of a blind +X.
