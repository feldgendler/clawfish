# M3.D — Quiescence search

Status: complete (2026-04-29). Replaces M3.C's `depth == 0 → evaluate(pos)` short-circuit with `depth == 0 → qsearch(...)`. Restores tactical correctness past the negamax horizon by extending captures + queen-promotions until the position is "quiet". No new ADR — qsearch design fully covered by ADR-0016 §9 + the prior-art research's headline calls.

**20-0 sweep** vs `M3.A` at fixed depth 4 (preserves M3.C's ceiling result; secondary signal: 7 of 20 games adjudicated by mate detection vs 0 in M3.C — qsearch's mate-extension visible). **10.87 Mnps** single-threaded depth-8 from startpos (+27% vs M3.C's 8.55 Mnps; total node count dropped 28% via better mate-distance pruning effectiveness). Score `cp 8` from depth-8 startpos with PV `e2e4 e7e5 b1c3 b8c6 g1f3 g8f6 d2d4 f8d6` (Italian-style opening line). 680 lib + 5 integration tests passing in BOTH debug and release.

## What landed

**Quiescence search**:

- **`AlphaBetaMover::qsearch`** private method in `src/search.rs` (~120 lines). Fail-soft negamax leaf-extension with the plan §3 step ordering:
  1. Per-frame nodes increment + cancellation poll (4096-node cadence — the sole counter for depth==0 leaves; negamax delegates to qsearch BEFORE its own increment, preserving M3.C's "1 leaf = 1 node" budget contract under `go nodes <N>`).
  2. Mate-distance pruning (may short-circuit before stand-pat is computed; safe).
  3. In-check triage via `in_check(pos)`.
  4. Stand-pat lower-bound (only when NOT in check; `>= beta` early-return; `> alpha` tightens; `best_init = stand_pat` on not-in-check, `-INF` on in-check).
  5. Move generation: full list in check (evasions), captures + queen-promos otherwise (filter from `generate_moves` output).
  6. Terminal handling: in-check + empty → `-(MATE - ply)` (mate); not-in-check + empty → return `best_init = stand_pat` (false-stalemate guard per CPW pitfall §10.7).
  7. MVV-LVA ordering (reuses M3.C's `mvv_lva_score`).
  8. Fail-soft recursion with post-recursion abort propagation.

- **`qsearch_move_filter`** free function. Accepts `Capture | EnPassant | QueenPromo | QueenPromoCapture`. Excludes under-promotions (Knight/Bishop/Rook) and under-promo-captures despite the latter being captures — under-promotion's tactical value is rare enough at M3 strength that the extra qsearch breadth isn't justified.

- **`qsearch_for_test`** `#[cfg(test)] pub(super)` thin forwarder — mirrors `negamax_for_test` from M3.C. Required because `qsearch` is private; tests cannot call private methods directly.

**`negamax` restructure** (per plan §5):

- M3.C step 1 (`self.nodes += 1; cancellation poll`) **moves to M3.D step 3, conditioned on the non-leaf path** (only frames where `depth > 0` increment + poll).
- M3.C step 2 (`pv.clear_ply(ply)`) **moves to M3.D step 1** so it runs even on the leaf path — otherwise a prior subtree's stale `lengths[ply]` could cause the parent's `pv.update` to copy stale child PV moves.
- M3.C step 5 (`if depth == 0 { return evaluate(pos); }`) **becomes M3.D step 2** (`if depth == 0 { return self.qsearch(pos, alpha, beta, ply, ctx); }`), moved before the nodes increment.
- M3.C's body from `let mut ml = MoveList::new();` (currently `src/search.rs:387`) through end (line 451) **preserved verbatim**, including the three load-bearing M3.C must-fixes: (a) empty-searchmoves-in-check pre-triage, (b) post-recursive-call abort check, (c) `root_score` lockstep update at `ply == 0`.

### `negate_window` refactor — closing the v2 mutation gap

The v2 surface had 1 surviving mutant: `delete - in AlphaBetaMover::qsearch` at the recursive call (passes `beta` instead of `-beta` as child's alpha). After several iterations failed to construct a fixture where the divergence propagates to parent's returned score (M3.D fixtures are 1–2 plies; broken's degenerate child window is masked by parent stand-pat dominance or chain symmetry; the property-test approach asserting fail-soft score invariance under window narrowing was unsound because alpha-beta legitimately changes scores across windows), the **structural fix** dropped in v3: extract the open-coded `(-beta, -alpha)` bound-negation into a named module-level helper:

```rust
fn negate_window(alpha: i32, beta: i32) -> (i32, i32) {
    (-beta, -alpha)
}
```

Both negamax and qsearch's recursive calls now use `let (child_alpha, child_beta) = negate_window(alpha, beta);` instead of the open-coded `(-beta, -alpha)` literal. This isolates the bug-prone bound-negation in a pure function that's directly unit-testable. `negate_window_negates_both_bounds_and_swaps_them` pins both `delete -` mutations on the helper's body via asymmetric and symmetric window cases — verified empirically by manual application of each mutation (test fails in seconds against either broken form).

Lessons:

- **Structural fix beats exclusion.** When a mutation is structurally hard to catch at the call site, refactoring the bug-prone pattern into a named, isolated helper makes the mutation catchable via direct unit tests. The `.cargo/mutants.toml` `exclude_re` rule briefly considered for this gap was rejected because line-number-anchored regexes are fragile to refactoring (any unrelated edit shifting the line silently breaks the exclusion).
- **`negate_window` discipline forward.** The same pattern (`(-beta, -alpha)` open-coded at recursive call sites) recurs in M4+ search refinements (PVS, null-move pruning, LMR — each adds new recursive call sites with bound transformations). Future call-site additions should re-use `negate_window` rather than re-introduce the open-coded form.

### M3.C-precedent fixture-validation discipline

The plan's §10 "M3.C mate-in-2 fiasco" lesson translated into runtime fixture validation in every test where a chess-geometry claim is load-bearing:

- `qsearch_in_check_with_no_legal_moves_returns_mate`: docstring + runtime asserts `in_check(pos) == true` and `generate_moves` count == 0.
- `qsearch_does_not_stand_pat_in_check`: docstring + runtime asserts `in_check(pos) == true` and `evaluate(pos) > 500` (so the differential `< eval - 100` has signal).
- `qsearch_extends_capture_to_resolve_material`: runtime asserts the capture is legal AND the captured piece has no defenders (post-make recapture count == 0).
- `negamax_horizon_calls_qsearch_not_evaluate`: runtime asserts Qxd5 is legal, Bxd5 is legal post-Qxd5, AND `-evaluate(pos_after_qxd5) > 700` (so the `score < 700` bound has signal — without runtime validation, the fixture's "trap" framing is unverified).
- `qsearch_recursive_ply_increments_for_mate_score`: runtime asserts Qxd8 is legal AND post-Qxd8 black is in check AND has 0 legal moves (mate verified, not asserted from chess intuition).

This pattern should generalize to all future tactical-fixture tests across M3.E and M4+.

### Fast iteration > slow re-runs

The user's mid-flight nudge ("can't you just check whether ONE specific mutation is caught, instead of re-running mutation testing for hours?") shifted the workflow. Manually applying a mutation via Edit + running a targeted `cargo test --lib qsearch_*` test takes seconds. This collapsed an hour-long iteration into a minute-long one and made the structural-undetectability conclusion empirically verifiable rather than speculative. Codified in `.cargo/mutants.toml`'s top-of-file comments under "Triaging a single survivor" — try the targeted-test-against-applied-mutation loop FIRST, fall back to full cargo-mutants only if the survivor's nature is unclear.
