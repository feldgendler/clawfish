# M5.F — Qsearch in TT (retrospective)

Sixth M5 sub-phase. Adds **TT probe + store inside `qsearch`**, closing the +5–15 Elo gap acknowledged in ADR-0018 §6 when M4.A first shipped TT support but deliberately scoped qsearch out. M5.E (qsearch correctness) landed first so the TT does not memoize qsearch holes.

ADR: [`docs/decisions/0028-qsearch-in-tt.md`](../decisions/0028-qsearch-in-tt.md). Plan: [`docs/plans/m5.f.md`](../plans/m5.f.md). Research: [`docs/research/m5-qsearch-in-tt.md`](../research/m5-qsearch-in-tt.md).

## What landed

Five production changes:

1. **TT probe at qsearch entry (step 2.5)**, after MDP + before in_check triage. Mirrors negamax's MDP-then-probe ordering so the probe sees the tightened window. No depth comparison: any TT entry's depth is at least qsearch's notional 0. Three cutoff arms: `Exact → return tt_score`, `Lower if tt_score >= beta → return tt_score`, `Upper if tt_score <= alpha → return tt_score`. Retains `tt_move` for ordering on no-cutoff.

2. **TT store at all six real-result return points** via the `qsearch_store_and_return(pos, score, bound, best_move, ply)` helper method — abort guard, mate-score adjustment, depth-0 convention, and tt.store call centralised in one place. Per-path bound per ADR-0028 §"Per-path store table": Lower for stand-pat fail-high (path A), Exact for true stalemate (B) and mate at horizon (D), helper-classified Lower/Upper for single-reply extension (C) and completed loop (F), Upper for false-stalemate guard fall-through (E). MAX_PLY ceiling (path X) and abort (path Y) skip the store.

3. **`qsearch_tt_bound_for_completed_node(best, beta) -> TtBound` helper.** Returns Lower if `best >= beta`, else Upper. Never Exact for non-terminal qsearch — Stockfish 45e5e65 precedent: qsearch's restricted move set means an "exact" classification overstates precision. Terminal Exact stores (paths B and D) bypass the helper.

4. **Empty-slot discriminator change** in `src/tt.rs`: `is_empty()` now `self.key == 0` (sole field). The store-side `debug_assert!(data.depth >= 1)` is replaced with `debug_assert!(key != 0)`. Forward-planned in `src/tt.rs:222` comment; required because qsearch entries store `depth = 0`. Polyglot Zobrist key of any reachable position is non-zero with probability `1 − 2⁻⁶⁴`.

5. **Move-loop `cutoff_move: Option<Move>` accumulator** with first-cut-wins guard. The under-promo inner loop sets `cutoff_move = Some(under_mv)` unconditionally; the outer cutoff guards with `if cutoff_move.is_none() { ... }` so the under-promo's record (the actually-cutting rook/bishop variant) is preserved when both cutoff sites trigger at the same `alpha >= beta` value.

New surface:
- `pub(crate) fn qsearch_tt_bound_for_completed_node(best: i32, beta: i32) -> TtBound` helper.
- `qsearch_tt_probes: u32` and `qsearch_tt_stores: u32` `#[cfg(test)]` counters with `_for_test` accessors.
- `qsearch_store_and_return(pos, score, bound, best_move, ply)` private method.
- 36 new tests across `src/tt.rs::tests` (9) and `src/search.rs::tests` (27).

No changes to `src/mov.rs`, `src/position.rs`, `src/eval.rs`, movegen, or the `TranspositionTable` struct.

## Implementation highlights

- **Bench delta exceeded the prediction by ~2×.** Plan forecast −5% to −15% (research §11 cited Crafty's "wash" precedent for fast-eval engines); actual −26.9%. The pattern matches M5.A NMP (66% reduction vs 30–50% prediction): high-quality M4 ordering (TT-move-first + killers + history + aspiration + the new qsearch TT probe) compounds beyond the literature's reference baselines. Each new pruning/caching layer benefits from the prior layers' first-move ordering quality.

- **Two test fixture corrections during impl.** (1) `qsearch_tt_store_completed_loop_lower` original fixture had `beta=10` while stand-pat was ~620cp, so path A fired before the move loop reached the cutoff; changed `beta` to 700 (sits between stand_pat ≈620 and post-capture score ≈1025). (2) `qsearch_tt_move_used_when_in_check` original used `alpha=-INF, beta=INF` which can't produce ordering-sensitive node-count differences; changed to bounded window where Kxe2 cuts and ordering matters.

- **One pre-existing test re-pinned**: `negamax_does_not_mid_loop_store_under_partial_iteration`. M5.F's TT probe efficiency reduced kiwipete depth=1 node count below the 4096 abort cadence, so iteration 1 now completes instead of aborting mid-iteration as it did pre-M5.F. The test was widened to accept either outcome (marker survives = iter-1 aborted, OR a valid depth=1 entry = iter-1 completed); the structural invariant (no mid-loop partial store) is still verified.

- **First-cut-wins for `cutoff_move` tracking.** The M5.E #3 under-promo inner loop's `alpha >= beta` break sets `cutoff_move = Some(under_mv)` unconditionally; the outer move-loop cutoff guards with `if cutoff_move.is_none() { ... }`. This composes correctly: the standard non-under-promo case has only the outer break (cutoff_move is None at break time, so the guard is satisfied); the M5.E corner case has both, and the under-promo's more-specific cutter (rook/bishop synthesized from queen-promo's stalemate child) is the move that gets stored. Without the guard, the queen-promo would silently overwrite the under-promo's record.

- **Asymmetry: store-side no-Exact, probe-side Exact-IS-honored.** The "no Exact in non-terminal qsearch" rule (Stockfish 45e5e65) lives at the store side. The probe accepts an `Exact` cutoff because the only sources of stored Exact entries are negamax-tier (depth ≥ 1, full-width) and FIDE-definite-terminal qsearch (true stalemate, mate at horizon). Both are sound to use for cutoffs. Non-terminal qsearch never emits an Exact — the store discipline prevents bad Exacts from existing. Documented in ADR-0028 §5.

## Plumbing / process highlights

- **Three plan-review passes converged.** Pass 1 raised 2 must-fix (probe placement vs MDP — diagram had the probe before MDP but rationale assumed after; path-F best_move tracking unspecified) + 7 should-fix + 4 nits. Pass 2 raised 6 should-fix (mostly fixture-discriminator details and Exact-at-probe asymmetry rationale) + 2 nits. Pass 3 returned `no further substantive issues`.

- **Three test-suite-review passes converged.** Pass 1 raised 2 must-fix (path-C and path-E store tests entirely missing — only 4 of the 6 paths had tests as drafted) + 3 should-fix + 2 nits. Pass 2 raised 1 must-fix (`stores == 1` exact assertions in completed-loop tests would fail against a correct impl because recursive children also store; relaxed to `>= 1`) + 1 should-fix + 2 nits. Pass 3 returned `no further substantive issues`.

- **One final-review pass converged.** Pass 1 returned `no further substantive issues` with 3 nits (E51 stale doc-comment + function name still saying "M5.D frontier futility pruning" → addressed by renaming to `bench_signature_deterministic_across_two_runs_with_qsearch_tt`; the other two nits are stylistic and consistent with M5.C precedent).

- **Test scaffolding committed before implementation.** The chess-coder agent first wrote the `is_empty()` discriminator change + helper signature + counter fields + 36 tests (with most failing because the production probe/store didn't exist yet). Test-suite review ran on the failing tests. Then a second agent wrote the production probe + store + ordering + cutoff_move tracking, which made all 36 tests pass.

- **Mutation campaign required `--skip` to bypass `make_move_no_from_scratch_in_release`.** First two attempts failed at the unmutated-baseline phase: (1) `--timeout 90` was too short for the from-scratch build + test in the mutants temp dir; (2) `cargo mutants ... -- --release --skip ...` was misparsed because the `--skip` belongs to the test runner, not cargo. Final invocation: `cargo mutants --in-diff $diff --timeout 240 -- --release -- --skip make_move_no_from_scratch_in_release`. The `make_move` perf test fires under any instrumentation overhead per M5.C/D/E precedent; same skip pattern applies here.

## Test surface

36 new tests across nine §6 categories from plan + the path-C/E adds during test-suite review:

- **§6.1 — `src/tt.rs` discriminator tests** (5): default-is-empty under new rule; key=0 + other-fields-nonzero stays empty; nonzero-key + depth=0 is NOT empty; store panics on key=0 in debug; store with depth=0 round-trips.
- **§6.2 — `src/tt.rs` qsearch-tier replacement tests** (4): qsearch-replaces-qsearch (same gen, same depth=0); negamax-replaces-qsearch (depth 5 over 0); qsearch-does-NOT-replace-negamax (0 over 5); terminal-exact-at-gen-zero-round-trips (covers the previously-impossible `key != 0 && depth == 0 && age_and_bound == 0` case).
- **§6.3 — `qsearch_tt_bound_for_completed_node` helper unit tests** (5): Lower at >=, Upper at <, panics in debug on -INF, Lower at boundary zero, non-Exact-ever sweep over the would-be-Exact zone.
- **§6.4 — Probe behavior** (4): Exact returns score; Lower returns when >= beta; Upper returns when <= alpha; no-cutoff falls through and stores.
- **§6.5 — Store behavior, one per real-result return point** (8 total: 6 paths + path-C/E added in test-review): A/B/C/D/E/F + MAX_PLY skip + counter-stays-0-when-skipped.
- **§6.6 — TT-move ordering** (3): capture promoted to index 0; quiet skipped at not-in-check; any legal move used in-check.
- **§6.7 — Negamax-qsearch interaction** (3): negamax probe skips depth=0 qsearch entry; qsearch uses negamax depth-N entry for cutoff regardless of depth; negamax extracts tt_move from qsearch entry.
- **§6.8 — Mate-score round-trip** (2): mate-at-horizon ply-adjusted correctly; centipawn score not ply-adjusted.
- **§6.10 — Counter reset** (2): probes counter resets per qsearch_for_test; stores counter resets per qsearch_for_test.

(§6.9 was a placeholder for new compile-time invariants; M5.F adds none.)
