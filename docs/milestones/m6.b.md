# M6.B — Pawn structure + pawn hash (retrospective)

Second M6 sub-phase. Lands the pawn-structure infrastructure (pawn hash +
pawn-only Zobrist substream + isolated/doubled/backward/connected predicates
+ passed-pawn detection) shipping **only the connected-pawn term active**
(`PAWN_STRUCTURE_IN_EVAL = true`; ISO/DBL/BWD weights zeroed in `eval::data`).
The original all-four §6 literature-default config SPRT'd **H0, Δ Elo
−99.88** vs `M6.A`; a per-term **subset screen** (no value tuning) falsified
"one bad term" and exposed a catastrophic **ISO×CONN connectivity-axis
double-count**. CONN-only is the largest confirmed gain and the only
interaction-immune subset; landing-gate mixed-TC SPRT vs `M6.A` =
`continue@400-cap`, **Δ Elo +45.42 [+19.68, +71.67]**, lands by the
M5.F/M5.G-v2 outcome-ladder precedent. M6.I re-introduces ISO/DBL/BWD via
joint Texel + rescales CONN (ADR-0032 §7).

## What landed

- **Pawn-Zobrist substream.** `Position::pawn_zobrist: u64` = XOR of
  `zobrist::piece_key(pawn, sq)` over all pawns, side-to-move excluded.
  Maintained by the **structural three-XOR form** in
  `update_zobrist_after_make` (pawn-mover out@`from`; pawn-non-promo in@`to`;
  pawn-victim out@`capture_sq`) — *no* per-`MoveFlag` match. EP's two-pawn
  delta and all promo / promo-capture arms are correct by construction.
  Restored structurally in `unmake_move` from `Undo.prior_pawn_zobrist`;
  from-scratch round-trip `debug_assert` in make/unmake/make_null_move.
- **Pawn hash table.** `PawnHashTable` — fixed 4 MiB (`#[repr(C)]` 32-byte
  entries, 2¹⁷, `const`-size-pinned), always-replace, owned by
  `AlphaBetaMover`, cleared in `Search::reset()` (fires on `ucinewgame` +
  per bench position). `key == 0` never cached (sentinel/no-pawn conflation).
- **Pawn-structure terms** (white-relative formula). **Shipped config:
  connected-pawn term only** — `CONN_*` rank-scaled `phalanx | defended`
  (LERF-indexed, literature default); `ISO/DBL/BWD` weights **zeroed** in
  `src/eval/data.rs` (kept as named M6.I-tunable constants, term math live
  at zero weight). Passed-pawn **detection only** (`passed[2]` cached for
  M6.C). Pure stack — no if-else suppression (ADR-0032 §6).
- **Eval entry point.** `evaluate_core` (shared blend) + pure `evaluate`
  (uncached) + `evaluate_cached(pos, &mut PawnHashTable)` (qsearch hot path).
  `evaluate_cached == evaluate` for all positions / any hash state — the
  cache is a pure accelerator (D6 proptest). Mop-up keeps PST-only inputs
  unchanged from M6.A (regression-pinned).
- **Bitboard primitives.** `north_fill`/`south_fill`/`file_fill` +
  `{white,black}_front_spans` + `{white,black}_attack_front_spans` (`const fn`).

Files: `src/eval/pawns.rs` (new), `src/eval.rs`, `src/eval/data.rs`,
`src/bitboard.rs`, `src/mov.rs`, `src/position.rs`, `src/zobrist.rs`,

## Subset rework (the cheap-Elo recovery)

The first M6.B landing shipped the infra **score-neutral** because the
all-four literature-default config SPRT'd H0 −99.88 and the
zero-the-knob/diff-bench triage proved the regression was 100% the weights,
not a bug. Rather than wait for M6.I, a **per-term subset screen** recovered
the cheap Elo with **no value tuning** — only choosing which literature
defaults to keep vs zero:

- **Method.** An env-var-driven term mask (`CLAWFISH_PAWN_MASK`, bits
  ISO=1/DBL=2/BWD=4/CONN=8) read once at startup — one build, every subset
  selectable per-process. Verified inert at mask 0 (`bench` == score-neutral
  M6.B == M6.A) and faithful at mask 15 (`bench` == the recorded all-four
  `1141125`). Each subset SPRT'd vs cached `M6.A` (single-TC `10+0.1`,
  elo0=0/elo1=10, shared seed for paired low-variance comparison). The
  experiment patch was fully reverted before the clean apply.

| Subset | Δ Elo vs `M6.A` | verdict |
|---|---|---|
| ISO only | +82.70 [+50.57, +116.29] | H1 @214g |
| DBL only | +31.35 [+9.43, +53.53] | CI fully + |
| BWD only | −7.53 [−27.84, +12.73] | ≈ neutral |
| CONN only | **+103.08 [+65.54, +143.13]** | **H1 @222g** |
| ISO+DBL+CONN | +9.85 [−13.92, +33.70] | ≈ neutral |
| ISO+CONN | **−197.94 [−281.29, −131.31]** | H0 @66g |
| (ISO+CONN)/2 | +6.37 [−14.15, +26.93] | ≈ neutral (probe) |

- **The a-ha.** Σ marginals ≈ +209 yet all-four = −99.88, and **ISO+CONN
  alone = −197.94** (worse than all-four; dropping BWD made it *worse*). Not
  one rotten term — a **catastrophic ISO×CONN interaction**. ISO and CONN are
  opposite-signed measurements of the *same pawn-connectivity axis* with
  grossly mismatched magnitudes (CONN rank-scaled to +95; ISO flat −20),
  coherent only after the joint Texel co-calibration ADR-0032 §6 always
  assigned to M6.I. CONN-only is the largest confirmed gain *and*
  structurally interaction-immune (a single term cannot interact with
  itself) → **shipped**.
- **`(ISO+CONN)/2` probe** — halving *both* weights moved ISO+CONN
  −197.94 → **+6.37 [−14.15, +26.93]** (≈ flat). Decomposes the −198:
  **~+204 Elo was pure over-magnitude** (uniform downscale rescues it),
  but the co-scaled pair still **plateaus ≈0, ~100 Elo below CONN-only
  (+103) and ISO-only (+83)** — a *scale-invariant* structural/wrong-shape
  residual no global multiplier fixes (flat ISO vs rank-scaled CONN,
  opposite signs on one axis). Confirms CONN-only (no swap) and converts
  M6.I's brief from "rescale the literature weights" to **reshape**:
  re-attach CONN's modulation context + decorrelate the axis via joint
  Texel. **Provenance corroborates** (research §1/§6): the four defaults
  are a non-co-calibrated pastiche — ISO/DBL hand-picked range-midpoints,
  CONN a de-modulated fragment of the Stockfish-lineage `Connected[]`
  expression stripped of its phalanx/supported/opposed modulators.

## Implementation highlights

- **Structural §5 form (Opus slice).** The pawn-Zobrist delta mirrors the
  existing unified main-Zobrist update — three conditional XOR sites, no flag
  match — so EP (`capture_sq ≠ to`) and promotions are correct by
  construction. (Unchanged in the subset rework.)
- **Geometric-impossibility finding.** Promo-capture-with-pawn-victim is
  impossible (victim sits on the mover's back rank); EP is the only
  two-pawn-removal pawn-key case. The structural form handled it for free.
- **Connected predicate** = `phalanx | defended` with the bare-defender
  exclusion (ADR-0032 §6 / plan §6) — the *only* term that survives into the
  shipped config, and the one that carries the +45 Elo.
- **Symbolic test re-expression.** Zeroing ISO/DBL/BWD broke 4 magic-number
  `pawn_eval` pins; rather than re-pin to 0 (low signal) they now assert the
  composition *formula* over the `eval::data` constants and the
  no-suppression claim over predicate popcounts — green at the shipped zero
  weights and auto-valid when M6.I re-tunes (the file's own M6.I-maintenance
  note anticipated exactly this).

## Lessons learned

- **Marginals do not predict combinations for raw literature eval weights —
  but a cheap subset screen recovers the Elo without tuning.** Each of
  ISO/DBL/CONN is individually a large SPRT gain at its literature default,
  yet all-four = −100 and ISO+CONN = −198. The interaction is structural:
  **two opposite-signed terms measuring the same axis (pawn connectivity) at
  mismatched scale double-count catastrophically** when applied raw; the
  literature tables are co-calibrated, not independently additive. The
  recovery technique — an env-var term mask, one build, per-term + candidate
  SPRTs vs the prior tag on a shared seed, ship the largest interaction-immune
  subset — turned a deferred-to-M6.I −100 into a shipped +45 with **zero
  value tuning**. Generalizable: when a bundled literature-weight feature
  SPRT-regresses, screen the subset lattice before concluding "needs Texel."
- **A catastrophic term interaction is not necessarily a magnitude problem —
  probe with a co-scale before assuming "just tune the weights."** The
  `(ISO+CONN)/2` probe split the −198 into ~+204 of pure over-magnitude
  (uniform downscale rescues it) and a ~−100 *scale-invariant* structural
  residual (the co-scaled pair plateaus ≈0, still ~100 below either term
  alone). A global multiplier provably cannot recover a wrong-*shape*
  double-count of two opposite-signed terms on one axis — only a joint
  *reshape* (here: re-attach CONN's modulation context, decorrelate the
  axis) can. Provenance corroborated the diagnosis: the defaults are a
  non-co-calibrated pastiche (ISO/DBL range-midpoints; CONN a de-modulated
  Stockfish-lineage fragment). Takeaway: a cheap co-scale probe cleanly
  separates "over-weighted" from "wrong-shaped" and tells the tuning phase
  whether scalar SPSA suffices or a structural rework is required.
- **`continue@cap` with a strongly-positive CI lands by the outcome ladder —
  but document the non-H1 status and any per-TC pathology honestly.** +45.42
  [+19.68, +71.67] did not cross H1; it lands on the M5.F/M5.G-v2 precedent.
  The per-TC depth reversal (fast-TC strong, 60+0.6 negative) is atypical for
  an eval term and is direct evidence the literature CONN magnitude is
  over-scaled for this engine — recorded as a load-bearing M6.I input, not
  buried.
- **`cargo test --release` masks the `debug_assert!` correctness net.** (From
  the score-neutral landing; still standing.) Any slice touching
  make/unmake or debug-assert-guarded code must run a plain debug `cargo
  test`.
- **A coder "deviation" that changes settled-ADR semantics is
  must-investigate** (Slice C's ISO/BWD mutual-exclusion vs ADR-0032 §6) —
  fix the defective fixture, not the spec.
- **Sandbox blocks `git worktree add` of historical commits + `nice` for
  backgrounded harness commands** (`Operation not permitted`). All SPRT /
  screen / calibration runs require `dangerouslyDisableSandbox: true`.
