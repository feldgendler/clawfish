# M6.H — Robust on-demand Lichess/CCRL ingestion

**Landed 2026-05-22. Data-acquisition infra; functional gate, NOT SPRT — no
Elo claim. Production HEAD remains `M6.F` (bench `1213649` / d4 `90591`
byte-for-byte; no `evaluate`/search touch).** ADR-0036; extends ADR-0035 §11.

## What landed

A network-layer extension of the M6.G corpus infra: a new `corpus fetch
--source={ccrl,lichess}` subcommand + `corpus::fetch` library module that
streams a compressed PGN dump over HTTPS, decompresses on the fly, and feeds the
*existing* M6.G ingest path (`pgn::stream_pgn` → `filter::game_admitted` →
`store::append_block` into `pgn-shard.bin`) — reused **verbatim**, so R1 atomic
per-game block log + dedup come for free. The synchronous
`corpus::fetch::stream_to_ingest(...)` is the primitive M6.I's bi-level driver
calls ("give me N more positions from source X").

Four modules (`src/corpus/fetch/`): `gates` (HTTP-status classify / PGN
prefix-sniff / parse-sanity / `statvfs` disk pre-check), `catalog` (Lichess URL
builder + `fetch-state.json`, reusing `manifest`'s minimal JSON parser),
`reader` (`ResumableHttpReader<R,F>` state machine + the ureq wiring), `mod`
(the streaming-vs-temp-file orchestration + `stream_to_ingest`). Plus the
`corpus fetch` CLI arm.

## Key decisions / highlights

- **Feature-gated network stack.** `ureq` 3.3 / `zstd` 0.13 / `zip` 8.6 are all
  behind the **non-default `corpus-fetch`** Cargo feature, so the engine binary
  and its `cargo build`/`audit`/`deny` are untouched (the lean-dep posture
  extended to dependencies). The engine bench is `1213649` either way.
- **TLS = `platform-verifier`** (OS trust store / macOS Security framework) —
  the better realization of the roadmap's "validate against the OS trust store /
  rustls-native-certs" intent (subsumes the static snapshot; works on
  corporate-root-CA networks). ADR-0036 §2.
- **Two-level resume + games-parsed stall watchdog.** In-attempt HTTP `Range`
  resume keeps the same decoder alive (zero re-decompression); the outer
  infinite-backoff loop does byte-0 restarts. The watchdog keys on *games
  parsed* (not byte-liveness) so it catches a byte-alive-but-semantically-dead
  stream; `timeout_recv_body = stall_timeout` is the heartbeat (no fictitious
  `set_read_timeout` — the plan-review caught that). ADR-0036 §3.
- **Decoder-agnostic early termination + idempotent byte-0 restart.** A shared
  position counter (not the decoder's terminal state) drives classification, and
  a disambiguating peek separates drained-at-target (`Eos`) from `EarlyTarget`.
  `base_game_id` pinned once + skip-re-seen-ids ⇒ in-process restart is a true
  no-op append; cross-process re-ingest is FEN-deduped at `corpus build`
  (ADR-0035 §8). ADR-0036 §4.
- **CCRL is `.7z`-only** (verified 2026-05: official site distributes only
  `.7z` and is bot-hostile) → **`--source ccrl` requires an operator `--url`** to
  a `.zip`/`.pgn.zst` mirror; Lichess auto-constructs its URL. 7z support is out
  of scope. See `docs/data-catalog.md`. ADR-0036 §5.
- **License gate clean with no `deny.toml` edit.** The precautionary
  `Unicode-3.0`/`Zlib` + `ring`-clarify additions proved unnecessary — modern
  ring/zstd-sys/miniz_oxide declare clean SPDX licenses all matching the
  existing allowlist. +~76 transitive crates, all permissive, `cargo audit`
  clean.

## Verification

- **Tests:** 1858 lib (release) + 10 `corpus_fetch` integration (localhost
  HTTP/1.1 server, real `.pgn.zst`/`.zip` payloads — no real network) + the rest
  of the suite, all green. Integration coverage: early-termination byte bound
  (`bytes_received < compressed_len/3`), drop+resume for both `.zst` and `.zip`,
  EOS, EOS-at-target tie-break, permanent-404-no-hang, HTML-rejection-no-ingest,
  byte-0-restart idempotence (via a `200`-on-resume server forcing `RangeIgnored`),
  CCRL zip temp-file parity + cleanup, stop flag.
- **`cargo fmt --check`** clean; **`cargo clippy --all-targets -- -D warnings`**
  clean both with and without the feature; **`cargo deny check`** + **`cargo
  audit`** clean (no `deny.toml` edit).
- **Bench:** `1213649` nodes / d4 `90591` — byte-identical to `M6.F`/`M6.G` (no
  engine touch).
- **Coverage** (region, `llvm-cov` with the pre-existing instrumentation-
  incompatible `mov.rs` perf sentinel `--skip`ped): catalog 96.4%, gates 96.2%,
  reader 92.7%, mod 89.5% (manifest 85.4%, mostly pre-existing). The uncovered
  fetch regions are error/backoff paths + the production `http_opener` arms
  (integration-covered, not lib).
- **Mutation:** scoped to the pure-logic files (`gates`/`reader`/`catalog`) over
  lib tests (the M6.G `--in-diff`-scoped precedent — `mod.rs` orchestration +
  `http_opener` are integration-covered). Initial run 81 caught / 19 missed / 5
  timeout / 6 unviable; 5 gap-closing tests added; the catalog+gates re-run is
  **71 caught / 1 missed / 1 timeout**. Residual: the 1 missed is `disk_precheck`
  `< → <=` (immaterial 1-byte boundary on a multi-GB floor — equivalent); the
  timeout is `sniff += →*=` (caught-via-hang, infinite whitespace loop); the
  `reader.rs` `http_opener` survivors are the production ureq wiring
  (integration-covered) and the `do_reconnect`/`read` timeouts are caught-via-
  hang. (Reader's final-review `last_game_at`-reset fix is covered by the
  reworked stall tests; not separately re-mutated.)
- **Review loops:** plan (3 passes → converged), test-suite (2 passes →
  converged), final (2 passes → converged) — all blind-reviewed.

## M6.I interface

`stream_to_ingest` is the on-demand counterpart to `corpus selfplay`: the M6.I
bi-level learning-curve driver requests N positions from CCRL or Lichess and
blocks (infinite backoff) until they arrive or the stream drains, then consults
`fetch-state.json` (per-URL `early_target`/`eos`) to decide revisit-vs-advance.
