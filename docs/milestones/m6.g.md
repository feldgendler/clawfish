# M6.G — Corpus construction (retrospective)

**Landed:** 2026-05-20.
**Disposition:** data-quality gate PASS; no SPRT, no Elo claim — the corpus is data infra (the M5.E correctness-only-gate precedent applied to data).
**Engine impact:** none. `bench` byte-identical to `M6.F` (`1213649` / d4 `90591`). The only engine touch is an **additive read-only** `pub fn search::quiescence_eval_white` + `pub struct QSearcher` seam.
**Frozen artifact:** `bench/corpus/` (12 self-play games, `corpus_sha256 = c03f5aa99dcf20bcedb69801c1633b8c34e8e85c1880528be4e62a0ef0f50e60`).
**ADR:** [ADR-0035](../decisions/0035-corpus-construction.md).

## What landed

- **`src/corpus/` library** (12 modules):
  - `mod.rs` — shared types (`Label`, `Source`, `CorpusRecord`, `CorpusError`) + the M6.G↔M6.I **pinned interface constants** (`QUIET_MARGIN_CP=30`, `OPENING_SKIP_PLIES=8`, `HIGH_SCORE_CP=600`, `PER_GAME_CAP=10`).
  - `prng.rs` — SplitMix64 (golden-pinned to identical literals as `elo_iterate::prng`; deliberate ~20-LOC dup keeps M6.G off the SPRT-critical harness).
  - `pgn.rs` — streaming PGN reader, SAN parser that disambiguates against the **legal** move set (ADR-0007), whole-game-drop on any parse failure (Texel-poisoning prevention).
  - `filter.rs` + `quiet.rs` — game/position admission + the pinned quiet predicate (`!in_check ∧ |static − qsearch| < 30 cp`).
  - `selfplay.rs` + `store.rs` — in-process deterministic fixed-depth self-play (fresh `AlphaBetaMover` per game, R3 bit-identical-resume) + per-game CRC-framed append-block log + checkpoint ordering (R1/R2).
  - `dedup.rs` — bounded-memory external sort-merge FEN dedup, deterministic min-`(source,game_id,ply)` survivor (independent of shard order — the reproducibility-gate prerequisite).
  - `split.rs` — game-level train/val split (no game spans both sides).
  - `objective.rs` — Texel K-fit + logistic loss + stratified objective; **frozen-snapshot outpost stratum** (copy of `eval::tier1::outpost_squares` taken at M6.F — never a live call; closes the M6.I re-tune circularity).
  - `manifest.rs` — hand-rolled SHA-256 + JSON (NIST-vector-tested) + filter_spec writer.
  - `quality_gate.rs` — the six-check data-quality landing gate (3 must-PASS).
- **`src/bin/corpus.rs`** — CLI: `calibrate-ladder` / `selfplay` / `ingest-pgn` / `build` / `quality-gate` / `export` / `rerun`; SIGTERM/SIGINT-graceful (R7).
- **`src/search.rs`** — added the additive `QSearcher` opaque wrapper + `pub fn quiescence_eval_white`. Behavior-neutral: bench byte-identical to `M6.F`.
- **`scripts/corpus.sh`** — operator fresh-build wrapper.
- **`bench/corpus/`** — vendored frozen artifact: `manifest.json` + `filter_spec.txt` + `corpus_stats.txt` + `shard.bin` + `val.bin` + `checkpoint.bin` + `re-run.sh` (operator-facing, reads every knob from the manifest).
- **`tests/corpus_crash_safety.rs`** — the roadmap "Verification" clause: fast `crash_kill_after_first_game_resumes_to_uninterrupted_corpus` (real `libc::kill(pid, SIGKILL)`, asserts multiset byte equality to uninterrupted reference) + `#[ignore]`-gated heavy randomized + SIGSTOP/SIGCONT suspend variant.
- **`tests/corpus_reproducibility.rs`** — `rerun_byte_identical` drives the full pipeline twice into sibling temp dirs, asserts SHA-256 equality of `shard.bin` + `val.bin`.

## The ADR-0003 label-provenance audit verdict (the load-bearing finding)

The audit *passed* by producing a **documented REJECTION of Zurichess `quiet-labeled.epd`**:

- Research §3 found, from the Zurichess Bitbucket README quoted in the announcing TalkChess thread, that `quiet-labeled.epd`'s `c9` labels are **NOT** the original 75K Zurichess self-play game outcomes — they are the results of separate games played by **Stockfish 080916** from each quiet position. That is the exact "labeling-engine bias" ADR-0003 (by spirit) prohibits.
- The `Source` enum in `src/corpus/mod.rs` enumerates exactly the three permitted provenances: `SelfPlay`, `Ccrl`, `LichessOpen` — Zurichess is intentionally absent.
- The audit's three-layer programmatic defense: (a) the `Source` enum omission (compile-time); (b) `Source::from_u8` returns `None` for `b ≥ 3` so `store::decode_block` rejects unrecognized frames wholesale; (c) `check_adr0003_audit` carries an unconditional (not debug-only) `assert_eq!(accept_list.len(), 3, ...)` that fails the audit if a future variant slips past the audit logic.

This audit's REJECTION is what M6.I, the tuning-backlog Arm B, future SPSA, and M10 NNUE data-prep all freeze on — they consume only original-game-result-labeled positions.

## The R4 / VirtualClock reasoned exception (owned, not papered)

R4 literally mandates `VirtualClock` for M6.G self-play. The M6.G plan + ADR-0035 §5 argue the deviation:

- VirtualClock exists to make *wall-clock* play load-independent. Fixed-depth play is load-independent **without a clock at all**, so VirtualClock is unnecessary here, not merely moot.
- ADR-0021 §4's node-TC rejection is scoped to **cross-version SPRT comparability**. M6.G is one frozen build — §4's reasoning does not bite.
- Roadmap R-TC explicitly carves out "fixed-shallow-depth stratified across their effective depths … (ADR-0021 §4 does NOT forbid fixed-depth/fixed-nodes for corpus generation — one fixed build, not a version comparison)."
- VirtualClock still binds the M6.I SPRT — M6.I's concern.

The R-TC depth ladder is **empirically anchored** via `corpus calibrate-ladder` (run over `bench::BENCH_POSITIONS` at each deployment movetime bucket), not literals — the proxy is validated, not asserted.

## The R3 fresh-searcher-per-game finding (resolved inline mid-review)

Pass-1 final review surfaced that the integration coder's `selfplay::run` reused one `AlphaBetaMover` across all games per worker — making post-crash games' continuations diverge from the warm-from-prior-games uninterrupted baseline. The R3 plan §3.5 contract ("resumed run bit-identical modulo the one in-flight game") was structurally violated.

**Resolution:** `selfplay::run`'s worker loop now allocates a fresh `AlphaBetaMover::new()` at the start of every game. R3 collapses to "bit-identical" under `--workers 1` + the deterministic write-order sort. Also improves self-play decorrelation (research §2.4). Pinned by `fresh_vs_warm_searcher_same_seed_same_game_identical` (plays game 0 then game 5 on the same searcher; plays game 5 on a fresh searcher; asserts identical `GameRecord`).

## The two-pass design (closes the parallelization-map honesty edge)

Pass-1 plan-review flagged that the §7 parallelization map had a hidden `selfplay → quiet` edge. The resolution: `selfplay.rs` emits **every** post-opening-skip position with the game label + `depth_rung`, transactionally per game — it does NOT apply the quiet predicate. The separate `corpus build` pass applies quiet/cutoff/dedup/cap/split. The map's `selfplay → quiet` edge is genuinely absent.

## Reproducibility — the manifest pins every knob

Pass-1 final-review must-fix MF4: the original `bench/corpus/re-run.sh` defaulted `GAMES=200` and didn't pass `--max-plies` or `--opening-random-plies`, so re-running could not byte-reproduce the committed artifact. Resolution:

- `Manifest` extended with `games`, `max_plies`, `opening_random_plies`, `workers`, `val_fraction` (in addition to `self_play_seed`, `split_seed`, `depth_ladder`, `corpus_sha256`).
- `cmd_build` emits `train.bin` + `val.bin` with records sorted by `(game_id, ply, fen)` per game-block → corpus bytes are a deterministic function of the input multiset, **independent of self-play worker scheduling**.
- `bench/corpus/re-run.sh` reads every knob from the manifest — no `${X:-default}`.
- `scripts/corpus.sh` SEED aligned with the committed manifest (`12648430 = 0xC0FFEE`); fixed hex math; header documents it as the **operator fresh-build** tool vs `re-run.sh` for byte-identical reproduction.
- `tests/corpus_reproducibility.rs::rerun_byte_identical` is the test-side proof of the contract.

## Lessons learned

- **The ADR-0003 audit produced its expected output: a documented REJECTION** (not a rubber-stamp PASS on suspicious labels). The Zurichess `c9` finding is the load-bearing audit verdict — research surfaced it, the audit programmatically enforces it. Pattern: an audit *passing* can mean the audit *correctly rejected the inputs it was given*.
- **Parallel coders sharing the main tree have subtle race / coordination costs.** The fan-out spawned 7 slices; 4 ran in the main tree (race-clobbered, but file-disjoint kept correctness) and 3 ran in proper worktrees (had to be hand-pulled because the agents didn't commit). The manifest agent worked blind to the real `corpus::CorpusError` and `Manifest` shape and diverged structurally — required orchestrator-side reconciliation (a `Json` variant added to canonical `CorpusError` + the integration coder normalized manifest.rs). Future-large-units lesson: **pre-commit Slice 0 + branch all fan-out worktrees off that base + brief each agent with the *exact* Slice-0 shared types so blind divergence is impossible**.
- **The plan-review loop's pass-1 critique was the dominant value source for this unit.** 12 concerns → revisions → pass-2 convergence. Three concerns were genuinely correctness-load-bearing (R-TC empirical anchoring, R1/R2 per-game atomic frame, SAN-disambiguation-against-legal); the others tightened reproducibility / interface contracts. The agent's prose was structurally clearer than the original plan in several places (the §1 scoping decision; the §3.5 R4 deviation argument). **Plan-review for large prescriptive plans yields more architectural improvement per token than the test-suite or final review at the same stage.**
- **The "code+tests together per slice" sequencing deviation from strict step-5/step-6 separation was acceptable for a 12-module unit with a highly prescriptive plan.** Both review loops still ran (pass-2 each); the test-suite reviewer caught real should-fix items (heavy crash-safety variant assertion strength, ADR-0003 audit `debug_assert` vs `assert` in release) that strict-ordering would have caught at the same place. Pattern: **strict step-5/6 separation can be reordered to code+tests-together when (a) the plan is prescriptive at the test-name level and (b) both review loops still run on the assembled result**. The justification belongs in chat at the reorder point (not silently).
- **Fixed-depth deterministic self-play makes R1–R7 dramatically simpler.** No VirtualClock, no suspend-discard surface, no wall-clock-comparability concerns. The roadmap R-TC clause's "fixed-shallow-depth stratified" carve-out is *exactly* the right shape for corpus generation; the optimization-tractability-style argument that drove M6.F's endgame-scaling decision applies in the same spirit here.
- **The committed-bytes contract (vs the network-re-derivable recipe contract) is load-bearing for downstream consumers.** The pass-1 review's must-fix #4 was the single most important architectural correction: the manifest must pin every knob, the on-disk order must be deterministic, and the bytes consumers freeze on must be reproducible from a single re-run. The strong R5 guarantee covers the self-play slice (offline + seed); the weaker re-derivable guarantee covers CCRL/Lichess slices (network + source availability).

## Pull-from-backlog

- **M6.I (next phase) consumes the frozen `bench/corpus/` artifact + the §3.1 pinned interface constants.** The committed artifact is self-play-dominant (plan §1 admitted shortfall); for a production-scale M6.I tune the operator runs `scripts/corpus.sh` (with `GAMES=200+`) or stages CCRL/Lichess + runs `re-run.sh` to extend the artifact before kicking off the joint Texel pass. The `manifest.json` + `filter_spec.txt` are the stable contract surface.
- **Tuning-backlog "PST co-tuning" Arm B** (per `docs/tuning-backlog.md`) inherits the same frozen-artifact contract.
- **Future SPSA campaigns** (the §"PST co-tuning Arm B" entry's documented follow-up) likewise.
- **M10 NNUE data-prep** will reuse the parser + filter + self-play infra (with a likely extension to per-position engine-eval annotations — a *different* label type that the ADR-0003 audit is structurally able to reject from co-mingling into the HCE corpus).

**Deferred follow-ups (recorded for the M6.I plan / tuning-backlog):**
- Strict end-to-end reproducibility test (load committed `manifest.json` → run `re-run.sh` → assert produced bytes match `corpus_sha256` field). The current `rerun_byte_identical` test proves determinism between two fresh runs; the transitive-determinism argument is sound but a direct test would close the manifest→bytes axis.
- `cmd_build`'s no-cleanup of `pgn-shard.bin` after a build — latent for the multi-PGN-ingest workflow not exercised by the committed artifact. Operator-handled until M6.I or a corpus extension exercises it.
- Wider-surface mutation testing (pgn / filter / quiet / split / objective / manifest / quality_gate / selfplay) when a tuning-backlog slot opens. The unit-test surface is comprehensive; the deferral is judgment, not blind.
- A documented follow-up to allow operator-supplied bench corpus to bypass `corpus calibrate-ladder` on slow hardware (re-running calibrate-ladder on a slower machine produces a different ladder; the committed ladder is dev-machine-local).

## Post-tag amendment — four-source taxonomy (2026-05-21)

After the M6.G tag landed and several operator-workflow follow-up commits extended the corpus pipeline (notably the `book_fraction` per-game-coin-flip and the vendored opening book), a design dialog ahead of M6.I concluded that **`book_fraction` is qualitatively the wrong shape for a meta-tunable**: it's a corpus-*generation* knob (irreversible without regeneration) while every other M6.I meta-axis (CCRL share, Lichess share, N) is a training-time reweighting on a frozen corpus. To make the book / off-book proportion mechanically identical to the CCRL / Lichess proportion, **`Source::SelfPlay` was split into `Source::SelfPlayOnBook` + `Source::SelfPlayOffBook`** and the `book_fraction` coin-flip was replaced by a per-campaign `OpeningMode::{Book, Random}`:

- One self-play campaign per opening regime; every committed record carries that regime's source variant.
- The book vs off-book share becomes a training-time per-source reweighting at M6.I — same machinery as `StratObjective::per_source` already provides for the CCRL / Lichess axes.
- ADR-0003 audit accept-list grows from 3 to 4: `{SelfPlayOnBook, SelfPlayOffBook, Ccrl, LichessOpen}` (the cardinality pin in `check_adr0003_audit` was bumped accordingly).
- The redundant `STRATUM_BOOK_OPENING` stratum bit was removed — bit 2 reserved.
- Manifest field `book_fraction: f64` was replaced by `opening_mode: Option<String>`. The generated `bench/corpus/re-run.sh` reads `opening_mode` from the manifest and dispatches the matching `corpus selfplay` invocation.
- Wire-format change: source-byte assignment is now `SelfPlayOnBook=0, SelfPlayOffBook=1, Ccrl=2, LichessOpen=3`. Shards committed under the prior `SelfPlay=0, Ccrl=1, LichessOpen=2` numbering are not migrated; the committed `bench/corpus/shard.bin` / `val.bin` were deleted in preparation for M6.I regeneration under the new taxonomy.

The amendment leaves M6.G's data-quality gate semantics untouched (the three must-PASS checks still apply; the ADR-0003 audit verdict is unchanged); it leaves the M6.G↔M6.I interface constants (`QUIET_MARGIN_CP`, `OPENING_SKIP_PLIES`, `HIGH_SCORE_CP`, `PER_GAME_CAP`, `FEN_LEAKAGE_TAU`) byte-identical; it does not touch any engine code (bench remains `1213649` / d4 `90591`). Verification: 1848 lib tests + 8 crash-safety + 2 reproducibility integration tests pass, `cargo fmt --check` + `cargo clippy --release --all-targets -- -D warnings` clean. See ADR-0035 §10 for the design rationale.

**Lesson:** post-tag amendments to the data layer are cheap when (a) no SPRT baseline depends on the artifact (the M6.I baseline is `M6.F`, not `M6.G`) and (b) the on-disk format change can land alongside a regeneration window. The same change *during* an M6.I tune would be far more expensive — the timing-vs-correctness window for data-layer corrections is between the data-infra landing and the first downstream consumer's run. The four-source split was identified before the M6.I tune began; future similar amendments should be hunted for in the same gap.
