# M5.E — Qsearch correctness (retrospective)

Fifth M5 sub-phase. Two narrow corrections to quiescence search bundled because each is < 100 LOC standalone and both touch the same `qsearch` body. Closes the M3.D horizon hole on legally-forced quiet replies and the M3.D queen-only-promo filter gap. Lands before M5.F (qsearch-in-TT) so the TT does not memoize qsearch holes.

**SPRT framing**: no-regression rather than positive-Elo. Both corrections target corner-case-frequency events (queen-promo-stalemate is endgame-rare; positions where qsearch's filter empties at not-in-check with exactly one legal move are also rare). Roadmap predicted `<10 Elo combined`; combined signal `<5 Elo` is plausible. Correctness, not Elo, is the gate.

## What landed

Four production changes in `src/search.rs::AlphaBetaMover::qsearch`:

1. **Single-reply extension (M5.E #1)** — terminal-handler refinement: when `!in_chk && moves_vec.is_empty() && ml.len() == 1`, recurse on the unique legal move at qsearch with `ply + 1`. Pre-M5.E this branch returned stand-pat unconditionally — a horizon hole when the forced move is materially decisive.

2. **True-stalemate detection (M5.E #2, corollary of #1)** — when `ml.is_empty()` (zero legal moves, not in check), return `0` (FIDE 9.2 stalemate draw) instead of stand-pat. Mechanically free once we test legal-move emptiness for #1; documented separately for clean SPRT signal attribution.

3. **Stalemate-conditional rook/bishop under-promotion (M5.E #3)** — in the move loop, when a `QueenPromo | QueenPromoCapture` move's post-make child is stalemate (`legal_moves.is_empty() && !in_check(child)`), additionally search the rook + bishop variants of the same `(from, to)`. Knight-promo deliberately not searched (fork-tactic motivation, separate). Move-loop reshape: under-promo loop runs **before** the per-move beta cutoff (block 10b) so a queen-promo's stalemate score (= 0) cannot suppress the under-promo recursions via `alpha >= beta`.

4. **MAX_PLY ceiling guard (M5.E #4)** — defense-in-depth against pathological forced-quiet chains under #1: if `qsearch_short_circuit_at_ply_ceiling(ply, pos)` (extracted helper: `ply >= MAX_PLY - 1 && !in_check(pos)`), return `evaluate(pos)` without recursing. The `!in_check` arm is guarded only — at in-check + ply ceiling the existing evasion arm runs as before, since returning a fabricated mate would propagate through `score_to_uci`, `score_to_tt`, and mate-distance pruning.

New surface:
- `pub(crate) fn stalemate_avoiding_under_promos(mv: Move) -> [Option<Move>; 2]` helper (capture-aware queen-promo → rook+bishop variant synthesis).
- `pub(crate) fn qsearch_short_circuit_at_ply_ceiling(ply: u32, pos: &Position) -> bool` helper (extracted from inline guard for mutation-coverage discrimination per the M3.D `negate_window` precedent).
- `qsearch_single_reply_firings: u32` and `qsearch_under_promo_firings: u32` test-only counters with `_for_test` accessors.
- ADR-0027 records the policy commitments.

No changes to `src/mov.rs`, `src/position.rs`, `src/tt.rs`, `src/eval.rs`, or movegen.

## Implementation highlights

- **Predicate placement matters for `history.pop()` / `unmake_move` adjacency.** The M5.E #3 `queen_promo_stalemates` predicate is captured between `make_move` and the recursion (NOT between `history.pop()` and `unmake_move`), keeping the M3.D abort-discipline pairing intact ("the push/pop above is balanced even on abort because the abort check runs AFTER both `history.pop()` and `unmake_move`").
- **Cutoff hoisted out of `if score > best` block.** Plan §4.3 reshape moves the `alpha >= beta` cutoff to a sibling block (10c) so the under-promo loop (10b) runs between alpha-tightening (10a) and the cutoff. Behavior-preserving on non-queen-promo moves; load-bearing for M5.E #3 (a queen-promo's stalemate score = 0 raising alpha to 0 = beta would otherwise trigger the cutoff before under-promos run).
- **No `is_quiet` defense-in-depth gate at the M5.E #1 call site.** The `ml.len() == 1` unique-move case is structurally guaranteed to be a non-promo quiet by movegen invariant (legal-direct movegen always emits all 4 promotion variants together). Pinned by `qsearch_single_reply_under_promo_uniqueness_is_structurally_unreachable`. Adding a redundant gate would be dead code.
- **Helper extraction for mutation-coverage discrimination.** `qsearch_short_circuit_at_ply_ceiling` was extracted from an inline `ply >= MAX_PLY - 1 && !in_check(pos)` guard after the first `cargo mutants --in-diff` run reported 3 surviving mutants on the inline arithmetic / negation. The mutants were structurally undetectable at the qsearch integration level: at the only callable ply value (`MAX_PLY - 1`) the qsearch fall-through path also returns stand-pat, so cargo-mutants couldn't discriminate the inline operators. The helper's named function and 3 unit tests give mutation testing a discriminating surface — same precedent as M3.D `negate_window`, M3.E `aborted_fallback_result`, M3.F `compute_bench_nps`.
- **Tightened `qsearch_under_promo_finds_winning_rook_promo_when_queen_stalemates` assertion.** Initial `score > 0` passed vacuously due to root stand-pat (~+800 cp from white's K+B+B+P vs lone K). The tightened assertion `score > stand_pat + 100` discriminates sign-flip mutations on the under-promo recursion (line 2194:39) and wrong-direction `best`-update mutations (line 2202:36). The under-promo's continuation reaches K+R+B+B vs K (~+1200 cp), well above the root stand-pat.

## Test surface

22 new tests added to `src/search.rs::tests`:

- **5 helper tests** for `stalemate_avoiding_under_promos` (rook+bishop returned for queen-promo / queen-promo-capture; empty for non-queen-promo; from/to preserved; never includes Knight or Queen).
- **3 helper tests** for `qsearch_short_circuit_at_ply_ceiling` (at-ceiling-not-in-check returns true; below-ceiling returns false; in-check-at-ceiling returns false — kills MAX_PLY arithmetic + `!in_check` mutants).
- **8 single-reply / true-stalemate / MAX_PLY behavior tests** including: single-reply fires (with anti-vacuous sister); recursion-propagates-score; structural-unreachability of under-promo single-reply; true-stalemate returns 0; mate-in-ply preserved; false-stalemate guard preserved; MAX_PLY guard at ceiling (!in_check returns stand-pat; in-check arm runs evasions).
- **6 under-promo behavior tests**: fires when queen-promo stalemates (with anti-vacuous: doesn't fire when checkmates / leaves replies / non-queen-promo); finds winning rook-promo (mutation-killing tightened assertion); respects existing alpha-beta cutoff (firings == 2; score < alpha; under-promos contribute fail-soft); synthetic moves preserve from/to.

Tests dropped during loops:
- `qsearch_under_promo_extension_runs_before_cutoff`: omitted at test-suite-review pass 3. A discriminating fixture requires `stand_pat < beta <= 0` (so step-4 stand-pat cutoff doesn't fire AND queen-promo's stalemate score 0 raises alpha to ≥ beta) — meaning the side-to-move must be materially behind. But the M5.E #3 trigger requires a queen-promo whose post-make child is stalemated, which typically requires the promoting side to be materially ahead. The two requirements push in opposite directions; no compact natural fixture satisfies both. The ordering invariant is documented in plan §4.3 + ADR-0027 §6 and pinned structurally by the production code's block layout (10a → 10b → 10c). Final review's code reading is the load-bearing check.
- `qsearch_single_reply_chain_fires_recursively`: omitted at test-suite-review pass 1. Constructing a natural fixture where both sides are simultaneously zugzwanged into single forced quiets is hard. The recursion's correctness is structurally invariant (a single recursive call site with no special chain handling); `qsearch_single_reply_recursion_propagates_score_correctly` exercises one recursion level. NOTE comment in test module documents the omission.

## Plumbing / process highlights

- **Three plan-review passes converged.** Pass 1 raised 2 must-fix + 7 should-fix. The under-promo expansion's ordering (before vs after cutoff) was the load-bearing must-fix; the `is_quiet` gate on M5.E #1's unique move was the other (later dropped at pass 2 after analyzing movegen's promo-variant invariant). Pass 2 raised 0 must-fix + 2 should-fix + 3 nits. Pass 3 returned `no further substantive issues`.
- **Four test-suite-review passes** — exceeded the project's default 3-pass cap due to fixture construction iterations:
  - Pass 1 raised 3 must-fix + several should-fix. The orchestrator's draft FENs had 3 chess illegalities (pawn-on-back-rank, kings-adjacent, queen-promo-doesn't-stalemate-as-claimed) that the test author's empirical verification caught.
  - Pass 2 raised 2 must-fix + 2 should-fix. The true-stalemate FEN (`8/8/8/8/2k5/2p5/2K5 w - - 0 1`) was wrong (white K c2 has b1/c1/d1 legal); replaced with `7k/5Q2/6K1/8/8/8/8/8 b - - 0 1`. The MAX_PLY guard test was vacuous against an always-return-0 stub on KvK (eval = 0); replaced with KvKR fixture.
  - Pass 3 raised 1 must-fix (`qsearch_under_promo_extension_runs_before_cutoff` cannot discriminate the swap-fail on its fixture due to step-4 stand-pat cutoff) + 2 should-fix. The must-fix dropped the test rather than re-fixturing it.
  - Pass 4 returned `no further substantive issues` (3 nits surfaced informationally; loop terminated per cap rule).
- **Mutation campaign in 3 passes.** First pass: 23/33 caught + 9 missed + 1 timeout. Tightening `qsearch_under_promo_finds_winning_rook_promo_when_queen_stalemates`'s score assertion to `score > stand_pat + 100` caught 2 more (sign-flip on the under-promo recursion + wrong-direction `best`-update). Extracting `qsearch_short_circuit_at_ply_ceiling` as a helper with 3 dedicated unit tests caught 3 more (the previously-equivalent inline guard arithmetic + `delete !` on `!in_check`). Final tally: **30 caught + 4 missed + 1 timeout = 35 mutants; effective catch rate 31/35 = 88.6%.** The 4 remaining survivors are equivalent on the test surface (3 are mate-distance arithmetic on `ply + 1` increments at lines 2119/2198; 1 is alpha-update direction at line 2208 where the rook+bishop pair's alpha-tightening has no observable downstream effect with only 2 under-promo variants — a hypothetical knight-promo activation would make this observable).
- **Plan refinement during impl.** Plan §0 #1 originally committed to a defensive `is_quiet(only_mv)` gate on the single-reply branch. Test-suite-review pass 2 flagged that the case is structurally unreachable (movegen invariant). Plan was updated to drop the gate and replace with a structural-unreachability test pinning the invariant. The simpler logic is mutationally cleaner.
- **Bench unchanged from M5.D-v2.** M5.E corner cases don't fire on the 16-position middlegame bench corpus. This is plausible — true qsearch stalemate, forced-quiet-only positions, and queen-promo-stalemate are all corner cases that don't arise in typical middlegame play. The SPRT result determines whether M5.E provides measurable strength gain on real games or stays as pure-correctness without observable Elo signal.
