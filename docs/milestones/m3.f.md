# M3.F — `bench` UCI command + SPRT validation

Status: complete (2026-04-29). Closes M3. Adds (a) the deterministic `bench` UCI command — a node-count regression baseline for use in CI/PR workflows and as a strength-change fingerprint; (b) `scripts/sprt.sh` wrapping fastchess SPRT against historical-commit baselines per `docs/workflow.md` §SPRT; (c) the first SPRT match validating M3's exit criterion ("beats RandomMover ~100%"); (d) infrastructure for a first rating estimate vs Stockfish 1320.

`bench` from production binary at default depth 7: **`bench: 172312700 nodes 11489045 nps`** (16 positions × 7 plies aggregate). SPRT vs `M2.E`: **148 games, 148-0-0, LLR=2.95 H1 accepted in 3m35s**. M3 exit criterion satisfied.

## What landed

**`bench` UCI command:**

- New `src/bench.rs` module with `pub(crate) const BENCH_POSITIONS: [&str; 16]` — vendored FENs covering 3 opening / 8 middlegame / 5 endgame positions; module-scope `const _: () = assert!(...)` ties `BENCH_DEFAULT_DEPTH = 7` to the parser's `1..=63` range.
- New `Command::Bench { depth: Option<u32> }` variant + `parse_bench` sub-parser (strict-on-extra-tokens; bare `bench` → default, `bench <N>` → override).
- New `Engine::handle_bench` (synchronous on orchestrator thread) iterating the corpus, driving `Search::go` at fixed depth, summing node counts, emitting `info string` summary + signature lines per ADR-0011's "all non-spec output through `info string`" discipline.
- New `compute_bench_nps(total_nodes: u64, total_ms: u128) -> u128` `pub(crate) fn` extracted from the handler body to give cargo-mutants direct test coverage on the NPS arithmetic (3 mutations on the inline expression were structurally undetectable at the integration-test layer; same precedent as M3.D's `negate_window` and M3.E's `aborted_fallback_result`).
- New E43 integration test driving `bench 4` end-to-end through a real subprocess.

**`scripts/sprt.sh`:**

- Three subcommands: `sprt <baseline-tag>` (SPRT match HEAD vs baseline; weakest-tier bounds `elo0=0, elo1=10, alpha=0.05, beta=0.05`, up to 400 games), `match <baseline-tag>` (fixed-game-count match, 200 games default), `rating-estimate` (fixed-game-count match HEAD vs Stockfish UCI_Elo=1320, 200 games default).
- `git worktree`-isolated baseline checkouts at `target/sprt-baselines/<tag-slug>/`. Cached binaries reused across runs; `SPRT_REBUILD=1` forces a clean worktree.
- Baseline-binary sanity check via `printf 'uci\nquit\n' | <bin> | grep '^uciok$'` before fastchess starts — catches stale-toolchain rebuilds. Suggests `SPRT_REBUILD=1` retry on failure.
- Forward-compatible with the historical `chess` → `clawfish` package rename (between M2.E and M3.A): reads the package name from the baseline's `Cargo.toml` to derive the binary path.
- Field-standard fastchess invocation: `tc=10+0.1`, `-concurrency 6`, `-repeat`, adjudication via `-resign movecount=3 score=600 -draw movenumber=34 movecount=8 score=20 -maxmoves 200`, `-report penta=true` for pentanomial statistics.

**Doc-level adoption:**

- `Bench: <N>` commit-message convention adopted manually at M3.F (Fishtest/OpenBench standard). Pre-commit hook validating the `\b[Bb]ench[ :]+\d+\b` regex deferred to M4.
- `M3.F` annotated tag at the M3.F commit as the M4 SPRT reference point.

## Plumbing / process highlights

### Workflow loops

- **Plan-review (3 passes):** 2 + 0 + 0 must-fix items. Material catches: (a) the planned per-position `reset()` was a no-op for `prior_root_move` because `AlphaBetaMover::reset()` only clears `history`; reframed comment + risk bullet + test to reflect that `Search::go`'s top-of-go reset is the load-bearing protection. (b) The rating-estimate path was wavering between two alternatives in v1; pass 1 forced commitment to a `sprt.sh rating-estimate` subcommand.
- **Test-suite review (3 passes):** 1 + 1 + 0 must-fix items. Material catches: (a) `handle_bench_emits_summary_lines_at_default_depth` would have run for ~30s on CI (depth 7 from production); switched to `bench 2`, with E43 covering the production default-depth path end-to-end. (b) `handle_bench_joins_in_flight_search_worker`'s docstring overstated the temporal-ordering claim; narrowed to "no-deadlock + both lines appear."
- **Final review (2 passes):** 1 must-fix + 1 should-fix + 3 nits, then 0 across the board. The must-fix was a **real correctness bug** (see "Must-fix bug found by final review" below).

### Must-fix bug found by final review

`Engine::handle_bench`'s first action is `join_in_flight_worker()`, which sets `self.stop = true` and joins. v1's impl never cleared `self.stop` afterward — every per-position `Search::go` then inherited `stop=true` from the shared `Arc<AtomicBool>`. The contamination's effects depend on depth:

- At `bench 1` (the test surface chosen for unit-test wallclock budget), iteration 1 from any startpos-class position visits ~20 nodes — well below the 4096-node cancellation cadence — so iteration 1 completes despite `stop=true`. `depth >= max_depth` exits the ID loop before the inter-iteration stop check fires. The bug is structurally invisible at depth 1.
- At default `BENCH_DEFAULT_DEPTH = 7` (production), iteration 1 completes (~20 nodes) but the inter-iteration stop check at `src/search.rs:383` breaks the ID loop. Bench's per-position node counts collapse to ~tens of nodes instead of millions. Total bench signature would be ~320 nodes instead of ~172M.

Fix: `self.stop.store(false, Ordering::Relaxed);` immediately after `join_in_flight_worker()` — same pattern as `handle_go` line 214. Pinned by a new `handle_bench_after_go_infinite_produces_clean_state_results` test that runs `bench 2` twice — once on a fresh engine, once after a `[position startpos, go infinite]` sequence — and asserts per-position node-count vector equality. Test fails on v1 (per-position counts diverge), passes on v2.

The test surface deficiency that masked this bug is itself a calibration data point: the original test (`handle_bench_joins_in_flight_search_worker`) used `bench 1` for wallclock budget reasons, which structurally couldn't trip the contamination mechanism. The new equivalence test is more expensive (two full benches at depth 2) but catches the actual correctness invariant. Generalizable lesson: tests that exercise an invariant via a code path must use inputs that actually traverse that path, not just inputs that happen to be small.

### `compute_bench_nps` extraction

Three cargo-mutants survivors on the inline `(total_nodes as u128 * 1000) / total_ms` expression in v1: `/ → %`, `/ → *`, and `* → +`. The integration test's NPS check was loosened to "order-of-magnitude band" (`[nodes/1000, nodes × 10⁹]`) to absorb sub-millisecond per-position timing jitter, which made the band too wide to catch precise arithmetic mutations.

Same playbook as M3.D's `negate_window` and M3.E's `aborted_fallback_result`: extract the bug-prone expression into a named helper that's directly unit-testable. The chosen `(10, 3)` fixture distinguishes all three mutations:

- Original `(10 * 1000) / 3 = 3333`.
- `/ → %`: `10000 % 3 = 1`.
- `/ → *`: `10000 * 3 = 30000`.
- `* → +`: `(10 + 1000) / 3 = 336`.

A single equality assertion (`compute_bench_nps(10, 3) == 3333`) fails for every mutant; one test catches all three.

### Project-rename forward-compat in `sprt.sh`

The package was renamed `chess` → `clawfish` between M2.E (`M2.E`) and M3.A (`M3.A`). v1 of the SPRT script hardcoded `target/release/clawfish` as the baseline binary path, which fails for the M2.E baseline (binary at `target/release/chess`).

Fix: read the package name from the worktree's `Cargo.toml` via `grep -E '^name *= *"' "$BASELINE_DIR/Cargo.toml" | head -1 | sed -E 's/.*"([^"]+)".*/\1/'`. Forward-compatible with future renames (none anticipated, but cheap insurance).

### Sandbox interaction

`git worktree add` creates files under `target/sprt-baselines/<tag>/.claude/agents/*.md` (the M2.E baseline shipped these as part of its tree). The default Bash sandbox blocks writes to `.claude/` paths even within the project directory; the SPRT script must run with `dangerouslyDisableSandbox: true`. Documented in `docs/workflow.md` SPRT methodology section as a known interaction; not a blocker for routine SPRT runs (the orchestrator runs the script directly).

### Bench output format

`bench` emits all output through `info_string_always` per ADR-0011's "all non-spec engine output via `info string`" discipline. The OpenBench scraper convention expects bare-prefix `bench: <N> nodes <NPS> nps` lines; the `info string`-prefixed form is *substring-grep-compatible* with the OpenBench regex but not bytewise-OpenBench-format. Acceptable since clawfish doesn't have a CLI bench mode at M3.F (where bytewise format would matter for OpenBench's CLI invocation pattern). M4+ may revisit if OpenBench integration is desired.

### Plan §3.2 prose drift caught at impl

The plan's §3.2 prose claimed the corpus distribution was "4 opening, 8 middlegame, 4 endgame" but the actual table only had 3 distinct openings. Reconciled at impl time: kept the 16 fixtures from the table, updated the module docstring + phase-classification test to reflect the actual 3+8+5 distribution. The plan retains the off-by-one prose for historical reference; the module docstring is the canonical source.
