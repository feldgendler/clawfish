# M6.K — King-safety attacker S-curve activation → REMOVED (closed negative)

**Both SPRT probes regressed vs `M6.J`; the attacker S-curve was REMOVED. M6.K closes negative. Production HEAD stays `M6.J` (eval byte-identical, bench `1357063` / d4 `112497`).**

M6.K attempted to activate the king-safety attacker-count S-curve — the one M6
eval term the M6.I/M6.J Texel-on-quiet-positions pipeline structurally could not
tune (ADR-0037 §3) — via a pure `src/eval/data.rs` data edit (multipliers
`2/2/3/4` + the 100-entry CPW S-curve, scaled by a global gain `g` realized as a
pre-scaled table, not a runtime knob — ADR-0038 §3). The two-stage probe found
the term **doesn't pay at the joint M6.J landscape at any magnitude**:

- **Stage 1 — g=1 (full literature):** mixed-TC + virtual-clock SPRT **Δ Elo
  −44.54 [−72.13, −17.50]** vs `M6.J` (verdict=continue at the 400-game cap, LLR
  −1.25; CI entirely below zero). Rung-4. The M6.E **double-count is real** — the
  500cp S-curve ceiling double-counts the castled-king safety already priced into
  the PeSTO MG king PST.
- **Stage 2 — g=0.5 (deflate):** table = round(literature × 0.5), saturating at
  250cp; multipliers unchanged. SPRT **~−48 Elo** (W55-L89-D106 at 250 games,
  ~43%, stopped on the remove decision) — **same regression class as g=1**.
  Halving the magnitude did not help ⇒ the optimum is g≈0.
- **Outcome — REMOVED.** The attacker S-curve (`KING_SAFETY_TABLE`, the 4
  `KING_ATTACK_WEIGHT_*` multipliers, the per-node attacker-zone computation in
  `king_safety_term_white`, the `texel::features::king_safety_scurve_mg`
  reference term + its `EvalParams`/`EvalParamsI32` plumbing, and the S-curve
  tests) was deleted. The removal is **eval-neutral vs `M6.J`** (the term
  contributed 0 in production; deletion is byte-identical — d4 bench `112497`
  confirmed) and slightly faster (no per-node zone-attack computation for four
  piece types). The **shield + open/semi-open-file** king-safety sub-terms
  (Texel-tuned at M6.I) are unaffected and stay. M6.K is re-addable later from
  git + ADR-0038 if the NNUE era (M11) ever revisits classical king safety.

## Why this term, why now, why a data edit

M6.J's same-campaign STS pinned **King Activity 555 / AKPC 628** as the largest
residual classical-eval gap. The S-curve is the fix, and it is the one term the
Texel pipeline could not reach:

- **Non-linear in the tunable surface.** `score = TABLE[Σ multiplier·attackers]`.
  With multipliers at zero, `units ≡ 0` ⇒ only `TABLE[0]` reachable ⇒ the table
  is dead by construction. A live index needs non-zero multipliers, which break
  the linear inner solve.
- **Quiet-corpus blind spot.** The `|static − qsearch| < 30` filter strips the
  sharp king-attack positions whose game outcome would train the curve.

King danger is realized in *games* ⇒ tune on games (SPRT, SPSA), not a
quiet-position static regression. Stage 1 needs only the literature constants
turned on, which is a pure data edit — the S-curve computation (`king_zone`, the
`< 2 attackers ∨ no queen` gate, the `units.clamp(0,99)` index) already existed
and was unit-tested since M6.E.

## What was tried, then removed

The probe activated the S-curve as a pure `src/eval/data.rs` data edit
(multipliers `2/2/3/4` + the 100-entry CPW table at g=1, then g=0.5), added 6
bare-literal/differential king-safety tests (table-value pins, monotonicity,
multiplier pin, the `(-73,0)`→`(-56,0)` activation anchor, an MG-only
differential, a saturation differential) + the gate/units tests, and wired the
S-curve into the Texel reference scorer (`features.rs::king_safety_scurve_mg` +
the `EvalParams`/`EvalParamsI32` frozen fields). When both SPRTs regressed, **all
of that was deleted** — the S-curve computation in `king_safety_term_white`, the
`KING_SAFETY_TABLE` + `KING_ATTACK_WEIGHT_*` constants, the texel reference term
+ its plumbing, and the S-curve tests. The depth-4 bench pin returns to `112497`
(M6.J). The git history + ADR-0038 preserve the design for a possible NNUE-era
revisit. What remains: the **shield + open/semi-open-file** king-safety sub-terms
(Texel-tuned at M6.I) and the zone-geometry / shield / open-file tests.

## Texel interaction (during the probe; now moot)

While the S-curve was live, the §7 reference scorer recomputed it from
`EvalParams`' frozen fields, so the Tier-1 cross-check
`reference_score_white(pos, shipped()) == static_eval_white(pos)` stayed green by
construction (both sides read the same constants), and the fast **linear** model
excluded the S-curve by design (the Tier-2 test zeroed it to isolate linear-core
fidelity). With the S-curve removed, the reference scorer and the linear model
again agree trivially (no S-curve term on either side), and the noted "future
re-tune must fold the active S-curve into the model" consequence no longer
applies.

## SPRT results (both stages, mixed-TC + virtual-clock vs `M6.J`)

Run via `scripts/sprt.sh sprt M6.J` with `SPRT_TC_SAMPLE=10+0.1:1,20+0.2:1,40+0.4:1,60+0.6:1`,
`SPRT_VIRTUAL_CLOCK=1`, `SPRT_ELO1=5`, perf-mode launch.

- **Stage 1 (g=1):** verdict=continue at the 400-game cap, LLR −1.25, **ci: Δ Elo
  −44.54 [−72.13, −17.50]**, ptnml=[27,59,68,30,16]. Rung-4.
- **Stage 2 (g=0.5):** stopped at 250 games on the remove decision — W55-L89-D106
  (~43% / ≈ −48 Elo), same regression class as g=1.

Applying the ADR-0038 / ADR-0037 §9 ladder: rung-4 (mean < 0 ∧ CI lower ≤ −10) at
both magnitudes → the term is removed and M6.K closes negative. The shield +
open-file king-safety (M6.I) is untouched.

## Lessons

- **STS is a diagnostic, not the gate; only within-campaign EPD deltas are valid.**
  The candidate-land "+43 King Activity / +279 STS" was a cross-campaign artifact
  (movetime-EPD swung the `M6.J` baseline 10205→10646 for the *same binary*); the
  clean same-campaign battery showed King Activity −33, agreeing with the SPRT.
- **The PeSTO king PST already prices castled-king safety** (the M6.E HIGH
  transfer-risk verdict): the classical attacker S-curve double-counts it, and
  the double-count persists at half magnitude (g=0.5) — so deflation can't salvage
  it; the optimum is g≈0 (off).
- **Removing a zeroed-equivalent term is a free win:** eval byte-identical to
  `M6.J`, slightly faster (no per-node zone-attack computation), and clippy/test
  prove no dead code or harness inconsistency remained.

## Pre-NNUE decay (why we stopped at g=0.5, didn't sweep the full grid)

NNUE (M11) re-trains the eval from scratch and obsoletes all classical
king-safety weights. With g=1 and g=0.5 both regressing the same amount, a full
`g ∈ {0.25, 0.75}` + multiplier-sweep grid was not worth the SPRT cost for a term
NNUE will replace — the evidence already pointed to g≈0 (remove).
