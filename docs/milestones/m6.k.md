# M6.K — King-safety attacker S-curve activation (stage 1)

**Candidate landed 2026-05-29. Stage-1 mixed-TC SPRT vs `M6.J` PENDING (operator-gated, ~10 h, ADR-0037 §10). NOT yet shipped — production HEAD remains `M6.J`.**

Activates the king-safety attacker-count S-curve — the one M6 eval term the
M6.I/M6.J Texel-on-quiet-positions pipeline structurally could not tune
(ADR-0037 §3). Pure `src/eval/data.rs` data edit: the per-kind multipliers
`KING_ATTACK_WEIGHT_{N,B,R,Q}` flip `0/0/0/0 → 2/2/3/4` and `KING_SAFETY_TABLE`
flips `[0;100] →` the 100-entry Glaurung-1.2-lineage CPW S-curve (global gain
`g = 1`). This is **stage 1** ("literature on/off probe") of the two-stage
campaign; the SPRT decides ship vs stage-2 SPSA-deflate vs revert. ADR-0038.

Bench `1357063` / d4 `112497` → **`1431810` / d4 `117941`** (eval scores change
⇒ search cutoffs change; a determinism anchor, not a no-regression signal).

## Why this term, why now, why a data edit

M6.J's same-campaign STS pinned **King Activity 555 / AKPC 628** as the largest
residual classical-eval gap. The S-curve is the fix, and it is the one term the
Texel pipeline could not reach:

- **Non-linear in the tunable surface.** `score = TABLE[Σ multiplier·attackers]`.
  With multipliers at zero, `units ≡ 0` ⇒ only `TABLE[0]` reachable ⇒ the table
  is dead by construction. A live index needs non-zero multipliers, which break
  the linear inner solve.
- **Quiet-corpus blind spot.** The `|static − qsearch| < 30` filter strips the
  sharp king-attack positions whose game outcome would train the curve.

King danger is realized in *games* ⇒ tune on games (SPRT, SPSA), not a
quiet-position static regression. Stage 1 needs only the literature constants
turned on, which is a pure data edit — the S-curve computation (`king_zone`, the
`< 2 attackers ∨ no queen` gate, the `units.clamp(0,99)` index) already existed
and was unit-tested since M6.E.

## Texel interaction (faithfulness preserved by construction)

The §7 reference scorer recomputes the S-curve from `EvalParams`' frozen fields
(`features.rs::king_safety_scurve_mg`), which read `eval::data` via
`EvalParams::shipped()`. So the Tier-1 cross-check
`reference_score_white(pos, shipped()) == static_eval_white(pos)` stays green
automatically — both sides read the same now-non-zero constants. The fast
**linear** model (`extract`/`model_score_white`) excludes the S-curve by design
(it is the excluded nonlinear term that keeps the gradient solve linear), so its
Tier-2 equivalence test now zeroes the frozen S-curve in its comparison params
to isolate the linear-core fidelity it actually validates. **Consequence
(deferred):** a future re-tune with the S-curve *active* must fold the frozen
S-curve into the model base or freeze it consistently — recorded in ADR-0038 §2.

## Stage 2 (only if stage 1 H0/regresses) — SPSA-deflate as data

The M6.E HIGH transfer-risk double-count (PeSTO MG king PST already prices
~30–50 cp of castled-king safety) may make stage 1 regress. If so, deflate via a
**pre-scaled table** `TABLE[i] = round(literature[i] · g)` for
`g ∈ {0.25, 0.5, 0.75}` (a manual grid, each cell a data edit + SPRT vs `M6.J`),
then a coarse multiplier sweep if `g`-alone is insufficient. **Do not** tune the
100 individual entries (keep the literature shape). No runtime gain knob —
consistent with the hardcoded-weights ethos (ADR-0038 §3).

**Stage-2 prerequisite (artifact hygiene):** `bench/m6-params.json` still carries
the zeroed S-curve fields (generated pre-activation). Harmless for stage 1
(`texel-tune apply` never writes the S-curve), but regenerate or hand-reconcile
the JSON before any stage-2 re-apply so zeroed params are not applied over the
activated table.
