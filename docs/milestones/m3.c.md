# M3.C — Negamax + alpha-beta core

Status: complete (2026-04-29). First *searching* phase: replaces M3.A's depth-1 GreedyMover with full alpha-beta recursion at fixed depth (set via `go depth N`; default 4). Single-iteration; no iterative deepening, no qsearch (deferred to M3.D / M3.E). Calls `evaluate(pos)` at depth==0 (horizon effect accepted). Fail-soft negamax with `i32` scores, `MATE = 30000`, ply-adjusted mate-in-N, mate-distance pruning, triangular PV table (8 KiB inline on AlphaBetaMover), MVV-LVA capture ordering, M3.B repetition/50-move helper integration at `ply > 0`, 4096-node cancellation cadence with sentinel-return + post-call abort check + parallel `root_score` lockstep update. **ADR-0016** codifies the search structure.

**20-0 sweep** vs M3.A `baseline/material-greedy` worktree at fixed depth 4 (no SPRT — strength sanity check; SPRT runner lands at M3.F). ~8.55 Mnps single-threaded depth-8 from startpos on Apple M4. 660 lib + 5 integration tests passing in BOTH debug and release builds (the pre-commit gate the M3.B commit relied on stays satisfied).

## What landed

**Production search switch**:

- **`AlphaBetaMover`** struct in `src/search.rs` — replaces `GreedyMover`. Fields: `pv: PvTable` (inline 8 KiB), `history: Vec<u64>` (search-owned, cloned from `ctx.history` at `Search::go` start), `nodes: u64`, `aborted: bool`, **`root_score: Option<i32>`** (added in v2 to fix the score-contamination bug under partial abort).
- **`AlphaBetaMover::negamax`** private method — implements ADR-0016 §5's 11 numbered steps: cancellation poll, clear-ply, repetition + 50-move at `ply > 0`, mate-distance pruning, depth==0 horizon, generate + searchmoves filter at root, terminal handling (mate / stalemate / empty-filter-at-root short-circuit before in_check triage), MVV-LVA sort, fail-soft recursion + post-call abort check + alpha-update + PV+root_score lockstep update + beta-cutoff returning `best`.
- **`PvTable`** — 2D `[[Move; 64]; 64]` + `[usize; 64]` lengths, with `clear_ply` and `update` methods. Triangular semantics via the 2D-square layout (8 KiB; the flat-triangular `[Move; 2080]` ≈ 4 KiB layout was rejected for indexing simplicity).
- **`mvv_lva_score`** + **`score_to_uci`** — pure helpers. `mvv_lva_score` uses PeSTO MG values (P=82, N=337, B=365, R=477, Q=1025) for `victim × 16 - attacker` ordering; non-capture queen-promo scored at `promo_value` (~1025), placing it intentionally above QxP (287). `score_to_uci` switches between `cp <N>` and `mate <N>` formats with `(plies + 1) / 2` rounding for mate distance per UCI spec.

**Helper integration**:

- M3.B's `is_repetition` and `is_fifty_move_draw` consumed at top of negamax body, gated by `ply > 0` (root must always pick a move per CPW single-occurrence-in-search rule).
- History push/pop balanced around each recursive call: `history.push(post_make_zobrist)` then `negamax(...)` then `history.pop()` then `unmake_move`. Invariant `history.last() == pos.zobrist()` maintained throughout recursion.

**Production switch**:

- `src/engine.rs` `run_stdio()` switches `Engine::new(stdout, GreedyMover::new(0))` → `AlphaBetaMover::new()`.
- `Random_Seed` UCI option **preserved as no-op** (alpha-beta is deterministic; cleanup deferred to a separate commit per plan §1).
- `GreedyMover` + `splitmix64_next` + the M3.A D1 SplitMix64 reference test deleted. M3.A's GreedyMover-specific tests (D13–D22, E1) deleted.
- E38 deleted (M3.A self-play seed=0 / ply=116 / `f2f3` test); replaced with E39 — `position startpos` + `go depth 3` + `bestmove b1c3` regression guard.

**Other**:

- `Move::default()` derived in `src/mov.rs:147` to give a zero-bits sentinel (`Move(0)` = `from=A1, to=A1, flag=Quiet`, never produced by movegen) for `PvTable` array initialization. Distinct from M5's null-move pseudo-move concept (the existing `from_uci` doc-comment about "no `Move::NULL` sentinel today" remains accurate — we did not introduce `NULL` as a name).
- `pub(crate) use data::MATERIAL` in `src/eval.rs` exposes the PeSTO material table to `src/search.rs::mvv_lva_score` without renaming round-trips.
- ADR-0016 codifies: fail-soft negamax, `i32` scores with `MATE=30000`, ply-adjusted mate scoring, mate-distance pruning, 2D-square triangular PV table, MVV-LVA, 4096-node cancellation cadence, `Search::go` trait surface unchanged, `Search::go` clone-from-ctx history (not `&mut SearchContext`), `Random_Seed` deferred-cleanup. v2 update extends ADR §5's PV-update lockstep invariant to the new `root_score` field.

## Implementation highlights

- **The `root_score` lockstep fix** was the substantive must-fix surfaced by final-review. Before the fix: when an abort fired AFTER the first root move's subtree had completed (e.g. under `quit`-during-search), `pv.lengths[0] > 0` (PV from the completed subtree) but the negamax return value was the abort sentinel 0 propagated up the stack. `Search::go` emitted `info ... score cp 0 pv <real-line>` — `bestmove` was correct but the score was the sentinel, misleading any UCI consumer reading `score cp` for analysis / adjudication. Fix: track `root_score: Option<i32>` updated in lockstep with PV at `ply == 0 && score > alpha`; `Search::go` uses `self.root_score.unwrap_or(0)` instead of the negamax return value when `self.aborted`. Regression test pins the partial-completion case via `nodes: Some(5000)`.
- **The empty-searchmoves-in-check trap** was caught at test-suite review. Without the special-case, a `go searchmoves <illegal-moves>` from a check position would fall into the in-check-no-moves arm and return `-MATE` falsely. Fix: at `ply == 0 && ctx.limits.searchmoves.is_some() && moves.is_empty()`, return 0 BEFORE the in_check triage. Three-pass test-suite review caught this; without it the regression would have shipped.
- **The mate-in-2 fixture turned out to be mate-in-1.** The test-suite reviewer + orchestrator + initial impl all "verified" first-principles that `6k1/4Q3/5K2/8/8/8/8/8 w - - 0 1` (Kf6+Qe7 vs Kg8) was mate-in-2, but Qe7-g7 covers all of g8 (g-file), f8 (NW diagonal from g7), h8 (NE diagonal from g7), h7 (rank 7); f7 covered by Kf6; Kxg7 illegal (Qg7 protected by Kf6) — actually mate-in-1. Caught at impl time when alpha-beta returned `MATE - 1` instead of `MATE - 3`. Test renamed to `alphabeta_finds_forced_mate_from_dominating_position`; assertion relaxed to `score >= MATE_IN_MAX_PLY` (any winning mate). Recorded as a calibration data point — chess-geometry first-principles verification is genuinely hard without engine assistance.
- **Debug-build `cargo test` timeouts** were the second must-fix. M2.D-era engine tests had 1-second `bestmove`-poll timeouts calibrated for GreedyMover's depth-1 latency. AlphaBetaMover's default-depth-4 search exceeds 1 s in debug builds → the M3.A-era tests started timing out under the new production search. Fix: relax 13 `Duration::from_secs(1)` patterns to `Duration::from_secs(5)` mirroring an existing precedent already in the diff. Pre-commit hook (which runs `cargo test` in debug mode) now passes.
- **Sonnet+Opus chess-coder calibration deferred to M3.D**. The plan §11 trigger fired but the worktree-isolation A/B was incompatible with the uncommitted-test-slice state at impl time. Single-Sonnet impl pass caught the negamax body cleanly but missed the two must-fixes that final-review surfaced — exactly the kind of subtle judgment calls the workflow's "When to flag a coder slice for Opus" criteria flag. M3.D will be the actual A/B trigger.
- **Mutation testing was unstable** in the orchestrator's sandbox during the v2 verification (3 separate fork attempts failed despite the v1 partial run succeeding in the final-reviewer's environment — same machine, but different sandbox restrictions). The v1 partial run (40/101) showed 100% kill rate (37 caught + 2 timeout-as-effective-catch + 0 missed). Re-run before any future SPRT-validated change against this baseline.
- **No baseline tag at M3.C commit**. Plan §10 step 13 deferred the `baseline/alpha-beta-no-tt` tag to M3 end / M4.A start (the tag's "without TT but with qsearch + ID + time-management" semantic only matches the M3.F-end commit, not the bare M3.C alpha-beta).
