# M3.B — Game-history + draw-detection plumbing

Status: complete. Pure plumbing phase — `Engine::game_history: Vec<u64>` carries the full Zobrist trajectory (including the current position) under invariant `history.last() == position.zobrist()`. `SearchContext::history: Vec<u64>` is owned and cloned from `Engine::game_history` at `go`-spawn time. Helper functions `is_repetition(history: &[u64], halfmove_clock: u8) -> bool` and `is_fifty_move_draw(halfmove_clock: u8) -> bool` live in `src/search.rs` as `pub(crate)` free functions, ready for M3.C's negamax to consume. GreedyMover unchanged; no production-search consumer of the helpers until M3.C lands. No new ADR. 648 lib tests (623 prior + 25 new), 0 failing. Mutation 11/11 caught on the diff. fastchess `--compliance` 40/40 (UCI surface unchanged).

## What landed

Three small pieces of code wired together, all enforcing one invariant:

- **`src/search.rs::is_repetition`** — single-occurrence-in-search repetition test. Walks `history` priors backward in 2-ply steps (only same-side-to-move positions can match — the Zobrist turn key flips on every ply), capped at `min(halfmove_clock, history.len()-1)`. `halfmove_clock` is the irreversible-move stop (any pawn move or capture severs the repetition chain); `history.len()-1` is the safety bound (FEN-loaded clocks may exceed observed history depth). Empty history returns `false` via `split_last`. Per CPW "Repetitions": a single match counts inside the search; FIDE 9.2 three-fold-claim is the GUI/adjudicator's job.
- **`src/search.rs::is_fifty_move_draw`** — `halfmove_clock >= 100`. 100 plies = 50 moves by each player without pawn move or capture, the FIDE 9.3 claimable threshold. The 75-move auto-draw at 150 plies is not separately handled — once claimable, treated as drawn for search reasoning.
- **`src/search.rs::SearchContext::history: Vec<u64>`** — owned, populated by `handle_go` via `self.game_history.clone()`. The clone is intentional; M3.C's negamax will mutate the worker's copy via push/pop on make/unmake, while the engine's `game_history` stays pristine for subsequent `go` invocations.
- **`src/engine.rs::Engine::game_history: Vec<u64>`** — private field with `pub(crate)` test accessor. Lifecycle:
  - `Engine::new()` initializes to `vec![Position::starting_position().zobrist()]`.
  - `handle_ucinewgame` sets `position = starting_position()` then `game_history = vec![starting_position().zobrist()]`, restoring the invariant.
  - `handle_position` rebuilds: on FEN parse error, returns *before* touching `game_history` (preserves both prior fields). On success of `base` build, initializes a working `let mut hist = vec![base.zobrist()];` from the new base. Each successful move pushes `pos.zobrist()` after `make_move`. On move error, resets `self.position = base` and `self.game_history = vec![base.zobrist()]` (single entry, *new* base — not the prior history, not the partially-built `hist`). On full success commits both atomically.
  - `handle_go` clones `self.game_history` into the new `SearchContext::history` field.

## Implementation highlights

- **Invariant pairing.** `(self.position, self.game_history)` are written as a pair on every code path. The plan §8 step 5 spelled out the exact code shape per error path; no novel logic to invent. The four error-path tests in Group D each include a `assert_eq!(hist.last().copied(), Some(pos.zobrist()), ...)` co-assertion to pin the joint invariant under each error condition.
- **Plan §11 deferred decision: `SearchContext::history`'s long-term home.** M3.C's negamax will need `push`/`pop` on the history vector during recursion. `Search::go` currently takes `ctx: &SearchContext` (immutable borrow), which precludes in-place mutation. M3.C will choose between (a) `&mut SearchContext`, (b) `Cell`/`RefCell`, or (c) moving `history` to a separate `&mut Vec<u64>` parameter. M3.B's tests are mostly location-agnostic (`handle_go_does_not_consume_engine_history` doesn't read `ctx.history` at all); only `handle_go_clones_history_into_search_context` is location-coupled.
- **`is_repetition` form.** `for i in (2..=max_back).step_by(2)` — the 2-ply step is structural in the loop, not a manual `i += 2` increment. Empty range (when `max_back < 2`) handles the `halfmove_clock = 0`, single-entry, and empty cases in one expression.
- **Cap-by-length safety.** `let max_back = (halfmove_clock as usize).min(prior.len());` — required because `halfmove_clock` is FEN-loaded and may exceed actual observed history depth. Without it, an indexing of `prior[prior.len() - i]` would underflow to a giant `usize` and panic. Two paired tests (`..._exceeds_history_match` and `..._exceeds_history_no_match`) pin both directions of the cap.
- **Test-suite review took 3 passes.** Pass 1 caught the tautological clone test in plan v1; pass 2 caught a duplicate even-distance fixture and asserted that the four error-path D.4 tests should also co-assert the joint invariant; pass 3 caught the structural weakness in `handle_position_history_invariant_holds_after_every_handler` (error-path commands in the *middle* of the sequence are repaired by subsequent happy-path commands before the terminal assertion fires). Final form: four independent fresh-engine sub-sequences, each ending on a different *kind* of handler, with the assertion observing that handler's post-state.
- **Plan §6.1 mutants sub-list audit.** Plan-reviewer pass 2 verified each named mutant against the listed test row that catches it. Resulting prose was tightened: the `i = 0` start-mutant catch is via panic (out-of-bounds) not via wrong return; the `i = 1` start-mutant (the more-likely cargo-mutants candidate) is caught by row 8's odd-distance test; only row 11 catches the cap-by-`prior.len()` removal mutant (row 10 returns the same true with or without the cap).
- **No `RandomMover` ghosts.** Final-review pass 1 verified the M3.A retro entry, the M2.D self-play test, and the `Random_Seed` UCI option all stay correct (the seed PRNG is now owned by GreedyMover, untouched by M3.B).
- **Plan-reviewer caught the `handle_go_does_not_consume_engine_history` tautology in v1**: the original test mutated a captured clone and asserted the captured clone unchanged — trivially true. Rewritten in v2 to assert against `engine.game_history` directly after `run` returns (post-`handle_quit`-join), which actually exercises the clone-not-take contract.
