# 0006 — Stockfish is the sole oracle for perft validation

**Status:** Accepted, 2026-04-27

## Context

M1 needs an external trusted source against which to validate the engine's move generation. Multiple options exist: published numbers on the Chess Programming Wiki, perft-specific tools (qperft, Roce), perft test files distributed by various engines, Stockfish's built-in `go perft`. Hunting down and cross-referencing the canonical numbers across these sources is its own time sink — none of it informs how to *write* the move generator, only how to test it.

## Decision

**Stockfish 18** (current Homebrew stable, installed via `brew install stockfish`) is the **sole** oracle for all perft data used in our test suite — plain totals and divide output. We do not vendor perft fixtures from CPW or any other source. Test expectations are generated by running Stockfish on the test positions, captured to fixture files, and committed to the test suite.

## Caveat: categorized perft

Stockfish's built-in `go perft N` outputs:

- The **total leaf count** at depth N.
- A **divide listing** — each legal first move with its sub-count.

It does **not** natively output **categorized counts** (captures, en passant captures, castles, promotions, checks, discovered checks, double checks, checkmates). For our M1 testing this is sufficient: divide narrows any total-mismatch bug to a specific first-move subtree, and recursive divide narrows further to the exact discrepancy position. Categorized counts are a debugging convenience, not a correctness requirement.

If we ever want categorized counts, our own engine will produce them as **internal sanity checks** (e.g. invariant "total = sum of categories"); they are **not** externally validated against Stockfish.

## Consequences

- Tests verify "our engine agrees with Stockfish," not "our engine agrees with absolute truth." Practically identical: Stockfish's move generation is the most-tested chess code in existence and has been cross-verified by the engine community for ~20 years.
- A bug in Stockfish's move generator would silently pass our tests. Risk accepted as theoretical.
- The Stockfish version installed at fixture-generation time **must** be recorded with the fixtures so we can re-verify later if a number is ever doubted.
- Consistent with `decisions/0003-no-third-party-source-code-reading.md`: we consume Stockfish's UCI output as data, never read its source. Running the binary and parsing stdout is data consumption, not code reading.
- Eliminates the need for `prior-art.md` to track CPW perft tables, qperft, Roce, or other historical perft data sources. They were nice-to-have; with Stockfish as the oracle they're redundant.

## How to apply

- Test fixtures (likely `tests/perft_fixtures/` or similar once the Cargo project exists) record the Stockfish version that generated them in a header field or sibling metadata file.
- Re-verify with the latest Stockfish if any number is ever doubted.
- Use `go perft N` via UCI for plain totals + divide; do not write a categorized-perft requirement against Stockfish.
- If a categorized-perft check is needed for our own engine's internal consistency, generate it inside our engine and assert invariants on it — do not seek external categorized data.
