# M8.A — Principal Variation Search (PVS)

**Milestone:** M8.A (Search refinements I, pre-NNUE). First search-layer change since M7.B.2.
**Baseline tag for SPRT:** `M7.B.2` (current production search HEAD; eval `M6.J`).
**Research:** [`docs/research/m8.a-pvs.md`](../research/m8.a-pvs.md).
**ADR:** ADR-0043 (PVS) lands with this unit; amends ADR-0025 §5 (two-step → three-step LMR ladder). ADR-0018 §11 (`is_pv` TT-cutoff gating) is left **unchanged** (see §3.1 — the parameter is retained).

## 1. Goal

Search non-first children with a null window `(alpha, alpha+1)`; on an interior result (`alpha < score < beta`) re-search full-window. Compose with LMR as the canonical three-step ladder. The synthetic `is_pv` parameter is **retained** (see §3.1 for why the window-derivation cleanup the roadmap names is *deferred*, not done here).

### 1.1 This is a strength change, not a bit-exact refactor

PVS is value-exact vs *pure* alpha-beta. But this engine's NMP/RFP/FFP/LMR prunes are `is_pv`-gated, and PVS marks the full-window re-search node `is_pv=true` (prunes suppressed) where today the only full-window search of a late move runs `is_pv=false` (prunes fire). PVS also scouts non-first children of a PV node with a *narrow* window where today they got the full window — changing window-dependent prune firing (RFP/NMP read `beta`). So PVS **changes the search tree** and is **not** bench-identical to `M7.B.2`. It is SPRT-gated per the roadmap M8 exit criterion. Expected +5–15 Elo / 10–15% node reduction (research §6).

## 2. Files modified

- `src/search/tests.rs` — new PVS tests + exactness property test. Re-pin the handful of *exact*-count anchors that PVS legitimately shifts (bench/firing counts); all `> 0` / structural assertions and every existing `is_pv`-argument call site stay **unchanged**.

## 3. Design

### 3.1 `is_pv`: keep the parameter (window-derivation deferred)

The roadmap names "retire the synthetic `is_pv` in favour of `beta - alpha == 1`." Deriving `is_pv = ply==0 || beta-alpha>1` and **dropping the parameter** was the first design; it is **rejected for this unit** because it makes the state "non-PV node with a wide search window" *unrepresentable*, which breaks two classes of existing test irrecoverably:

1. ~16 prune-*firing* tests pass `is_pv=false` with a wide `(-INF,INF)` window and assert `lmr_reduced_searches > 0` (anti-vacuous). A width-1 window — the only way to derive `is_pv=false` — collapses the search to an immediate fail-low/high, so the firing can no longer be elicited.
2. `negamax_skips_lmr_at_ply_zero_even_when_is_pv_false` (and NMP/RFP siblings) pass `ply=0, is_pv=false` to anchor the `ply>0` defense-in-depth root guard *independently of `is_pv`*. Derivation forces `is_pv=true` at `ply==0`, so the `is_pv=false`-at-root state — the only thing that distinguishes `ply>0` from `!is_pv` — cannot be constructed; the guard becomes untestable.

Behaviorally, keeping the parameter is **identical** to deriving it: every production call site already passes an `is_pv` consistent with its window (root wide ⇒ `true`; NMP/SE children width-1 ⇒ `false`; first child inherits, scout `false`, re-search `is_pv`). The only thing derivation buys is one fewer `bool` in the signature — a roadmap-aesthetics win that does not earn the test-coverage loss. **Window-derivation is deferred to a future mechanical-cleanup unit** that can re-express the affected tests through the production `go()` path; ADR-0043 records the deferral and the reason.

The four production call sites stay correct (evidence, not assertion):
- Root call (`go`): aspiration window width is `(-INF,INF)` at depth 1 and floors at **width 50** for depth ≥ 6 (`aspiration_half_width` clamps the half-width at `ASPIRATION_MIN_DEFAULT=25`). The `ply==0`/wide-window state is `is_pv=true`. ✓
- NMP child (`search.rs:1146`): `(-beta,-beta+1)`, `is_pv=false`. ✓
- SE verification (`search.rs:1287`): `(s_beta-1,s_beta)`, `is_pv=false`; same `ply` (not `ply+1`), but SE needs depth ≥ 6 so never fires at the root — the `ply==0` distinction is moot there. ✓
- Move-loop children: §3.2. ✓

### 3.2 PVS move-loop ladder

Replace the per-move search block (`search.rs:1419-1528`). For each searched move (`mv`, `cur_i`), with `R = lmr_reduction` (0 when LMR-ineligible) and `ext = move_extension` (only `cur_i==0`):

```
first searched move:
    score = search_child(depth-1+ext, alpha, beta,  child_is_pv = is_pv)   // full window
    move_is_full_depth = true

subsequent moves:
    // Step 1 — pilot: reduced depth, null window, non-PV child
    score = search_child(depth-1-R, alpha, alpha+1,  child_is_pv = false)
    move_is_full_depth = (R == 0)
    // Step 2 — verify: full depth, null window (only if reduced pilot beat alpha)
    if R > 0 && score > alpha:
        score = search_child(depth-1, alpha, alpha+1,  child_is_pv = false)
        move_is_full_depth = true
    // Step 3 — exact: full depth, full window, PV child (only if interior to the real window)
    if score > alpha && score < beta:
        score = search_child(depth-1, alpha, beta,  child_is_pv = is_pv)
        move_is_full_depth = true
```

- **`child_is_pv`:** first move and Step-3 re-search get `is_pv` (the parent's PV-ness — at a PV node ⇒ `true`, the canonical "re-search node is a PV node", research §3.2); scouts get `false`. This is the *only* change from today's single `child_is_pv = is_pv && cur_i == 0` (which already yields `is_pv` for the first move, `false` for others).
- **Non-PV node collapse (correctness):** at a non-PV node `beta == alpha+1`, the null window equals the node window, and Step-3's `score < beta` ⇒ `score < alpha+1` ⇒ impossible after `score > alpha` ⇒ Step 3 never fires. The node degenerates to today's full-window scout. No special-casing.
- **Step 2 vs Step 3 are mutually exclusive per node-type:** Step 2 requires `R>0` ⇒ LMR ⇒ `!is_pv` ⇒ `beta==alpha+1` ⇒ Step 3 unreachable. Step 3 fires only at PV nodes, where `R==0`. So `pvs_lmr_verify_searches` (Step 2) and `pvs_research_full_window` (Step 3) never co-increment for the same move — by construction, not a bug.
- **Step 2 is the existing LMR re-search, not new behavior (key for §5 coverage).** Because LMR is gated `!is_pv` (`search.rs:1323`), Step 2 (`R>0`) fires *only* at non-PV nodes, where `beta==alpha+1` so the Step-2 null window `(alpha,alpha+1)` **equals** the old ADR-0025 §5 full-window re-search `(alpha,beta)`. Step 2 is therefore behaviorally identical to today's LMR full-depth re-search — the window relabeling is a no-op at every node where it fires — and is covered by the existing LMR re-search tests plus the non-PV bit-identity anchor (§5). The genuinely new paths are the PV-node scout (Step 1 at `R==0`) and the Step-3 full-window re-search. (The three-step framing matters only if a future change ever permits LMR at PV nodes; the ADR-0025 amendment records this.)
- **First-move detection:** a `first_searched: bool` flag (init `true`, cleared after the first non-excluded move). The first non-excluded move always gets the **full window `(alpha,beta)` at full depth** — never a scout — even at an SE verification frame where `cur_i==0` is the excluded TT move and the first searched move is `cur_i==1` (else the verification score would be a scout result, not a real one). SE `move_extension` keeps using `cur_i==0` (unchanged; verification frames are non-PV, so the `child_is_pv` distinction is moot there).
- **Abort discipline:** each `search_child` is followed by the existing `if self.aborted { return 0; }` (one per call, matching current LMR structure).

### 3.3 `move_is_full_depth` provenance

`false` only when the contributing score is reduced-depth — `R>0 && pilot_score <= alpha` (Step 1, no escalation). Identical to today's reduced-only rule; feeds `best_is_full_depth_after_score` and the ADR-0025 §6 reduced-only TT-store suppression unchanged. A move that clears Steps 1–2 but fails low at Step 3 is still full-depth-witnessed (the Step-2 score is full-depth), so `move_is_full_depth=true` there is correct (research §2.4).

### 3.4 MATE-boundary safety

`alpha+1` with `alpha ≤ MATE_IN_MAX_PLY=29936` ⇒ ≤ 29937; worst case `alpha=INF-1=30000` ⇒ `alpha+1=INF=30001`, a valid width-1 window (research §7.3). No overflow; `score_to_tt` narrowing to i16 stays within `|adjusted| ≤ MATE+MAX_PLY = 30064 < i16::MAX` (ADR-0018 §5). Pinned by a unit test asserting both no-panic search **and** correct fail-high TT store round-trip.

### 3.5 Diagnostic + exactness-harness fields (`#[cfg(test)]`)

Counters (mirror `nmp_firings`/`lmr_*`; reset in `go` and `negamax_for_test`):
- `pvs_scout_searches` — Step-1 pilots run (non-first moves).
- `pvs_lmr_verify_searches` — Step-2 full-depth null-window verifies run.
- `pvs_research_full_window` — Step-3 full-window re-searches run. Re-search rate `= pvs_research_full_window / (non-first PV-node moves)` is the ordering-health diagnostic (research §6.2; expect 5–20%).

Exactness-harness flags (default `false`; compiled out of release; used only by §5's anchors):
- `test_force_all_pv` — forces `child_is_pv = true` for **every** recursive child, neutralizing all `is_pv`-gated prunes (NMP/RFP/FFP) and LMR throughout the subtree. (Consequently `R==0` everywhere under this flag, so Step 2 is unreachable *by design* — Step 2 lives only at non-PV/LMR nodes, covered by the non-PV bit-identity anchor instead.)
- `test_disable_scout` — replicates the **pre-PVS move loop exactly**: non-first children get the LMR reduced pilot at the *full* window `(alpha,beta)` → full-depth full-window re-search if `>alpha`; non-LMR children at full window. Serves as the value reference for both §5 exactness anchors.

## 5. Test strategy (`src/search/tests.rs`)

New tests (names):
- `pvs_research_fires_only_when_score_interior` — PV node: a non-first move scoring in `(alpha,beta)` ⇒ exactly one Step-3 re-search; `≤alpha` ⇒ none; `≥beta` ⇒ cut, no re-search (counter assertions).
- `pvs_non_pv_node_never_full_window_researches` — width-1 node ⇒ `pvs_research_full_window == 0` regardless of child scores.
- `pvs_first_move_searched_full_window` — first move never scouted (`pvs_scout_searches` excludes index 0).
- `pvs_lmr_three_step_ladder_counters` — LMR-eligible late move failing high reduced→full: Step-1 + Step-2 fire (Step-3 absent at the non-PV node where LMR lives); a reduced-only fail-low asserts `move_is_full_depth=false` via the stored TT bound.
- `pvs_exact_under_all_pv_vs_full_window` (+ `prop_pvs_exact_under_all_pv`, proptest) — **strong exactness anchor for the new PV paths.** With `test_force_all_pv=true` (all prunes/LMR neutralized), for curated positions and random positions at depth ∈ [1,4]: PVS-on (`test_disable_scout=false`) must equal the full-window reference (`test_disable_scout=true`) on **both** score and bestmove. Exercises the PV-node scout *and* the Step-3 re-search in isolation from the prune interaction — the actual behavioral delta. (Step 2 is `R==0`-dead here by design; the next anchor covers it.)
- `pvs_nonpv_bit_identical_to_reference` (+ proptest) — **Step 1 + Step 2 value anchor.** At a non-PV node (width-1 window `(x,x+1)`, `ply>0`, depth ≥ 3 so LMR fires) under normal config (prunes/LMR on), PVS-on must be **bit-identical** to `test_disable_scout` (today's loop) on score *and* node count — because at a non-PV node the scout window equals the node window, so PVS and the pre-PVS loop coincide exactly. This value-covers Step 1 (reduced pilot) and Step 2 (full-depth re-search) where they actually fire, catching any window/depth arithmetic error in the reduced/verify path.
- `pvs_depth1_exact_vs_full_window` — secondary anchor: at a depth-1 *root* call (children are prune-free qsearch; root is PV so RFP/FFP suppressed), PVS score+bestmove equal a full-window reference on startpos/Kiwipete/tactical positions. Cheap and assumption-light.

**TT handling for all exactness anchors:** each run (PVS-on and reference) uses a **fresh per-run mover with `tt: None`** (or a freshly-cleared TT) — never shared between the two runs. Otherwise scout-generated Lower/Upper entries would perturb the reference's move ordering and flip a tie-broken bestmove. Matches the existing exactness-test convention in the suite.
- `pvs_mate_boundary_null_window` — `alpha=INF-1` node: null window `(INF-1, INF)` searched without panic; fail-high stores and round-trips correctly (§3.4).
- `pvs_root_research_when_first_move_fails_low` — **research §5 gotcha:** at the root under an aspiration-narrowed window, force the first root move to fail low (alpha unmoved), then a later root move scoring in `(alpha,beta)` still triggers a Step-3 re-search (the `score>alpha && score<beta` condition, not `>original_alpha`). Driven through `go()` with a constructed position.
- ~~`pvs_aspiration_root_is_pv_guard`~~ — **dropped (not implemented):** would assert `is_pv` stays effective at a synthetic width-1-window `ply==0` root, but that state is unreachable (production aspiration floors at width 50, §3.1) and the retained `..._at_ply_zero_even_when_is_pv_false` guards already anchor the ply-0 root guard independently of `is_pv`. Striking it avoids testing an unreachable state.

Migrated/re-pinned existing tests: the stacked-NMP canary (`negamax_passes_allow_null_false_in_null_subsearch`, `STACKED_NULL_GATE_REACHABLE`) is re-validated — PVS introduces null windows in the move loop, the exact condition it guards; confirm `STACKED_NULL_GATE_REACHABLE` stays provably **0** and re-pin its `NMP_FIRINGS_PINNED` secondary anchor to the new PVS tree. Any other exact node/firing-count anchor that shifts is re-pinned with a PVS-attribution comment. The ~16 wide-window `is_pv=false` firing tests and the `..._at_ply_zero_even_when_is_pv_false` guards stay **unchanged** (the parameter is retained — §3.1).

## 8. Risks & rejected alternatives

- **Drop-the-parameter / window-derivation (rejected for this unit, §3.1).** Loses unit-testability of prune-firing-under-wide-window and the root `ply>0` guard. Deferred to a mechanical-cleanup unit.
- **Two-step vs three-step ladder.** Research §2.2 recommends three-step (intermediate full-depth null-window verify) for an NMP/TT-instability engine. Adopted. If SPRT is flat/negative, dropping Step 2 (two-step) is the first tuning lever.
- **Re-search as PV vs non-PV.** Step-3 marks the child `is_pv=true` (canonical; prunes suppressed in the likely new-best line). If SPRT regresses, `child_is_pv=false` at Step 3 (re-search stays non-PV, closer to a pure scout optimization) is the second lever.
- **Not bench-identical (§1.1).** Surfaced, not a defect — SPRT is the gate.
