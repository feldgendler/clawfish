# M7.C — SEE capture futility / delta pruning at frontier nodes

**Status:** PLAN (ready for review). Production HEAD = `M6.J` (eval) + `M7.B.2` (search).
This is the third and final M7 sub-phase and the explicit **ADR-0026 §10 deferral**
("Per-move SEE-based capture futility / delta pruning") + the **ADR-0040 §Consequences**
hand-off ("the negamax-side SEE capture-futility / delta pruning is out of scope — M7.C").

Prior-art survey: [`docs/research/m7-see-capture-futility.md`](../research/m7-see-capture-futility.md).
The research **corroborates this two-layer alpha-relative design** as the Stockfish
pattern (MVV delta-prune first, SEE gate second) and **argues** (first-principles,
not an empirical per-TC measurement) the key property: **alpha-relative capture
futility is self-regulating in TC** — alpha rises from below as deeper search finds
refutations, so the prune fires *less* at depth, the opposite of M7.B's
alpha-*independent* threshold. So v1 ships **flat, with no root-depth ramp** (the
M7.B.2 fix is predicted unnecessary here). Caveat: the regulation is via the node's
*window* (alpha), not total — branch (a) still prunes on a depth-1-quality parent
`static_eval` even at a frontier node reached deep in a slow-TC tree — so the per-TC
SPRT read is a **gate**, not a footnote (§10): if 60+0.6 regresses, the M7.B.2-style
ramp (M7.C.1) ships *before* M7.C, mirroring the M7.B→M7.B.2 sequence. The
alpha-*independent* `see < -k·depth²` lever (research §1c) is the TC-risky class and
is explicitly a *separate future mechanism*, not part of v1 (§11.5).

## 1. Problem / scope

Frontier futility pruning (FFP, M5.D / ADR-0026) prunes only **quiet** moves at a
frontier node: when `static_eval + margin ≤ alpha`, a quiet's true score cannot
reach alpha, so it is skipped. Captures, promotions, and EP are deliberately left
untouched by FFP because a capture swings material and FFP's quiet ceiling
(`static_eval + margin`) doesn't account for it.

M7.C closes that gap for **captures**, using the SEE evaluator (`see(pos, mv)`,
ADR-0039) to bound the material swing. It is the natural complement to FFP and the
**second production consumer of SEE** (after M7.B's qsearch SEE-pruning). SEE is a
search primitive that NNUE does not obsolete (ADR-0039), so this is a permanent gain.

**In scope:** capture-futility pruning of non-promotion captures at the existing
FFP frontier-node gate, in the negamax move loop.

**Out of scope (v1, deferred tunables — §10):** promotions / promo-captures;
gives-check captures (exemption); depth extension beyond `FFP_MAX_DEPTH`; a
root-depth ramp (the M7.B.2 mechanism); TT-move / killer exemptions.

## 2. Mechanism

At a frontier node already cleared by the FFP node-level gate, for each
**non-promotion capture** `mv` (flag ∈ {`Capture`, `EnPassant`}), skip it iff an
optimistic upper bound on its score cannot reach alpha. Two layered conditions —
a **sound delta-prune** (optimistic, no `see()`) and an **aggressive SEE refinement**
(losing captures only):

```
victim   = SEE_VALUE[captured kind]      // EP-aware: captured pawn for EnPassant
attacker = SEE_VALUE[mover kind]
margin   = capture_futility_margin(depth)

// (a) Delta prune — even taking the victim for FREE (no recapture) can't reach alpha.
//     `victim` is the maximum material a non-promo capture can net, so this is a
//     SOUND optimistic ceiling. No see() call.
mvv_bound = static_eval + victim + margin
if mvv_bound <= alpha  ->  PRUNE (bound = mvv_bound)

// (b) SEE refinement — only for materially-losing captures (victim < attacker),
//     i.e. the qsearch fast-out's "expensive class" (QxP / RxN-defended / ...).
//     A losing capture whose realistic (recapture-aware) outcome can't reach
//     alpha is pruned. Winning/equal captures (victim >= attacker) are NEVER
//     SEE-pruned in v1 (safety: they are the most likely saving tactic; perf:
//     bounds see() to the rare losing-capture class).
else if victim < attacker:
    see_bound = static_eval + see(pos, mv) + margin     // see <= victim => see_bound <= mvv_bound
    if see_bound <= alpha  ->  PRUNE (bound = see_bound)
```

Both bounds are valid fail-soft **upper** bounds on the move's true score
(`see ≤ victim ⇒ see_bound ≤ mvv_bound`, and both `≤ alpha` on a fire), so the
fail-soft accounting is identical to FFP (§4).

**Why this is exactly "SEE capture futility / delta pruning":** (a) is textbook
delta pruning (optimistic material ceiling vs alpha); (b) is the SEE consumer that
makes the prune tighter for losing captures (e.g. RxR-defended-by-a-pawn — `see ≈ 0`,
`victim ≈ 477` — that (a) misses but (b) catches in a lost position). The roadmap row
names both ("capture futility / delta pruning").

**Honest scope of v1: MVV delta-pruning + a *thin* losing-capture SEE addon.** The
`victim < attacker` gate on (b) means the SEE refinement fires only on `attacker >
victim` captures (QxP / RxN-defended / …) where (a) already failed — a real but
narrow band (the `see`-vs-`victim` gap must straddle alpha). The literature (research
§1b) applies the SEE gate to **all** captures; we restrict it in v1 for two reasons,
of unequal strength:
- **Perf (strong):** bounds `see()` to the same `attacker > victim` class as the
  validated `qsearch_see_pruneable` fast-out (ADR-0040 §3) — winning/equal captures
  never pay for the resolver.
- **Conservatism (moderate, not absolute safety):** winning/equal captures are the
  likeliest saving tactics, so excluding them de-risks v1 — **but** note this does
  forgo some real prunes on *equal* trades in lost positions (`victim == attacker`,
  `see ≈ 0`: (a) clears it as `mvv_bound > alpha`, and (b) is gated out), so the claim
  is "fewer false prunes," not "no missed prunes."

Consequence for the SPRT read: if v1 comes back **marginal-positive**, broadening (b)
to all captures (§11.2) is the **first** lever to try — *before* the margin sweep —
because the restriction is exactly what makes the SEE half thin.

## 3. Node gate — REUSE FFP's `ffp_static_eval` (zero new node-level cost)

The capture block fires under the **same frontier-node gate** as FFP, which is
already computed once before the move loop as `ffp_static_eval: Option<i32>`
(search.rs ~2047): `ply > 0 && !is_pv && depth ∈ [1, FFP_MAX_DEPTH] &&
alpha.abs() < MATE_IN_MAX_PLY && !in_check(pos)`, payload = STM-relative static eval.

The capture block matches on `Some(static_eval)` exactly like the quiet block.
**No new node-level computation, no new `Option`, no second `in_check` read.** This
couples CFP's frontier-node definition to FFP's (a future `FFP_MAX_DEPTH` change
moves both) — intentional: "the same frontier nodes, for captures." A separate
`CFP_MAX_DEPTH` is a deferred tunable (§10) if captures ever want a different depth
band than quiets.

Every gate clause transfers verbatim:
- `!in_check` — in check the loop holds evasions; pruning any is unsound (ADR-0026 §3 / ADR-0040 §1). **Load-bearing.**
- `!is_pv` — PV nodes must search all moves to build the PV.
- `ply > 0` — structural-root guard (defense-in-depth).
- `alpha.abs() < MATE_IN_MAX_PLY` — cp margins are meaningless near mate.
- `depth ∈ [1, FFP_MAX_DEPTH]` — frontier band; margin unsound beyond it.

## 4. Fail-soft floor + provenance downgrade (load-bearing — mirror ADR-0026 §7)

On a fire, before `continue`, floor `best` with the pruned bound, routed through
the M5.C provenance helper with `move_is_full_depth = false`:

```rust
best_is_full_depth = best_is_full_depth_after_score(best, best_is_full_depth, bound, false);
best = best.max(bound);
continue;
```

This is **byte-for-byte the FFP §7 accounting** (the bound is `≤ alpha`, so it never
improves alpha, never causes a cutoff — it only floors the fail-soft return and
downgrades the TT-store provenance flag so an all-captures-pruned node does not
advertise a phantom full-depth bound). Same reasoning as ADR-0026 §7 walk-through;
no new correctness argument, the helper generalizes verbatim.

**`quiets_searched` / `quiet_index` / history:** untouched. CFP-pruned captures are
not quiets — they never entered `quiets_searched` (the push is gated on `is_quiet(mv)
&& move_is_full_depth`, search.rs ~2286), never advanced `quiet_index`, and captures
never receive a history malus regardless. The `continue` is placed in the capture
arm, before the quiet/LMR machinery, so none of it is reached. (Captures already
bypass the LMR block today — `lmr_reduction` is `None` for non-quiets.)

**No mate/stalemate misdetection** (the literature's "search the first legal move
before pruning" exemption is unnecessary here). Terminal mate/stalemate is decided by
`stager.is_empty()` (a legal-move-count check, search.rs ~1941) **before** the move
loop runs, so a node whose every capture is CFP-pruned cannot be misreported as
mate — it returns the floored fail-soft `best` (`≤ alpha`) as an Upper bound, exactly
as a captureless node already does. Verified structurally in plan-review.

## 5. Placement in the move loop

Immediately **after** the FFP quiet-skip block (search.rs ~2102–2126) and **before**
the LMR/recursion decision. The two blocks are domain-disjoint (`is_quiet(mv)` vs
`mv.is_capture() && !mv.is_promotion()`), so order between them is immaterial; placing
CFP adjacent to FFP keeps the two frontier-prunes together and both share
`ffp_static_eval`. The excluded-move skip (SE, ~2072) and `move_extension` (~2080)
remain ahead of both — CFP must not fire on the SE excluded move (it `continue`s
earlier) and CFP captures are not the TT move's SE concern.

## 6. Helper — `cfp_pruned_bound` (mirror `ffp_pruned_bound`)

```rust
/// M7.C — SEE capture-futility pruned bound. STM-relative `static_eval`/`alpha`
/// at the parent node. Returns `Some(bound)` (a fail-soft upper bound `≤ alpha`)
/// iff the non-promo capture `mv` should be pruned; `None` otherwise.
/// Domain-guarded to `[1, FFP_MAX_DEPTH]` (defense-in-depth, M5.C precedent).
/// Caller guarantees `mv.is_capture() && !mv.is_promotion()` (flag ∈ {Capture, EnPassant}).
pub(crate) fn cfp_pruned_bound(
    pos: &Position, mv: Move, static_eval: i32, depth: u32, alpha: i32,
) -> Option<i32> {
    use crate::mov::MoveFlag;
    use crate::piece::PieceKind;
    use crate::see::{SEE_VALUE, see};
    if depth == 0 || depth > FFP_MAX_DEPTH { return None; }
    let margin = capture_futility_margin(depth);
    // Victim read — the SAME match as `qsearch_see_pruneable` (search.rs ~3338):
    // EP captures the pawn off the to-square (to is empty for EP — reading
    // piece_at(to) would be a bug); every other capture takes the piece on `to`.
    let victim = match mv.flag() {
        MoveFlag::EnPassant => SEE_VALUE[PieceKind::Pawn as usize],
        _ => SEE_VALUE[pos
            .piece_at(mv.to_square())
            .expect("cfp_pruned_bound: capture to-square occupied")
            .kind as usize],
    };
    let mvv_bound = static_eval.saturating_add(victim).saturating_add(margin);
    if mvv_bound <= alpha {
        return Some(mvv_bound); // (a) sound delta-prune; returns BEFORE any see() call
    }
    let attacker = SEE_VALUE[pos
        .piece_at(mv.from_square())
        .expect("cfp_pruned_bound: capture from-square occupied")
        .kind as usize];
    if victim >= attacker {
        return None; // winning/equal capture: never SEE-pruned in v1 (§2 / §11.2)
    }
    let see_bound = static_eval.saturating_add(see(pos, mv)).saturating_add(margin);
    if see_bound <= alpha { Some(see_bound) } else { None } // (b) SEE refinement
}
```

The victim/attacker reads and `expect` messages mirror `qsearch_see_pruneable`
(ADR-0040 §3) exactly — same EP-aware `match`, same convention. **Branch (a)'s
`return Some(mvv_bound)` happens before `attacker`/`see()` are touched** — the
delta-prune is the cheap sound ceiling, `see()` is reached only for losing
(`victim < attacker`) captures that branch (a) did not already prune (pinned by a
test, §8.12). The `saturating_add`s mirror `ffp_pruned_bound`'s overflow defense.

**`see ≤ victim` is provably unconditional for non-promo captures** (verified in
plan-review against `see.rs`): a non-promo `Capture`/`EnPassant` sets `gain0 = victim`
with no promo bonus, and the swap-list backup only ever *subtracts* a non-negative
recapture (`gain[i-1] -= max(0, gain[i])`) — even an opponent recapture-promotion
only enlarges the subtracted term. Hence `see_bound ≤ mvv_bound`, and both `≤ alpha`
on a fire ⇒ both are valid fail-soft upper bounds.

**Margin constants** (mirror the FFP table; only depth 1 active at `FFP_MAX_DEPTH = 1`):

```rust
pub(crate) const CFP_MARGIN_D1: i32 = 150;   // active (FFP_MAX_DEPTH = 1)
pub(crate) const CFP_MARGIN_D2: i32 = 300;   // inactive until FFP_MAX_DEPTH ≥ 2
pub(crate) const CFP_MARGIN_D3: i32 = 500;   // inactive until FFP_MAX_DEPTH ≥ 3
fn capture_futility_margin(depth: u32) -> i32 { /* table, 0 outside [1,3] */ }
```

The margin is the **positional** slack only (material is already in `victim`/`see`),
so it can be tighter than a pure-MVV capture-futility margin. `CFP_MARGIN_D1 = 150`
is the research-anchored v1 value (MadChess d1 = 150; Heinz ≈ 125; TalkChess
"200–300 safe" — captures carry more positional volatility than quiets, so this sits
above FFP's quiet `FFP_MARGIN_D1 = 100`). A **larger** margin is the *safer*
direction (it makes the prune condition harder to satisfy → fewer false prunes), so
150 is the conservative-but-not-inert v1 pick; the D2/D3 entries (300/500) mirror the
MadChess `{150,250,400,600}` slope and are defined for a forward-compat
`FFP_MAX_DEPTH` raise (the FFP-table precedent, ADR-0026 §4). Single active value for
clean SPRT attribution (the M5.D `{100,150}` precedent). Margin sweep is the top
deferred lever (§11).

## 8. Tests (TDD — written + reviewed before implementation)

**Margin-table tests** (mirror `frontier_futility_margin_at_depth_*`; **required for
clippy** — `CFP_MARGIN_D2/D3` and the depth-2/3 arms of `capture_futility_margin` are
forward-compat dead constants at `FFP_MAX_DEPTH = 1`, and survive `clippy -D warnings`
only if pinned by a test, exactly as the FFP D2/D3 constants do):
0a. `capture_futility_margin(1) == 150`, `(2) == 300`, `(3) == 500`, `(0) == 0`, `(4) == 0`, and an anti-vacuous "not always zero" pin.

**Helper unit tests** (`cfp_pruned_bound`, mirror the `ffp_pruned_bound` suite):
1. depth 0 → `None`; depth `FFP_MAX_DEPTH + 1` → `None` (domain guard).
2. delta-prune branch (a): synthetic `static_eval`, big `alpha`-gap → `Some(mvv_bound)`; boundary `<=` inclusive (mvv_bound == alpha fires; == alpha+1 does not).
3. SEE branch (b): a `victim < attacker` losing capture position where `mvv_bound > alpha` but `see_bound ≤ alpha` → `Some(see_bound)`; sister where `see_bound > alpha` → `None`.
4. winning/equal capture (`victim >= attacker`) with `mvv_bound > alpha` → `None` (never SEE-pruned).
5. EP victim read = Pawn (EP capture position).
6. overflow: `i32::MAX` static eval saturates, no panic.
6a. **branch-ordering / no-needless-see (perf contract):** a position where `mvv_bound ≤ alpha` AND `victim < attacker` AND `see_bound ≠ mvv_bound` → the helper returns `Some(mvv_bound)` (branch (a)), **not** `Some(see_bound)`. Pins that (a) is checked first and returns before `see()` — kills a reorder/early-return-drop mutant that would change the `see()`-call population (NPS) even when the prune decision is unchanged (the mutation §9 commits to catching).

**Integration tests** (real `negamax_for_test`, `cfp_firings_for_test`, mirror the
FFP move-loop suite — each with a PASS sister and a gate-blocked sister):
7. fires on a frontier capture at a non-PV, non-check, depth-1, losing position; PV sister → 0.
8. ply-0 gate-skip; in-check gate-skip (legal fixtures, the ADR-0026 §legal-position invariant); depth > `FFP_MAX_DEPTH` gate-skip; mate-alpha gate-skip.
9. a winning capture (RxQ) at a frontier node is **not** pruned (searched) — guards branch (b)'s `victim >= attacker` exemption.
10. counter increments exactly once per skip; pruned move recorded; CFP-pruned capture does not corrupt `quiets_searched` (separate quiet still searched).
11. **all-captures-pruned fail-soft soundness** (NOT a byte-identity check — CFP is *designed* to change node counts; the d4/d7 digests will move, §9): a fixture where every legal capture at a frontier node is CFP-pruned returns the stand-pat-class Upper bound (a value `≤ alpha`), **not** `-INF`/a phantom fail-high — i.e. the §4 floor fires. (Bench re-pin is a §9 mechanical step, recorded in `bench/m7.md`, not asserted as identity in a unit test.)

## 10. SPRT plan

Mixed-TC + virtual-clock SPRT vs `M7.B.2` (the `…D01B` production HEAD), standard
verdict ladder (ADR-0037 §9), 2-seed confirm per the M5.F-item-3 lesson (a single
seed's CI-lower>0 is NOT sufficient for a search micro-lever). **Read the per-TC
breakdown** — the M7.B caveat (60+0.6 regression from over-aggressive qsearch
pruning) is the cautionary tale. CFP is structurally less prone to it (alpha-relative:
it only fires when even optimistic material can't reach alpha, i.e. already-lost
positions, where a "losing" capture is very unlikely to be a saving tactic), but the
slow-TC bucket is a **gate, not a watch-item**: if 60+0.6 regresses, the remediation
is the **same lever as M7.B.2** — a root-depth ramp on the margin — shipped as
**M7.C.1 *before* M7.C** (the M7.B→M7.B.2 sequence), not shipped blind.

Marginal-but-positive lands per the M5.F precedent; clear regression reverts.

## 11. Deferred tunables / open levers (post-landing backlog)

1. `CFP_MARGIN_D1` sweep (and activate D2/D3 by raising `FFP_MAX_DEPTH`, jointly with the FFP table).
2. Drop the `victim >= attacker` v1 safety gate, broadening branch (b) to apply the SEE refinement to **all** captures passing the MVV test (the literature applies the SEE gate to all captures; research §1b) — more aggressive, more `see()` calls, riskier. **Top lever if v1 SPRTs marginal-positive.**
3. Gives-check capture exemption (needs `gives_check` infra; the long-standing FFP §1 / ADR-0026 deferral; research §3/§4 flags discovered-check risk).
4. Root-depth margin ramp (M7.B.2 mechanism) — **only if** the per-TC SPRT shows a slow-TC regression. Research §4 argues this is unlikely (alpha self-regulates), so v1 ships flat.
5. **Mechanism 1c — absolute SEE-by-depth (`see(mv) < -k·depth²`, alpha-independent).** A *separate* future mechanism, not a tune of v1. Research-recommended only after the alpha-relative form lands; carries the M7.B alpha-independent slow-TC risk, so it would need depth/root-depth conditioning from the start.
6. TT-move / killer-capture exemption if SPRT traces a regression to over-pruning trusted captures (ADR-0040 §5 remediation precedent).
7. MVV-ordered-capture early loop-exit (research §4) — a perf-only micro-opt, only if the bench shows a `see()`/iteration cost worth removing.
