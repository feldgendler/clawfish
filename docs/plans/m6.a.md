# M6.A — Tapered eval foundation

**Plan unit.** `M6.A — Tapered eval foundation`. Replaces M3.A's single-PSQT eval representation with a tapered MG/EG pair blended by a material-derived phase tag. Bundles three piggybacks that depend on the new representation: bishop pair, KBvKB-same-color insufficient-material, and a simple mop-up term for KQK/KRK.

**Predecessor.** `M5.H1` (tagged 2026-05-10; the M5 milestone close).

**Research.** [`docs/research/m6-tapered-eval.md`](../research/m6-tapered-eval.md) — closes all open ADR bullets. Headline commitments:
- Phase tag `[P=0, N=1, B=1, R=2, Q=4, K=0]` summing to 24 at full material; **accumulate raw, clamp to 24 only at blend time**.
- Blend formula `(mg · min(raw, 24) + eg · (24 − min(raw, 24))) / 24` with Rust integer truncation.
- Storage: explicit triple `(static_mg_white: i32, static_eg_white: i32, raw_phase: u8)` on `Position`. Packed-i32 ruled out (sign-extension hazard); packed-i64 offers no advantage.
- Bishop pair: predicate `bishops cover both color complexes`; MG +30 / EG +50.
- KBvKB-same-color: total_count==4, each side exactly one bishop, both bishops on the **same** color complex → 0. **Logically opposite** of bishop-pair predicate.
- Mop-up: gate on `raw_phase < 4` ∧ `advantage_cp > 100`; formula `4·CMD(losing_king) + 2·(14 − chebyshev(kings))`; max ~50 cp.

**Expected size.** ~700 LOC including tests, ADR, retrospective. Per roadmap row.

**Expected Elo.** Literature prior +50 to +80 (per roadmap). SPRT is the gate; per-piggyback STS sub-gates are the secondary discipline (§13).

## §1. Scope and non-goals

**In scope.**
- Tapered eval representation on `Position`: replace `static_eval_white: i32` with `(static_mg_white: i32, static_eg_white: i32, raw_phase: u8)`.

- `evaluate(&Position) -> i32` rewritten to: (a) check extended insufficient-material set (M3 cases + KBvKB-same-color), (b) read `(mg, eg, raw_phase)`, (c) apply mop-up addend (white-perspective signed), (d) apply bishop-pair MG/EG addends (white-perspective signed), (e) blend via the formula, (f) flip for side-to-move.

- Bench refresh; **WAC + STS diagnostic with per-theme RUN-ALONE re-baseline against `M5.H1`** (per roadmap §"Per-theme STS as a secondary gate"); mixed-TC SPRT vs `M5.H1` (`elo0=0, elo1=5`).

**Out of scope (deferred to later M6 phases or follow-up campaigns).**

- Mobility (M6.D).

### §4.1 Bitboard constants

In `src/bitboard.rs`:

```rust
impl Bitboard {
    // ...existing constants...

    /// Light squares in LERF (a1=0). a1 is dark by chess convention, so the
    /// light squares are those where `(file + rank) % 2 == 1` — bits {1, 3,
    /// 5, 7, 8, 10, 12, 14, ...}. The rank-1 byte is `0b10101010 = 0xAA`
    /// (b1, d1, f1, h1 light); rank-2 byte is `0b01010101 = 0x55` (a2, c2,
    /// e2, g2 light); the pattern alternates byte-by-byte up the board.
    pub const LIGHT_SQUARES: Bitboard = Bitboard(0x55AA_55AA_55AA_55AA);
    /// Dark squares: complement of `LIGHT_SQUARES`. a1, c1, e1, g1, b2, ...
    /// are dark.
    pub const DARK_SQUARES: Bitboard = Bitboard(0xAA55_AA55_AA55_AA55);
}
```

**Mask derivation cross-check.** Rank-1 (LERF bits 0..7): a1=dark, b1=light, c1=dark, d1=light, e1=dark, f1=light, g1=dark, h1=light → light-bit pattern `0b10101010` = `0xAA` in rank-1 byte. Rank-2 (LERF bits 8..15): a2=light, b2=dark, ... → light-bit pattern `0b01010101` = `0x55` in rank-2 byte. Concatenated low→high: `0x55_AA_55_AA_55_AA_55_AA` (rank-2 byte first because bits 8..15 land in the second byte of the u64). **The plan commits to `LIGHT_SQUARES = 0x55AA_55AA_55AA_55AA`** and `DARK_SQUARES = !LIGHT_SQUARES = 0xAA55_AA55_AA55_AA55`. Unit tests at §10.2 pin: (a) `LIGHT_SQUARES | DARK_SQUARES == FULL`, (b) `LIGHT_SQUARES & DARK_SQUARES == EMPTY`, (c) a1 is in DARK, (d) a2 is in LIGHT, (e) h1 is in LIGHT.

Accessors (replace existing `static_eval_white()` getter):

```rust

pub(crate) fn static_eg_white(&self) -> i32 { self.static_eg_white }
pub(crate) fn raw_phase(&self) -> u8 { self.raw_phase }

/// Blended white-perspective static eval (MG/EG by phase). Used by
/// the search-side static-eval reads in RFP / NMP / FFP that need
/// "raw heuristic eval" without insufficient-material zeroing. The
/// blend matches the formula in `evaluate(&Position)` minus the
/// insufficient-material check, mop-up addend, and bishop-pair addend.
pub(crate) fn static_eval_white(&self) -> i32 {
    let phase = self.raw_phase.min(24) as i32;
    (self.static_mg_white * phase + self.static_eg_white * (24 - phase)) / 24
```

**Rationale for keeping `static_eval_white()` with the same signature.** The search.rs RFP/NMP/FFP call sites (`:1570, :1572, :1602, :1604, :1814, :1816, :10373, :10375`) and `stm_static_eval` test helper consume a side-relative i32 derived from `pos.static_eval_white()` with an STM sign-flip. Migrating the field name forces churn across ~12 call sites that aren't M6.A's concern. Instead, the accessor preserves its signature; the change is purely the underlying representation. The bishop-pair / mop-up *additions* live in `evaluate()` only — they are NOT in the blended static-eval read because: (a) RFP/NMP/FFP care about the gradient at adjacent positions which the PSTs already carry, (b) including bishop-pair would require a per-call bitboard scan that costs more than the gain at the depths where RFP fires, (c) mop-up is correctness-driven (gradient toward mate) and only matters at deep search, not at the cheap pruning gates. This is consistent with the M3.A precedent of factoring insufficient-material into `evaluate` but not `static_eval_white()`.

- `Position::starting_position` (line 222): same.
- `refresh_static_eval` (line 509): write all three via `eval_state_from_scratch`.

## §7. Incremental delta: `update_static_eval_after_make`

Extend the helper at `src/mov.rs:1064` to compute MG, EG, and phase deltas across all 14 flag arms. The structure mirrors the existing M3.A six-arm switch; each existing M3.A line splits into one MG line + one EG line + (where applicable) a PHASE_DELTA contribution.

Three accumulators: `mg: i32`, `eg: i32`, `phase: i32` (i32 for signed subtraction in capture arms; cast to u8 at apply time).

Per-arm phase deltas:

| Flag arm | `phase` delta |
|---|---|
| `Quiet`, `DoublePush` | `0` (no piece added or removed) |
| `KingCastle`, `QueenCastle` | `0` (king + rook stay on the board) |
| `Capture` (non-EP) | `-PHASE_DELTA[victim.kind]` |
| `EnPassant` | `0` (EP victim is always a pawn; `PHASE_DELTA[Pawn] == 0`). **Explicit `0` literal, not a `-= PHASE_DELTA[Pawn]` no-op** (the no-op is mutation-test-invisible). |
| `KnightPromo`..`QueenPromo` | `+PHASE_DELTA[promo_kind]` (pawn out has delta 0; promoted piece enters) |
| `KnightPromoCapture`..`QueenPromoCapture` | `+PHASE_DELTA[promo_kind] − PHASE_DELTA[victim.kind]` |

Per-arm MG and EG deltas are *structurally identical* to the existing M3.A `update_static_eval_after_make` code, applied twice — once with `PSQT_MG[us][kind][sq]` and once with `PSQT_EG[us][kind][sq]`. The "+/− piece on square" structure carries through unchanged for both tables (see existing `src/mov.rs:1083–1126`).

Apply step:

```rust
let new_mg = pos.static_mg_white() + mg;
let new_eg = pos.static_eg_white() + eg;
let new_raw_phase_signed = pos.raw_phase() as i32 + phase;
debug_assert!(
    (0..=255).contains(&new_raw_phase_signed),
    "raw_phase out of u8 range after delta: prior={}, delta={}",
    pos.raw_phase(), phase,
);
// Release builds rely on the invariant; the cast is sound because raw_phase
// in any reachable position fits in u8 (max ~56 with 8 promoted queens).
pos.refresh_static_eval_from_triple(new_mg, new_eg, new_raw_phase_signed as u8);
```

**No-op-in-EP-arm clarification.** Don't emit `phase -= PHASE_DELTA[Pawn]` (the form is structurally a no-op — `x ± 0 == x` regardless of operator — so any cargo-mutants mutation on that operator is equivalence-undetectable; the line provides zero coverage and only adds noise). Just keep the EP arm out of the `phase` accumulation entirely (phase contribution `0` baseline). The comment in the EP arm states the invariant.

**Cost analysis.** Two PSQT table reads per piece-touch (was one). Per-move cost grows ~2×. Bench expectation per roadmap §"Bench-node-count regression policy": NPS drops modestly; SPRT Elo gain absorbs.

## §8. `evaluate(&Position)` rewrite

Algorithmic structure (the full body is short — ~25 lines — but stays inline; the helper signatures below pin the API surface for §10 tests):

1. `if is_insufficient_material(pos) { return 0; }` — extended set.
2. Read `mg = pos.static_mg_white()`, `eg = pos.static_eg_white()`, `phase = pos.raw_phase().min(24) as i32`.
3. Compute `bp_mg = bishop_pair_term_white(pos, BISHOP_PAIR_MG)` and `bp_eg = bishop_pair_term_white(pos, BISHOP_PAIR_EG)` (signed addends from white-perspective).
4. Compute `mop_up_white = mop_up_term_white(pos, mg, eg)`.
5. Blend: `blended = ((mg + bp_mg) * phase + (eg + bp_eg) * (24 - phase)) / 24`.
6. Combine: `result_white = blended + mop_up_white`.
7. Debug-assert mate-band: `result_white.abs() < MATE_IN_MAX_PLY - 1`.
8. Side-to-move flip on return.

`MATE_IN_MAX_PLY` is `pub(crate)` from `search.rs`; bring into scope via `use crate::search::MATE_IN_MAX_PLY;`.

### §8.1 Function signatures (frozen API surface)

```rust
fn is_insufficient_material(pos: &Position) -> bool;
fn is_kbkb_same_color(pos: &Position) -> bool;        // caller guarantees total == 4
fn bishop_pair_term_white(pos: &Position, value: i32) -> i32; // +value/−value/0 per side
fn center_manhattan_distance(sq: Square) -> i32;       // ∈ [0, 6]
fn chebyshev_distance(a: Square, b: Square) -> i32;    // ∈ [0, 7]
fn mop_up_term_white(pos: &Position, mg_white: i32, eg_white: i32) -> i32;
```

Semantics:

- **`is_insufficient_material`**: matches `pos.occupied_all().count()`. `2 → true` (KvK). `3 → (#knights == 1 || #bishops == 1)` (KvN, KvB). `4 → is_kbkb_same_color(pos)`. Else `false`.
- **`is_kbkb_same_color`**: total == 4 caller invariant. `(wb.count() == 1) && (bb.count() == 1) && (wb on light) == (bb on light)`. "on light" via `(bishops & LIGHT_SQUARES).any()`. **Predicate is logically *opposite* of bishop-pair** (research §4.3 / §9.2 — both color complexes vs. same color complex).
- **`bishop_pair_term_white`**: `wb` has the pair iff `(wb & LIGHT).any() && (wb & DARK).any()`; same for `bb`. Returns `value` if only White has the pair, `−value` if only Black has it, `0` otherwise (including the symmetric starting-position case where both sides have it). Called twice: once with `BISHOP_PAIR_MG = 30`, once with `BISHOP_PAIR_EG = 50`.
- **`center_manhattan_distance`**: `min(|f − 3|, |f − 4|) + min(|r − 3|, |r − 4|)` — distance to the nearest center square in the 2×2 set {d4, e4, d5, e5}. Anchors at §10.1: `cmd(a1) = 6`, `cmd(d4) = 0`, `cmd(a8) = 6`, `cmd(h1) = 6`, `cmd(h8) = 6`.
- **`chebyshev_distance`**: `max(|fa − fb|, |ra − rb|)`. Anchors: `cheb(a1, h8) = 7`, `cheb(a1, b2) = 1`, `cheb(a1, a8) = 7`.
- **`mop_up_term_white`**: Two gates first — `raw_phase >= MOP_UP_PHASE_MAX` returns 0; computed blended-without-bishop-pair advantage `≤ MOP_UP_MIN_ADVANTAGE_CP` returns 0. Otherwise: identify winning king (white if advantage > 0 else black) and losing king; compute `bonus = 4·cmd(losing_king) + 2·(14 − cheb(winning_king, losing_king))`; return `+bonus` if white winning, `−bonus` if black winning.

**Mop-up range.** `cmd ∈ [0, 6]`, `cheb ∈ [1, 7]` (legal-position invariant: kings never adjacent in a legal position; but the function only cares that it's bounded, so the safer `cheb ∈ [0, 7]` range is fine for type purposes). Bonus range `[14, 50]` — small relative to KQK material gradient.

**Bishop-pair and mop-up live at the `evaluate()` boundary, not in the incremental delta.** Both are O(few bitboard ops); the cost is amortized across the whole eval call. Per-call recomputation eliminates a class of bugs where incremental tracking falls out of sync with the position state under deep search trees (analogous to how M3.A's PSQT delta is the chosen integration point but the insufficient-material check is at the `evaluate()` boundary).

## §9. `eval_state_from_scratch`

Replaces `eval_white_from_scratch`. Single pass returning `(mg, eg, raw_phase)`.

```rust
pub(crate) fn eval_state_from_scratch(pos: &Position) -> (i32, i32, u8) {
    let mut mg = 0i32;
    let mut eg = 0i32;
    let mut phase: u32 = 0;
    for kind in PieceKind::ALL {
        for color in [Color::White, Color::Black] {
            let mut bb = pos.pieces_colored(color, kind);
            while let Some(sq) = bb.pop_lsb() {
                mg += PSQT_MG[color as usize][kind.index()][sq.index() as usize];
                eg += PSQT_EG[color as usize][kind.index()][sq.index() as usize];
                phase += PHASE_DELTA[kind.index()] as u32;
            }
        }
    }
    debug_assert!(phase <= 255, "phase overflow (only possible with > 255-piece-equivalent material)");
    (mg, eg, phase as u8)
}
```

`Position::refresh_static_eval` becomes:

```rust
pub(crate) fn refresh_static_eval(&mut self) {
    let (mg, eg, raw_phase) = crate::eval::eval_state_from_scratch(self);
    self.static_mg_white = mg;
    self.static_eg_white = eg;
    self.raw_phase = raw_phase;
}
```

## §16. Risk register

1. **Phase-clamp omission.** Research §9.1 — the single most dangerous gotcha. Mitigation: the clamp lives in `Position::static_eval_white()` (the blended accessor) AND in `evaluate()`; both paths apply `min(24)`. Test `eval_promoted_queen_position_phase_clamped` is the canary.
2. **Bishop-pair vs. KBvKB predicate confusion.** Research §9.2. Mitigation: explicitly named functions `bishop_pair_term_white` vs `is_kbkb_same_color`. The two test names are explicit.
3. **Light/dark mask inversion.** Research §9.3. Mitigation: `light_dark_squares_partition_full_board` + `a1_is_dark_square` tests pin the LERF alignment.
4. **EG king PST positive central values + mop-up interaction** (research §9.4, §9.6). The EG king PST has large positive central values (e.g. e4/d5 ≈ +27 for white-perspective `static_eg_white`). In KQK with **white** winning, both terms reinforce: white king PST favors centralization (correct for winning side); mop-up adds a corner-attractor for the losing black king. But in KQK with **black** winning, the white-king PST drives white centrally (white-perspective +27 on d4), while mop-up correctly drives the *losing* white king to the corner (mop-up contribution to white-perspective is negative for the cornered-king case). The two terms *partially cancel* but in opposite directions; the mop-up signal needs to dominate at conversion-relevant positions. Mitigation: `mop_up_kqk_losing_king_centralized_worse_than_cornered` test at §10.1 pins the expected ordering empirically. If the mop-up is too small to dominate the king-PST gradient, the test will fail and the scaling needs revision before SPRT.
5. **Phase-field gating insufficient-material wrongly** (research §9.5). Mitigation: `is_insufficient_material` runs *before* reading `raw_phase` and uses `pos.occupied_all().count()` not `phase`. Test `eval_kbvkb_same_color_returns_zero_*` pins.
6. **Mop-up direction bug** (research §9.6). Mitigation: explicit `if advantage > 0 { ... } else { ... }` branch; `mop_up_direction_white_vs_black` test exercises both.
7. **Phase delta on promotion-with-capture** (research §9.7). Mitigation: C6 test family pins.
8. **C4 proptest timeout under triple assert.** Mitigation: §10.5 timing audit; halve `cases` if needed.
9. **Search.rs RFP/NMP/FFP behavior change from blended `static_eval_white()`.** The accessor now returns a blended (MG, EG) value instead of pure MG. The pruning gates' firing patterns shift in EG positions where the blend leans EG (the EG king PST has large positive central values; RFP/FFP can fire on positions where they previously couldn't, and vice versa). SPRT signal commingles tapered eval + bishop pair + KBvKB + mop-up + *changed RFP/NMP/FFP firing semantics*. Mitigations:
   1. The SPRT itself is the headline gate; +50 to +80 Elo literature prior far exceeds any plausible firing-pattern noise.
   2. **Instrumentation: record RFP/NMP/FFP firing-count deltas on the bench corpus** in the M6.A retrospective. The `_for_test` firing counters (`rfp_firings`, `nmp_firings`, `ffp_firings`) already exist in search.rs (test-only); promote a measurement script that sums them over the bench corpus and report the per-feature deltas vs. M5.H1. This makes the confound *measurable* even if not isolatable, and gives M6.B a baseline for any further accessor-behavior changes.
   3. Alternative split (rejected at plan time, recorded for future reference): introduce a separate `pos.static_mg_white()` accessor and keep RFP/NMP/FFP MG-only at M6.A. Rejected because the blended value is the correct semantic for the pruning gates (an EG position should use the EG-weighted static eval to decide whether to prune); the MG-only behavior was a M3.A simplification born of the single-phase representation, not a correctness commitment.
10. **Stale test fixtures with hard-coded eval values.** Many search.rs tests reference fixtures where `evaluate()` returns specific values. These will likely change under tapering. Mitigation: when fixing test fixtures, prefer relative assertions (`>`, `<`, sign-check) over absolute values; document any fixture value updates in the implementation pass.
