# M8.A.1 — Depth-Conditioned PVS (smooth root-depth scout-start ramp)

**Milestone:** M8.A.1 (Search refinements I, pre-NNUE). Tuning/conditioning layer on top of
M8.A PVS (ADR-0043), the M7.B → M7.B.2 playbook applied to PVS's depth-amplifying profile.
**Branch:** `m8a1-depth-conditioned-pvs` (off `m8a-pvs`; M8.A.1 *extends* the PVS code).
**Baseline tag for SPRT:** `M7.B.2` (current production search HEAD; eval `M6.J`).
**Research:** [`docs/research/m8.a.1-depth-conditioned-pvs.md`](../research/m8.a.1-depth-conditioned-pvs.md).
**ADR:** ADR-0044 (depth-conditioned PVS ramp); references ADR-0043 (PVS), ADR-0041 (the
M7.B.2 root-depth-ramp precedent), and the M5.K depth-gate cautionary record.

## 1. Goal

Recover the M8.A fast-TC regression (10+0.1 ≈ −45 … 40+0.4 ≈ −20) **without** giving up the
slow-TC gain (60+0.6 ≈ +73, 2-seed-robust) by enabling PVS scouting only at deep ID root
iterations. The mechanism: a **smooth, monotonic root-depth ramp on the scout-start move
rank** — off (byte-identical to `M7.B.2`) at shallow root depths, full PVS (≡ M8.A) at deep
root depths, gradual in between. See research §4.

Success = aggregate Elo > 0 vs `M7.B.2`, 2-seed, with the fast-TC buckets at/near neutral
and a positive 60+0.6.

## 3. Design

### 3.1 The ramp function

```rust
/// M8.A.1 depth-conditioned PVS ramp constants (ADR-0044). Tunable; see research §5.
const PVS_RAMP_D0: u32 = 12;    // root depth at/below which PVS is fully off (≡ M7.B.2)
const PVS_RAMP_BASE: u32 = 16;  // scout-start rank one ply above D0 (scout only the deep tail)
const PVS_RAMP_SLOPE: u32 = 4;  // move-ordering ranks unlocked for scouting per ply above D0

/// Lowest move-ordering rank (`cur_i`) eligible for the PVS null-window scout at this ID
/// root iteration depth. `u32::MAX` ⇒ no move scouted (≡ M7.B.2). Monotonically
/// non-increasing in `root_depth`; reaches 1 (full PVS ≡ M8.A) at d ≥ D1 = 16.
fn pvs_scout_start(root_depth: u32) -> u32 {
    if root_depth <= PVS_RAMP_D0 {
        return u32::MAX;
    }
    PVS_RAMP_BASE
        .saturating_sub(PVS_RAMP_SLOPE * (root_depth - PVS_RAMP_D0))
        .max(1)
}
```

Values: d≤12 → MAX; d13 → 12; d14 → 8; d15 → 4; d≥16 → 1. Pure function of `root_depth`;
no allocation, no `self`. (`root_depth - PVS_RAMP_D0` cannot underflow — guarded by the
`<= D0` early return; `PVS_RAMP_SLOPE * (…)` cannot overflow `u32` for any realistic depth.)

### 3.2 Move-loop restructure

Today (ADR-0043) the per-move block is:

```
if is_first            { <full-window first move> }
else if test_disable_scout { <reference full-window LMR path> }   // test-only
else                   { <PVS three-step ladder> }
```

M8.A.1 makes the reference path a **production** path for non-scouted moves. Compute once
per move, after `is_first` is known and `cur_i` is in scope:

```rust
// M8.A.1: scout only late-ranked non-first moves, gated by the root-depth ramp.
// `test_disable_scout` forces the reference path (exactness anchor); in production the
// ramp decides. cur_i is the move-ordering rank (FFP-skipped quiets `continue` earlier).
// cur_i is usize, pvs_scout_start returns u32 — cast to compare (scout_start is small).
let should_scout =
    !test_disable_scout && cur_i as u32 >= pvs_scout_start(self.root_depth);
```

Then:

```
if is_first       { <full-window first move> }       // unchanged
else if should_scout { <PVS three-step ladder> }     // unchanged body (the M8.A ladder)
else              { <reference full-window LMR path> } // unchanged body (was test_disable_scout)
```

The two branch *bodies* are unchanged from M8.A — only the **guard** moves from
`test_disable_scout` (test-only) to `!should_scout` (production-active). Consequences:

- `test_disable_scout = true` ⇒ `should_scout = false` ⇒ reference path always ⇒ the M8.A
  exactness anchors keep their reference semantics. ✓
- Production, `root_depth ≤ D0` ⇒ `pvs_scout_start = MAX` ⇒ `cur_i >= MAX` never true ⇒
  reference path always ⇒ **byte-identical to M7.B.2**. ✓
- Production, deep ⇒ scout per rank; `scout_start = 1` ⇒ every non-first move scouted ⇒ ≡ M8.A. ✓

### 3.3 Counter semantics under the reference path

The reference path carries **no** `pvs_*` / `lmr_*` counter instrumentation (ADR-0043: it was
test-only and counters there would be dead). Now that it runs in production for non-scouted
moves, the `#[cfg(test)]` counters (`pvs_scout_searches`, `pvs_lmr_verify_searches`,
`pvs_research_full_window`, `lmr_reduced_searches`, `lmr_full_researches`) **will not increment
for non-scouted moves**. This is correct (those moves are not on the PVS ladder) but it means:

- **The M8.A counter/exactness tests run at small `negamax_for_test` depths with
  `root_depth = 0`** (reset in `negamax_for_test`, ADR-0043) **⇒ scouting is OFF ⇒ the PVS
  counters would read 0 and those tests would break.** They must set `root_depth` above `D0`
  to exercise the ladder. This is the main test-update obligation (§5).
- The reference path needs LMR counters for any test that asserts LMR firing while
  scouting is *off*. The existing `is_pv=false` wide-window LMR-*firing* tests
  drive `negamax_for_test` with `root_depth = 0`; under M8.A.1 those moves take
  the reference path, which has no `lmr_*` instrumentation → assertions break. **Fix:** mirror
  onto the reference path the **complete** `#[cfg(test)]` LMR instrumentation the M8.A ladder
  has (Step 1 `search.rs:~1648`, Step 2 `~1678`), **all gated on `self.lmr_trace_root_ply ==
  Some(ply)`** — not just the scalar counters:
  - **Step-1 mirror (reduced pilot, `r > 0`):** `self.lmr_reduced_searches += 1;` **and**
    `self.lmr_reduced_moves.push(mv);` (the vector — `search.rs:1651`).
  - **Step-2 mirror (full-depth re-search, `r > 0 && reduced > alpha`):**
    `self.lmr_full_researches += 1;` **and** `self.lmr_researched_moves.push(mv);` (the vector
    — `search.rs:1680`).

  The vectors are load-bearing: three named LMR-firing tests assert on them, *not* the scalars,
  and run with `root_depth` unset (so they hit the reference path under M8.A.1):
  `negamax_reduces_late_quiet_when_all_gates_pass` (`tests.rs:~9577`,
  `lmr_reduced_moves_for_test().contains(&mate_quiet)`),
  `negamax_researches_full_depth_when_reduced_score_beats_alpha` (`~9608`,
  `lmr_researched_moves_for_test().contains(..)`), and
  `negamax_reduced_only_quiet_does_not_enter_quiets_searched` (`~9624`, set-difference of both
  vectors). Omitting the vector pushes (or the trace gate) fails these. The reference path does
  **not** get `pvs_*` counters (those events exist only on the ladder). Verify by running the
  full suite — these three plus the ~16 scalar LMR-firing tests must stay green with
  `root_depth` unset.

> Design note: the alternative — make every LMR-firing test set `root_depth > D0` — touches
> ~19 tests and couples them to the ramp constant. Instrumenting the reference path (one path,
> the full mirror set above) is lower-churn and keeps LMR-firing tests ramp-agnostic. The
> PVS-*specific* counter tests still must set `root_depth > D0` (the scout only exists on the
> ladder); §5 lists those.

### 3.4 Test-harness `root_depth` control

`negamax_for_test` resets `self.root_depth = 0` at entry (ADR-0041 depth-0 qsearch delegation),
so a PVS test that wants the scout active cannot just set the field first — the reset clobbers
it. **The tree already solved this exact problem for M7.B.2:** `qsearch_at_root_depth_for_test`
(`search.rs:2525`) is a sibling test entry that runs the same per-entry resets and **then** sets
`self.root_depth = root_depth` before calling the search. Mirror it directly — zero
existing-caller churn, no parameter threading, sidesteps the reset-clobber entirely:

```rust
/// Test-only sibling of `negamax_for_test` that publishes `root_depth` *after* the per-entry
/// resets (so it survives) to drive the M8.A.1 depth-conditioned PVS ramp. Mirrors
/// `qsearch_at_root_depth_for_test`.
#[cfg(test)]
pub(super) fn negamax_at_root_depth_for_test(
    &mut self,
    pos: &mut Position,
    depth: u32,
    ply: u32,
    alpha: i32,
    beta: i32,
    is_pv: bool,
    allow_null: bool,
    excluded_move: Option<Move>,
    ctx: &SearchContext,
    root_depth: u32,
) -> i32 { /* same body as negamax_for_test, but `self.root_depth = root_depth;` */ }
```

To avoid the ~15-line reset block drifting between the two entries, **extract the reset block**
(`search.rs:1857–1887`, everything except the final `self.root_depth = 0` and
`self.lmr_trace_root_ply = Some(ply)`) into a private `#[cfg(test)] fn reset_negamax_test_state(&mut self)`.
Then:
- `negamax_for_test` = `reset_negamax_test_state(); self.root_depth = 0; …` (unchanged behavior).
- `negamax_at_root_depth_for_test` = `reset_negamax_test_state(); self.root_depth = root_depth; …`.

PVS tests (§5) call `negamax_at_root_depth_for_test(…, 16)` for full PVS (or an intermediate
value to exercise the ramp). All existing `negamax_for_test` callers are **untouched**. This is
the contract §7's Implementer B depends on; the precedent makes it stub-able immediately.

## 4. New tests (ramp behavior)

All in `src/search/tests.rs`. Drive `negamax`/`go` so the ramp is real.

- **`pvs_scout_start_ramp_values`** — pure unit test of `pvs_scout_start`. Assert the full
  enumerated table to kill every arithmetic/comparison mutant: **d=0 → MAX, d=11 → MAX,
  d=12 → MAX** (kills `<=`→`<`/`==`/`>=` on the `root_depth <= D0` guard — needs both a
  strictly-below and the boundary), **d=13 → 12, d=14 → 8, d=15 → 4** (kills `*`→`+`/`-`→`+`
  on `SLOPE*(d-D0)` and `BASE - …`), **d=16 → 1, d=17 → 1** (kills `.max(1)`→`.max(0)`/`.min(1)`
  and `saturating_sub` mutants — the clamp floor). Also assert monotone non-increasing across
  d∈[0,20].
- **`pvs_disabled_below_d0_matches_reference`** — at `root_depth = D0` (and `D0 - 1`), PVS-on
  is **bit-identical** (score + node count) to `test_disable_scout` reference on curated +
  random positions (depth ∈ [1,4]). The "≡ M7.B.2 below D0" guarantee, the headline safety
  property. (Mirrors the M8.A `pvs_nonpv_bit_identical_to_reference` harness.)
- **`pvs_full_above_d1_matches_m8a`** — at `root_depth >= D1`, PVS-on equals the *un-ramped*
  M8.A ladder (set `root_depth = 16` vs a reference that always scouts): bit-identical score +
  node count. Confirms the ramp's "on" regime is exactly M8.A.
- **`pvs_ramp_scouts_only_late_ranks`** — at an intermediate `root_depth` (e.g. d14 →
  scout_start 8), in a position with ≥10 legal moves, assert `pvs_scout_searches` counts only
  moves with `cur_i >= 8` (and that ranks `< 8` took the reference path: a partner counter or
  a node-count comparison against a hand-computed reference). Anti-vacuous: assert
  `pvs_scout_searches > 0` *and* `< (legal_non_first_moves)`.
- **`pvs_ramp_monotone_node_count_in_depth`** — sanity: node count at fixed search depth is
  non-increasing as `root_depth` rises from `D0` to `D1` (more scouting ⇒ ≤ nodes), on a
  curated position. Guards against an inverted ramp.

## 5. Updated M8.A tests (set `root_depth` so scouting is live)

The M8.A PVS-ladder tests assume scouting is always on; under the default ramp at small
`negamax_for_test` depths (`root_depth = 0`) it is off. Each must run via
`negamax_at_root_depth_for_test(…, 16)` (§3.4) so `root_depth >= D1 = 16` (full PVS):

- `pvs_exact_under_all_pv_vs_full_window` (+ proptest) — set `root_depth = 16` on the PVS-on run.
- `pvs_depth1_exact_vs_full_window`
- `pvs_research_fires_only_when_score_interior`
- `pvs_non_pv_node_never_full_window_researches`
- `pvs_first_move_searched_full_window`
- `pvs_lmr_three_step_ladder_counters`
- `pvs_mate_boundary_null_window`
- `pvs_root_research_when_first_move_fails_low` — **re-target off `go()` onto
  `negamax_at_root_depth_for_test(…, 16)`** at the root frame (`ply = 0`). **Pass a finite,
  narrowed `(alpha, beta)`** (the aspiration-style window the `go()` version got implicitly) —
  at a literal wide `(-INF, INF)` window no move can fail low, so the gotcha would go vacuous.
  Driving
  through `go()` is either vacuous (a cheap unit `go()` won't reach d13 ⇒ silently tests the
  reference path, not PVS root research) or too slow (forcing d13+). The new hook makes the
  scout active deterministically and fast while preserving the research §5 gotcha being tested
  (first root move forced to fail low ⇒ alpha unmoved ⇒ a later interior move still triggers a
  Step-3 re-search via `score > alpha && score < beta`, not `> original_alpha`). Keep the
  forcing setup; only the entry point changes.
- `pvs_nonpv_bit_identical_to_reference` — this one asserts PVS == reference; with the ramp it
  is *trivially* true below D0. Re-target it to `root_depth = 16` so it still tests the
  non-PV-node window-equality property (not a vacuous pass).

The `STACKED_NULL_GATE_REACHABLE` / `NMP_FIRINGS_PINNED` canaries and any exact node-count
anchor that shifts get re-pinned with an M8.A.1 attribution comment. The ~16 wide-window
`is_pv=false` LMR-*firing* tests stay **unchanged** *iff* the reference path is instrumented
with `lmr_*` counters (§3.3); confirm by running them.

## 6. Mechanical-check plan (pre-final-review)

`cargo build` + full `cargo test` (lib + integration) green; `cargo clippy --all-targets`
+ `cargo fmt --check` clean; `cargo llvm-cov` on `src/search.rs` (target ≥ the M8.A 97%);
`cargo mutants --in-diff` 0-missed (the diff is small: the ramp fn + the guard + counters).

**Bench is the headline-safety proof, not a number to update.** Record d4 / d7 and **assert
byte-identical to M7.B.2's d4 `45788` / d7 `662085`** (bench depth ≤ 7 ≤ D0 ⇒ `scout_start = MAX`
⇒ every non-first move takes the reference path). A mismatch is **stop-the-line**: it means the
reference path has *diverged* from the pre-PVS / M7.B.2 loop (do **not** just re-record the
number). Note: M8.A's own bench (d4 `47763` / d7 `654940`) differs from M7.B.2 because the
ladder changed the tree; no existing test pins that the reference path reproduces M7.B.2's exact
node counts, so this bench equality *is* the proof of the off-regime byte-identity property.

**Why off-regime byte-identity holds (the load-bearing dependency to verify, not assume):** the
reference path equals the pre-PVS loop *only because LMR can never fire at a PV node* (LMR is
`!is_pv`-gated, ADR-0025 §2). At a PV node `r = 0` ⇒ the reference path's `r==0` arm searches
once at `pv_scout_child = false` (= M7.B.2's `is_pv && cur_i==0` ⇒ `false` for non-first moves);
at a non-PV node both `pv_scout_child` and `pv_full_child` are `false`. If LMR *could* fire at a
PV node, the reference re-search would use `pv_full_child = is_pv = true` and diverge. State this
one-liner in the ADR.

Integration sweep: grep `tests/` for any `go depth N` with `N >= 13` that asserts an exact
bestmove / node count (would shift once the ramp engages). Expected: none (production behavior
changes only at `root_depth > 12`); record the check result.

## 9. Risks

See research §6: the crossover is ~1 ply wide (tight); the off-regime byte-identity +
conservative constants + the §5.1-research tuning levers are the mitigations. If even a swept
ramp cannot net positive, shelve with the honest conclusion that PVS's gain is not
depth-separable on this engine (a clean negative result, like M7.C / M7.A's ordering split).
