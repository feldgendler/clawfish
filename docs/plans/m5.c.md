# M5.C — Late move reductions (LMR)

Third M5 sub-phase. Adds **late move reductions** to the negamax move loop: at non-PV, non-root, non-check interior nodes with sufficient depth, later quiet moves are searched at reduced depth first and re-searched at full depth only when the reduced search returns above alpha. Layered on top of M4's ordering infrastructure (TT move via reorder, killers, history) and M5.A/B's prologue pruning.

Research synthesis: [`docs/research/m5-late-move-reductions.md`](../research/m5-late-move-reductions.md).

The roadmap row commits to the broad shape: log-log reduction, full-depth re-search on fail-high, and a skip policy for TT/killer/in-check/high-history quiets. This plan narrows those commitments into clawfish's current code surface.

## 0. Goals

- Pure helper `late_move_reduction(depth, quiet_index) -> u32` with the log-log shape, explicit clamp, and direct unit-test coverage.
- Pure helper `is_lmr_eligible_quiet(...)` for the per-move skip policy (separate from the formula so each is independently mutation-killable).
- Move-loop integration with **node-level gates** (`ply > 0`, `!is_pv`, `depth >= LMR_MIN_DEPTH`, `!in_check`) and **per-quiet gates** (not first-quiet, not killer, not high-history).
- A **quiet-only ordinal** inside the move loop. The reduction decision keys off the move's position among quiets, not the raw enumerate index polluted by captures and TT-move reordering.
- On eligible quiets: reduced first pass at `depth - 1 - R`; full-depth re-search at `depth - 1` iff `reduced_score > alpha`.
- An explicit **`quiets_searched` policy for reduced-only quiets** (see §4.5) and an explicit **TT-store policy for reduced-only best scores** (see §4.6), each with rationale.
- `#[cfg(test)]` instrumentation so the suite can pin direct LMR behavior (eligibility / reduced-first-pass / re-search) without depending on brittle global node-count deltas.
- ADR-0025 records the policy commitments.

Mutation testing follows the M5.A/M5.B precedent: the per-unit `--in-diff` campaign is **deferred** to the project's overnight backlog (`docs/mutants-backlog.md`). The user has invoked the same standing instruction across M4.B–M5.B (recorded in `docs/milestones/m5.a.md` and `docs/milestones/m5.b.md`); M5.C inherits it. The plan still prepares the diff-scope and the anticipated catchable surface for the campaign agent.

## 1. Out of scope

- Reducing captures or promotions. M5.C is **quiet-only**.
- Special cases for passed pawns, pawn pushes, or quiet checking moves. Tuning extensions, not v1.
- Adaptive re-search depth on reduced fail-high. v1 always re-searches at the parent's full child depth `depth - 1`. (Rationale in §4.4.)
- "Reduce less" for trusted quiets. v1 simply **skips reduction entirely** for killers and high-history quiets.
- Any qsearch changes (M5.E / M5.F).
- Late-move pruning or frontier futility (M5.D / later).
- Hoisting state into `Position` or adding new movegen annotations. M5.C consumes existing search-time signals only.

## 3. Type definitions and signatures

### 3.1 Constants

New constants in `src/search.rs`, adjacent to existing M5 constants. **All five are conservative starting values; see §8 for the SPRT-tunable surface.**

```rust
pub(crate) const LMR_MIN_DEPTH: u32 = 3;
pub(crate) const LMR_MIN_QUIET_INDEX: u32 = 2;
pub(crate) const LMR_BASE_OFFSET: f64 = 0.99;
pub(crate) const LMR_LOG_DIVISOR: f64 = 3.14;
pub(crate) const LMR_HIGH_HISTORY_THRESHOLD: i16 = 4_096;

const _: () = assert!(LMR_HIGH_HISTORY_THRESHOLD as i32 <= MAX_HISTORY as i32);
```

Probe table for the formula at the chosen constants (`floor(0.99 + ln(depth) * ln(quiet_index) / 3.14)`):

| `depth\quiet_index` | 2 | 3 | 5 | 10 | 20 |
|---|---|---|---|---|---|
| 3 | 1 | 1 | 1 | 1 | 1 |
| 6 | 1 | 1 | 1 | 2 | 2 |
| 8 | 1 | 1 | 2 | 2 | 2 |
| 12 | 1 | 1 | 2 | 2 | 3 |

Reductions stay in `0..=3` over the realistic depth/quiet-index range (default bench depth is 7), never collapsing the reduced child below depth 1 once the §4.3 clamp is in force. The base offset `0.99` deliberately rounds the d=3, q=2 case to 1 (first late-quiet boundary cleanly proven). `LMR_LOG_DIVISOR = 3.14` is intentionally the engineering "small reduction unless both depth and index grow" knob; the resemblance to π is incidental, and the constant is SPRT-tunable. Linting around `clippy::approx_constant` is addressed by an explicit `#[allow(clippy::approx_constant)]` on the constant with a one-line `// SPRT-tunable, not π` rationale.

**Bench-delta expectation**: ~30–55% drop vs `baseline/m5b-rfp`'s `3,355,270` nodes (M5.B precedent: -37.2%; M5.A: -66.3%). A drop < 10% indicates a wiring bug (LMR not firing); a drop > 80% suggests over-reduction. The §11 docs reconciliation step uses these bands as the determinism-and-magnitude check.

`LMR_HIGH_HISTORY_THRESHOLD = 4096` exempts quiets with sustained positive history. Under M4.C's `+depth*depth` bonus, that requires e.g. ~15 cutoffs at depth 5, or ~6 at depth 8; quiets short of that bar still get LMR. The compile-time `const` assert pins `THRESHOLD <= MAX_HISTORY`, killing a refactor that silently disables the skip.

### 3.2 Helper functions

Two narrow helpers, not one combined predicate. M3.D `negate_window` precedent: keeping the formula math separable from the skip-list policy lets each be unit-tested in isolation, and lets the formula's mutation surface be killed without dragging in the `Position` / `HistoryTable` plumbing.

```rust
pub(crate) fn late_move_reduction(depth: u32, quiet_index: u32) -> u32;

fn is_lmr_eligible_quiet(
    mv: Move,
    pos: &Position,
    quiet_index: u32,
    killer0: Move,
    killer1: Move,
    history_table: &HistoryTable,
) -> bool;

fn lmr_needs_full_research(reduced_score: i32, alpha: i32) -> bool;

fn tt_bound_for_completed_node(
    best: i32,
    beta: i32,
    original_alpha: i32,
    best_is_full_depth: bool,
) -> Option<TtBound>;

fn best_is_full_depth_after_score(
    best: i32,
    best_is_full_depth: bool,
    score: i32,
    move_is_full_depth: bool,
) -> bool;

fn update_history_on_quiet_cutoff(
    history_table: &mut HistoryTable,
    side: Color,
    cutoff_move: Move,
    quiets_searched: &MoveList,
    depth: u32,
);
```

`late_move_reduction`:

- **In-domain behavior pinned**: returns `0` for `depth < LMR_MIN_DEPTH` OR `quiet_index < LMR_MIN_QUIET_INDEX` (the helper is `pub(crate)` and the unit tests cover the boundary; do not rely on the call-site gate alone).
- **1-based `quiet_index`**: `1` = first quiet at this node.
- **Clamp**: `min(raw, depth - 2)` so the reduced child is at least depth 1. The §3.1 lower-bound guard prevents underflow before the subtraction.

`is_lmr_eligible_quiet`:

- Returns `false` for non-quiets, for `quiet_index < LMR_MIN_QUIET_INDEX`, for either killer slot, and for high-history quiets.
- Does NOT check `is_pv`, `in_check`, `depth`, or `ply` — those are node-level and held at the caller.
- **The TT move is implicitly exempt**: after the step-12 reorder it is the first searched move (ADR-0018 §12 pins TT-move-at-index-0); if it is a quiet it receives `quiet_index = 1` and the floor at `LMR_MIN_QUIET_INDEX = 2` rules it out. No explicit TT-move parameter is threaded through. The implicit exemption depends on ADR-0018 §12; if a future ordering refactor moves the TT move off index 0, an explicit TT-move parameter must be added (a behavioral test `negamax_tt_move_when_quiet_is_never_reduced` would catch the regression directly).

`lmr_needs_full_research`: returns `reduced_score > alpha`. Pinned strictly-greater (a fail-low at exactly alpha is **not** improving and need not be re-searched).

### 3.3 Test-only instrumentation

Add to `AlphaBetaMover` under `#[cfg(test)]`:

```rust
lmr_reduced_searches: u32,
lmr_full_researches: u32,
lmr_reduced_moves: Vec<Move>,
lmr_researched_moves: Vec<Move>,
lmr_history_candidates: Vec<Move>,
lmr_trace_root_ply: Option<u32>,
```

Counters / move lists are recorded only at the frame named by `lmr_trace_root_ply` (set by `negamax_for_test` to its entry `ply`), so descendants don't pollute. Re-entry of the same `ply` within a single test call is structurally impossible (each recursive `negamax` call increments `ply`; the entry `ply` is never revisited), so the `Some(ply)` filter is unambiguous. The two-counter shape (reduced + research) is deliberately distinct from M5.A/M5.B's `<feature>_firings` singular: LMR has two distinguishable events that both need direct pinning.

Accessors mirror `nmp_firings_for_test` / `rfp_firings_for_test`.

## 4. Planned production change in `negamax`

### 4.1 Quiet-only ordinal

```rust
let mut quiet_index: u32 = 0;        // pre-increment counter
// inside loop, after `is_quiet(mv)`:
quiet_index += 1;
let current_quiet_index = quiet_index;  // 1-based
```

The first quiet at a node is unambiguously `current_quiet_index = 1`. The reduction helper never sees `0`. Captures / TT moves do not advance the counter.

### 4.2 Node-level gate

```rust
let lmr_node_eligible =
    ply > 0
    && !is_pv
    && depth >= LMR_MIN_DEPTH
    && !in_check(pos);
```

Rationale per gate:

| Gate | Why |
|---|---|
| `ply > 0` | **Structural-root guard. Defense-in-depth against a future PVS refactor that would change `is_pv` semantics. Parallels ADR-0023 §3 / ADR-0024 §3.** Listed first so the cheapest predicate fails fast. |
| `!is_pv` | Preserve PV exactness. |
| `depth >= LMR_MIN_DEPTH` | A reduced child must still have a useful depth budget. |
| `!in_check` | Evasions are tactically dense; reducing them risks missing forced sequences. |

Computed once before the move loop, not inside it.

### 4.3 Reduction clamp

`late_move_reduction(depth, current_quiet_index)` MUST be ≤ `depth - 2` so `depth - 1 - reduction ≥ 1`. The clamp lives in the helper (§3.2), backed by a `debug_assert!` at the call site as a tripwire against a future helper-edit that violates it.

### 4.4 Re-search policy

```text
if reduced_score > alpha:   full-depth re-search at depth - 1
else:                        accept reduced_score
```

`> alpha` (not `>= alpha`, not `>= beta`): a fail-low at exactly alpha did not improve the bound; only a strict improvement triggers the re-search. **Re-search depth is `depth - 1` (the original child depth), not adaptive**: v1 chooses the simplest correctness-preserving choice. The literature's "re-search at `depth - 1 - R/2`"-style adaptive variants are observable strength gains but add a tuning surface that would weaken attribution for the M5.C SPRT signal. Deferred.

### 4.5 `quiets_searched` policy for reduced-only quiets

A reduced-only quiet (one that took LMR's first pass and did NOT trigger the full-depth re-search) **does not enter `quiets_searched`**.

Rationale: ADR-0019 §3 includes killers in `quiets_searched` because killers are *full-depth tried-and-failed* signals; the malus has matching evidentiary weight. Reduced-only LMR probes are *coarser-depth tried-and-failed* signals — including them at full `+depth*depth` magnitude over-trains history on noisy probes. The principled alternative would be to weight the malus by the actual probe depth (e.g., `(depth - 1 - R)^2`), but that is an SPRT-tunable refinement, not a v1 commitment. The binary v1 choice is therefore **exclude**, narrowing ADR-0019 §3's "tried-and-failed" notion to "full-depth tried-and-failed" within LMR-eligible nodes.

A pinned test asserts that a reduced-only quiet does not appear in `quiets_searched`. A second pinned test asserts that a quiet that was re-searched at full depth (whether it then cut or not) follows the existing M4.C semantics.

**Cutter provenance is automatic.** The cutter at this node is by construction full-depth-witnessed: a beta-cutoff requires `score >= beta > alpha`, and §4.4 forces a full-depth re-search on any reduced score `> alpha`. So the cutter passed through `update_history_on_quiet_cutoff` is always a full-depth result; the `+depth*depth` bonus is not contaminated by reduced-only probes. ADR-0019 §3's history soundness argument extends to the LMR-modified loop without modification.

### 4.6 TT-store policy for reduced-only best scores

Track a per-move local `move_is_full_depth: bool` and propagate to a node-local `best_is_full_depth: bool` whenever `score > best`. On equal-score ties, `best_is_full_depth |= move_is_full_depth` (a later full-depth witness restores eligibility — see helper `best_is_full_depth_after_score` below).

At step 14, **suppress the TT store iff `best_is_full_depth == false`**.

Helper:

```rust
fn tt_bound_for_completed_node(
    best: i32,
    beta: i32,
    original_alpha: i32,
    best_is_full_depth: bool,
) -> Option<TtBound>;
```

Returns `None` (suppress store) when `best_is_full_depth == false`; otherwise the existing Lower/Exact/Upper classification. Pure function; directly unit-testable.

**Why suppression is a real correctness call, not a tautology.** Walk the three TT-bound shapes:

- **Lower** requires `best >= beta`. To reach `best`, a move's accepted score must beat the running `best` (and thus eventually `alpha`). Under §4.4, any reduced-only score `> alpha` triggers a full-depth re-search; the score that lands in `best` is that re-search result, which is full-depth-witnessed. So a Lower bound is always full-depth-proven.
- **Exact** requires `best > original_alpha && best < beta`. Same argument as Lower for the `best > original_alpha` half: only a full-depth re-search produces a score that updates `best` past `original_alpha`. Exact is always full-depth-proven.
- **Upper** requires `best <= original_alpha`. This is the case suppression actually changes. A reduced search at depth `d - 1 - R` proved `score <= alpha`; this does NOT prove `score <= alpha` at the parent's claimed depth `d`, because a deeper search can find new tactical resources that improve the score. Storing an Upper entry tagged with depth `d` would be *false advertising*: a future probe at depth `d` could legitimately re-use the entry without triggering a full search, propagating an under-tight bound. We prefer the suppression: occasionally re-search the position later, never store an inflated-depth bound.

The "strict-improvement carries new provenance" semantics of `best_is_full_depth_after_score` (a `score > best` always replaces `best_is_full_depth` with `move_is_full_depth`) are sound by the same Lower/Exact argument: any `score > best ≥ original_alpha` after the first move is already full-depth-witnessed via §4.4, so the first move's provenance never "leaks" into a later improvement. The first move at any node carries `quiet_index = 1` (or is non-quiet), and §3.1's `LMR_MIN_QUIET_INDEX = 2` ensures the first quiet is never reduced — so the first move's `move_is_full_depth` is always `true` regardless. The corner where strict improvement could lose information is therefore impossible by construction. The §5.1 helper tests pin both directions: `best_is_full_depth_after_score_strict_improvement_takes_new_provenance` and `tt_bound_for_completed_node_lower_requires_full_depth_witness`.

The alternative — store at the *actual* probe depth `d - 1 - R` — is theoretically sound but complicates `entry.depth` semantics across the rest of the search and is harder to argue against ADR-0018 §13's bound-handling rules. Deferred.

This is the single load-bearing correctness commitment in M5.C beyond the move-loop mechanics.

### 4.7 History bonus/malus on quiet beta-cutoff

Existing M4.C semantics preserved: on a quiet beta-cutoff, `+depth*depth` to the cutter and `-depth*depth` to the priors in `quiets_searched`. Because §4.5 already excludes reduced-only quiets from `quiets_searched`, the malus only ever lands on full-depth tried-and-failed quiets. No change to the bonus side.

The history-update body is extracted into a named helper `update_history_on_quiet_cutoff` so the `+/-` arithmetic is mutation-killable as a pure function (M3.D `negate_window` precedent).

### 5.3 Existing-pin audits

Implementation is expected to disturb several existing search-shape pins. Plan discipline:

- `NMP_FIRINGS_PINNED` — almost certainly moves; legitimate re-pin under the new LMR-pruned tree.
- Aspiration-window `mate_prior` test (current depth-6+ window-contained pin) — may shift as LMR moves the first mate-discovery iteration; if so, narrow to a property pin (mate-prior iteration is window-contained whenever the same mate persists across iterations) rather than chasing the depth.

- `engine::tests::handle_setoption_random_seed_bad_value_silent_when_debug_off` and `engine::tests::greedy_mover_determinism_across_repeated_runs_with_fixed_seed` — these run `go` with no time budget through `AlphaBetaMover`; the M5.B → M5.C transition can shift the bestmove. Each failing case is investigated individually: if the test's invariant is "same input → same bestmove" the test is correct as-is and the failure is a real determinism regression to fix at the implementation level (most likely: a race with the time-budget default that exposes when the search finishes earlier). Do not blanket-classify as "unrelated."
- Bench signature pin in `bench/m5.md` and `CLAUDE.md` and the ADR — must reflect the actual production-binary `bench` output, verified by a fresh run after the implementation lands.

## 8. Open SPRT-tunable parameters

Post-M5.C campaigns (mirror ADR-0023 §"Open SPRT-tunable parameters" / ADR-0024 ditto):

1. `LMR_BASE_OFFSET` and `LMR_LOG_DIVISOR` jointly — re-fit the formula to the post-M5.C tree.
2. `LMR_MIN_DEPTH` — compare 2 / 3 / 4.
3. `LMR_MIN_QUIET_INDEX` — compare 2 / 3.
4. `LMR_HIGH_HISTORY_THRESHOLD` — compare 2048 / 4096 / 8192, or replace the binary skip with a "reduce less" rule (R−1 instead of skip).
5. `quiets_searched` policy for reduced-only quiets — compare exclude (v1) / include / depth-weighted (`(depth - 1 - R)^2`).

The v1 commitments above are conservative and chosen for **clean SPRT attribution**, not for proven optimality.
