# M6.C — Passed pawns (plan)

Third M6 sub-phase. Adds a passed-pawn evaluation term (per-rank bonus +
king-distance + path-clear/blocked discriminator) to `evaluate()`, reading the
`passed[2]` bitboards M6.B already caches in the pawn hash. Computed **live**
(king-distance and path depend on non-pawn state — not pawn-only, ADR-0032 §3).

- Research: [`docs/research/m6-passed-pawns.md`](../research/m6-passed-pawns.md).
- No new ADR (roadmap M6.C row commits the path-blocked semantic — "no separate
  ADR"). ADR-0032 gets a one-paragraph M6.C addendum at landing.
- Builds on M6.A tapered `(static_mg_white, static_eg_white, raw_phase)`
  (ADR-0031) and M6.B's cached `PawnEval.passed` (ADR-0032 §3).

## 1. Scope

In:
- `passed_pawn_term_white(pos, &passed) -> (i32 mg, i32 eg)` in `src/eval/pawns.rs`
  — white-perspective, three additive sub-terms per passer:
  - **Rank bonus**: `PASSED_MG/EG[rel_rank]` per passed pawn (MadChess defaults).
  - **Path discriminator** (EG-only `±PASSED_FREE_EG_DELTA[rel_rank]`):
    three-state on the front-span bitboard (empty of *all* pieces → +delta;
    *enemy* piece on path → −delta; friendly-only → 0).
  - **King-distance** (EG-only): rank-scaled Chebyshev to the promotion square;
    own king near → bonus, enemy king near → penalty (placeholder coeffs).
- `data.rs` literature-default constants for all three.
- `evaluate_core` blend wired to add the white-perspective `(pp_mg, pp_eg)`.
- Bench signature re-pin; mop-up-exclusion regression assertion.

Out (deferred — research §6, all confirmed safe):
- Candidate / connected-passer-extra / protected-passer-extra (M6.F).
- Unstoppable passer / rule-of-the-square (search-interacting; M8+).
- Tarrasch rook-behind-passer; outside passer; pawn-race tempo.
- **Weight calibration** — literature defaults ship un-tuned; M6.F joint Texel.

## 2. Decisions (rationale in research note)

| # | Decision |
|---|---|
| D1 | Whole passed-pawn term is **computed live** in `evaluate_core`, reading `pe.passed` (M6.B cache). King-distance + path need non-pawn state → not pawn-only (ADR-0032 §3). NOT added to the pawn-hash entry. |
| D2 | **Additive stacking, no suppression** (M6.B / ADR-0032 §6 precedent). A connected passer gets both CONN and the passed bonus — different axes (research §4.3). M6.F Texel reconciles. |
| D3 | Distance measured to the **promotion square** (`Square::from_file_rank(file, 7|0)`), Chebyshev, clamped to `PASSED_KDIST_CAP=5`, rank-scaled (research §2). Reuses `super::chebyshev_distance`. |
| D4 | **Path discriminator = the roadmap-committed "simplest CPW variant", explicitly chosen over the rejected finer split.** The roadmap M6.C row commits: *"blocked = any opposing piece occupies a square on the pawn's path-forward bitboard … the simplest CPW variant; **alternative semantics rejected at plan time**."* We therefore ship **one** `±PASSED_FREE_EG_DELTA[rel]` over the **whole front-span** (`white_front_spans`/`black_front_spans` of the passer; excludes own square, **includes** promo square — research §3.4). The finer stop-square-vs-deep-path *magnitude split* documented in research §3.3 (big malus if the stop square is blocked, smaller if only the deep path is) is precisely the "alternative semantics rejected at plan time" — **deliberately deferred to M6.F**, not an oversight. The three-state refinement (research §3.2: own-piece-only on path → neutral) is *not* an alternative semantic — it is the correct reading of the committed word "**opposing** piece" (enemy-only), so it is in-scope and committed here. |
| D5 | **Ship all three sub-terms at literature defaults** (MadChess rank+path co-calibrated; king-distance placeholder). No hand-tuning (M6.F's job). Per research §9, SPRT the full M6.C vs `M6.B` *without* term isolation first; **king-distance is the pre-designated prime suspect** if it regresses (R2). Contingency screen pre-committed if SPRT regresses (§11). |
| D6 | Rank-bonus MG rank-7 entry = `0` (MadChess; the bonus is overwhelmingly EG — research §1.2/§7). Path + king-distance are **EG-only** (MG components zero). |
| D7 | Mop-up keeps **PST-only** `(mg, eg)` inputs — passed-pawn term excluded from the mop-up advantage estimate, exactly as bishop-pair / pawn-structure are (ADR-0031 / ADR-0032 §4). Pinned by a regression assertion. |

## 4. Type / signature surface

`src/eval/data.rs` (indexed by relative rank 0..7; ranks 0/1/7-MG = 0):

```rust
pub(crate) const PASSED_MG: [i32; 8] = [0, 0, 3, 8, 15, 24, 34, 0];
pub(crate) const PASSED_EG: [i32; 8] = [0, 0, 4, 18, 42, 75, 118, 170];
/// EG-only path-clear delta: +when front-span empty of all pieces,
/// −when an enemy piece is on it, 0 when friendly-only (research §3).
pub(crate) const PASSED_FREE_EG_DELTA: [i32; 8] = [0, 0, 4, 16, 35, 63, 98, 141];
/// EG-only king-tropism placeholder coefficients (NOT co-calibrated; M6.F).
pub(crate) const PASSED_KDIST_OWN_PER_STEP: i32 = 5;
pub(crate) const PASSED_KDIST_ENEMY_PER_STEP: i32 = 7;
pub(crate) const PASSED_KDIST_CAP: i32 = 5;
```

`src/eval/pawns.rs`:

```rust
/// White-perspective passed-pawn eval (rank bonus + EG path discriminator +
/// EG king-tropism). Reads the M6.B-cached `passed[White|Black]`; computed
/// **live** (king-distance/path are not pawn-only — ADR-0032 §3). Returns
/// `(mg, eg)` white-perspective; black passers subtract symmetrically.
pub(crate) fn passed_pawn_term_white(
    pos: &Position,
    passed: &[Bitboard; 2],
) -> (i32, i32);
```

`src/eval.rs` `evaluate_core` blend becomes:

```rust
let (pp_mg, pp_eg) = if PASSED_PAWNS_IN_EVAL {
    pawns::passed_pawn_term_white(pos, &pe.passed)
} else { (0, 0) };
let blended = ((mg + bp_mg + pe_mg + pp_mg) * phase
             + (eg + bp_eg + pe_eg + pp_eg) * (24 - phase)) / 24;
```

`mop_up` is added **after** the blend (`result_white = blended + mop_up`,
eval.rs:264) and is **not** modified — the passed-pawn term enters the
numerator only, never the mop-up path (reinforces D7; the coder must not fold
`pp` into `mop_up_term_white`'s inputs).

## 5. `passed_pawn_term_white` algorithm

```
(mg, eg) = (0, 0)
occ_all = pos.occupied_all()
for (side, sign, enemy_color) in [(White,+1,Black), (Black,-1,White)]:
    own_king   = pos.king_square(side)
    enemy_king = pos.king_square(enemy_color)
    enemy_occ  = pos.occupied(enemy_color)
    for sq in passed[side.index()]:
        rel = side==White ? sq.rank() : 7 - sq.rank()         # 0..7
        mg += sign * PASSED_MG[rel]
        eg += sign * PASSED_EG[rel]
        # path discriminator (EG-only, three-state)
        path = side==White
               ? white_front_spans(bb(sq)) : black_front_spans(bb(sq))
        if (path & occ_all).is_empty():        eg += sign *  PASSED_FREE_EG_DELTA[rel]
        elif (path & enemy_occ).any():         eg += sign * -PASSED_FREE_EG_DELTA[rel]
        # else friendly-only on path → neutral (0)
        # king-distance (EG-only, rank-scaled, to promo square)
        promo = Square::from_file_rank(sq.file(), side==White ? 7 : 0).unwrap()
        own_d   = min(chebyshev_distance(own_king,   promo), PASSED_KDIST_CAP)
        enemy_d = min(chebyshev_distance(enemy_king, promo), PASSED_KDIST_CAP)
        eg += sign * (rel as i32) * PASSED_KDIST_OWN_PER_STEP   * (PASSED_KDIST_CAP - own_d)
        eg += sign * (rel as i32) * PASSED_KDIST_ENEMY_PER_STEP * (enemy_d - PASSED_KDIST_CAP)
return (mg, eg)
```

- Own king closer to promo (small `own_d`) → larger `(CAP - own_d)` → **bonus**.
- Enemy king closer (small `enemy_d`) → `(enemy_d - CAP)` more negative → **penalty**.
- `rel` (0..7) linear rank-scale; rel 0/1 unreachable for a passer → naturally 0.
- `bb(sq)` = `Bitboard::from_square(sq)`. Black path/relrank/promo are the
  direction-reversed analogues (no `mirror(pos)` helper — symmetry pinned by
  the §7 mirrored-FEN-pair fixtures, the M6.B color-symmetry precedent).
- **Mate-band, derived.** Max reachable relative rank for a real pawn is **6**
  (LERF rank 6, one push from promoting; `PASSED_*[7]` is never hit mid-search
  — data-comment precedent). Per-passer worst-case |EG|: `PASSED_EG[6]=118`
  `+ PASSED_FREE_EG_DELTA[6]=98` `+ |king-dist|` (max `rel(6)·ENEMY(7)·CAP(5)
  = 210`) `= 426`. Max 8 passers/side (enemy pawnless) → `|Σ pp_eg| ≤ 8·426 =
  3408`, an order of magnitude below `MATE_IN_MAX_PLY-1 = 29935`; it stacks on
  the existing PST/material/bp/pe sum the M6.B `evaluate_core` debug assert
  already bounds well under the band. The existing
  `debug_assert!(result_white.abs() < MATE_IN_MAX_PLY-1)` covers it; §7 adds
  an explicit extreme-passers band test. `pp` is `i32` end-to-end and **not**
  cached → no i16-range concern (unlike `pe.mg/eg`).

## 11. Contingency ladder if the M6.B-vs-M6.C SPRT regresses

Pre-committed so the run stays unattended (mirrors the M6.B method exactly —
`docs/milestones/m6.b.md` "Subset rework"; **zero hand-tuning**, only choosing
which literature defaults to keep):

1. **Env-mask subset screen (cheap *relative* filter only).** Throwaway
   experiment patch: `CLAWFISH_PASSED_MASK` read once at startup, bits
   RANK=1 / PATH=2 / KDIST=4 (PATH & KDIST are per-passer adjustments —
   meaningless without RANK, so the lattice is `{RANK}`, `{RANK+PATH}`,
   `{RANK+KDIST}`, `{RANK+PATH+KDIST}`; **screen `{RANK}` and `{RANK+PATH}`
   first** — KDIST is the R2 prime suspect, so the KDIST-out subsets are the
   leading hypotheses). Sanity-checks of the *patch*: at mask 7 `bench` ==
   the clean all-three HEAD; at mask 0 `bench` == `M6.B`. **Disanalogy with
   M6.B noted:** M6.C ships the term *live*, so mask-0 inertness validates
   only the throwaway patch's plumbing — it is **not** a production "provably
   inert default" property (M6.B could claim that because its shipped state
   *was* the inert one; M6.C's is not). SPRT each subset vs cached `M6.B`
   (single-TC `10+0.1`, elo0=0/elo1=10, shared seed — paired low-variance,
   the M6.B screen protocol). Patch fully reverted before clean apply.
   - **TC-asymmetry defense (the M6.B slow-TC blind-spot, inverted here).**
     The single-TC `10+0.1` screen is valid as a *relative paired ranking*:
     all M6.C subsets share the same EG-heavy character (§10 hypothesis), so
     a uniform TC-profile shift moves them together and the *ranking* is
     robust even if absolute single-TC Elo mis-estimates the mixed-TC value.
     **Guard:** the all-three SPRT's per-TC breakdown is inspected first. If
     it shows the §10-hypothesized slow-TC-positive / fast-TC-weak inversion
     (the *opposite* of M6.B's CONN-only profile), the single-TC screen could
     mis-rank — so in that case the **top-2 screen candidates are
