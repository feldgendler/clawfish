# M6.K — King-safety attacker S-curve activation (stage 1)

**Status:** plan v2 — plan-review loop converged (reviewer: "no further substantive issues", pass 2).
**Baseline for the SPRT:** `M6.J` (current production HEAD, bench `1357063` / d4 `112497`).
**ADR:** placeholder **ADR-0038** (allocated at landing).
**Roadmap anchor:** `docs/roadmap.md` §M6.K scope-detail (lines ~489–500) + the M6.K baseline-tag row.

## 1. Goal and scope

Activate the one M6 eval term the M6.I/M6.J Texel pipeline structurally left off: the
**king-safety attacker-count S-curve** (the 100-entry `KING_SAFETY_TABLE` + the 4 per-kind
`KING_ATTACK_WEIGHT_{N,B,R,Q}` multipliers). They ship at zero today (`units ≡ 0` ⇒ only
`KING_SAFETY_TABLE[0]` reachable ⇒ table dead by construction). This unit flips them on to the
**literature CPW-Engine defaults** (multipliers `2/2/3/4`, the 100-entry Glaurung-1.2-lineage
S-curve, global gain `g = 1`), which is exactly **stage 1 ("literature on/off probe")** of the
roadmap's two-stage campaign.

**What this unit delivers (the code):** the activated constants + tests + the bench-pin re-pin +
docs/ADR. The candidate is committed **SPRT-pending** (M6.I/M6.J precedent — `f390b46` "candidate
weights applied; SPRT vs M6.I pending"). **What this unit does NOT do (the campaign):** run the
stage-1 SPRT — it is a ~10 h mixed-TC match, **operator-gated** (ADR-0037 §10: "cannot run in an
interactive session"). The unit hands the operator the exact SPRT command + the verdict ladder.

### Out of scope (deferred to stage 2, only if stage 1 fails)

Stage 2 ("SPSA-deflate") is **conditional** on stage 1 returning H0/regress and is **not built in
this unit** (roadmap: "stage 2 in particular is not worth heavy hand-tuning if stage 1 doesn't
pay"). When/if reached, stage 2 is realized **as further `eval::data` edits**, not new runtime
machinery — see §6.

## 2. Chosen approach and the key alternative (decided)

**Decided: stage 1 is a pure `src/eval/data.rs` constant edit. No new runtime knob, no
`texel-tune apply` extension, no marker region.** Rationale:

- The S-curve **computation** (`king_safety_term_white`, `king_zone`, the `<2 attackers ∨ no queen`
  gate, the `units.clamp(0,99)` index) already exists and is unit-tested (`src/eval/king_safety.rs`).
  Activation only changes the **frozen data** it reads.
- The Texel harness **already** recomputes the S-curve from `EvalParams`' frozen fields
  (`src/texel/features.rs::king_safety_scurve_mg`, lines 246–291), which read from `eval::data` via
  `EvalParams::shipped()`. So the §7 faithfulness equality cross-check
  (`reference_score_white(pos, shipped()) == static_eval_white(pos)`, features.rs:516) **stays green
  automatically** once the constants are non-zero — both sides read the same constants. **No Texel
  change is required and the S-curve stays excluded from the tuned core vector** (it remains a frozen
  term, just frozen at literature instead of zero).

**Alternative considered and rejected for this unit — a runtime global-gain `g` knob.** Roadmap
stage 2 frames `g ∈ (0,1]` as "a global gain on the table output" tuned by SPSA. A runtime `g`
would let a (not-yet-built) SPSA harness tune it continuously. Rejected because: (a) it is YAGNI
for stage 1 (`g = 1`); (b) the project ethos is hardcoded weights, not runtime tuning knobs
(ADR-0037 §9 "ship hardcoded like PeSTO"); (c) the roadmap explicitly sanctions a **manual
coordinate grid `g ∈ {0.25, 0.5, 0.75, 1.0}`** as an acceptable substitute "if the SPSA harness
landing is deferred" — and it is. Under the grid, each `g` is realizable as a **pre-scaled table**
(`table_g[i] = round(literature[i] · g)`), i.e. another data edit, with no runtime knob. This keeps
both stages on the same minimal code surface. Noted in ADR-0038.

## 5. Test plan

The existing king-safety tests fall into two classes:

- **Symbolic-from-data tests** (`king_safety_attack_units_symbolic_from_data`,
  `…_all_kinds_symbolic`, `…_gate_below_two`, `…_gate_no_queen`, shield/open-file tests): they
  derive `expected` from the `eval::data` constants, so they **auto-track** activation and stay
  green with no edit. **Do not rewrite them** — they remain valid and now exercise non-zero values.
- **Literal-zero tests:** only `king_safety_startpos_is_zero` asserts a literal `(0,0)`. It
  **survives** — start position has no king-zone attacker (gate fires) and is color-symmetric ⇒
  `(0,0)` independent of weights. Update its doc comment to say "by gate + symmetry" not "at zeroed
  weights".
- **`src/eval.rs` accessor tests (survive, comment-only cleanup):** `static_accessor_excludes_king_safety`
  (~1633) asserts `static_mg/eg_white() == PST-only from-scratch` — the S-curve never enters the
  static accessor (ADR-0033 §6), so it stays green. `mop_up_addend_excludes_king_safety_vs_m6d`
  (~1692) asserts `bonus == 26` from PST-only inputs — also structurally excludes the S-curve. Both
  **pass unchanged**; only their stale docstrings need the §3 refresh. Enumerated here so the
  reviewer/operator confirms them in the green run rather than discovering them as a surprise.

**New / strengthened tests (in `src/eval/king_safety.rs::tests`):**

1. `king_safety_literature_table_values_pinned` — pin representative `KING_SAFETY_TABLE` entries
   against transcription typos: `[0]==0, [1]==0, [2]==1, [5]==5, [10]==18, [31]==150, [32]==169,
   [60]==494, [61]==500, [99]==500`. (Replaces/augments the existing len-only guard
   `king_safety_tables_have_expected_lengths`, which stays.)
2. `king_safety_table_monotonic_nondecreasing` — `∀ i: TABLE[i] ≤ TABLE[i+1]` and `TABLE[99]==500`
   (saturating tail). Encodes the S-curve shape invariant; kills "wrong order / dip" typos a
   point-pin set might miss.
3. `king_safety_multipliers_literature_pinned` — `KING_ATTACK_WEIGHT_{N,B,R,Q} == 2,2,3,4`.
   Anchors the activation itself (a future accidental re-zero fails here).
4. `king_safety_activated_penalty_is_negative` — **the non-symbolic anchor.** Reuse the
   `…_symbolic_from_data` fixture (`k7/8/8/8/4q3/3n4/8/6K1 w`): White Kg1 under attack by Black
   Nd3+Qe4, gate passes (2 attackers + queen), units = 2·1 + 4·3 = **14** → `TABLE[14] = 35`. The
   established white-POV derivation of the *full* term on this fixture is
   `mg = −TABLE[14] + KS_ADJ_SEMI_OPEN_MG + KS_BOTH_ADJ_SEMI_OPEN_MG = −35 + (−15) + (−23) = −73`
   (the open-file penalties are themselves negative and **add to** the penalty). **To prove
   activation actually changed behavior, the assertion must use a BARE LITERAL, not a recompute
   from `eval::data`** — a recompute would pass against the zeroed table too (it would assert
   `mg == 0`). So assert two things: (a) `mg <= -35` with `35` written as a **bare integer literal,
   independent of `KING_SAFETY_TABLE`** — this isolates the S-curve as the dominant negative term
   and fails hard against the zeroed table; (b) `eval::king_safety::king_safety_term_white(&pos).0
   == -73` as a hardcoded literal documenting the exact post-activation value. (The existing
   `…_symbolic_from_data` test continues to cover the auto-tracking exact-arithmetic angle; this
   test is deliberately the literal-pinned complement.)

   **Correction to the floor (verified by full arithmetic):** the M6.I open-file penalties are
   *already active* on this fixture, so the non-activated term is **`(-38, 0)`** (white open-file
   −95 vs black −57), **not** `(0, 0)`. Therefore a `mg <= -35` floor would *pass* against the
   zeroed table (−38 ≤ −35) and prove nothing. The genuine bare-literal anchor is the exact pair
   **`king_safety_term_white(&pos) == (-73, 0)`** (activated: white-POV `−35` S-curve on top of the
   `−38` open-file delta), which fails against the non-activated `(-38, 0)`. Implement assertion
   (b) only — the exact literal `(-73, 0)` — and document the non-activated `(-38, 0)` value in a
   comment so the activation-proving property is explicit. (The plan's earlier `mg <= -35` floor is
   retracted as arithmetically unsound for this fixture.)
5. `king_safety_eg_unaffected_by_scurve` — the S-curve is MG-only (ADR-0033 §2/§5): in a
   queen+attackers fixture, assert the `eg` component is unchanged by the attacker term
   (driven only by shield, here 0). Guards against an accidental EG coupling.

**Color-symmetry / antisymmetry** (`king_safety_color_mirror_antisymmetric`): unchanged — the
white−black sign-flip construction is weight-independent; the test stays green with non-zero
weights and now exercises them. Confirm (do not edit) it still holds.

**Bench pin** (`tests/uci_integration.rs`, E51): recompute after build, re-pin
`M6K_DEPTH4_BENCH_NODES`. The two-runs-equal determinism assertions are unaffected.

**No new property tests** beyond the monotonicity invariant (#2) — the term's other invariants
(symmetry, gate) are already covered by existing constructed tests and the monotonicity property is
the one invariant more compact as a property than an enumeration.

## 6. Stage-2 recipe (documented in m6.k.md + ADR-0038; NOT implemented now)

If the stage-1 SPRT returns H0/regress (the M6.E double-count materialized at the joint M6.J
landscape), stage 2 runs a **manual grid**, each cell a data edit + SPRT vs `M6.J`:

- **Deflate via pre-scaled table:** `KING_SAFETY_TABLE[i] = round(literature[i] · g)` for
  `g ∈ {0.25, 0.5, 0.75}` (1.0 = stage 1). Highest-leverage knob; sweep first.
- **Coarse multiplier sweep** only if `g`-alone is insufficient: e.g. `{1/1/2/3, 2/2/3/4, 3/3/4/5}`.
- **Do NOT** tune the 100 individual entries (no signal at corpus scale; keep the literature
  *shape*, deflation is the lever — roadmap "What NOT to tune").

Each cell reuses this unit's test scaffolding (re-pin the table-value test + bench). No new code.

## 7. ADR-0038 content outline

- **Decision:** activate the king-safety attacker S-curve to literature CPW defaults (stage 1);
  realize stage 2 (if needed) as pre-scaled-table grid data edits, not a runtime gain knob; defer
  the SPSA harness.
- **Why now:** M6.J STS King Activity 555 / AKPC 628 — largest residual classical-eval gap;
  structurally untunable by the quiet-corpus Texel pipeline (ADR-0037 §3); gate is open
  post-M6.J-ship.
- **Faithfulness note:** activation keeps the Texel §7 cross-check green by construction (reference
  scorer recomputes from the same frozen fields); S-curve stays excluded from the tuned core.
- **Verdict ladder** (vs `M6.J`, mirrors ADR-0037 §9): rung-1 CI lower ≥ 5 → ship + tag `M6.K`;
  rung-2 mean ≥ 5 ∧ CI lower > −10 → ship + retro note; rung-3 mean ≥ 0 ∧ CI lower > −10 → ship +
  caveat; rung-4 (mean < 0 ∨ CI lower ≤ −10) → **revert the activation** (back to zeroed), M6.K
  closes negative, recommend SPSA follow-up. **"Revert" target is the zeroed M6.J state** (there is
  no other production value to revert to).
- **STS sub-gates:** primary King Activity (555 → expected lift); secondary AKPC (628 → expected
  flat-to-modest). Strong-negative King Activity with flat SPRT = should-fix (M6 §297 rule).
- **Pre-NNUE decay:** M12 obsoletes all classical king-safety weights; stage 2 not worth heavy
  tuning if stage 1 doesn't pay.

## 8. Order of operations

1. **Tests first (TDD).** Add the new tests (§5 #1–#5) and re-pin a *placeholder* bench value;
   tests #1–#4 FAIL against the still-zeroed data (table-value/multiplier pins fail; the
   negative-penalty anchor fails). Test-suite review loop on the test diff.
2. **Flip the constants** in `data.rs` → tests #1–#5 + all symbolic tests pass.
3. **Build + bench** → read the real depth-4 node count → set `M6K_DEPTH4_BENCH_NODES`.
4. **Mechanical checks** (fmt / clippy / `cargo test --release` / llvm-cov / `cargo mutants
   --in-diff`). Note: the S-curve data is **excluded from cargo-mutants** already
   (`.cargo/mutants.toml`, "data constants not logic"); confirm the activation didn't move any
   *logic* into the diff (it shouldn't — data only). Triage survivors.
5. **Final review loop** (code + tests jointly).
6. **Bench record + WAC/STS diagnostic** vs `M6.J` (eval changed ⇒ required; both run ALONE).
   Record King Activity / AKPC deltas — the STS sub-gates ADR-0038 commits to.
7. **Docs/ADR** (§3 doc files).
8. **Commit the candidate** ("M6.K: candidate king-safety S-curve activated; stage-1 SPRT vs M6.J
   pending"), push. **Hand off** the stage-1 SPRT command to the operator.

## 9. Strength-validation handoff (operator-run)

WAC + STS diagnostics run in-session (deterministic, minutes, ALONE). The **stage-1 SPRT** is the
gate and is operator-run (~10 h):

```sh
# mixed-TC + virtual-clock SPRT, candidate (working-tree HEAD) vs M6.J baseline tag
scripts/sprt.sh sprt M6.J            # elo0=0 / elo1=5 (marginal-change bounds) per ADR-0037
# (mixed-TC --tc-sample + --virtual-clock per docs/workflow.md "Mixed-TC SPRT")
```

The operator applies the §7 / ADR-0038 verdict ladder to `summary.txt`'s `ci:` line and either
tags `M6.K` (ship) or reverts (rung-4) → then stage 2.

## 10. Parallelization map

Small unit; mostly sequential (data → tests-pass → bench depends on build). Genuine parallelism:

- **Concurrent:** the doc/ADR writing (§3 doc files) can run on a separate agent while the
  code+tests land — they share no code surface.
- **Sequential (one coding agent):** tests (#5) → flip constants → bench re-pin → mechanical checks.
  The bench re-pin depends on the built binary; tests depend on the data values. Not worth splitting
  across coding agents.

Honest assessment: **near-sequential**; the only safe fan-out is docs ∥ code, and even that is
"**draft concurrently, finalize sequentially**" — the ADR's faithfulness note and m6.k.md's
verdict-ladder/bench references depend on facts the code agent establishes (exact activated values,
recomputed bench number), so the doc agent drafts structure concurrently but reconciles those
references after the bench re-pin lands. Not fully independent.

## 11. Dependencies / risks

- **Dep:** `M6.J` ship complete (done 2026-05-29 — gate open).
- **Risk (expected, documented):** the M6.E HIGH transfer-risk double-count (PeSTO MG king PST
  already prices castled-king safety) may make stage 1 H0/regress. That is a *documented outcome*,
  not a failure of this unit — it routes to stage 2. The unit's job is to land a clean, correct,
  reviewable candidate + the SPRT handoff, not to guarantee a positive verdict.
- **Risk (low, but a stage-2 prerequisite):** `bench/m6-params.json`'s frozen S-curve fields still
  read zero (generated pre-activation). For stage 1 this is harmless — `texel-tune apply` never
  writes the S-curve (no marker, not in `const_value_map`), so a future re-apply preserves the
  activated table, and the §7 golden reads `EvalParams::shipped()` from `data.rs` (not the JSON) so
  it stays green. **But** the on-disk JSON becomes a stale shadow of the live constants, which would
  mislead a hand-inspection. **Mandate:** regenerate `bench/m6-params.json` (so its frozen S-curve
  fields match the activated `data.rs`) as part of this unit if cheap; otherwise record it as an
  **explicit prerequisite in m6.k.md before any stage-2 re-apply** (not merely an "optional nit"),
  so a stage-2 operator does not re-apply zeroed params over the activated table.
