# M5.H1 — Staged movegen (architecture refactor, bench-neutral)

**Plan unit.** `M5.H1`. Introduces a `MoveStager` type that yields the negamax move sequence in five stages (TT → captures → killer 0 → killer 1 → quiets), replacing the monolithic `order_moves` + `for mv in moves_vec` pattern at the negamax move loop. **All moves are still generated and sorted eagerly at construction**: this is a pure architectural refactor with bench parity as the verification gate. M5.H2 will flip generation to lazy and is the SPRT-gated unit.

**Predecessor.** `M5.G` (M5.G v2 retune landing commit, tagged 2026-05-10).

**Research.** [`docs/research/m5-staged-movegen.md`](../research/m5-staged-movegen.md). Headlines: stage order TT → captures (MVV-LVA) → killer 0 → killer 1 → quiets (history); typed-validate-or-membership-scan for TT and killer slots; H1/H2 split is the literature-supported path because lazy generation changes history-score timing and therefore node counts (research §15.6, §16.4); SE excluded-move stays at the caller side per M5.G's existing design (research §12.2 Option B); qsearch out of scope (research §13).

**Expected size.** ~600 LOC including tests + ADR + retrospective.

**Expected Elo.** **Zero by design.** H1 produces the byte-equivalent move sequence that today's `order_moves` + iteration produces, so node counts, bench signature, and strength are unchanged. The bench-parity check is the empirical no-regression gate; a defensive 50-pair confirmation match is run as cheap insurance (see §11).

## §1. Scope and non-goals

**In scope.**
- New `MoveStager` struct in `src/search.rs` exposing `new`, `next`, `peek`, `len`, `is_empty`. Stage-aware design with five stages; eager generation at construction; iteration via `next() -> Option<Move>`.
- The `searchmoves` filter is folded into `new()` as a constructor parameter (`Option<&[Move]>`) so the stager has no temporal coupling between filter and `next()`. No separate `retain_root_filter` method.
- Replace the negamax move-loop body's call sequence (`generate_moves` → `moves_vec.retain(searchmoves)` → `order_moves` → `for (i, &mv) in moves_vec.iter().enumerate()`) with `MoveStager::new` + `while let Some(mv) = stager.next()` plus an explicit position counter for `i`.
- Pure helpers (each its own mutation-discrimination surface): `extract_move_by_bits`, `extract_move_by_eq`, `partition_captures_quiets`, `mvv_lva_sort_in_place`, `history_sort_in_place`. Per the M3.D `negate_window` / M5.C `late_move_reduction` / M5.D `ffp_pruned_bound` precedent.
- Wire `stager.peek()` into the M5.G SE block in place of `moves_vec[0]`.
- Wire `stager.is_empty()` into the step-11 terminal-check in place of `moves_vec.is_empty()`.
- ADR-0030 (outline in §2.1).
- Bench refresh (must equal M5.G's `1147614 nodes` exactly); E51 depth-4 pin (must equal `89_080`); extended perft sweep per the movegen-adjacent gate (canonical_six_d4_heavy_slow, canonical_six_d5_slow, whittington_epd_d4_slow); 50-pair defensive SPRT confirmation match.

**Out of scope (deferred to M5.H2 or later).**
- **Lazy generation** — captures and quiets are still generated up-front in `MoveStager::new`. Lazy generation (deferring `generate_moves` until the stage is reached, and skipping it entirely on early cutoff) is M5.H2's surface. H1 is *only* the architectural restructuring.
- **Typed TT-move validation** without a generated list. H1 looks up the TT move in the already-generated legal list (the same approach today's `order_moves` uses at `src/search.rs:2906`). H2 may switch to a typed validator if/when lazy generation requires it.
- **SEE split** of captures into good (≥0) and bad (<0). MVV-LVA only at H1 and H2.
- **Countermoves stage.** Research §17 recommends leaving room in the stage enum (`CounterMove` between `Killer1` and `GenerateQuiets`); per `CLAUDE.md` "Don't design for hypothetical future requirements," **we do not add it now**. M6+ will introduce the stage when countermoves are implemented.
- **Selection-sort within stages.** Both capture and quiet stages use `sort_by_cached_key` (today's pattern). Selection sort is a future micro-optimization.
- **Qsearch stager.** Qsearch keeps its current `sort_by_cached_key` + TT-promotion pattern unchanged. Research §13.3 advises against type-sharing.
- **Deletion of `order_moves` from production AND test surface.** §1.1 below: `order_moves` is demoted to `#[cfg(test)]` so its 14 existing test call sites continue to function as the score-tier-discipline pin.

### §2.1 ADR-0030 outline

ADR-0030 follows the M5.G ADR-0029 precedent. Sections:

- **§1 Context.** Today's negamax move-loop conflates ordering (`order_moves`'s monolithic sort) with iteration. Cutoff-skip economy (the staged-movegen Elo signal) requires per-stage generation, but per-stage generation changes history-score timing; the literature splits this into refactor-first / lazy-second.
- **§2 Decision.** Introduce `MoveStager` as the iterator. H1: eager generation at construction; bench-equivalent yield order. H2 (separate unit): lazy per-stage generation; SPRT-gated.
- **§3 Stage taxonomy.** Five stages: TT → captures → killer 0 → killer 1 → quiets. No countermove stage; no SEE split.
- **§4 Legality discipline.** Membership-scan (lookup in legal-move list) for TT and killers — no typed `is_pseudo_legal` validator at H1. H2 may revisit if lazy generation needs the typed path.
- **§5 SE interaction.** `stager.peek()` replaces `moves_vec[0]`. The peek-stability invariant (idempotent under non-mutation) is load-bearing for the SE block's double-call.
- **§6 Position counter.** The move-loop's `i` becomes `cur_i` from an explicit counter that preserves M5.G's "skip increments position" semantics on the excluded-move skip.
- **§7 Consequences.** Bench parity is the no-regression gate; H1 is SPRT-exempt by design (no claimed strength change). A defensive 50-pair confirmation match is run as belt-and-suspenders.
- **§8 Open questions deferred.** Typed TT/killer validators; SEE split; countermove stage; selection-sort within stages.
- **§9 References.** Research note; CPW Move Ordering / Move List; TalkChess t=76835.

## §3. The `MoveStager` type and API

```rust
/// M5.H1 — stage-aware iterator over the negamax move sequence.
///
/// Yields, in order:
///   1. TT move (if `tt_move != 0` and a move with matching bits exists in
///      the post-`searchmoves`-filter legal-move list).
///   2. Captures (and queen promos) sorted MVV-LVA descending, with the TT
///      move excluded if it was a capture.
///   3. Killer slot 0 (if non-zero, present in the post-filter legal-quiets
///      set, and not equal to the TT move).
///   4. Killer slot 1 (if non-zero, present in the post-filter legal-quiets
///      set, and not equal to either the TT move or killer 0).
///   5. Remaining quiets sorted by history score descending, with the TT
///      move and both killers excluded.
///
/// **H1 generation discipline.** All moves are generated by a single
/// `generate_moves` call at construction. The stager partitions and sorts
/// into stages but does not defer generation. M5.H2 will change this to
/// lazy per-stage generation; the public API stays the same.
///
/// **Lifetime.** `MoveStager` is `'static`-data: `pos: &Position` and
/// `history: &HistoryTable` are read in `new()` and not retained. No
/// lifetime parameter; `Send` by construction (only `Move` and `Vec<Move>`
/// fields).
pub(crate) struct MoveStager {
    tt: Option<Move>,
    captures: Vec<Move>,    // MVV-LVA-desc; TT excluded if capture
    k0: Option<Move>,       // None if invalid/dup/filtered-out
    k1: Option<Move>,       // None if invalid/dup/filtered-out
    quiets: Vec<Move>,      // history-desc; TT, k0, k1 excluded
    stage: Stage,
    cap_idx: usize,
    quiet_idx: usize,
    /// Total move count yielded over the stager's full lifetime
    /// (TT present + captures + k0 present + k1 present + quiets).
    /// Computed at construction, immutable afterward. Read by `len()`,
    /// `is_empty()`. NOT decremented by `next()` — the temporal contract
    /// is "pre-iteration count" (see §3.1).
    total_len: usize,
}

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
enum Stage {
    Tt,
    Captures,
    Killer0,
    Killer1,
    Quiets,
    Done,
}

impl MoveStager {
    /// Eagerly generate, optionally apply searchmoves filter, partition,
    /// and sort the legal-move list at `pos`.
    ///
    /// `tt_move == 0` → no TT yield. `killer{0,1}.bits() == 0` → that
    /// slot is unset (the `Move::default()` sentinel — `Move::default()`
    /// is constructed at `(a1, a1, Quiet)` and is NEVER produced by
    /// `generate_moves`, so the membership lookup naturally rejects it).
    /// `searchmoves_filter == None` → no filter (typical at ply > 0);
    /// `Some(&[])` → empty filter (yields zero moves; the negamax caller
    /// short-circuits to `return 0` per `src/search.rs:1700` semantics).
    /// `Some(&[m1, m2, ...])` → only retain those moves at every stage.
    pub(crate) fn new(
        pos: &Position,
        killer0: Move,
        killer1: Move,
        history: &HistoryTable,
        tt_move: u16,
        searchmoves_filter: Option<&[Move]>,
    ) -> Self;

    /// Advance one move. Returns `None` once `Stage::Done` is reached.
    /// The yielded sequence is byte-equivalent to today's
    /// `moves_vec.retain(filter); order_moves(...); moves_vec.iter()` order.
    pub(crate) fn next(&mut self) -> Option<Move>;

    /// Return what `next()` would yield without advancing.
    ///
    /// **Idempotency invariant.** `peek()` reads `self.stage` plus the head
    /// of the current stage's `Option<Move>` or slice element without
    /// advancing any state. Calling `peek()` N consecutive times returns
    /// the same `Option<Move>` value. This is load-bearing for the M5.G
    /// SE block, which calls `peek()` twice (once in the gate predicate,
    /// once in the verification call's `excluded_move` argument).
    /// Receiver is `&self` (not `&mut self`) — type-enforced.
    pub(crate) fn peek(&self) -> Option<Move>;

    /// Total number of moves the stager will yield over its full lifetime,
    /// from construction. **Temporal contract**: this value is the
    /// pre-iteration count and does NOT decrement as `next()` advances.
    /// `is_empty()` is therefore meaningful only before any `next()` call.
    /// The negamax move loop calls `is_empty()` exactly once, at the
    /// step-11 terminal check, satisfying the contract.
    pub(crate) fn len(&self) -> usize;

    /// `true` iff `len() == 0`. Same temporal contract as `len()`.
    pub(crate) fn is_empty(&self) -> bool;

    /// Test-only: materialize the full yield sequence by repeatedly calling
    /// `next()` on a clone. Used by the H1-P1 equivalence proptest.
    #[cfg(test)]
    pub(crate) fn yield_sequence(&self) -> Vec<Move>;
}
```

The stager is `Send` and stores no references after construction.

### §3.1 The `total_len` temporal contract

`total_len` is computed eagerly in `new()` from the post-filter `tt.is_some() + captures.len() + k0.is_some() + k1.is_some() + quiets.len()`. After construction, `len()` and `is_empty()` are valid only **before any `next()` call**. The implementation does NOT decrement `total_len` on `next()`. Callers must not call `is_empty()` mid-iteration; the negamax move loop honors this (single call at step 11, before the loop starts).

This is documented in §3 and pinned by `H1-S17` (post-iteration `len()` returns the original total, not zero).

**`MoveStager` does NOT implement `Iterator`.** Standard Rust `ExactSizeIterator::len()` decrements as items are yielded, which would conflict with the temporal contract above. Keeping `MoveStager` as a custom type with explicit `next()` / `peek()` methods (rather than `impl Iterator for MoveStager`) avoids this surprise. Future H2 / consumers of the stager should NOT add an `Iterator` impl without re-evaluating the `len()` semantic.

## §4. Construction algorithm

In pseudo-Rust (real implementation in `src/search.rs`):

```rust
pub(crate) fn new(
    pos: &Position,
    killer0: Move,
    killer1: Move,
    history: &HistoryTable,
    tt_move: u16,
    searchmoves_filter: Option<&[Move]>,
) -> Self {
    // Step A. Eager full generation. Same MoveList path as today.
    let mut ml = MoveList::new();
    generate_moves(pos, &mut ml);
    let mut all: Vec<Move> = ml.iter().collect();

    // Step B. Apply searchmoves filter (root-only; None at non-root).
    //   Mirrors today's `moves_vec.retain(|m| filter.contains(m))` at
    //   src/search.rs:1691, applied BEFORE order_moves.
    if let Some(filter) = searchmoves_filter {
        all.retain(|m| filter.contains(m));
    }

    // Step C. Extract TT move from filtered legal list (lookup by bits).
    //   Mirrors today's order_moves @ src/search.rs:2906:
    //     moves_vec.iter().position(|m| m.bits() == tt_move)
    //   `extract_move_by_bits` is order-preserving (Vec::remove).
    //   `tt_move == 0` returns None without scanning.
    let tt = extract_move_by_bits(&mut all, tt_move);

    // Step D. Partition into captures and quiets, manually for explicit
    //   order-preservation guarantee (instead of relying on undocumented
    //   stability of Iterator::partition).
    let mut captures: Vec<Move> = Vec::with_capacity(all.len());
    let mut quiets: Vec<Move> = Vec::with_capacity(all.len());
    for m in all {
        if is_quiet(m) {
            quiets.push(m);
        } else {
            captures.push(m);
        }
    }

    // Step E. Extract killer slots from quiets (full Move equality).
    //   Killers are quiets-only by ADR-0019; defensive: treating any
    //   non-quiet killer slot as "no killer" by routing through the
    //   quiets-only Vec. The `bits() == 0` guard rejects the
    //   Move::default() sentinel without scanning.
    let k0 = if killer0.bits() != 0 {
        extract_move_by_eq(&mut quiets, killer0)
    } else {
        None
    };
    let k1 = if killer1.bits() != 0 && killer1 != killer0 {
        extract_move_by_eq(&mut quiets, killer1)
    } else {
        None
    };

    // Step F. Sort captures MVV-LVA-desc; sort quiets history-desc.
    //   Both stable (sort_by_cached_key); within-tier movegen-order
    //   tiebreak preserved, matching today's monolithic-sort behavior.
    mvv_lva_sort_in_place(&mut captures, pos);
    history_sort_in_place(&mut quiets, pos, history);

    // Step G. Cache the total length.
    let total_len =
        tt.is_some() as usize
            + captures.len()
            + k0.is_some() as usize
            + k1.is_some() as usize
            + quiets.len();

    Self {
        tt, captures, k0, k1, quiets,
        stage: Stage::Tt,
        cap_idx: 0,
        quiet_idx: 0,
        total_len,
    }
}
```

### §4.1 Bench-equivalence proof (per-case)

Today's `order_moves` performs ONE sort by `negamax_move_order_score` over the full vector, then promotes TT to index 0 via `Vec::remove(idx)` + `insert(0, ...)`. The stager partitions before sorting. We argue equivalence by case analysis. For all cases below, assume `searchmoves_filter` is `None` (the filter case reduces to the no-filter case on a smaller legal-move list — same arguments apply post-filter).

**Notation.** Let `L` be the legal-move list in `generate_moves`-emit order. Let `s(m) = negamax_move_order_score(m, pos, k0, k1, history)`.

**Case 1 — `tt_move == 0`, no killers.** Today: full sort of `L` by `s(m)` desc; no TT promotion. Stable sort puts captures (high `s` via `CAPTURE_OFFSET`) first in MVV-LVA-desc order, then quiets in history-desc order. Stager: TT extraction returns `None`; killers extraction returns `None`; captures + quiets are `L` partitioned, then sorted within each. **Equivalent**: captures in MVV-LVA-desc order, quiets in history-desc order, both with stable movegen-order tiebreaks.

**Case 2 — `tt_move != 0`, TT in `L`, TT is a capture, no killers.** Today: full sort places captures (including TT) first in MVV-LVA-desc; promotion moves TT to index 0. The remaining captures (originally at higher MVV-LVA than TT, or tied with TT and earlier in movegen-order) shift down by one but their relative order is preserved by the order-preserving `Vec::remove` + `insert(0, ...)`. Stager: TT extracted (order-preserving) from `L`; remaining captures partitioned out, sorted MVV-LVA-desc. The captures sort sees `L`-minus-TT in original movegen-order (because partition preserves order); after sort, they are MVV-LVA-desc with movegen-order tiebreak. **Equivalent**: same captures in same MVV-LVA-desc order behind the TT move.

**Case 3 — TT in `L`, TT is a capture tied (same MVV-LVA score) with another capture C2 that is earlier in movegen-order.** Today: stable sort places C2 before TT. Promotion moves TT to index 0; C2 ends up at index 1. Stager: TT extracted; C2 is in the captures partition; sort places C2 first (stable, movegen-order tiebreak). Yield: TT, C2, ... **Equivalent**: TT yielded first, C2 next.

**Case 4 — TT in `L`, TT is a quiet, killer0 == TT.** Today: `negamax_move_order_score` returns `KILLER0_SCORE` for TT (because `mv == killer0` matches). Pre-promotion sorted order: `[captures, TT (KILLER0_SCORE), killer1 (if distinct), history-quiets]`. Promotion (`Vec::remove(idx_TT) + insert(0, TT)`) shifts all elements at indices `[0, idx_TT)` rightward by one — captures and killer1 retain their relative order. Post-promotion: `[TT, captures, killer1, history-quiets]`. Stager: TT extracted from `all`; killer0 extraction (== TT) finds nothing in quiets (TT already removed); k0 = None. Killer1 extracted iff `killer1 != killer0` (= TT) and present. Quiets sorted history-desc. Yield: `TT, captures, killer1, history-quiets`. **Equivalent.**

**Case 5 — TT in `L`, TT is a quiet (distinct from both killers), killer0 + killer1 both quiet and present.** Today: pre-promotion sort places `[captures, killer0 (KILLER0_SCORE), killer1 (KILLER1_SCORE), history-quiets-including-TT]`. TT (a non-killer quiet) sits in the history-quiets band at whatever index its history score dictates. Promotion: `Vec::remove(idx_TT) + insert(0, TT)` is **order-preserving for all elements not at the moved index** — captures, killer0, killer1, and the history-quiets above and below TT all retain their stable-sorted relative positions, just shifted rightward by one for indices `[0, idx_TT)`. Post-promotion: `[TT, captures, killer0, killer1, history-quiets-minus-TT]`. Stager: TT extracted; killers extracted from quiets (still present, both ≠ TT); quiets sorted history-desc. Yield: `TT, captures, killer0, killer1, history-quiets-minus-TT`. **Equivalent.**

**Case 5b — TT in `L`, TT is a quiet, distinct from both killers, AND TT happens to be the highest-history-score quiet.** Today: same as Case 5; TT sits in the history-quiets band at the top by virtue of its history score, but the score-tier discipline still places killers (KILLER0/1_SCORE) above it. Pre-promotion: `[captures, killer0, killer1, TT (top of history-quiets), other-history-quiets]`. Promotion to index 0 produces `[TT, captures, killer0, killer1, other-history-quiets]`. Stager: TT extracted; quiets sorted history-desc with TT removed → `[other-history-quiets in history-desc]`. Yield: `TT, captures, killer0, killer1, other-history-quiets`. **Equivalent** — the stager's quiet stage produces the same `other-history-quiets` order regardless of whether TT was originally the top history-quiet.

**Case 6 — TT not in `L` (collision/stale), killer0 present.** Today: `position(|m| m.bits() == tt_move)` finds nothing; promotion is a no-op; sort order remains. First move is the highest-scoring move (capture if any, else killer0). Stager: TT extraction returns `None` (lookup miss). First yield from captures (if any) or killer0. **Equivalent.**

**Case 7 — `tt_move == 0`, killer0 == killer1 (slot dedup at update time should prevent this, but defense-in-depth).** Today: both score `KILLER0_SCORE` and `KILLER1_SCORE` respectively, but only one move matches (since they're equal); the comparator returns `KILLER0_SCORE` first (the `if mv == killer0` arm), `KILLER1_SCORE` only fires for moves *not* equal to killer0. So one move scores `KILLER0_SCORE`, no other scores `KILLER1_SCORE`. Stager: `extract_move_by_eq(quiets, killer0)` extracts; the `killer1 != killer0` guard short-circuits k1 extraction. **Equivalent.**

**Case 8 — `searchmoves_filter` excludes the TT move.** Today: `retain` removes TT before `order_moves`; `position` finds nothing; no promotion. Stager: filter applied at Step B before TT extraction; TT extraction lookup misses; tt = None. First yielded move is the highest-scoring filtered legal move. **Equivalent.** Test: `H1-I5`.

**Case 9 — `searchmoves_filter` is `Some(&[])` (empty filter).** Today: post-`retain`, `moves_vec.is_empty()`; the negamax `if ply == 0 && ctx.limits.searchmoves.is_some() { return 0; }` at `src/search.rs:1700` short-circuits. Stager: filter applied to empty all; total_len = 0; `is_empty()` returns true; the negamax block at step 11 routes to the same `return 0`. **Equivalent** (driven by negamax, not by stager internals; stager just reports the empty state).

These nine cases cover the cross-product of `{tt_move == 0, tt-in-L, tt-stale}` × `{tt-is-capture, tt-is-quiet, tt-equals-killer0}` × `{filter-none, filter-excludes-tt, filter-empty}` modulo non-meaningful combinations. The H1-P1 proptest in §8 is the broader machine check over `arb_position()`.

## §5. Negamax integration

Replace the existing block at `src/search.rs:1682-1726` (current steps 10-12: `generate_moves` → searchmoves filter → empty check → killer reads → `order_moves`) with the stager construction:

// 10-12. Construct the stager. Eagerly generates, partitions, and sorts.
//        searchmoves filter folded into new() — root-only.
let killer0 = self.killers[ply as usize][0];
let killer1 = self.killers[ply as usize][1];

    ctx.limits.searchmoves.as_deref()
} else {

};
let mut stager = MoveStager::new(
    pos,
    killer0,
    killer1,
    &self.history_table,
    tt_move,
    searchmoves_filter,
);

// 11. Terminal: no legal moves (post-filter).
if stager.is_empty() {

## §6. Pure helpers

Each free function, placed alongside `is_quiet`, `update_killers`, etc. in the helper block ~`src/search.rs:2790+`. Mutation tests target each by name. All take `&mut Vec<Move>` (not `&mut [Move]`) for signature consistency with `extract_move_by_*`; the `sort_by_cached_key` slice-method is reachable through deref-coercion.

```rust
/// Remove and return the first move in `v` whose `bits()` equal `target`.
/// `Vec::remove` (O(N), order-preserving) — chosen over `swap_remove` so
/// post-removal element order matches today's `order_moves` semantics
/// (captures and quiets in their movegen-emit order, then sorted).
/// `target == 0` returns `None` without scanning, matching today's
/// `tt_move != 0` guard at order_moves (`src/search.rs:2905`).
fn extract_move_by_bits(v: &mut Vec<Move>, target: u16) -> Option<Move> {
    if target == 0 { return None; }
    let idx = v.iter().position(|m| m.bits() == target)?;
    Some(v.remove(idx))
}

/// Same as `extract_move_by_bits` but compares against a full `Move`
/// (flag bits included). Used for killer-slot extraction.
fn extract_move_by_eq(v: &mut Vec<Move>, target: Move) -> Option<Move> {
    let idx = v.iter().position(|&m| m == target)?;
    Some(v.remove(idx))
}

/// Partition `all` into `(captures, quiets)` by `is_quiet`. Manual
/// implementation rather than `Iterator::partition` to make the
/// order-preservation guarantee explicit. Within each output Vec, original
/// movegen-emit order is preserved.
fn partition_captures_quiets(all: Vec<Move>) -> (Vec<Move>, Vec<Move>) {
    let mut captures: Vec<Move> = Vec::with_capacity(all.len());
    let mut quiets: Vec<Move> = Vec::with_capacity(all.len());
    for m in all {
        if is_quiet(m) { quiets.push(m); } else { captures.push(m); }
    }
    (captures, quiets)
}

/// MVV-LVA-desc stable sort. Stable within ties (movegen-order preserved).
/// Same comparator as today's negamax_move_order_score's non-quiet arm,
/// modulo CAPTURE_OFFSET (irrelevant within a captures-only slice).
fn mvv_lva_sort_in_place(captures: &mut Vec<Move>, pos: &Position) {
    captures.sort_by_cached_key(|&m| -mvv_lva_score(m, pos));
}

/// History-score-desc stable sort over a slice of quiet moves.
/// Same comparator as today's negamax_move_order_score's history arm.
fn history_sort_in_place(quiets: &mut Vec<Move>, pos: &Position, history: &HistoryTable) {
    let stm = pos.side_to_move();
    quiets.sort_by_cached_key(|&m| -(history.score(stm, m.from_square(), m.to_square()) as i32));
}
```

There is no `is_killer_legal_in_position` typed validator at H1 — killer legality is established by membership (`extract_move_by_eq` finds the killer in the quiets Vec iff a legal quiet move with matching bits exists). Today's behavior is the same (the killer's score in `negamax_move_order_score` only fires when `mv == killer0` for some `mv` in the legal list).

## §10. Mutation-coverage strategy

Per `cargo mutants --in-diff`. Three mutant categories:

**Pure-helper mutants** (H1-H1..H10 cover): mutating `extract_move_by_bits` / `extract_move_by_eq` / `partition_captures_quiets` / `mvv_lva_sort_in_place` / `history_sort_in_place` is detected by direct unit tests on each.

**Stager-construction mutants** (H1-S1..S19 + H1-P1 cover): mutating stage order / dedup conditions / total_len arithmetic / Stage enum transitions. The H1-P1 proptest at 2048 cases is the broad backstop — any stager bug producing a different yield sequence than `order_moves` is caught with high probability.

**Integration-site mutants** (H1-I1..I6 cover):
- `cur_i = i; i += 1` — off-by-one mutant kills via H1-I4b (skipped move increments cur_i).
- `i += 1; let cur_i = i` (swap) — different SE-frame-first-move PV semantics; H1-I4 assertion catches.
- `let mut i = 0;` → `let mut i = 1;` — `child_is_pv` and `move_extension` lose their `cur_i == 0` triggers (TT move searched without SE extension and without PV propagation). Direct catch surface: `H1-B1` bench-parity (SE-eligible nodes lose the +1-ply extension, depth-7 bench node count drifts) and the existing PV-propagation tests on the M5.G fixtures.
- `if Some(mv) == excluded_move { continue; }` → `if Some(mv) != excluded_move { continue; }` — flips SE skip; verification frame would skip ALL moves; `se_extensions == 0` regression; H1-I3 catches.
- `stager.peek().map_or(0, ...)` → `stager.peek().map_or(1, ...)` — false-positive SE gate; H1-I6 catches via stale-TT non-fire.
- `Some(stager.peek().expect(...))` → `None` — verification's excluded-move missing; SE block enters infinite recursion (verification doesn't exclude TT, sees same TT-cut, returns same score, no extension); H1-I3 catches via expected `se_extensions == 1` for fixture position.

**Expected survivors** (triaged at landing per "equivalent / structurally undetectable / catchable" classification):
- Within-tier stable-sort tiebreak: `sort_by_cached_key` → `sort_unstable_by_cached_key`. The proptest H1-P1 should distinguish on positions where movegen-order matters for ties.
- `total_len` arithmetic equivalence: `tt.is_some() as usize + ...` ≡ `1 - tt.is_none() as usize + ...`. Equivalent mutants; document via `exclude_re` if surfaced.
- `Vec::with_capacity(all.len())` capacity arithmetic: micro-allocation tuning; behaviorally invisible.
