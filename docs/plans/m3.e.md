# M3.E — Iterative deepening + time management

Wraps M3.C/M3.D's negamax + qsearch in an iterative-deepening (ID) outer loop with soft/hard time-cap discipline. Adds a `MoveOverhead` UCI option for latency hedging and a prior-iteration root-PV ordering hint. **ADR-0017** lands here, codifying the time-management formulas.

Research already covers every headline call: `docs/research/m3-time-management.md` (algorithm + test table) and `docs/research/m3-search-basics.md` §6 (ID outer-loop discipline). No additional research needed.

## 0. Goals

- `compute_caps(&SearchLimits, Color, move_overhead) -> TimeCaps` pure function, mocked-clock-testable, returns soft+hard `Duration`s. `Duration::MAX` for non-time-bounded searches (`infinite`, `depth N`, `nodes N`, `mate N`, no-clock).
- ID outer loop in `AlphaBetaMover::go`: iterate `for d in 1..=max_depth`, abort between iterations when `elapsed >= soft_cap`, abort mid-iteration via `should_abort` when `elapsed >= hard_cap`.
- Mid-iteration aborts discard partial result; reported bestmove/score/PV come from the **last fully completed** iteration.
- `prior_root_move: Option<Move>` field on `AlphaBetaMover`, set after each completed iteration; consumed by negamax at `ply == 0` to reorder the root move list (prior-iteration best tried first, rest in MVV-LVA order).
- `MoveOverhead` UCI option (`spin default 50 min 0 max 5000`) emitted in `handle_uci`, parsed in `handle_setoption`, stored in `Engine::move_overhead: u64`, threaded into `compute_caps`.
- Per-iteration `info` line emission (one per completed iteration) instead of M3.D's single line at end.
- ADR-0017 codifies the formulas + ID discipline + MoveOverhead option.

## 3. Type definitions

### 3.1 `TimeCaps`

```rust
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub(crate) struct TimeCaps {
    /// "Don't start the next ID iteration past this point." `Duration::MAX` ⇒ no soft cap.
    pub soft: Duration,
    /// "Abort the current iteration immediately past this point." `Duration::MAX` ⇒ no hard cap.
    pub hard: Duration,
}
```

**The "no cap" sentinel is `Duration::MAX` exactly** — `Duration::new(u64::MAX, NANOS_PER_SEC - 1)`. Tests asserting "no cap" must use `Duration::MAX` as the literal; `Duration::from_millis(u64::MAX)` is a different value, and `Duration::from_secs(u64::MAX)` panics on overflow. Wiring code that builds `Instant`s from caps (§7.4) MUST guard with `(caps.soft != Duration::MAX).then(|| now + caps.soft)`; otherwise `now + Duration::MAX` overflows the `Instant` arithmetic.

### 3.2 `SearchContext` extension

Add one field:

```rust
pub struct SearchContext {
    // ... existing fields ...
    /// ID-loop soft deadline. Polled BETWEEN iterations only; `should_abort`
    /// is unchanged (it remains the hard-cap check). `None` ⇒ no soft cap.

}
```

`SearchContext::should_abort` is **unchanged** — it polls only the hard-cap path (`stop` / `deadline` / `nodes`). The ID-loop checks `soft_deadline` directly via `Instant::now() >= soft` between iterations.

## 4. `compute_caps` body

```rust
pub(crate) fn compute_caps(
    limits: &SearchLimits,
    side_to_move: Color,
    move_overhead: u64,
) -> TimeCaps {
    // Non-time limits → no cap.
    if limits.infinite
        || limits.ponder
        || limits.depth.is_some()
        || limits.nodes.is_some()
        || limits.mate.is_some()
    {
        return TimeCaps { soft: Duration::MAX, hard: Duration::MAX };
    }

    // movetime overrides clock-based: soft = hard = movetime - move_overhead.
    if let Some(mt) = limits.movetime {
        let v = (mt.max(0) as u64).saturating_sub(move_overhead).max(1);
        let d = Duration::from_millis(v);
        return TimeCaps { soft: d, hard: d };
    }

    // Clock-based.
    let (rem_signed, inc_opt) = match side_to_move {
        Color::White => (limits.wtime, limits.winc),
        Color::Black => (limits.btime, limits.binc),
    };
    let Some(rem_signed) = rem_signed else {
        // No movetime, no clock — degenerate `go` with no time information.
        // Treat as infinite (matches `go infinite` shape).
        return TimeCaps { soft: Duration::MAX, hard: Duration::MAX };
    };

    let rem = rem_signed.max(0) as u64;
    let inc = inc_opt.unwrap_or(0);

    // Very-low-time floor: when both clock and increment are zero (or negative
    // clock + zero increment), emit immediately from the first completed iteration.
    if rem == 0 && inc == 0 {
        let d = Duration::from_millis(1);
        return TimeCaps { soft: d, hard: d };
    }

    let denom: u64 = match limits.movestogo {
        None => 20,           // sudden death (research §5: conservative N=20)
        Some(0) => 1,         // spec violation; defensive fallback (research §1.3)
        Some(n) => n as u64,  // classical TC
    };

    let raw_soft = rem / denom + inc / 2;
    let soft_unclamped = raw_soft.saturating_sub(move_overhead);

    // Increment-only TC (rem == 0 with inc > 0): forfeit guard does NOT apply,
    // because the increment refills the clock after the move (research §5
    // special case). Hard = 3 × soft, no max-clamp.
    if rem == 0 {
        let soft = Duration::from_millis(soft_unclamped.max(1));
        let hard = Duration::from_millis(soft_unclamped.saturating_mul(3).max(1));
        return TimeCaps { soft, hard };
    }

    // Forfeit guard: soft and hard both clamped to (rem - move_overhead).max(1).
    let max_clamp = rem.saturating_sub(move_overhead).max(1);
    let soft_ms = soft_unclamped.min(max_clamp).max(1);
    let hard_ms = soft_ms.saturating_mul(3).min(max_clamp).max(1);
    TimeCaps {
        soft: Duration::from_millis(soft_ms),
        hard: Duration::from_millis(hard_ms),
    }
}
```

**Subtleties:**

- **Ordering**: non-time-limit short-circuit first; movetime override second; clock-based third. `infinite || ponder || depth || nodes || mate` win even when a clock is present (UCI: explicit non-time limits ignore the clock).
- **`movestogo = 0` is a spec violation**: defensive fallback to denom=1 (treat as "this is the last move"). Research §1.3.
- **`rem == 0` branch separation**: `rem == 0 && inc == 0` is the very-low-time path (1 ms / 1 ms). `rem == 0 && inc > 0` is the increment-only TC (no forfeit clamp; hard = 3 × soft per research §5+§9 test table).
- **`movestogo` is intentionally NOT consulted on the `rem == 0` branches.** When the clock is exhausted, allocation reduces to "spend at most half the increment to stay afloat" (research §5) regardless of how many moves are nominally left. A `movestogo = 1, wtime = 0, winc = 5000` user is in the same forfeit-imminent state as `movestogo = 40` with the same clock; both get the increment-only formula. Treat this as a *design choice*, not a bug — a future "fix" reintroducing `movestogo` here would over-allocate at the moment of greatest forfeit risk.
- **`saturating_sub` for `move_overhead`**: prevents underflow; if `raw_soft < move_overhead`, soft floors at 0 then `.max(1)` floors at 1 ms.
- **Cast `i64 → u64` after `.max(0)`**: handles negative clock (time-trouble overshoot) without underflow. `wtime=-200` becomes `rem = 0` and falls through to the `rem == 0 && inc == 0` floor (assuming inc=0).

## 5. ID outer loop in `Search::go`

```rust
fn go(&mut self, position: &Position, ctx: &SearchContext, info_sink: &dyn Fn(&str)) -> SearchResult {
    // Per-go reset.
    self.history = ctx.history.clone();
    self.nodes = 0;
    self.aborted = false;
    self.root_score = None;
    self.prior_root_move = None;
    for i in 0..MAX_PLY { self.pv.lengths[i] = 0; }

    // Determine max depth (cap iteration depth).
    let max_depth = max_depth_from_limits(&ctx.limits);

    let mut pos_clone = *position;

    // Tracks the last fully completed iteration's result. None until iteration 1 finishes.
    let mut last_complete: Option<(u32, Option<Move>, Vec<Move>, i32)> = None;

    for depth in 1..=max_depth {
        // Per-iteration reset (subset of per-go reset).
        self.aborted = false;
        self.root_score = None;
        for i in 0..MAX_PLY { self.pv.lengths[i] = 0; }

        let returned = self.negamax(&mut pos_clone, depth, 0, -INF, INF, ctx);

        if self.aborted {
            // Mid-iteration abort: discard partial PV/score; preserve prior `last_complete`.
            break;
        }

        // Iteration completed. Snapshot.
        let bestmove = (self.pv.lengths[0] > 0).then(|| self.pv.moves[0][0]);
        let full_pv: Vec<Move> = if self.pv.lengths[0] > 0 {
            self.pv.moves[0][..self.pv.lengths[0]].to_vec()
        } else { Vec::new() };
        last_complete = Some((depth, bestmove, full_pv.clone(), returned));
        self.prior_root_move = bestmove;

        // Emit info line for this completed iteration. Single Instant::now() reused
        // for both the elapsed-ms field and the soft-cap check below — avoids a
        // duplicate syscall and keeps the two reads coherent.
        let now = Instant::now();
        let elapsed_ms = (now - ctx.start).as_millis();
        let pv_str = if full_pv.is_empty() {
            "0000".to_string()
        } else {
            full_pv.iter().map(|m| m.to_uci()).collect::<Vec<_>>().join(" ")
        };
        info_sink(&format!(
            "info depth {depth} score {} nodes {} time {elapsed_ms} pv {pv_str}",
            score_to_uci(returned),
            self.nodes
        ));

        // Stop / depth / soft-cap checks between iterations. The stop check is
        // load-bearing: per-iteration `aborted` is reset at the top of the loop, so
        // a `stop` flipped between iterations would otherwise be missed until the
        // next 4096-cadence poll inside negamax — meaning a small completing
        // iteration could run unnecessarily after `stop` was already set.
        if depth >= max_depth { break; }
        if ctx.stop.load(Ordering::Relaxed) { break; }
        if let Some(soft) = ctx.soft_deadline
            && now >= soft
        {
            break;
        }
    }

    // Pick final result. Prefer last completed iteration; fall back to whatever the
    // aborted iteration left in `pv` (covers the pathological "iteration 1 aborted
    // before any root move improved alpha" case where `last_complete` is None).
    let (final_depth, final_bestmove, final_score) = match last_complete {
        Some((d, bm, _pv, sc)) => (d, bm, sc),
        None => {
            let bm = (self.pv.lengths[0] > 0).then(|| self.pv.moves[0][0]);
            let sc = self.root_score.unwrap_or(0);
            (0, bm, sc)
        }
    };

    // Honor infinite/movetime/ponder wait loop (unchanged from M3.D — `should_abort`
    // checks hard-cap deadline + stop flag + nodes cap).
    //
    // **Wait-loop interaction with ID under `go movetime <ms>`:** ID iterates until
    // either the soft cap fires between iterations (typical case for normal time
    // controls) OR the hard cap fires mid-iteration. Under `go movetime 1000` with
    // `MoveOverhead = 50`: caps = (950ms, 950ms). The ID loop exits when soft fires
    // (or earlier if iteration completes naturally to max_depth). The post-loop
    // wait spins UNTIL `should_abort` fires on the hard-cap deadline (also 950ms).
    // Net behavior: bestmove is emitted at ~950ms wall — UCI-correct ("don't return
    // before time budget"). Under `go infinite`: caps = (MAX, MAX), no soft check
    // ever fires; ID either reaches `max_depth = MAX_PLY-1 = 63` (cheap positions)
    // and falls into the wait loop, or never completes (typical case). Either way
    // the wait loop spins until `stop`, which is correct UCI semantics.
    let wait = ctx.limits.infinite || ctx.limits.movetime.is_some() || ctx.limits.ponder;
    if wait {
        while !ctx.should_abort(self.nodes) {
            std::thread::sleep(Duration::from_millis(1));
        }
    }

    SearchResult {
        bestmove: final_bestmove,
        depth: final_depth,
        score_cp: Some(final_score),
        nodes: self.nodes,
        ponder: None,
    }
}

fn max_depth_from_limits(limits: &SearchLimits) -> u32 {
    if let Some(d) = limits.depth {
        return d.min(MAX_PLY as u32 - 1);
    }
    let any_other_limit = limits.infinite
        || limits.ponder
        || limits.movetime.is_some()
        || limits.nodes.is_some()
        || limits.mate.is_some()
        || limits.wtime.is_some()
        || limits.btime.is_some();
    if any_other_limit { (MAX_PLY as u32) - 1 } else { 4 } // legacy default for bare `go`
}
```

**Subtleties:**

- **Per-iteration `pv` clear**: `lengths[0..MAX_PLY] = 0` resets the table. Otherwise iteration N+1's negamax starts with iteration N's stale `pv.moves[ply > 0]` slots and the depth==0 leaf's `pv.clear_ply` only fires on visited plies — so unvisited deeper plies could leak (theoretical, but cheap to guard against).
- **Per-iteration `aborted` + `root_score` reset**: required so iteration N+1's "last fully-explored root subtree" semantics are independent of iteration N. Without this, a quick-abort in iteration N+1 would preserve N's `root_score`, but `last_complete` already covers that — the per-iteration reset is for cleanliness.
- **`nodes` is NOT reset between iterations**: cumulative across iterations. Aligns with the standard interpretation of `info nodes N` ("total nodes searched in this `go`") and with `go nodes <N>`'s budget contract (the cap applies to the entire `go`, not per-iteration).
- **Soft-cap check is post-emit**: emit info line FIRST, THEN check soft cap. Otherwise we'd hide the info for the iteration that just finished — confusing for GUIs.
- **`depth >= max_depth` short-circuit before soft check**: when we hit the user's `go depth N`, we exit cleanly even if soft_deadline is None or far away. Saves an `Instant::now()` call.
- **Mid-iteration abort discards score AND PV**: `last_complete` retains the prior iteration's snapshot. The aborted iteration's partial PV table is overwritten on the next `go` (the per-go reset clears it).
- **Iteration 1 unconditional**: even when `soft_deadline` is in the past (e.g., a hard cap of 1 ms), we always START iteration 1. The hard cap will fire mid-iteration if needed; if iteration 1 aborts before completing, fallback returns whatever the partial PV captured. This matches CPW iterative-deepening discipline ("always have a move to play").
- **`prior_root_move` reset at top of `go`**: each new `go` starts clean. M3.E does NOT preserve hints across `go` boundaries (TT-style persistence is M4).

## 6. `negamax` ply==0 reorder

The only change to `negamax` body: at ply == 0, after MVV-LVA sort, prepend `prior_root_move` to the front if present in the move list.

The new step 8a is a **separate top-level `if`/`if let` chain in negamax's body** — NOT nested inside the existing searchmoves-filter `if` block. Indentation matters here: an editor's auto-merge could plausibly slip the new code inside the filter block, where it would only run when a `searchmoves` filter is active. Mirror the lexical position of step 8 (the existing MVV-LVA sort line) — both are sibling top-level statements at the same indentation level inside negamax.

```rust
// Inside negamax — sibling top-level statements, NOT nested:

// (existing) Searchmoves filter at root only.
if ply == 0
    && let Some(filter) = &ctx.limits.searchmoves
{
    moves_vec.retain(|m| filter.contains(m));
}

// (existing) Step 8: MVV-LVA descending.
moves_vec.sort_by_cached_key(|&m| -mvv_lva_score(m, pos));

// (NEW) Step 8a: Root reorder hint — try prior iteration's best move first.
if ply == 0
    && let Some(pm) = self.prior_root_move
    && let Some(idx) = moves_vec.iter().position(|m| *m == pm)
    && idx != 0
{
    let prior = moves_vec.remove(idx);
    moves_vec.insert(0, prior);
}
```

`remove(idx) + insert(0)` (rather than `swap(0, idx)`) preserves the relative MVV-LVA order of the rest of the list — only the prior-PV move moves to the front. `idx != 0` skips the no-op case (prior already first). The reorder runs AFTER the searchmoves filter intentionally: a prior PV move that no longer survives `searchmoves` simply fails the `position()` lookup and the reorder is a no-op (the remaining searchmoves get standard MVV-LVA ordering).

### 7.3 `handle_setoption` parsing

Add an arm for `MoveOverhead` (case-insensitive name match). Strict: parse as `u64`, reject if `> MAX_MOVE_OVERHEAD = 5000`. On accept: assign `self.move_overhead = n`. On reject: `info_string_debug` per the existing convention.

**Position the new arm AFTER the existing `Random_Seed` arm and BEFORE the `if self.debug { ... }` unknown-option fallback** (currently `src/engine.rs:291–298`). The early `return;` at the end of each known-option arm short-circuits the fallback; placing the `MoveOverhead` arm after the fallback would dead-code-path the new arm (the `if self.debug` block falls through to function end without `return`, but its `format!` allocation runs unconditionally for unknown options — a `MoveOverhead` arm placed after it would be syntactically reachable but only after first emitting the unknown-option diagnostic, double-handling the option). The lexical sequence inside `handle_setoption` is therefore: `Random_Seed` arm → `MoveOverhead` arm → unknown-option `if self.debug { ... }` fallback.

```rust
const MAX_MOVE_OVERHEAD: u64 = 5000;

if name.eq_ignore_ascii_case("moveoverhead") {
    let parsed: Option<u64> = value
        .as_deref()
        .and_then(|s| s.parse::<u64>().ok())
        .filter(|&n| n <= MAX_MOVE_OVERHEAD);
    match parsed {
        Some(n) => {
            // No need to join the in-flight worker — `move_overhead` is read at
            // the top of `handle_go` to build the next SearchContext, not by the
            // worker mid-search. Setting it concurrently with an in-flight `go`
            // does not race with the search.
            self.move_overhead = n;
        }
        None => {
            let msg = match value.as_deref() {
                Some(v) => format!("MoveOverhead: rejected value '{v}'"),
                None => "MoveOverhead: rejected (no value given)".to_string(),
            };
            self.info_string_debug(&msg);
        }
    }
    return;
}
```

### 7.4 `handle_go` wiring

```rust
fn handle_go(&mut self, params: GoParams) {
    self.join_in_flight_worker();
    self.stop.store(false, Ordering::Relaxed);

    let searchmoves: Option<Vec<Move>> = params.searchmoves.map(|raw| {
        raw.iter().filter_map(|s| Move::from_uci(s, &self.position).ok()).collect()
    });

    let limits = SearchLimits { /* same field-by-field as M3.D */ };

    let now = Instant::now();
    let caps = compute_caps(&limits, self.position.side_to_move(), self.move_overhead);
    let deadline = (caps.hard != Duration::MAX).then(|| now + caps.hard);
    let soft_deadline = (caps.soft != Duration::MAX).then(|| now + caps.soft);

    // Spawn worker (unchanged shape from M3.D except for the new ctx fields).
    let position = self.position;
    let search = Arc::clone(&self.search);
    let stdout = Arc::clone(&self.stdout);
    let ctx = SearchContext {
        stop: Arc::clone(&self.stop),
        deadline,
        soft_deadline,
        start: now,
        limits,
        history: self.game_history.clone(),
    };
    // ... rest unchanged from M3.D ...
}
```

The legacy "deadline from movetime only" computation (`params.movetime.map(...)`) is removed — `compute_caps` subsumes it (and applies `move_overhead` to movetime, fixing research §10's "MoveOverhead not applied to movetime" pitfall).

## 12. Risks and gotchas

- **Soft-cap-only ID-loop test fragility**: `id_aborts_between_iterations_when_soft_deadline_passed` relies on iteration 1 completing before the soft check fires. On a slow CI, iteration 1 might exceed 1 ms. Mitigation: set `soft_deadline = now + 100ms` and compute the test fixture so iteration 1 completes well within 50 ms.
- **`info`-line counting in existing tests**: M3.D assumed one info per go; ID emits multiple. Audit ALL `assert_eq!(info_lines.len(), 1)` patterns and convert to `>= 1` or specific-line lookups.
- **Negative-clock UCI cast**: `wtime=-200` arrives as `i64::-200`. `(rem.max(0) as u64)` is safe. Never cast a negative `i64` to `u64` directly without `.max(0)` first.
- **`movestogo=0` is a spec violation**: defensive fallback to 1. Pinned by `compute_caps_movestogo_zero_treated_as_one`.
- **Duration overflow**: `Duration::from_millis(u64::MAX)` is fine; `soft.saturating_mul(3)` on the underlying `u64` ms value is the safe path. Don't compute `soft * 3` as `Duration * 3` (that's `Duration::saturating_mul(u32)` and our scalar is u64).
- **`prior_root_move` after `searchmoves` filter**: the prior PV move from a prior iteration MAY have been filtered out by a different `go searchmoves` set. The `position()` lookup handles this (returns None → no reorder). Pinned by `id_prior_root_move_no_hint_when_not_in_movelist`.
- **`Random_Seed` and `MoveOverhead` interaction**: both options now exist. The `setoption` dispatch order matters for case-insensitive matches (currently `if name.eq_ignore_ascii_case("random_seed") { ... return; }` early-returns). The new `MoveOverhead` arm follows the same shape — no interaction risk.
- **Mid-iteration abort with `last_complete = None`**: the fallback to "whatever pv[0] currently has" might return a partial-iteration bestmove (NOT a full PV). Acceptable — better than `bestmove 0000` when the engine has thought for some time. UCI conforming.
- **`soft_deadline` constructed when `caps.soft == Duration::MAX`**: `Instant::now() + Duration::MAX` would panic on overflow. Guard with `(caps.soft != Duration::MAX).then(|| now + caps.soft)`. Same for hard. Pinned by the wiring shape in §7.4.
- **Non-time `go` flag with `wtime` present**: per UCI spec, `go infinite wtime 1000` should be infinite. `compute_caps` respects this — `infinite` is checked first.
- **`go ponder`**: M3 doesn't ponder, but the limits flag must not trigger time-based caps when set. Treated as non-time-limit in `compute_caps`. Same as `infinite`.
- **Fastchess `--compliance` interaction**: the new `MoveOverhead` option must appear in the `option …` block before `uciok`. Currently `Random_Seed` is the only option line; `MoveOverhead` follows. Step 12 of fastchess's compliance walks options; verify no failure.
- **CI clock skew**: integration tests E40/E41/E42 use real wall clock. Use generous bounds (1000ms budget, 2000ms test timeout) to absorb CI jitter.
