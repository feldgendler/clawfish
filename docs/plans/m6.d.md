# M6.D — Piece mobility (plan)

Fourth M6 sub-phase. Adds a **piece-mobility eval term** (N/B/R/Q
pseudolegal-attack count ∩ mobility area, per-kind MG/EG tables) shipped
**live at Stockfish-HCE literature-default weights**, gated by a canonical
mixed-TC SPRT vs `M6.C` with a pre-committed contingency screen ladder.

- Research: [`docs/research/m6-mobility.md`](../research/m6-mobility.md).
- Roadmap: M6.D row + "M6.D scope detail" (semantic committed there; **no
  separate ADR** — per the roadmap row).
- Precedent: M6.B (CONN-only subset screen) / M6.C (screen ladder, score-neutral
  floor), ADR-0032 §4 (eval-boundary rule), §7/§8.
- Production HEAD / SPRT baseline tag: **`M6.C`**.

## 1. Goal & non-goals

- **Goal.** A white-perspective `(mg, eg)` mobility term entering
  `evaluate_core`'s blend numerator, weighted by per-kind literature-default
  tables; SPRT-gated vs `M6.C`.
- **Non-goal (deferred by design, roadmap-committed).**
  - Pinned pieces scored **pseudolegally** (full pseudolegal attack set
    credited; no king-ray pin detection at the eval leaf). Research §4.
  - **No x-ray/battery mobility** — plain `magic::*_attacks(sq, occ_all)`,
    no see-through-own-rook/queen. Research §5; M6.H watch-item.
  - No richer minor-piece mobility-area exclusion (only enemy *pawn* attacks
    subtracted). Roadmap row.
  - King & pawn mobility excluded (king PST / pawn structure already cover).
  - Weight calibration is **M6.H**'s joint Texel pass; M6.D ships literature
    defaults (roadmap: "each prior phase ships literature defaults").

### `src/eval/mobility.rs` — the term

```rust
//! Piece-mobility eval term (M6.D). White-perspective (mg, eg); black
//! pieces subtract symmetrically. Computed live in `evaluate_core` (not
//! pawn-only ⇒ never cached; ADR-0032 §3 class). Pseudolegal (pins ignored),
//! no x-ray — deliberate deferrals (plan §1; research §4/§5).

pub(crate) fn mobility_term_white(pos: &Position) -> (i32, i32);
```

Algorithm (the body the coder transcribes verbatim — prescriptive):

```rust
let occ_all = pos.occupied_all();
let (mut mg, mut eg) = (0i32, 0i32);

let wp = pos.pieces_colored(Color::White, PieceKind::Pawn);
let bp = pos.pieces_colored(Color::Black, PieceKind::Pawn);
let white_pawn_atk = wp.shift_north_east() | wp.shift_north_west();
let black_pawn_atk = bp.shift_south_east() | bp.shift_south_west();

for (side, sign) in [(Color::White, 1i32), (Color::Black, -1i32)] {
    let enemy_pawn_atk = match side {
        Color::White => black_pawn_atk,
        Color::Black => white_pawn_atk,
    };
    // mobility area = all − (own-occupied ∪ enemy-pawn-attacked)
    let area = !(pos.occupied(side) | enemy_pawn_atk);

    for sq in pos.pieces_colored(side, PieceKind::Knight).iter() {
        let c = (movegen::masks::knight_attacks(sq) & area).count() as usize;
        debug_assert!(c < KNIGHT_MOBILITY_MG.len(), "knight mob idx {c}");
        mg += sign * KNIGHT_MOBILITY_MG[c];
        eg += sign * KNIGHT_MOBILITY_EG[c];
    }
    for sq in pos.pieces_colored(side, PieceKind::Bishop).iter() {
        let c = (magic::bishop_attacks(sq, occ_all) & area).count() as usize;
        debug_assert!(c < BISHOP_MOBILITY_MG.len(), "bishop mob idx {c}");
        mg += sign * BISHOP_MOBILITY_MG[c];
        eg += sign * BISHOP_MOBILITY_EG[c];
    }
    for sq in pos.pieces_colored(side, PieceKind::Rook).iter() {
        let c = (magic::rook_attacks(sq, occ_all) & area).count() as usize;
        debug_assert!(c < ROOK_MOBILITY_MG.len(), "rook mob idx {c}");
        mg += sign * ROOK_MOBILITY_MG[c];
        eg += sign * ROOK_MOBILITY_EG[c];
    }
    for sq in pos.pieces_colored(side, PieceKind::Queen).iter() {
        let c = (magic::queen_attacks(sq, occ_all) & area).count() as usize;
        debug_assert!(c < QUEEN_MOBILITY_MG.len(), "queen mob idx {c}");
        mg += sign * QUEEN_MOBILITY_MG[c];
        eg += sign * QUEEN_MOBILITY_EG[c];
    }
}
(mg, eg)
```

**Index-bound invariant (load-bearing).** Knight 8 / bishop 13 / rook 14 /
queen 27 are the **empty-board** geometric attack maxima and equal the table
top indices exactly; real `occ_all` (sliders) and `& area` can only *reduce*
the count below that maximum, so `c` is always in-bounds — the invariant is
strictly more robust than "max equals table top." The `debug_assert!`
documents it and trips loudly if a future `magic::*_attacks` change violates
it; release trusts it (no clamp — clamping would silently mis-score a real
bug; the M6.A `mop_up_term_white` "trust-the-invariant-in-release"
precedent). Verify imports resolve: `crate::magic`,
`crate::movegen::masks`, `Bitboard::shift_*`, `Bitboard::count`,
`Position::{occupied,occupied_all,pieces_colored}`.

## 4. Test coverage strategy

M6.B/C technique: **weight-free structural/definitional pins** (survive any
M6.H re-tune) + **symbolic-over-`eval::data` value pins** (auto-correct at
shipped live weights and at any re-tune). Tests in `src/eval/mobility.rs`
unless noted.

| Test | Asserts | Kind |
|---|---|---|
| `mobility_startpos_is_zero` | symmetric start → `(0,0)` | structural |
| `mobility_color_mirror_antisymmetric` | a FEN and its vertical color-mirror → exactly negated `(mg,eg)` | structural |
| `mobility_area_excludes_friendly_occupied` | a knight blocked only by friendly pieces: count == popcount(attacks minus friendly) | definitional |
| `mobility_area_excludes_enemy_pawn_attacked_empty_sq` | empty square attacked by an enemy pawn is NOT counted | definitional |
| `mobility_slider_blocker_enemy_nonpawn_counts` | enemy non-pawn sitting on a **rook/bishop first-blocker square** (non-pawn-attacked) IS counted — exercises the magic-attack-includes-blocker semantic, not just area membership (a knight fixture wouldn't, no occupancy dependence) | definitional |
| `mobility_friendly_pawn_attacked_empty_sq_counts` | friendly-pawn-attacked empty square stays in area | definitional |
| `mobility_knight_symbolic_value_from_data` | hand-counted N count on a fixture → `(sign*KNIGHT_MOBILITY_MG[c], …EG[c])` computed from `eval::data` | symbolic |
| `mobility_bishop_symbolic_value_from_data` | same, bishop (slider + occ_all) | symbolic |
| `mobility_rook_symbolic_value_from_data` | same, rook | symbolic |
| `mobility_queen_symbolic_value_from_data` | same, queen (max-component fixture) | symbolic |
| `mobility_pinned_piece_scored_pseudolegally` | absolutely-pinned knight credited its full pseudolegal count (deferral pinned as intended behavior) | structural |
| `mobility_no_xray_through_friendly_slider` | rook behind friendly rook: count reflects the blocker (no x-ray) | structural |
| `mobility_indices_within_bounds_max_geometric` | lone queen on empty-ish board (max ~27) + lone rook(14)/bishop(13)/knight(8): no panic, term finite | corner |
| `mobility_tables_have_expected_lengths` | `len()` == 9/14/15/28 (vendoring-typo guard) | structural |
| `static_accessor_excludes_mobility` *(in `src/eval.rs`)* | on a mobility≠0 fixture: `pos.static_mg_white()`/`static_eg_white()` byte-equal `eval_state_from_scratch(pos)`'s `(mg,eg)` (PST-only triple) — proves the RFP/NMP/FFP pruning accessor is untouched by mobility. Weight-free | boundary regression (ADR-0032 §4) |
| `mop_up_addend_excludes_mobility_vs_m6c` *(in `src/eval.rs`)* | mirrors `mop_up_addend_excludes_passed_pawns_vs_m6b` **verbatim in shape**, including its load-bearing fixture-invariant assertion: first `assert!(mobility::mobility_term_white(&pos) != (0, 0), "fixture invariant: mobility must be non-zero")` (the parallel of the M6.C test's `assert!(!…passed[White].is_empty())` — without it the test vacuously passes since a `(0,0)` term cannot perturb mop-up whether or not it were wrongly routed). Then a mop-up-eligible KQ-vs-K fixture where `mop_up_term_white(pos, static_mg_white, static_eg_white)` byte-equals the **hand-derived literal `38`** (same Kg1/Ka8 king geometry: `4·CMD(a8)=24 + 2·(14−cheb(g1,a8)=7)=14`). The literal is independent of all eval-term code, so it fails if mobility is ever routed into the mop-up estimate — not a delta tautology | boundary regression (ADR-0032 §4) |

The two boundary tests replace a single combined test deliberately: an
`evaluate`-delta-equals-mobility-addend assertion is a **tautology** (it
passes even if mobility wrongly perturbs the mop-up estimate, since the delta
would still equal "mobility's total effect on `evaluate`"). The
hand-derived-literal mop-up test + the PST-only-triple accessor test pin §4
the way the M6.A/M6.C `_vs_m6a`/`_vs_m6b` precedent tests do.

Symbolic tests compute the *expected* value from `crate::eval::data`
constants, never literal cp — correct at the shipped live weights AND after
M6.H. Structural/definitional tests use popcounts/bitboards — weight-free.

Confirmation-bias guard: every symbolic test independently re-derives the
mobility count from the FEN (hand-listed attacked squares minus area
exclusions), not from calling `mobility_term_white` and asserting it equals
itself.

## 5. Order of operations

1. **Test-scaffolding + tests slice.** Append the `data.rs` arrays (pure
   vendored data, no logic — safe to land early) + `mobility_term_white`
   **stub returning `(0, 0)`** with the final signature + `mod mobility;`
   in `eval.rs` (NOT yet wired into `evaluate_core`). Then write all tests
   (`src/eval/mobility.rs` `#[cfg(test)]` + the two `eval.rs` boundary
   tests). TDD state against the stub: symbolic/definitional/value tests
   **fail** (they demand real computation — the anti-confirmation-bias
   property), structural-only tests (`mobility_startpos_is_zero`,
   `mobility_tables_have_expected_lengths`) pass. Crate compiles.
2. Test-suite blind-review loop → convergence.
3. Implement: replace the stub body with the real algorithm → wire
   `evaluate_core` (the `MOBILITY_IN_EVAL` block + blend extension). All
   tests go green.
4. `cargo test` green (+ release suite). No extended perft (not triggered).
5. Pre-review mechanical checks (§7) → final-review loop.
6. Benchmark (bench signature + NPS) → strength gates (§10).
7. Commit + push + tag `M6.D`; docs (§12).

## 6. Parallelization map

**None — sequential.** The unit is ~250–350 LOC across 3 tightly-coupled
files; the data arrays, the term function, and the wiring are a single
coherent change and the test slice precedes implementation (TDD step
ordering). Splitting `data.rs` (pure transcription) from `mobility.rs` would
save no wallclock at this size and adds a merge seam. One coder slice for
tests, one for implementation, run in sequence.

## 9. Bench & NPS

- From M6.A bench node count is **not** a no-regression signal (live leaf
  scores reshuffle root ordering — roadmap policy). Record the new bench
  signature + depth-4 pin; deterministic-bench contract still holds (stable
  across reruns at HEAD; anchors M6.E).
- **M6.D is the heaviest per-leaf eval addition in M6 so far** — the first
  *uncached whole-board piece-attack scan*. M6.B's pawn scan is
  pawn-hash-cached; M6.C's passed term reads that cache + does cheap
  per-passer work. M6.D's slider sweep (up to ~14 magic-table lookups +
  AND + popcount per leaf, both colors' B/R/Q) is **correctly uncached**
  (not pawn-only — ADR-0032 §3) so it lands fully on the `evaluate_cached`
  qsearch hot path. The roadmap M6.B scope-detail explicitly anticipated
  this compounding ("mobility has no caching").
- **Pre-impl expectation: a per-leaf eval-cost increase, NPS drop in the
  low-single-digit-% to ~10% range.** Lower bound anchor: M6.C's live-screen
  build measured **+2.6% NPS** (its term was far cheaper, so M6.D will be
  worse than that, not better). The M6.A "2× eval cost absorbed by +250" is
  **not** a precedent for M6.D's +20–35 budget — flag explicitly.
- **NPS regression > 10% is a should-fix flag** (workflow). The cheap hoists
  are *already in the algorithm* (pawn-attack spans computed once; `area`
  per-side not per-piece) — they are the baseline, not the mitigation. If
  the >10% gate trips, the named mitigation is: skip the per-kind loop for a
  kind with no pieces (early `is_empty()` continue — already implicit in the
  `.iter()` over an empty bitboard, so measure first) and, if still over,
  surface in chat with an NPS profile rather than silently rolling forward
  (workflow §"Communication norms"). A genuine >10% drop with a
  not-clearly-positive SPRT is a stop-and-surface, not an auto-land.
- Record the new bench signature + depth-4 pin; deterministic-bench
  contract holds (stable across reruns at HEAD; anchors M6.E).

## 10. Exit criteria — landing-gate SPRT vs `M6.C`

Canonical mixed-TC 4-bucket `10+0.1:1,20+0.2:1,40+0.4:1,60+0.6:1`,
elo0=0 / elo1=5, fresh seed, **RUN ALONE**. WAC+STS same-campaign
re-baseline first (RUN ALONE), then SPRT. Verdict ladder (M5.F / M5.G-v2 /
M6.B `continue@cap` + M6.H-style rungs):

1. **H1-accept** (Wald upper) **or continue@cap with CI-lower ≥ +5** → ship
   live all-four; tag `M6.D` at the live build.
2. **Small-but-not-regression** (mean ≥ 5 ∧ CI-lower > −10) → ship live,
   retrospective notes the inconclusive SPRT (M5.F outcome-2).
3. **Marginal** (mean ≥ 0 ∧ CI-lower > −10) → ship live with retrospective
   caveat (M6.H-style rung; a co-calibrated 4-kind set landing small-positive
   is real Elo not worth discarding).
4. **Regression / wide-negative** (mean < 0 ∨ CI-lower ≤ −10 ∨ H0) → enter
   the §11 contingency screen ladder (do not roll forward; surface in chat).

**WAC+STS secondary gate (per-theme, M6-onward) — gates outcomes 1–3.**
Mobility claims the piece-activity theme group — primary **#2 "Open Files
and Diagonals"** (the weakest activity theme, 51.1%, most directly
rook/bishop/queen-mobility driven), secondary **#3 "Knight
Outposts/…/Centralization"**. Same-campaign re-baseline vs `M6.C` (RUN
ALONE). **Outcomes 1–3 ship a *live* build, so this gate is NOT moot for the
shipped artifact** (the M6.C "moot" carve-out applies *only* to the §11
score-neutral floor, where the shipped eval is byte-identical to `M6.C`).
**A strong-negative move on a claimed STS theme (#2 or #3) at outcome 1, 2,
or 3 is a stop-and-surface before close** — do not roll forward on the
Elo-SPRT verdict alone; surface the theme regression in chat and treat it as
a `should-fix` per the roadmap M6 secondary-gate rule + M5.E
correctness-over-Elo precedent (a positive Elo SPRT with a regressed claimed
theme means the term is helping via an unintended channel — investigate
before tagging). Only the §11 score-neutral floor makes the per-theme gate
moot (shipped eval == `M6.C` by construction — the M6.C precedent), where the
live-term run is recorded as a rejected-config diagnostic.

**Stockfish Elo calibration.** Documentation-only (M6.A precedent); M6 not
closing at M6.D. Run only if the landing SPRT Δ ≳ +30 (judgment); else
in-chat document-skip.

## 11. Contingency screen ladder (pre-committed; unattended)

Mirrors M6.B/M6.C exactly — **zero hand-tuning**, only choosing which
literature-default kinds to keep. Entered only on §10 outcome 4.

1. **Per-kind env-mask subset screen** (cheap *relative* paired filter).
   Throwaway experiment patch: `CLAWFISH_MOBILITY_MASK` read once at startup,
   bits **N=1 / B=2 / R=4 / Q=8**; a zeroed bit forces that kind's tables to
   `0` for the run. Patch sanity: mask 15 `bench` == clean all-four HEAD;
   mask 0 `bench` == `M6.C` (provably-inert plumbing check — but M6.D ships
   the term *live*, so mask-0 inertness validates only the patch, not a
   production property; the M6.C disanalogy note verbatim). SPRT each
   candidate subset vs cached `M6.C`, single-TC `10+0.1`, elo0=0/elo1=10,
   shared seed (paired low-variance — the M6.B screen protocol). **Lead
   hypotheses first:** `{R,Q}` and `{N,B,R,Q}`-minus-one — research §8
   predicts knight/bishop (PeSTO PST double-count) are the weak kinds,
   rook/queen transfer cleanest. Patch fully reverted before clean apply.
   - **TC-asymmetry guard (the M6.C inversion defense).** Inspect the
     all-four per-TC breakdown first. If it shows a TC-profile inversion
     (one bucket carrying the loss, à la M6.B CONN fast-strong/slow-negative
     or M6.C KDIST slow-collapse), re-screen the **top-2 candidates at the
     canonical mixed-TC 4-bucket** before selection (≤2 extra SPRTs, still
     unattended). **"Top-2" once the pruning rule has collapsed the lattice
     to a single union-of-positive-kinds candidate = {that union, that union
     minus its single-TC-weakest member}**; if only one positive kind
     survives at all, "top-2" degenerates to that one kind (≤1 mixed-TC
     re-screen). Absent inversion the single-TC paired ranking stands.
   - **Lattice-pruning / stopping rule (bounds the sweep — the M6.C
     "don't exhaustively screen a structurally-confirmed-bad family"
     disposition).** Do **not** sweep all 15 non-empty subsets (~40h each at
     canonical mixed-TC is a multi-week unattended commitment). Bounded
     protocol: (a) one **4-way per-kind single-TC screen** — each kind alone
     vs `M6.C` (4 SPRTs) — identifies positive vs toxic kinds; (b) once a
     kind is *confirmed* single-TC-negative it is structurally pruned (every
     superset containing it inherits the regression — the M6.C
     "KDIST-bearing subsets all inherit the collapse" logic; do not screen
     them); (c) screen **only** the union-of-positive-kinds candidate (1
     SPRT) — if multiple kinds are individually positive their union is the
     single largest interaction-immune candidate, since unlike M6.B's
     ISO×CONN same-axis pair the 4 piece kinds are *independent axes* (no
     cross-kind double-count — research §7 "queen mobility does not
     double-count rook+bishop"); (d) the TC-asymmetry guard adds ≤2 mixed-TC
     re-screens only if inversion is detected. Total bounded at **≤ 4
     single-TC + 1 single-TC + ≤2 mixed-TC + 1 mixed-TC landing-gate ≈ 8
     SPRTs**, not 15. If step (c)'s union is itself negative, go to step 2
     (co-scale), then the §11.4 floor — do **not** enumerate intermediate
     subsets.
2. **If even the best single kind regresses** → uniform `×0.5` co-scale
   probe (all 8 arrays halved — the M6.B `(ISO+CONN)/2` / M6.C
   `{RANK+PATH}/2` precedent). Separates pure over-magnitude (downscale
