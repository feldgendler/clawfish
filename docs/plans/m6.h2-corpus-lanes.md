# M6.H2 — Corpus lanes: flat build-ready labelled positions, no split, per-lane dedup

**Type:** Data-infra refactor. **NO SPRT, NO bench change** — the engine `evaluate`/search
is untouched, so bench stays `1213649` / d4 `90591` byte-for-byte (a free confirmation at
the bench step). Landing gate = data-quality checks (the M6.G/M6.H precedent) + the
reproducibility + crash-safety integration tests.

## 0. Goal (user-decided; design HOW, not WHETHER)

Unify the four corpus lanes (ADR-0035 §10: `SelfPlayOnBook`, `SelfPlayOffBook`, `Ccrl`,
`LichessOpen`) so each is an **independent generator** that produces a FLAT list of N
**build-ready labelled positions** (`CorpusRecord`) inline:

- Per-lane inline pipeline: opening-skip (`OPENING_SKIP_PLIES=8`) → drop in-check →
  `|static_eval| ≤ HIGH_SCORE_CP (600)` → quiet filter (`is_quiet`, `QUIET_MARGIN_CP=30`;
  needs a static eval + a qsearch eval) → **per-lane** FEN dedup (first-seen-wins, WITHIN
  the lane only) → per-game cap (`PER_GAME_CAP=10`).
- **No train/val split** at generation (moves to M6.I).
- **No cross-lane dedup** — the same FEN may appear in up to 4 lanes, possibly with
  conflicting labels — explicitly accepted (M6.I's mixer weighs lanes).
- `--target`/`--cap-positions` counts **usable** (post-quiet/dedup/cap) positions for BOTH
  fetch and self-play.
- Per-lane target 2M usable each → 8M total.
- Lane corpora gitignored (deterministically regenerable); CCRL fetch URL pinned in the
  manifest for byte-re-derivability.

## 1. Load-bearing decisions

### 1.1 On-disk layout — one dir per lane, single flat `lane.bin`
Each lane lives in its **own** `--out <dir>` and produces a single flat artifact
**`lane.bin`** (the existing CRC-framed per-game-block `store.rs` format), plus
`manifest.json` + `filter_spec.txt` + `corpus_stats.txt`. Self-play writes `lane.bin`
(was `shard.bin`); fetch writes `lane.bin` (was `pgn-shard.bin`). The four lanes are never
co-located; the M6.I mixer reads four dirs and does the inter-lane mix + split. Per-lane
dirs delete the only reason the old code merged/cross-deduped (`shard.bin`+`pgn-shard.bin`
in one dir); each lane's `game_id` space is private, so resume/dedup reads exactly one file.

### 1.2 `build` removed; `finalize` added
Drop `cmd_build` (its transform role — dedup/cap/split/merge — is now inline per lane).
Add a thin **`corpus finalize --in <lane-dir>`** doing ONLY the surviving roles: recompute
`corpus_sha256` over `lane.bin`; write/update `manifest.json` + `filter_spec.txt` +
`corpus_stats.txt`; write the per-lane `re-run.sh`. No record transformation. This also
closes the old `cmd_build` UNIMPLEMENTED gap (it never re-applied per-position filtering to
ingested PGN) — PGN now gets the full inline pipeline in fetch.

**`cmd_ingest_pgn` (local-file PGN path, distinct from network `fetch`) MUST also become
build-ready** (reviewer MEDIUM-4): it is single-shot (no `CallState`), so it constructs a
**one-shot `LaneCommitter`** + its own `QSearcher` and applies the SAME per-position quiet
filter → dedup → cap → target as `fetch`, emitting `lane.bin`. Otherwise it stays a second,
divergent ingest path emitting unfiltered/undeduped records — violating the "all four lanes
are build-ready" contract.

### 1.3 Shared primitive — `pipeline::LaneCommitter`
New module `src/corpus/pipeline.rs` factors dedup+cap+commit so fetch and self-play
**cannot diverge**:

```rust
pub struct LaneCommitter { fen_set, cap_seed, target, committed }
impl LaneCommitter {
    // FETCH path: do our own single scan of an existing lane.bin (no consumer).
    // Rebuild fen_set + committed + committed-game-ids.
    pub fn resume(lane_path, cap_seed, target) -> (LaneCommitter, HashSet<u64>);
    // SELF-PLAY path: BE the consumer's dedup/cap/target state — constructed from
    // the consumer's SINGLE existing scan (no second full read of lane.bin).
    pub fn from_parts(fen_set, committed, cap_seed, target) -> LaneCommitter;
    // Caller pre-applies the per-POSITION filter (needs Position+QSearcher).
    // Committer applies: per-lane FEN dedup (first-seen-wins) → per-game reservoir
    // cap → EXACT target truncation; appends one CRC block to lane.bin.
    pub fn commit_game(lane_path, game_id, records) -> CommitOutcome;
    pub fn committed() -> u64;  pub fn target_reached() -> bool;
}
// CommitOutcome { usable_committed, empty_post_dedup, target_reached }
```

Order MUST match today's consumer: dedup first (cap reservoir samples among survivors) →
reservoir cap seeded by `substream_seed(cap_seed, game_id)` → **exact** target truncation
(reviewer HIGH-1): when committing a game would cross `target`, keep only
`target - committed` records of the boundary game (the existing consumer `room`/
`saturating_sub` partial-commit), so BOTH fetch and self-play land on target exactly — no
`< target + PER_GAME_CAP` overshoot, preserving the §1.3 "cannot diverge" goal. Move the
existing `inline_cap_dedup_survivors` reservoir logic into `pipeline.rs`. The committer
does NOT own the quiet filter (that needs `Position`+`QSearcher`, in the lane's game loop)
— exactly the split self-play already uses.

**Resume ownership (reviewer MEDIUM-1):** there is exactly ONE scan of `lane.bin` per
process. Self-play's `consumer::resume` keeps its rich protocol (torn-tail truncation,
checkpoint cursor, ghost-pending heal, `committed_ids_at_resume`, `positions_at_resume`),
builds `fen_set` in that one scan, and constructs the committer via `from_parts` — the
`LaneCommitter` does NOT re-scan. Fetch (no consumer) uses `LaneCommitter::resume`, which
does the single scan itself.

### 1.4 Fetch usable-count target (trickiest mechanism)
`ingest_game` must run the full per-position inline filter (`static_eval_white` +
`QSearcher::eval_white` + `is_quiet` + skip8 + |eval|≤600) BEFORE dedup+cap, then call
`LaneCommitter::commit_game`; `CallState.positions_ingested` is bumped by
`usable_committed` (NOT raw `recs.len()`). `target_reached()` early-terminates on usable
count, and `commit_game`'s exact truncation (§1.3) makes the final lane land on `target`
exactly. One `QSearcher` is created per `stream_to_ingest` call (reused across games — fetch
is single-threaded). **Placement (reviewer NIT):** the `QSearcher` lives in the `Attempt<'a>`
bundle (borrowed `&mut`), NOT in `CallState` (which is `Rc`-shared with `Cell` fields and
would force a `RefCell`); the `on_game` closure is already `&mut`/`FnMut`, so a `&mut
QSearcher` composes without a `RefCell`.

**Byte-0-restart × per-lane-dedup idempotence (CRITICAL invariant):**
- `LaneCommitter` is created ONCE per call (lifetime = `CallState`), persists across
  byte-0 restarts.
- A re-parsed game with `game_id ≤ max_appended_game_id` is skipped by `is_already_appended`
  BEFORE the committer → no double-insert into `fen_set`, no double-count.
- Cross-process resume: `LaneCommitter::resume` rebuilds `fen_set`+`committed`+ids from
  `lane.bin`; `max_existing_game_id+1` pins `base_game_id` so re-ingested early games are
  skipped by game_id.
- Empty-post-dedup game → zero block, `games_emitted`/`max_appended_game_id` unchanged;
  idempotent on restart (re-parses to same FENs, all still dups → zero). Stream order is
  monotone so the `<=` skip stays safe. **Pin with `fetch_empty_post_dedup_game_idempotent_
  across_byte0_restart`** asserting (a) zero net positions, (b) `games_emitted` unchanged,
  AND (c) the emptiness is **dedup-driven** (the game is at `game_id = max_appended + 1`, so
  it is NOT skipped by `is_already_appended` — it re-runs the pipeline and is empty only
  because its FENs are in `fen_set`). Without (c) the test could pass for the wrong reason
  (skip-by-game_id) and never exercise the dedup-driven path.
- Stall watchdog keys on games-parsed (`note_progress` per yielded game), NOT positions —
  unaffected by usable-vs-raw. `TargetGuard` + `ResumableHttpReader` early-term poll
  `target_reached()` (now usable) — fires later (correct: operator gets N usable).

### 1.5 No-split self-play consumer
Remove `split_by_game`/`is_val`/`val.bin` routing from `consumer.rs`; route dedup+cap+target
through `LaneCommitter` (via `from_parts`, §1.3); append every committed block to
`lane.bin`; `resume()` reads `lane.bin` only. `SelfPlayConfig`: remove `val_fraction`,
rename `split_seed`→`cap_seed` (keeps the reservoir-cap role, drops the split role).
`--cap-positions` is already usable-count for self-play.

**The consumer retains the cap→`stop` side-effect (reviewer MEDIUM-2):** on
`LaneCommitter::target_reached()`, the consumer must still `stop.store(true)` so the worker
threads drain their in-flight game and exit (R2) — `target_reached()` is the signal, the
consumer owns the side-effect; without it workers generate forever. **`committed_ids_at_
resume`/`next_consume_id`/`positions_at_resume` survive the refactor (reviewer LOW-2):**
`selfplay::run` still builds the dispatcher gap-list + ghost-pending heal from them, so the
`consumer::resume` → `ConsumerState` data-flow is preserved (the committer is constructed
from the same scan, not in place of it).

### 1.6 `split.rs` deleted; `dedup.rs` trimmed
- **Delete `src/corpus/split.rs`** (split moves to M6.I, which owns the contract over the
  four-lane input). Remove `pub mod split;`.
- **Delete `dedup_fen` + `per_game_cap` + spill machinery** from `dedup.rs` (used only by
  the removed `cmd_build`). Inline first-seen-wins + reservoir cap live in `pipeline.rs`.
  If `dedup.rs` empties, delete the file + `pub mod dedup;`.
- **Remove `CorpusRecord::dedup_key`** + its golden test. Determinism note: per-lane
  first-seen-wins = first-by-arrival within the lane. Within a lane, arrival order is
  deterministic (self-play: strict game_id order + ply order; fetch: stream order + ply
  order).
  - **Self-play stays byte-identical across restarts** — the dispatcher pins `game_id` to a
    strict counter independent of process restarts (resume reconstructs `next_consume_id`),
    so the survivor's full `(game_id, ply)` provenance is reproducible.
  - **Fetch determinism carve-out (reviewer HIGH-2):** the *content* of survivors (FEN +
    **label**) is stable across a cross-process resume, because first-seen is by **stream
    order** and the stream bytes are identical — the earlier physical game's FEN is already
    in `fen_set` (reconstructed from disk), so the same physical game/label wins whether the
    run was uninterrupted or resumed. What is NOT byte-identical across a resume is the
    surviving record's `game_id` *numeric tag*: fetch assigns `game_id = base + stream_pos`,
    and `base = max_existing_game_id + 1` shifts on a fresh process, so games committed in
    run 2 carry a different offset than an uninterrupted run. This is the **pre-existing
    ADR-0035 §8 "weaker / re-derivable" class for external sources — unchanged by M6.H2**,
    NOT a regression from dropping `dedup_key`. Byte-for-byte re-acquisition (the gitignore
    rationale) therefore means a *fresh uninterrupted* fetch from the pinned URL; a resumed
    fetch is content/label-equivalent but its `game_id` tags may differ. Tests pin the
    **within-call** multiset+order determinism only; cross-process resume is pinned at the
    content level (FEN+label multiset), not the `game_id` tag.

### 1.7 Gitignore
Replace the `bench/corpus/shard.bin`/`val.bin`/`pgn-shard.bin` lines with
`bench/corpus/**/lane.bin`, `bench/corpus/**/checkpoint.bin`, `bench/corpus/**/pending/`;
keep `fetch-state.json`. Committed test fixtures (under `tests/`, the vendored
`bench/data/openings.epd`) are NOT ignored.

## 3. Test plan (TDD — write + review before implementation)

**`pipeline.rs` units:** dedup-first-seen-within-lane; cap caps at 10 (deterministic per
`cap_seed`); dedup-then-cap order (mirror old `consumer_inline_cap_on_dedup_survivors`);
target truncates partial boundary game + `target_reached`; empty-post-dedup → no block;
resume reconstructs fen_set+count+ids and drops a re-committed dup (resume-invariance);
target resume-invariance (1.99M on disk + target 2M commits only the missing 0.01M).

**self-play / consumer:** keep determinism + worker-count-invariance + fresh-vs-warm tests,
re-point to `lane.bin`, drop `val_fraction`/`split_seed`; **delete** the split-routing test;
route assertions through `LaneCommitter`; keep ghost-pending/torn/wedge/poll tests.

**fetch (`tests/corpus_fetch.rs` + lib) — CRITICAL fixture fix (reviewer CRITICAL):** the
current fixture builds EVERY game from one shared `MOVETEXT_22PLY` (the per-game `noise()`
only varies the `Site` tag, not the positions). Under inline per-lane dedup, game 0
contributes its usable FENs and every later game is 100% duplicate → ZERO, so the corpus
saturates at one game's worth and the `n_games × POSITIONS_PER_GAME` model (and the
`target=700` early-termination test) break. **Resolution: replace the shared movetext with a
per-game-distinct legal-movetext generator** (parameterize by game index — e.g. a distinct
legal opening per game so post-skip8 FENs are fresh across games), so each game yields fresh
FENs and the per-game-count model holds. **Then recompute the golden usable-per-game count**
(post-skip8 + post-quiet + dedup + cap) by running `static_eval_white`+`QSearcher`+
`is_quiet`+skip8 over ONE distinct game's positions and pinning the literal;
`POSITIONS_PER_GAME` (raw) → `USABLE_PER_GAME` (post-pipeline) across the affected
assertions. New tests: `fetch_target_counts_usable_not_raw` (assert `positions_ingested ==
target` EXACTLY + `EarlyTarget`), `fetch_per_lane_dedup_drops_repeat_fen`,
`fetch_quiet_filter_applied` (a fixture position with a hanging piece is dropped),
`fetch_empty_post_dedup_game_idempotent_across_byte0_restart` (uses `DropOnceIgnoreRange`;
assertion set per §1.4); keep idempotence/resume/stall/early-term re-pointed.

**cross-lane (`tests/corpus_lanes.rs`, NEW):**
`same_fen_admitted_in_multiple_lanes_with_conflicting_labels` (both retain it, labels
differ — pins the accepted conflict); `no_cross_lane_dedup`.

**reproducibility:** both tests — `rerun_byte_identical` and `rerun_byte_identical_across_k`

digests across fresh runs and across K∈{1,4,10}; no `val.bin`, no `--val-fraction`. (The
K-invariance test already runs selfplay alone, so it mostly needs `shard.bin`→`lane.bin` +

**crash-safety:** all `shard.bin`→`lane.bin`; drop `val.bin`/`--val-fraction`/`--split-seed`

## 6. Risks / migration
- **Frozen-artifact format change:** no committed binaries (all gitignored) → no in-repo
  migration; operator regenerates local `bench/corpus/` dirs. Old schema-v1 manifests parse
  gracefully (tolerant key read) but lanes are regenerated, not migrated.
- **Self-play 2M-usable ≈ ~200K games** (with skip8+quiet+cap=10, usable/game < 10) — tens
  of CPU-hours per self-play lane. **Operator concern, not a landing gate:** the landing
  artifact + gate run on a tiny corpus (M6.G precedent); 8M is the M6.I-operator goal.
- **Fetch URL pinning + resume determinism:** CCRL filename embeds a changing game count →
  `--url` required, written to `source_url`; `re-run.sh` checks the source SHA and FAILs
  loudly on upstream drift. Fetch reproducibility class = "weaker (re-derivable)" —
  UNCHANGED from ADR-0035 §8. Per the §1.6 carve-out: a *fresh uninterrupted* fetch from the
  pinned URL is byte-identical; a *resumed* fetch is content/label-equivalent (same FEN+label
  multiset) but its `game_id` provenance tags may shift. The gitignore/"re-acquirable"
  rationale rests on the fresh-uninterrupted guarantee.
- **Conflicting-label-across-lanes accepted** (intended; M6.I mixer's problem). ADR-0003
  audit is per-lane (each lane's labels are original outcomes) → still passes per lane.
- **M6.I contract change (no code breaks today — M6.I unbuilt):** M6.I reads four flat
  `lane.bin` dirs, does the inter-lane mix AND the train/val split, tunes on
  `static_eval_white` (per-lane quiet certificate holds). Recorded in ADR-0035 §12 + the
  `mod.rs` contract comment.
- **Mutants:** removing `dedup_fen`/`split.rs` removes their mutants; `--in-diff` sees the
  new `pipeline.rs`. Carry the consumer's `room`/`saturating_sub` target-truncation
  boundary tests into `pipeline.rs`.
- **`QSearcher` on the fetch hot path:** same per-position cost self-play already pays;
  per-call-reused (not per-position-allocated). Does NOT touch `evaluate`/search behavior
  (existing `QSearcher::eval_white` seam) → engine bench unaffected; cost is in the `corpus`
  binary only.
