# M6.B — Pawn structure + pawn hash (plan)

Second M6 sub-phase. Adds isolated / doubled / backward / connected pawn-structure
terms + passed-pawn *detection* to `evaluate()`, accelerated by a search-owned
pawn hash table keyed by a pawn-only Zobrist substream maintained incrementally
in make/unmake.

- Research: [`docs/research/m6-pawn-structure.md`](../research/m6-pawn-structure.md).
- ADR: [`docs/decisions/0032-pawn-structure-and-pawn-hash.md`](../decisions/0032-pawn-structure-and-pawn-hash.md) (written with this plan).
- Builds on M6.A's tapered `(static_mg_white, static_eg_white, raw_phase)`
  representation (ADR-0031) and ADR-0009's Polyglot Zobrist.

## 1. Scope

In:
- Pawn-only Zobrist substream `pawn_zobrist: u64` on `Position` + `Undo`,
  covering all twelve pawn-touching `MoveFlag` arms via the structural
  three-XOR form (§5), reusing the Polyglot pawn keys.
- `PawnHashTable` (fixed 4 MiB, always-replace) owned by `AlphaBetaMover`.
- Pawn-structure terms: isolated, doubled, backward, connected (rank-scaled),
  passed-pawn detection (`passed_pawns[2]` bitboards).
- `evaluate_cached(pos, &mut PawnHashTable)` hot-path entry; pure `evaluate`
  preserved and provably equal.
- Bitboard fill primitives (general-purpose) added to `src/bitboard.rs`.

Out (deferred): passed-pawn *bonus* (M6.C), pawn-shield/king-safety reads of the
hash (M6.E), candidate passers, half-open-file backward amplification, Texel
weight calibration (M6.H).

## 2. Decisions (rationale in research note / ADR-0032)

| # | Decision |
|---|---|
| D1 | Pawn-Zobrist = **reuse Polyglot pawn keys** (`zobrist::piece_key(pawn, sq)` accumulated). No new vendored constants. Alternative (separate key set) rejected — see ADR-0032. |
| D2 | Pawn hash **search-owned, fixed 4 MiB, no UCI option**. Field on `AlphaBetaMover`; cleared in `Search::reset()` (fires on `ucinewgame` + per bench position). |
| D3 | Pawn structure lives **only in `evaluate()`**, not the incremental `static_eval_white()` accessor — RFP/NMP/FFP pruning inputs unchanged (M6.A precedent for bishop-pair/mop-up). |
| D4 | Entry caches **only `(key, mg, eg, passed[2])`** — every field has a live M6.B/M6.C consumer. The roadmap row's "isolated/doubled/backward/connected flag bitmaps" are *not* cached (no consumer; the score already integrates them; M6.E will add pawn-shield when it needs it). Deliberate deviation from the illustrative roadmap list — flagged for plan-review/user. |
| D5 | Backward = CPW-simple predicate. **Connected** = the CPW bitboard predicate `phalanx \| defended`, where `phalanx` = own pawns with an own pawn on an adjacent file of the *same* rank, and `defended` = own pawns standing on a square attacked by another own pawn (i.e. defended-from-behind). A lone defender that is itself neither defended nor in a phalanx is **not** connected (e.g. a solitary c3→d4 chain → connected = `{d4}` only, not c3). One rank-scaled bonus per connected pawn by relative rank. Doubled = per extra pawn on file. |
| D6 | `evaluate_cached` is a **pure accelerator**: `evaluate_cached(p, h) == evaluate(p)` for all p, any h state. Pinned by a proptest. |

## 4. Type / signature surface

`src/eval/pawns.rs`:

```rust
/// White-perspective pawn-structure eval + cached detection bitboards.
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub(crate) struct PawnEval {
    pub mg: i32,            // white-persp pawn-structure MG contribution
    pub eg: i32,            // white-persp pawn-structure EG contribution
    pub passed: [Bitboard; 2],   // passed_pawns[White], [Black] (M6.C reads)
}

/// Compute pawn-structure eval from scratch (no cache). Single source of truth.
pub(crate) fn pawn_eval(pos: &Position) -> PawnEval;

const PAWN_HASH_MIB: usize = 4;
const PAWN_HASH_ENTRIES: usize = PAWN_HASH_MIB * 1024 * 1024 / 32; // 2^17

#[derive(Copy, Clone)]
#[repr(C)]
struct PawnHashEntry { key: u64, mg: i16, eg: i16, passed: [Bitboard; 2] }
// Pin the 4-MiB/entry-count arithmetic against a future field reorder:
const _: () = assert!(core::mem::size_of::<PawnHashEntry>() == 32);

pub(crate) struct PawnHashTable { entries: Box<[PawnHashEntry]> }

impl PawnHashTable {
    pub(crate) fn new() -> Self;          // zeroed; key 0 = empty sentinel
    pub(crate) fn clear(&mut self);
    /// Probe-or-compute: returns PawnEval; on miss computes via pawn_eval + stores.
    pub(crate) fn get(&mut self, pos: &Position) -> PawnEval;
}
```

## 5. Pawn-Zobrist substream — structural form (mov.rs `update_zobrist_after_make`)

**Mirror the existing unified design, do not introduce a flag match.** The
existing `update_zobrist_after_make` (src/mov.rs:1014–1027) collapses all
twelve arms into three XOR sites — mover out@`from`, `lands_as` in@`to`,
captured out@`capture_sq` — with no per-`MoveFlag` match for the piece keys;
EP correctness falls out of the upstream-computed `capture_sq` and promotion
out of `mv.promotion_kind()`. The pawn substream is *the same shape restricted
to pawns*. Add, after the main-zobrist block, a parallel
`pz = undo.prior_pawn_zobrist` accumulation written via
`pos.refresh_pawn_zobrist_from(pz)`, with exactly three conditional XOR sites:

```text
let is_pawn_mover = mover.kind == Pawn;       // mover is by-value param — no pos read
// (a) mover pawn leaves `from` (always, when a pawn moves at all):
if is_pawn_mover { pz ^= pk(us, from); }
// (b) a pawn lands on `to` ONLY for a non-promoting pawn move
//     (promotions: the pawn leaves, a non-pawn arrives → no pawn in):
if is_pawn_mover && mv.promotion_kind().is_none() { pz ^= pk(us, to); }
// (c) a captured pawn leaves its actual square (capture_sq == to except EP):
if let Some(v) = captured { if v.kind == Pawn { pz ^= pk(them, capture_sq); } }
```

`pk(c, sq) = zobrist::piece_key(Piece::new(c, Pawn), sq)`. This is correct for
all twelve arms by construction:
- EP: `is_pawn_mover` true, not a promo → (a)+(b) on the capturer; (c) fires
  with `capture_sq ≠ to` (the value upstream already computed for the main
  zobrist) → the three-square delta is automatic, no EP arm needed.
- `*Promo`: (a) only — pawn leaves, (b) suppressed by `promotion_kind().is_some()`.
- `*PromoCapture`: (a) + (c) — (b) suppressed. **The (c) victim is never a
  pawn here**: a promo-capture victim sits on the mover's promotion (back)
  rank, and a pawn can never occupy its opponent's back rank (it would have
  already promoted). So `if victim.kind == Pawn` is statically false for
  promo-captures — the structural form is trivially correct for them (only
  the non-pawn-victim removal at `to` happens, which is *not* a pawn-key
  delta). **EP is therefore the only two-pawn-removal pawn-key case.** This
  corrects the research/roadmap flag-arm enumeration item "promo-capture, pawn
  victim → second removal," which is geometrically vacuous.
- Castling: `mover.kind == King` → none fire (castling never moves a pawn).

`mover`/`captured`/`capture_sq` are all **by-value parameters** of the helper
(order-agnostic boundary, §8) — the pawn block reads no mutable `pos` state,
matching the existing helper's discipline.

`unmake_move`: restore via `pos.refresh_pawn_zobrist_from(undo.prior_pawn_zobrist)`
(structural, same pattern as the main zobrist restore).

Debug round-trip asserts in `make_move`/`unmake_move` extended with:
```
debug_assert_eq!(pos.pawn_zobrist(), zobrist::pawn_zobrist_from_scratch(pos),
                 "incremental pawn_zobrist diverged after make_move {mv:?}");
```
(and the unmake mirror). Null move (`make_null_move`) does not move pawns →
`pawn_zobrist` untouched; add an assert there too for safety.

## 6. `pawn_eval` algorithm (white-perspective accumulation)

```
wp = pos.pieces_colored(White, Pawn); bp = pos.pieces_colored(Black, Pawn)
for (side, own, enemy, sign) in [(White, wp, bp, +1), (Black, bp, wp, -1)]:
    iso  = isolated_pawns(own)
    dbl  = doubled_pawns(own)              // per-extra-pawn set
    bwd  = backward_pawns(own, enemy, side)
    con  = connected_pawns(own, side)
    mg += sign * ( ISO_MG*|iso| + DBL_MG*|dbl| + BWD_MG*|bwd|
                   + Σ_{p∈con} CONN_MG[rank_of(p, side)] )
    eg += sign * ( ... EG analogues ... )
    passed[side] = passed_pawns(own, enemy, side)
return PawnEval { mg, eg, passed }
```

- `|x|` = popcount. ISO/DBL/BWD weights are negative (penalties); CONN positive.
- `rank_of(p, side)` = white: `sq.rank()`; black: `7 - sq.rank()` (relative
  advancement). `CONN_MG`/`CONN_EG` are 8-entry tables indexed by relative rank
  (ranks 0/1/6/7 unreachable for a *pawn* → entries 0; only 1..6 used; entry
  layout pinned by test).
- Isolated/doubled/backward **stack** (no if-else suppression) — simplest,
  Texel reconciles in M6.H. Pinned by a doubled+isolated fixture test.
- Black predicates are the white bitboard formulas with the shift/fill
  directions reversed (bit-reversed *formula*, not a mirrored `Position`).
  Color symmetry is pinned by the §9 mirrored-FEN-pair fixtures + per-term
  popcount equality — there is no general `mirror(pos)` helper and no
  property test over one.

`evaluate_core(pos, pe)` = current `evaluate` body with the blend
`((mg + bp_mg + pe.mg) * phase + (eg + bp_eg + pe.eg) * (24 - phase)) / 24
+ mop_up`, identical insufficient-material short-circuit and STM flip.
**Mop-up is unchanged from M6.A:** `mop_up_term_white(pos, mg, eg)` is called
with the **PST-only** `mg`/`eg` (`pos.static_mg_white()`/`static_eg_white()`),
*excluding* bishop-pair *and* pawn structure — exactly the M6.A precedent
(src/eval.rs:188–193: the mop-up advantage estimate deliberately excludes
non-PST addends). Pawn structure must NOT enter the mop-up advantage estimate;
a regression assertion (§9) pins a mop-up-eligible fixture's addend equal to
its M6.A value.
`evaluate(pos)` = `evaluate_core(pos, pawn_eval(pos))`.
`evaluate_cached(pos, ph)` = `evaluate_core(pos, ph.get(pos))`.

`PawnHashTable::get`: `key = pos.pawn_zobrist()`. **`key == 0` is never
cached** — it is both the zeroed-slot sentinel *and* a reachable real value
(the no-pawns position XORs to 0; some symmetric pawn structures too). For
`key == 0`, `get` recomputes `pawn_eval(pos)` and returns without probe or
store (correctness-neutral — D6 still holds; these positions are vanishingly
rare and the no-pawn pawn-eval is trivially `(0, 0, empty passers)`). Else
`idx = (key as usize) & (ENTRIES-1)`; if `entries[idx].key == key` →
reconstruct `PawnEval` (i16→i32); else compute `pawn_eval(pos)`, store
(`debug_assert` scores in i16 range — always true), return.

## 8. Parallelization map

- **Wave 1 (parallel, independent):**
  - Slice A — `src/bitboard.rs` fill/span primitives + tests.
  - Slice B — `pawn_zobrist` plumbing (position.rs, zobrist.rs, fen.rs init,
    mov.rs Undo field + structural delta + asserts). **Flag `model: opus`** —
    *order-agnostic-parameter-discipline* application: the
    `update_zobrist_after_make` boundary is explicitly order-agnostic (all
    prior/new values are by-value params, no mid-helper `pos` reads). An
    implementer who reads mutable `pos` state inside the helper reintroduces
    the M3.A `update_static_eval` ordering bug from the calibration log. The
    structural §5 form makes the *logic* prescriptive transcription, but the
    parameter-discipline judgment (do not byte-duplicate the existing helper;
    derive `us`/`them` from the `mover` param, not `pos.side_to_move()`) is the
    Opus-flag trigger per workflow.md "parallel-precedent / project-discipline

  - Slice C — `pawns.rs` (depends on A's span helpers).
  - Slice D — `eval.rs` refactor (depends on C's `PawnEval`/`pawn_eval`).
- **Wave 3 (after D):**
  - Slice E — `search.rs` wiring + bench re-pin (depends on D's `evaluate_cached`).

## 9. Test coverage strategy

**Bitboard primitives (Slice A).** `north_fill`/`south_fill`/`file_fill` on
single squares, full files, empty; `*_front_spans` exclude the pawn's own
square (off-by-one guard: e5 white front-span = {e6,e7,e8}); attack-front-spans
cover the diagonal capture files. Property: `file_fill(file_fill(x)) ==
file_fill(x)` (idempotent).

**Pawn-Zobrist substream (Slice B) — the correctness core.**
- `pawn_zobrist_startpos_nonzero_and_from_scratch_matches`.
- Per-arm round-trip: for each of quiet-pawn, double-push, pawn-capture,
  capture-of-pawn-by-piece, **`en_passant_pawn_zobrist_roundtrip`** (asserts
  three-square delta + restore — the *only* two-pawn-removal pawn-key case),
  each of 4 promos, each of 4 promo-captures (knight/other non-pawn victim —
  a pawn victim is geometrically impossible on the back rank, see §5) —
  make then unmake, assert key returns to prior. The two-pawn-removal failure
  mode is covered by the EP test + a promo-capture test pinning the (a)-only
  shape on a non-pawn victim.
- `pawn_zobrist_unchanged_on_non_pawn_quiet` (knight move: delta 0).
- `pawn_zobrist_unchanged_on_castling`.
- `pawn_zobrist_unchanged_on_null_move`.
- `pawn_zobrist_startpos_zero_only_if_no_pawns` / a constructed no-pawn
  position asserting `pawn_zobrist == 0` (pins the key==0-is-reachable
  decision; `get` on it returns correct `(0,0,empty)` and does not corrupt
  the table).
- The EP `capture_sq`-vs-`to` correctness is a **`cargo mutants` expected-
  killed-mutant** (the structural §5 form derives it from `capture_sq`); the
  `en_passant_pawn_zobrist_roundtrip` test must kill the `capture_sq → to`
  mutant — verified at the mechanical-check step via manual mutation per
  `.cargo/mutants.toml` triage (an unrunnable broken-impl negative test is not
  committed; this is exit-criteria §11, not a test file).
- Property: random legal-move walk (reuse the C4 proptest infra in mov.rs),
  assert `pos.pawn_zobrist() == pawn_zobrist_from_scratch(pos)` every ply.

**Per-term (Slice C).** One constructed FEN per predicate with hand-derived
expected bitboard/popcount: isolated (a-file isolani; center isolani),
doubled (doubled pair → 1; tripled → 2), backward (CPW-simple positive +
a near-miss where the stop sq is *not* enemy-attacked → not backward),
connected (phalanx → both members; lone chain c3→d4 → connected = `{d4}`
*only*, the bare defender c3 excluded per D5; rank-scaling: same shape rank 3
vs rank 6 gives larger bonus), passed (clear passer; blocked-by-adjacent-enemy
not passer; doubled rear pawn not passer). **Color symmetry** is pinned **per
term** (isolated, doubled, backward, connected — not isolated alone) by
hand-constructed **mirrored-FEN-pair fixtures** (no general position-mirror
helper — that would itself be an error-prone, separately-tested dependency):
for each term, a white-structure FEN and its hand-written vertical mirror with
colors swapped, asserting white-term popcount on the first equals black-term
popcount on the second and `pawn_eval` components are componentwise-negated
across the pair. Isolated+doubled stacking fixture (both penalties apply, no
if-else suppression — pins D5).

**Pawn hash (Slice C).** `get` miss-then-hit returns equal `PawnEval`;
`clear` forces miss; collision slot (two keys same idx) → second overwrites,
verification key rejects stale; `get` never panics on i16 range
(debug_assert).

**Eval integration (Slice D — authored by D's test author; exercises
Slice-C `PawnHashTable` + Slice-D `evaluate_cached` per §8's
test-author-per-slice rule).** `evaluate_cached_equals_evaluate` proptest
(random positions + random pre-populated/cleared hash → equal) — pins D6.
`evaluate` unchanged on pawn-free positions (== M6.A value: regression-guard
against accidental non-pawn-core drift). Startpos `evaluate == 0` (symmetric
pawn structure cancels). Insufficient-material short-circuit still 0.

**Search (Slice E).** `pawn_hash_cleared_on_reset`; bench determinism
(`bench` twice same HEAD → identical) ; `evaluate_cached` used by qsearch
(behavioral: a position where pawn structure changes the qsearch leaf score).

**Extended perft (Slice B/step 3 gate).** make/unmake delta touched →
`canonical_six_d4_heavy_slow`, `canonical_six_d5_slow`,
`whittington_epd_d4_slow` before commit.

## 10. Risks

| R | Risk | Mitigation |
|---|---|---|
| R1 | EP / promo-capture pawn-key desync (silent cache corruption). | Dedicated round-trip tests + always-on debug from-scratch assert + extended perft. |
| R2 | `evaluate_cached` ≠ `evaluate` (cache not a pure accelerator). | D6 proptest over random positions × hash states. |
| R3 | Backward predicate wrong (definition divergence). | CPW-simple, fixed in ADR-0032; positive + near-miss fixtures. |
| R4 | NPS regression > 10% (whole-board pawn scan even with cache). | Bench NPS recorded; >10% = should-investigate (roadmap policy). The hash is the mitigation; hit rate expected ≥95%. |
| R5 | Bench node count shifts (pawn eval changes qsearch leaf scores → ordering). | Expected & allowed from M6.A onward (roadmap). Re-pin signatures; determinism still required. |
| R6 | Color-perspective sign error. | `sign`-based accumulation + §9 mirrored-FEN-pair fixtures (per-term popcount equality + componentwise negation). |
| R7 | i16 entry overflow on extreme pawn structures. | `debug_assert` range; worst-case Σ bounded well under ±32767. |

## 11. Exit criteria

- All tests + extended perft green; fmt/clippy clean.
- `cargo mutants --in-diff` survivors triaged/closed per workflow. The EP
  `capture_sq → to` mutant on the §5 pawn block must be in the **caught** set
  (killed by `en_passant_pawn_zobrist_roundtrip`); verify by manual mutation.
- Mop-up-addend-unchanged-vs-M6.A regression assertion green (pins §6: pawn
  structure excluded from the mop-up advantage estimate).
- Final-review loop convergent.
- Bench deterministic at new HEAD; NPS drop ≤ 10% (else documented).
- WAC + STS same-campaign re-baseline vs `M6.A` (RUN ALONE). **Per-theme
  secondary gate:** M6.B claims STS themes "Advancement of a/b/c pawns",
  "Advancement of d/e/f/g/h pawns", "Pawn Play" (verify exact STS theme names

  regression" per M5.F precedent (roadmap M6 expects +20–40 Elo).
- Stockfish calibration only if SPRT delta ≳ +30 (judgment; M6.B prior is
  +20–40, below the usual trigger — likely documentation-skip with in-chat
