# M4.B — Killer moves

Second M4 phase. Adds two killer slots per ply, updated on quiet-move beta cutoffs and folded into negamax move ordering between captures/promos and remaining quiets. Builds on M4.A (TT + TT-move-first ordering); does not touch qsearch.

Research synthesis: `docs/research/m4-killer-moves.md`. Lands no new ADR — killers are a parameter-level addition, fully captured by this plan + the research note.

## 0. Goals

- New `killers: [[Move; 2]; MAX_PLY]` field on `AlphaBetaMover`. `Move` is `repr(transparent)` over `u16`, so the table is exactly `[[u16; 2]; 64] = 256 bytes` — fits in L1, matches research §8's recommended shape with no `Option<Move>` 2× memory penalty. Sentinel = `Move::default()` (`bits() == 0` per `mov.rs` doc-comment), same convention as `PvTable.moves` and the TT's no-move marker. **Two slots is universal** in the literature (research §2; Bob Hyatt rationale: slot 0 = persistent refutation, slot 1 = local refutation; 1-slot is weaker, 3+ adds uniqueness-maintenance overhead beyond gain). Ordered by recency (slot 0 = most-recent).
- New free helpers in `search.rs`, all directly unit-testable to make mutations catchable per the M3.D `negate_window` + M3.E `aborted_fallback_result` precedent:
  - `is_quiet(mv: Move) -> bool` — true iff `flag ∈ {Quiet, DoublePush, KingCastle, QueenCastle}`. Used for the killer update gate (only quiet beta-cutoffs update killers).
  - `update_killers(killers: &mut [[Move; 2]; MAX_PLY], ply: usize, mv: Move)` — shift-on-distinct: if `mv == killers[ply][0]` → no-op; else `killers[ply][1] = killers[ply][0]; killers[ply][0] = mv`.
  - `negamax_move_order_score(mv: Move, pos: &Position, killer0: Move, killer1: Move) -> i32` — wraps `mvv_lva_score`. For non-quiet moves returns `mvv_lva_score`. For quiet moves: returns `KILLER0_SCORE` if `mv == killer0`, `KILLER1_SCORE` if `mv == killer1`, else `0`. Constants pinned strictly between `0` and the smallest MVV-LVA capture (QxP = 82·16 − 1025 = 287 cp under our `victim × 16 − attacker` formula at search.rs:861) so killers slot above remaining quiets but below all captures and promos. **Values: `KILLER0_SCORE = 200`, `KILLER1_SCORE = 100`** — research §6 recommendation; M4.C will fit history scores into `[0, 99]` below killer1.
  - `order_moves(moves_vec: &mut Vec<Move>, pos: &Position, killer0: Move, killer1: Move, tt_move: u16)` — pure function that performs M4.B's full move-ordering pass: (a) `sort_by_cached_key(|&m| -negamax_move_order_score(m, pos, killer0, killer1))` descending, then (b) if `tt_move != 0`, find the TT move in the list by `m.bits() == tt_move` and swap it to index 0. Direct extraction of step 10's body into a named helper so that ordering invariants — TT-killer overlap, stale-bits-fallthrough, killer-above-quiet boundary, capture-above-killer boundary — are unit-testable in isolation against synthetic move lists. M3.D `negate_window` + M3.E `aborted_fallback_result` precedent.
  - `clear_killers(killers: &mut [[Move; 2]; MAX_PLY])` — free function that zeroes the table to `[[Move::default(); 2]; MAX_PLY]`. Single-statement body, but extracting the zero-fill into a named helper lets per-go / per-iteration / `Search::reset` call sites all share one lowering and lets mutation tests target the helper directly (the `[[Move::default(); 2]; MAX_PLY]` literal at multiple call sites would be three indistinguishable mutants pre-extraction).

- `AlphaBetaMover::negamax` body delta:
  - **Step 10 (ordering)** is replaced with a single call to `order_moves(&mut moves_vec, pos, self.killers[ply][0], self.killers[ply][1], tt_move)`. The pre-existing M4.A inline `sort_by_cached_key` + TT-move-first swap moves into `order_moves`'s body verbatim (modulo `mvv_lva_score` → `negamax_move_order_score`).
  - **Step 11 (recursion + cutoff)** adds a single conditional after the existing `cutoff_move = Some(mv); break;` line: when the cutoff fires AND `is_quiet(mv)`, call `update_killers(&mut self.killers, ply as usize, mv)` BEFORE the break. Captures/promos cutting fail the quiet-gate and don't dilute the slot.
- `Search::go` per-go reset: call `clear_killers(&mut self.killers)`. Per-iteration reset (top of the ID for-loop): same. **Inter-iteration policy: clear between iterations** — research §7 confirms as the defensible default. Research notes the persist-vs-clear question is genuinely unsettled (no direct Elo measurement found), but ships clear because (a) it is the only side with explicit forum guidance ([(TalkChess t=20068)](https://talkchess.com/viewtopic.php?t=20068) "Reset all killer array elements to 0" before progressive deepening), and (b) M4.D will revisit "persist across aspiration re-searches at the same depth" when aspiration re-search semantics become directly observable. (The plan's earlier reference to "consistent with M4.A's bench-determinism" is dropped — bench-determinism is a between-bench-position contract, not a between-iteration contract; the two are distinct lifecycle boundaries.)
- `Search::reset` calls `clear_killers(&mut self.killers)` (consumed by `handle_ucinewgame` via `Engine::reset_for_new_game`). M4.A established the discipline that engine-level `reset_for_new_game` calls `Search::reset` for any search-internal per-game state; killers are exactly that.
- No engine-side change. No UCI option. No new ADR. No qsearch change.
- SPRT and cargo-mutants run separately (per user directive: SPRT happens at merge-time; mutation testing deferred to a dedicated overnight campaign). The plan includes the mutant-prep but not the run.

## 1. Out of scope

- History heuristic (M4.C). The killer/history split is intentional: killers are a 2-slot exact-match table; history is a `(piece, to)` or `(from, to)` numeric counter table. Both consumed by the same ordering pass at M4.C, but landed separately so the M4.C SPRT measures history's marginal contribution.
- Aspiration windows (M4.D). The persist-vs-clear decision is conditional on aspiration's same-depth re-search semantics; deferring is fine because **the M4.B plan ships clear-between-iterations**, which works under both schemes — a re-search at the same depth restarts with empty killers. M4.D revisits if killer persistence within a single re-search cycle proves SPRT-positive.
- Qsearch participation. Killers don't apply to qsearch: qsearch's move list is captures + queen-promos + (in-check) full evasions, all of which are either non-quiet (so killer-ineligible by the M4.B update rule) or in-check evasions where the killer slots from a distant negamax frame don't generalize.
- Per-side / per-color killer split. Some engines key killers on `(side, ply)` rather than `ply`; ply alone is the M4.B baseline (CPW default; SPRT-tunable later if interesting).
- TT-move-and-killer overlap mitigation. Stale or duplicate handling is implicit under the unified-score approach (research §14 question 3 picks unified): in step 10's sort, a TT-move that happens to equal `killer0` is sorted with `KILLER0_SCORE`, then the post-sort TT-move-first swap unconditionally promotes it to index 0. The TT-move appears once in the move list — never tried twice. Pinned by S24e (constructed fixture: TT move == killer[0]; post-`order_moves` list has the move at index 0 and exactly once).
- Killer legality re-check via separate scan. The post-sort step compares moves against the **current ply's legal-move list** (the `moves_vec` produced by `generate_moves`); a stale killer from a different position whose bits don't match any legal move at this ply simply never moves to the front. Same defense-in-depth that the TT move enjoys per M4.A's "legality scan over the legal-move list rejects garbage values" (ADR-0018 §12). Research §9 + §12 confirm legal-list scan is the recommended approach; mirrors the TT-move check. No explicit `is_legal` call needed.
- "Cousin-killer" zeroing of `killers[ply+1]` on node entry (HGM's recommendation per research §14 question 4). Deferred — research notes the legality scan already mitigates the cousin-illegal-attempt risk. Add only if M4.C surfaces an ordering bug traceable to ply+1 contamination.
- Killers from `ply - 2` (research §13). Deferred per research recommendation; standard current-ply-only baseline first; revisit if M4.C history doesn't fully subsume the gain.
- Mate killer slot (a separate priority-above-captures slot for moves that refute with checkmate; CPW §11). Research §11 + §15 row 9 confirm: M4.B updates killers on **any** quiet beta-cutoff regardless of score magnitude (mates included). The dedicated mate-killer slot is a M5+ refinement.

### 3.2 `is_quiet`

```rust
/// Returns true iff `mv` is a non-capture, non-promotion, non-en-passant
/// move (the moves eligible to populate the killer slots).
///
/// Direct mirror of the existing MVV-LVA "quiets sort below all captures"
/// arm in `mvv_lva_score`. Free function so `cargo mutants` reports any
/// flag-bit mutation directly against this function's name.
fn is_quiet(mv: Move) -> bool {
    use crate::mov::MoveFlag::*;
    matches!(mv.flag(), Quiet | DoublePush | KingCastle | QueenCastle)
}
```

### 3.3 `update_killers`

```rust
/// Shift-on-distinct killer update.
///
/// `mv == killers[ply][0]` → no-op. Otherwise:
///     killers[ply][1] = killers[ply][0];
///     killers[ply][0] = mv;
///
/// Caller is responsible for the quiet-gate — `update_killers` doesn't
/// re-check `is_quiet(mv)`; it trusts the caller. Free function so the
/// shift is unit-testable in isolation (M3.D `negate_window` precedent).
fn update_killers(killers: &mut [[Move; 2]; MAX_PLY], ply: usize, mv: Move) {
    if killers[ply][0] != mv {
        killers[ply][1] = killers[ply][0];
        killers[ply][0] = mv;
    }
}
```

### 3.4 `negamax_move_order_score`

```rust
/// Killer-aware move-ordering score for negamax (NOT qsearch). Wraps
/// `mvv_lva_score`:
///   - non-quiet move → `mvv_lva_score(mv, pos)` (captures/promos).
///   - quiet move matching `killer0` → `KILLER0_SCORE`.
///   - quiet move matching `killer1` (and not `killer0`) → `KILLER1_SCORE`.
///   - other quiet → `0`.
///
/// Boundary discipline: `KILLER0_SCORE > KILLER1_SCORE > 0` and both
/// strictly less than the smallest possible MVV-LVA capture score
/// (QxP = 82·16 − 1025 = 287 cp under our `victim × 16 − attacker` formula).
/// Pinned by S23 — which constructs a real QxP at runtime and asserts
/// `KILLER0_SCORE < mvv_lva_score(qxp_move, &qxp_pos)` so the bound
/// follows the formula and PeSTO MG values rather than hardcoding 287.
fn negamax_move_order_score(
    mv: Move,
    pos: &Position,
    killer0: Move,
    killer1: Move,
) -> i32 {
    if !is_quiet(mv) {
        return mvv_lva_score(mv, pos);
    }
    if mv == killer0 {
        KILLER0_SCORE
    } else if mv == killer1 {
        KILLER1_SCORE
    } else {
        0
    }
}

const KILLER0_SCORE: i32 = 200;  // any value strictly between 0 and mvv_lva_score(QxP, _)
const KILLER1_SCORE: i32 = 100;  // any value strictly less than KILLER0_SCORE and > 0
```

The Move-equality test uses `PartialEq`/`Eq` — `Move` already derives both via `repr(transparent)` over `u16`. `Move::default() == Move::default()` is true (both are 0); the sentinel-empty slot will not match a real move because `Move::default()` decodes as `from=A1, to=A1, flag=Quiet`, never produced by movegen (a1→a1 is illegal — `mov.rs` line 152 doc-comment guarantees this).

### 3.5 `order_moves`

```rust
/// Apply M4.B's full move-ordering pass. Pure function; no side effects;
/// directly unit-testable on synthetic move lists.
///
/// Two-step:
///   1. Sort `moves_vec` descending by `negamax_move_order_score`.
///      Captures/promos rank above killers; killers above other quiets.
///   2. If `tt_move != 0` AND `tt_move` is found in the (now-sorted) list
///      AND it is not already at index 0, swap it to index 0.
///
/// **Killer legality discipline:** stale killers whose bits do not match
/// any legal move at this ply have no effect on ordering — the only path
/// by which a killer can move to the front is via `negamax_move_order_score`
/// returning `KILLER0_SCORE`, which requires `mv == killer0`. If no `mv`
/// matches the killer's bits, the score for every entry is its capture
/// value or 0, and the post-sort order is identical to the empty-killer
/// baseline. Pinned by S24f. Mirrors M4.A's TT-move legality scan
/// (ADR-0018 §12).
///
/// **TT-killer overlap:** the post-sort swap is unconditional on the TT
/// move's pre-swap position. If `killer0 == tt_move`, the move is already
/// near index 0 (after captures); the swap then moves it to index 0
/// exactly. The move appears in the list once; never tried twice.
/// Pinned by S24e.
fn order_moves(
    moves_vec: &mut Vec<Move>,
    pos: &Position,
    killer0: Move,
    killer1: Move,
    tt_move: u16,
) {
    moves_vec.sort_by_cached_key(|&m| -negamax_move_order_score(m, pos, killer0, killer1));
    if tt_move != 0
        && let Some(idx) = moves_vec.iter().position(|m| m.bits() == tt_move)
        && idx != 0
    {
        let mv = moves_vec.remove(idx);
        moves_vec.insert(0, mv);
    }
}
```

### 3.6 `clear_killers`

```rust
/// Zero the killer table. Single-statement body, but extracted as a
/// named free helper so all three call sites (per-go reset,
/// per-iteration reset, `Search::reset`) lower through the same line —
/// mutation testing on `[[Move::default(); 2]; MAX_PLY]` then targets
/// one helper instead of three indistinguishable inline literals.
fn clear_killers(killers: &mut [[Move; 2]; MAX_PLY]) {
    *killers = [[Move::default(); 2]; MAX_PLY];
}
```

## 5. Test fixtures — concrete move/position picks

S24/S24b/S24c/S24d/S24e/S24f are pure unit tests over synthetic `moves_vec` constructed in-test (no FEN required); the only real fixture concern is producing a `Move` with a known capture flag for S22/S23 (a constructed `Move::new(from, to, MoveFlag::Capture)` at a square containing a pawn for victim, queen for attacker).

S25 + S25b + S26 are integration tests that drive `negamax_for_test` against real positions. They require **deterministic** quiet-cutoff fixtures so the assertion is reproducible:

- **S25 (quiet cutoff):** Position FEN `4k3/8/8/8/8/8/4N3/4K3 w - - 0 1` (KvN+K endgame; tentative — refine at test-writing time). Run `negamax_for_test(depth=2, ply=0, alpha=-100, beta=-50, is_pv=true, ...)` against the white-to-move position; the test then asserts `mover.killers[1][0] == cutoff_move` (a child-ply killer populated when negamax recurses into ply=1 and that child-ply's narrow window forces a quiet beta-cutoff). The narrow window forces a quick beta-cutoff at the child. **Validate at test-writing time** by adding a `dbg!(killers[1][0])` and confirming the quiet move populates. (Earlier draft of this fixture entered at `ply=1` directly, but `ply=1` implies the root move was already made; the corrected entry runs at `ply=0` with the test asserting on the populated child-ply slot.)
- **S25b (capture cutoff):** Engineering a depth-2 capture-cutoff at a specific ply is brittle (captures sort first by MVV-LVA, so the cutoff condition is window-dependent). **Default fallback:** replace the integration-test mechanism with a unit-level shim that exercises the cutoff branch logic directly. Justification: `is_quiet(capture_move)` is already pinned by S15 returning `false`; the call-site gate is one branch with no inline computation. A unit test that constructs a capture `mv`, calls `is_quiet(mv) → false`, then verifies the gate's structural shape via code review (final-review loop) is sufficient. The integration-test path is kept as an aspirational option if the implementer can engineer a stable fixture.
- **S26 (sibling-node ordering signal):** Two-run differential. Reuse the S6 (TT-move-ordering) fixture pattern: run (a) records nodes from depth-3 search at startpos; run (b) pre-populates `mover.killers[1] = [chosen_killer_quiet, default]` via the test setter. **Pre-killer-position pinning:** the chosen quiet must NOT be the post-MVV-LVA index-0 move in the empty-killer baseline (otherwise the test passes for the wrong reason). Pick the quiet at the lexicographically-last index of the legal-move list (after `MoveList::iter().collect()`); assert at test-construction time that it has MVV-LVA score 0 (i.e., is genuinely quiet, not an under-promo with non-zero score). Different ordering → different node count.

Fixture validation at test-writing time: each test that depends on a "specific quiet move causes cutoff" assertion gets a manual run with `dbg!()` to confirm the cutoff fires on the expected move. If the picked fixture doesn't cause the predicted cutoff, the test is rewritten (not the implementation).

**Boundary-constant discipline.** Mutations on `KILLER0_SCORE = 200` / `KILLER1_SCORE = 100` themselves (e.g. `200 → 0`) would survive a test that does `assert_eq!(score, KILLER0_SCORE)` because both sides of the equality compare two copies of the mutated value. ## 10. Parallelization map

**Available split, rejected for diff-locality reasons.** A genuine two-coder split exists:

- **Coder A** writes the free helpers (`is_quiet`, `update_killers`, `negamax_move_order_score`, `order_moves`, `clear_killers`) + their unit tests (S14–S24f, S27). All synthetic input; no `AlphaBetaMover` interaction beyond reading the field-shape `[[Move; 2]; MAX_PLY]`.

Coder A's diff lands first; Coder B rebases. Merge cost = one rebase (the `AlphaBetaMover` struct field is a 1-line addition).

**Decision: serial, single-coder.** The helpers + their tests + the call-site rewires + the integration tests together total ~250 LOC of new code in one file. A single Sonnet coder finishes in one pass; the rebase coordination cost of a parallel split exceeds the wall-clock savings. The reviewer's challenge ("don't fabricate the race-on-field rationale") is honored: this plan rejects parallelization for diff-locality + coordination-cost reasons, not for technical-blocker reasons. M3.D / M4.A coder-tier discipline confirms Sonnet handles prescriptive plans of this scope cleanly; no Opus override flags apply.
