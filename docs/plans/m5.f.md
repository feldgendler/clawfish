# M5.F — Qsearch in TT

Sixth M5 sub-phase. Adds **TT probe + store inside `qsearch`**, closing the +5–15 Elo gap acknowledged in ADR-0018 §6 when M4.A first shipped TT support and deliberately scoped qsearch out. M5.E landed first to ensure the TT does not memoize qsearch holes; M5.F is the immediate next phase.

Research synthesis: [`docs/research/m5-qsearch-in-tt.md`](../research/m5-qsearch-in-tt.md).

## 0. Goals

Five production changes:

1. **TT probe in qsearch.** At qsearch entry, after the per-frame node-counter / cancellation poll (step 1) and after the MAX_PLY ceiling guard (M5.E #4), but before mate-distance pruning, probe the TT. On a key hit:
   - Extract `tt_move` for ordering, but only retain it if it passes `qsearch_move_filter` (capture / EP / queen-promo) when not in check, or any legal move when in check.
   - For the score-cutoff probe, **do not depth-gate** (qsearch's notional depth is 0; any TT entry's depth is ≥ 0 and is therefore at least as deep). Apply the standard fail-soft cutoff:
     - `Exact` → return ply-adjusted `tt_score`.
     - `Lower` if `tt_score >= beta` → return `tt_score`.
     - `Upper` if `tt_score <= alpha` → return `tt_score`.
   - On miss / non-cutoff, retain `tt_move` for ordering; continue.

2. **TT store in qsearch.** At all real-result return points (stand-pat fail-high, stand-pat fail-low after move loop, true stalemate, mate at horizon, single-reply extension, completed move loop including under-promo extension), store the result. Use `depth = 0` for every qsearch entry. Bound classification:
   - `best >= beta` → `Lower`.
   - **Otherwise → `Upper`** (NEVER `Exact` for non-terminal qsearch). Per Stockfish 45e5e65: qsearch's restricted move set means an "exact" classification overstates precision; future probes could short-circuit a PV-node negamax with an unsound score.
   - **Two terminal exceptions** that are FIDE-definite regardless of move restriction: (a) true stalemate at qsearch returns `0` with bound `Exact`; (b) mate at horizon returns `-(MATE - ply)` with bound `Exact`.
   - Skip the store on the MAX_PLY ceiling guard (the return is an artificial truncation, not a search-quality bound).
   - Skip on `self.aborted` (existing pattern).

3. **Empty-slot discriminator change in `src/tt.rs`.** Storing depth=0 entries breaks the current `is_empty()` test (`key == 0 && depth == 0 && age_and_bound == 0 && best_move == 0`) — a stored qsearch entry with all-zero fields except `score` and `best_move` would alias with the default. The forward-planning comment in `src/tt.rs:222–224` already anticipates this. Replace `is_empty()` with **`self.key == 0`** as the sole discriminator, and add a `debug_assert!(key != 0, ...)` at the store call site to guarantee the sentinel is never accidentally written. The Polyglot Zobrist key of any reachable real position is non-zero with probability `1 − 2⁻⁶⁴`; the assertion is defense-in-depth for the impossible case.

4. **Replace the `data.depth >= 1` debug-assert in `store()`.** With qsearch entries at depth=0, the existing assert is incorrect. Drop it; replace with the `key != 0` assertion above.

5. **Negamax probe + qsearch interaction left unchanged.** Negamax's existing probe rule `entry.depth as u32 >= depth` (where `depth >= 1`) naturally rejects depth=0 qsearch entries from causing negamax cutoffs — exactly correct (a qsearch score with restricted moves cannot soundly cut a full-width search). Negamax may still extract `tt_move` from a qsearch entry as an ordering hint (legality scan in `order_moves` rejects garbage). No code change needed in negamax.

ADR-0028 records the policy commitments. Constants: none added. Helpers: one (`qsearch_tt_bound_for_completed_node` — pure function classifying Lower/Upper/Exact for qsearch results, mirroring the M5.C `tt_bound_for_completed_node` precedent). Test-only instrumentation: `qsearch_tt_probes: u32` and `qsearch_tt_stores: u32` counters with `_for_test` accessors.

Mutation testing follows the M5.A–E precedent: per-unit `cargo mutants --in-diff` is run as part of pre-review mechanical checks.

## 1. Out of scope

- **Probe-only intermediate (no store).** ADR-0018 §6 noted this as a "cheap intermediate worth weighing"; the research §11 recommends full probe-and-store on Elo grounds (probe-only catches only pre-existing negamax entries, not qsearch-internal redundancy). Locked at probe-and-store.
- **Static-eval cache.** Some engines (Arasan) maintain a separate eval-only cache; we do not, and adding one is independent of M5.F.
- **PVS / `is_pv` threading into qsearch.** Research §4 recommends not threading PV semantics into qsearch (the "short PV" motivation does not apply — qsearch does not contribute to the displayed PV). Skip the cutoff suppression.
- **Repetition / 50-move detection in qsearch.** ADR-0027 §7 preserved M3.D's deliberate skip; M5.F preserves it too. The GHI exposure from qsearch TT entries is bounded to within-qsearch subtrees and is consistent with the main-search GHI accepted in ADR-0018 §10.
- **Qsearch `is_pv` cutoff suppression.** Not applied (research §4).
- **Per-entry `eval` field for static-eval reuse.** Some engines pack a static eval into the TT entry to avoid re-evaluating on probe; out of scope (would require widening the entry past 16 bytes or repurposing `_pad`).
- **Bucketing / multi-slot TT.** Direct-mapped depth-preferred replacement is unchanged.
- **Qsearch-to-negamax score promotion.** A qsearch entry at depth=0 cannot cut a negamax search (by §0.5). Out of scope.
- **Lockless XOR trick (M8 Lazy SMP).** Unchanged; deferred.

## 3. Type definitions and signatures

### 3.1 `src/tt.rs` change

```rust
impl TtEntry {
    /// True when the slot has never been written.

    /// Discriminator: `key == 0`. The Polyglot Zobrist of any reachable

    /// `key == 0` is forbidden by `store()`'s precondition assertion.
    /// This single-field discriminator is the M5.F replacement for the
    /// previous multi-field test (broken by qsearch entries with
    /// `depth = 0`).
    pub fn is_empty(&self) -> bool {
        self.key == 0
    }
    // ... (rest unchanged)
}
```

```rust
impl TranspositionTable {
    pub fn store(&self, key: u64, data: TtData) {
        // Empty-slot sentinel: an entry with `key == 0` is treated as
        // empty. Forbidding `store(0, ...)` keeps the discriminator
        // sound. The Polyglot Zobrist of any reachable position is
        // non-zero with probability `1 − 2⁻⁶⁴`; the assertion is
        // defense-in-depth.
        debug_assert!(
            key != 0,
            "TT store with key=0 collides with the empty-slot sentinel"
        );
        // ... (replace the prior `data.depth >= 1` assertion)
    }

```

The replacement-rule expression `old.is_empty() || old.age() != current_gen || old.depth <= data.depth` continues to work as written:
- Empty (`key == 0`): always replaceable. ✓
- Same-gen, depth-preferred: `old.depth <= data.depth` — qsearch (`d=0`) entries are overwritten by negamax (`d≥1`); same-tier qsearch entries replace each other. ✓
- Cross-gen: any old-gen entry is freely replaceable. ✓

### 3.2 Helper: bound classification for completed qsearch nodes

```rust
/// Classify the bound for a completed qsearch result.
///
/// Per Stockfish commit 45e5e65: qsearch's restricted move set (captures
/// + EP + queen-promo, plus in-check evasions) does not produce a true
/// minimax value over all legal moves. Calling `Exact` on a non-terminal
/// qsearch result overstates precision; storing it can short-circuit a
/// future negamax PV-node probe with an unsound score. M5.F therefore
/// stores **only Lower / Upper** for non-terminal qsearch results.
///
/// Terminal cases (handled at their own call sites with a forced
/// `Exact` bound, NOT this helper): true stalemate (returns 0) and mate
/// at horizon (returns `-(MATE - ply)`).
///
/// Precondition: `best != -INF`. The `-INF` seed at the in-check arm
/// either recurses (in which case any executed evasion's negated child
/// score satisfies `score > -INF`, so `best > -INF` after the first
/// completed iteration) or hits the empty-evasion terminal which
/// returns `-(MATE - ply)` directly via path D — that path stores
/// before reaching the post-loop classifier and never invokes this
/// helper. Pinned by debug_assert.
pub(crate) fn qsearch_tt_bound_for_completed_node(best: i32, beta: i32) -> TtBound {
    debug_assert!(
        best != -INF,
        "qsearch_tt_bound_for_completed_node: best == -INF unreachable at production sites"
    );
    if best >= beta { TtBound::Lower } else { TtBound::Upper }
}
```

Returns `TtBound` non-`Option` (matching the M5.C `tt_bound_for_completed_node` precedent of returning `TtBound` directly when input is always valid). The M5.D `ffp_pruned_bound -> Option<i32>` precedent doesn't apply here — its `None` is a genuine outcome (gate fail), whereas this helper's `-INF` input is structurally unreachable. The `debug_assert!` is the safety net.

**Call-site precondition audit (all four production sites supply `best != -INF`):**

1. Path C (single-reply extension) — `score` is the recursive child's return value (real i32 or 0 on abort, both `≠ -INF`).
2. Path F outer with at least one move evaluated — `best` was updated by `score > best`; recursive child returns are `≥ -INF + 1` by negation of `INF`-bounded scores.
3. Path F outer where moves_vec is non-empty but no recursion improved best — `best` remains seeded value; not-in-check seeds `best_init = stand_pat ≠ -INF`; in-check arm's `-INF` seed only reaches path F when at least one evasion completed (otherwise path D fires).
4. Path F under-promo combinations — feeds the same `best` accumulator as path F outer.

The "no Exact" rule is the load-bearing correctness commitment: in fail-soft, the formula `Lower if best > original_alpha; Upper if best < beta; Exact if both` (HGM convention, TalkChess t=63251) would normally produce Exact on `original_alpha < best < beta`. This helper deliberately deviates: even in the would-have-been-Exact zone, qsearch returns Upper. Stockfish 45e5e65 is the canonical reference; the cost of erroneous Exact storage is a future-search PV-node short-circuit with a score that doesn't account for unsearched quiets.

## 4. Planned production change in `qsearch`

The qsearch body is currently 14 numbered sections (ADR-0027 §0). M5.F adds two: a probe block at entry and a store block at exit. The probe is added as **step 2.5** (after MDP at step 2, before in-check triage at step 3); the store is added as **step 11** (the new tail-end of qsearch). The §4.5 diagram is the canonical ordering reference — §4.1 / §4.2 / §4.5 must agree.

### 4.1 Probe at entry (step 2.5)

**Location:** between the existing mate-distance pruning (step 2) and the in-check triage (step 3).

**Why this position:**
- AFTER MAX_PLY guard (step 1.5): at the ceiling, the function returns `evaluate(pos)` without recursing — we deliberately do not store at that path. Skipping the probe at the ceiling is also free (the guard returns immediately).
- AFTER nodes increment + cancellation poll (step 1): the probe is work; abort discipline must run before any work.
- AFTER MDP (step 2): mirrors negamax's step 7 (TT probe AFTER MDP at step 6). MDP can tighten `alpha` upward / `beta` downward; the tightened window allows more `Lower ≥ β` and `Upper ≤ α` cutoffs to fire on the same TT entry. Placing the probe before MDP would lose this tightening — exactly the regression the M5.A negamax plan §13 ordering pinned against.
- BEFORE in-check triage (step 3): in-check / not-in-check is irrelevant to whether a TT cutoff applies (the stored result is keyed only on Zobrist + bound + ply-adjusted score; in-check status of the probing frame doesn't affect soundness). One probe per frame, irrespective of arm.

**Code shape:**

```rust
// 2.5. TT probe (M5.F — ADR-0028). No depth comparison: qsearch's
//      notional depth is 0; any stored entry is at least as deep
//      (negamax entries: depth ≥ 1; qsearch entries: depth = 0).
//      Apply the standard fail-soft cutoff. Extract `tt_move` for
//      ordering iff it passes the qsearch move filter (or any legal
//      move when in_check). Naked tt_move (no filter) is unsound:
//      a quiet TT move from a prior negamax search would form a
//      "long chain" of TT-only moves with no captures to terminate
//      qsearch (Andrew Grant, TalkChess t=69629). Filter-gated tt_move
//      preserves the ordering benefit without the chain risk.
//
// Exact-at-probe IS sound. The no-Exact-in-store rule (Stockfish
// 45e5e65) bars Exact for non-terminal qsearch results — but the
// only stored Exact entries are FIDE-definite terminals (true
// stalemate: 0; mate at horizon: -(MATE - ply)) and negamax-tier
// entries (depth ≥ 1, full-width search). All three Exact sources
// produce a score that soundly cuts at the qsearch frame.
let mut tt_move: u16 = 0;
if let Some(tt) = &self.tt
    && let Some(entry) = tt.probe(pos.zobrist())
{
    #[cfg(test)] { self.qsearch_tt_probes += 1; }
    let candidate = entry.best_move;
    let tt_score = score_from_tt(entry.score as i32, ply as i32);
    match entry.bound() {
        TtBound::Exact => return tt_score,
        TtBound::Lower if tt_score >= beta => return tt_score,
        TtBound::Upper if tt_score <= alpha => return tt_score,
        _ => {}
    }
    // Cutoff did not fire — retain the candidate as the unfiltered
    // ordering hint. The filter is enforced implicitly at step 7's
    // membership scan: a quiet TT move is silently rejected because
    // the not-in-check `moves_vec` (post-`qsearch_move_filter`) does
    // not contain it; a capture or queen-promo TT move is found and
    // promoted to index 0. The "Filter-gated tt_move" idea is realized
    // at step 7, not at this probe site.
    tt_move = candidate;
}
```

**Ordering: filter the TT move at the call site, not in the probe.** The probe block above stores a *candidate* `tt_move`; the ordering step (existing step 7) filters by `qsearch_move_filter` for the `!in_chk` arm or accepts any legal move for the `in_chk` arm. Filtering at ordering time keeps the probe block free of `in_check(pos)` calls. The legality check (membership scan) catches collision-corrupted moves regardless.

**Exact-at-probe vs. no-Exact-in-store asymmetry.** The probe accepts an `Exact` cutoff because the only sources of a stored Exact entry at any Zobrist key are: (1) negamax-tier entries (depth ≥ 1) — these are full-width search results and sound to use as cutoffs; (2) qsearch terminal Exact entries — true stalemate (score 0) and mate at horizon (`-(MATE - ply)`) — these are FIDE-definite regardless of move-set restriction. The store-side prohibition is on *non-terminal* qsearch Exact stores. The probe does not need to discriminate among Exact sources; the store discipline is what prevents bad Exacts from existing.

### 4.2 TT store at all real-result return points (step 11)

The qsearch body has six paths that produce a "real" result eligible for TT memoization:

| # | Return point | Score | Bound | Notes |
|---|---|---|---|---|
| A | Stand-pat fail-high (`!in_chk`, `sp >= beta`) | `sp` | Lower | step 4 inner; one-line return today |
| B | True stalemate (`!in_chk`, `ml.is_empty()`) | `0` | Exact | M5.E #2 |
| C | Single-reply extension result (`!in_chk`, `ml.len() == 1`) | recursive `score` | classified by helper | M5.E #1 |
| D | Mate at horizon (`in_chk`, `moves_vec.is_empty()`) | `-(MATE - ply)` | Exact | M3.D (preserved) |
| E | False-stalemate guard fall-through (`!in_chk`, `moves_vec.empty()`, `ml.len() >= 2`) | `best_init = sp` | Upper | M3.D guard preserved |
| F | Completed move loop (after all captures + under-promo) | accumulated `best` | classified by helper | M5.E reshape preserved |

Two non-storing return points (no TT write):

| # | Return point | Reason |
|---|---|---|
| X | MAX_PLY ceiling guard (M5.E #4) | Artificial truncation; not a search-quality bound. |
| Y | Abort during recursion | Partial bounds are not real; existing pattern. |

**Store strategy:** rather than scatter store calls across six return points, refactor each return into:

```rust
return self.qsearch_store_and_return(pos, score, bound, best_move, ply);
```

where `qsearch_store_and_return` is a private method:

```rust
fn qsearch_store_and_return(
    &mut self,
    pos: &Position,
    score: i32,
    bound: TtBound,
    best_move: u16,
    ply: u32,
) -> i32 {
    if let Some(tt) = &self.tt
        && !self.aborted
    {
        #[cfg(test)] { self.qsearch_tt_stores += 1; }
        let adjusted = score_to_tt(score, ply as i32);
        debug_assert!(
            adjusted == adjusted as i16 as i32,
            "TT score overflow on qsearch store: adjusted={adjusted}"
        );
        tt.store(
            pos.zobrist(),
            TtData {
                score: adjusted as i16,
                depth: 0,
                bound,
                best_move,
            },
        );
    }
    score
}
```

This centralisation:
- Single place to maintain the abort guard, mate-score adjustment, depth-0 convention, and store-on-exit discipline.
- Mutation testing has a named helper to target.
- Each return site reads as `return self.qsearch_store_and_return(pos, score, bound, mv, ply);` — a one-liner that documents at the call site which (score, bound) is being committed.

**Per-path bound + best-move:**

- **A (stand-pat ≥ beta):** `bound = Lower, best_move = 0`. The stand-pat does not name a move; ADR-0018 §7 preserves any prior `best_move` on overwrite at the same key. **This is desired** — a prior tactical move (capture / queen-promo) that produced a fail-high at this key in an earlier search is exactly the right ordering hint for a future probe; passing `best_move = 0` lets §7's preservation rule keep that hint without explicitly tracking it at the path-A site.
- **B (true stalemate):** `bound = Exact, score = 0, best_move = 0`. Terminal node.
- **C (single-reply extension):** `bound = qsearch_tt_bound_for_completed_node(score, beta)`, `best_move = only_mv.bits()`. The unique forced quiet is the only move searched and is structurally the best. If the recursion returns a mate-bounded score, the move is still the right `best_move` to memoize — the score reflects what happens after that move; there is no alternative move to credit. **The bound stays Lower/Upper (never Exact) even when the recursive child found a definite mate.** Reason: the single-reply extension memoizes a one-move forced sequence at the *current* qsearch frame, not a position whose all-legal-move minimax is known. The "no Exact in qsearch" rule's terminal-only exception (paths B and D) does not extend to single-reply mate finds.
- **D (mate at horizon):** `bound = Exact, score = -(MATE - ply), best_move = 0`. Terminal node.
- **E (false-stalemate guard fall-through):** `bound = Upper, score = stand_pat, best_move = 0`. The fall-through occurs only when `ml.len() >= 2`; the move loop didn't run (filter rejected all), so no recovery move to store.
- **F (completed move loop):** `bound = qsearch_tt_bound_for_completed_node(best, beta)`, `best_move = bound==Lower → cutoff_move.bits() else 0`. Mirrors the negamax store discipline at step 14: only Lower bounds carry a best_move (the cutoff move).

**Move-loop best_move tracking (load-bearing for path F).** The existing qsearch move loop at `src/search.rs:2138–2227` does NOT track which move set `best`. M5.F introduces an accumulator:

```rust
let mut best = best_init;
let mut cutoff_move: Option<Move> = None;  // NEW for M5.F path F

for mv in moves_vec {
    // ... existing make/recurse/unmake ...
    if score > best {
        best = score;
        if score > alpha { alpha = score; }
    }

    // (existing M5.E #3 under-promo block reads `score` and updates
    //  `best`/`alpha` similarly; the under-promo block sets
    //  `cutoff_move` itself when its own internal `alpha >= beta`
    //  break fires — see snippet below.)

    if alpha >= beta {
        // First-cut-wins: don't overwrite an under-promo cutoff_move.
        // If the under-promo loop already cut at `under_mv`, that is
        // the *more specific* cutter (queen-promo led to stalemate;
        // rook/bishop promo was the actually-cutting move). The outer
        // `mv` here is just the queen-promo whose stalemate child
        // raised alpha to the cutoff via the under-promo recursion.
        if cutoff_move.is_none() {
            cutoff_move = Some(mv);
        }
        break;
    }
}
```

For the M5.E under-promo inner loop (around line 2206 in the current code), the same tracking applies inside the loop:

```rust
for under_mv_opt in stalemate_avoiding_under_promos(mv) {
    let Some(under_mv) = under_mv_opt else { continue; };
    // ... make/recurse/unmake ...
    if under_score > best {
        best = under_score;
        if under_score > alpha { alpha = under_score; }
    }
    if alpha >= beta {
        cutoff_move = Some(under_mv);  // under-promo cutoff
        break;
    }
}
```

**Why first-cut-wins.** The standard qsearch case (no under-promo) has the outer break as the only cutoff site; `cutoff_move` is None at break time, so the guard does not interfere. The M5.E corner case (queen-promo's child stalemates → rook/bishop under-promo cuts) is the only case where the under-promo records `cutoff_move` first, and the outer break should leave it intact. The negamax precedent at `src/search.rs:1719` records `cutoff_move = Some(mv)` unconditionally because negamax has no nested cutoff loop; M5.F's `is_none()` guard is the qsearch-specific addition.

**Why `cutoff_move` and not "last move that improved best"?** The negamax precedent (`src/search.rs:1719`) records the cutting move only at the cutoff site, not on every alpha-improvement. This matches the path F rule "Lower bound carries the cutoff move; Upper bound carries no move (best_move=0)" — Upper bounds occur when no move proved a fail-high, so there is no canonical "best move" to memoize.

At path F call site:

```rust
let bound = qsearch_tt_bound_for_completed_node(best, beta);
let best_move_packed = match bound {
    TtBound::Lower => cutoff_move.map(|m| m.bits()).unwrap_or(0),
    _ => 0,
};
return self.qsearch_store_and_return(pos, best, bound, best_move_packed, ply);
```

If `cutoff_move` is `None` and `bound == Lower` (impossible — Lower implies the cutoff fired, which sets `cutoff_move`), the `unwrap_or(0)` is a safety net; ADR-0018 §7 still preserves the prior best_move at the same key.

### 4.3 In-check arm probe semantics

The probe block in §4.1 fires regardless of in_check. The cutoff applies uniformly. Worked example: a position is reached as an in-check qsearch frame on Branch A, evasions are searched, the result is stored as Upper (or Lower if a counter-attack fail-high). Reached again as an in-check frame on Branch B — the probe hits, the cutoff applies, the redundant evasion search is saved.

For ordering, the in-check arm currently iterates **all legal moves** (full evasions). The TT move (if any) joins ordering as the first move — irrespective of the qsearch filter, since in-check legal moves are all evasion candidates. The legality scan in `order_moves` (TT-move-first promotion) handles this.

### 4.4 Move ordering with `tt_move`

Currently qsearch sorts via `mvv_lva_score` only. Add a TT-move-first reorder mirroring negamax's step 12 — **only** when the TT move passes the appropriate filter:

```rust
// Step 7 (was: order MVV-LVA descending; now extended)
moves_vec.sort_by_cached_key(|&m| -mvv_lva_score(m, pos));
if tt_move != 0
    && let Some(idx) = moves_vec.iter().position(|m| m.bits() == tt_move)
    && idx != 0
{
    let mv = moves_vec.remove(idx);
    moves_vec.insert(0, mv);
}
```

**The filter is implicit in membership.** `moves_vec` is constructed AFTER the in-check / not-in-check filter at step 5. A quiet TT move never appears in the not-in-check `moves_vec` (filter rejects it); the `position()` call returns `None`; the swap is skipped. An in-check TT move appears in `moves_vec` if it is legal; the swap runs. This satisfies the research §5 Option B without a separate gate — the construction of `moves_vec` already enforces it.

The same logic applies to the M5.E single-reply branch (`ml.len() == 1`): the unique legal move is structurally fixed by movegen; recursing on `only_mv` IS recursing on the TT move when they coincide, and is correct when they don't (a `tt_move` that disagrees with the sole legal move is structurally inadmissible — the membership scan would have rejected it anyway). **No code change at the M5.E #1 call site — the unique-move recursion is uncoupled from the TT machinery, but composes correctly with it.**

### 4.5 Order of operations diagram

```
qsearch(alpha, beta, ply)
├─ 1. nodes++ + cancellation
├─ 1.5. MAX_PLY ceiling guard (M5.E #4) → evaluate(pos), NO TT store  [path X]
├─ 2. mate-distance pruning   (may return early; pre-existing terminals
│                              do not store, matching M3.D semantics)
├─ 2.5. TT probe (NEW M5.F)
│        ├─ extract tt_move (raw u16)
│        ├─ Exact / Lower≥β / Upper≤α → return tt_score (NO new store)
│        └─ retain tt_move for ordering
├─ 3. in_check triage
├─ 4. stand-pat (NOT in check)
│        ├─ sp ≥ β → store_and_return(sp, Lower, 0, ply)  [path A]
│        └─ sp > α → α ← sp
├─ 5. movegen → moves_vec
├─ 6. terminal: empty moves_vec
│        ├─ if in_chk → store_and_return(-(MATE - ply), Exact, 0, ply)  [path D]
│        └─ else (not in_chk):
│            ├─ ml.is_empty() → store_and_return(0, Exact, 0, ply)  [path B]
│            ├─ ml.len() == 1 → recurse; bound = qsearch_tt_bound...(score, beta);
│            │                  store_and_return(score, bound, only_mv, ply)  [path C]
│            └─ ml.len() ≥ 2 → store_and_return(stand_pat, Upper, 0, ply)  [path E]
├─ 7. order: mvv_lva, then TT-move-first if member
├─ 8. recurse fail-soft (move loop) — track `cutoff_move` on `alpha >= beta`
├─ 9. abort propagation: existing pattern (NO store on abort)  [path Y]
├─10. (existing M5.E under-promo block + cutoff) — also tracks `cutoff_move`
└─11. completed-loop store_and_return(best, classified, cutoff_move, ply)  [path F]
```

The `store_and_return(...)` calls are pure refactor of existing return points — the same scores are produced, with a new TT side-effect on the way out.

**MDP early returns.** Step 2's MDP can short-circuit qsearch with a mate-bounded score before the probe runs. Pre-M5.F these returns do not write the TT (M3.D semantics); M5.F preserves that. Rationale: an MDP early return at qsearch is a side-effect of the calling search's window, not a property of the position; storing it would over-tighten future probes at the same key with looser windows. This matches negamax's MDP behavior (negamax's MDP at step 6 returns without storing).

The `probe()` body remains:
```rust
let entry = unsafe { (&*self.entries.get())[idx] };
if entry.is_empty() || entry.key != key {
    None
} else {
    Some(entry)
}
```

The `is_empty()` short-circuit is now redundant with `entry.key != key` when the probe key is non-zero. We could simplify to:
```rust
if entry.key == key && key != 0 { Some(entry) } else { None }
```
but the existing form remains correct (probing with `key == 0` is forbidden by the store-side assertion, but a malicious caller could still attempt it; `is_empty() || entry.key != key` returns `None` in both cases). **Keep the existing form** — a smaller diff and a defense-in-depth probe that tolerates a 0-key probe. Add an inline comment at the probe site noting the redundancy is intentional, so a future "simplifier" doesn't drop it without re-deriving the safety argument:

```rust
// Short-circuit on empty (key=0). Strictly redundant with the
// `entry.key != key` test below when the probe key is non-zero
// (which the store-side assertion enforces). Kept defensively
// against a future refactor that probes with key=0.
if entry.is_empty() || entry.key != key { None } else { Some(entry) }
```

**Polyglot Zobrist 0 release-build behavior.** In release builds the `debug_assert!(key != 0, ...)` is stripped. If a real position's Zobrist key collides with 0 (probability `2⁻⁶⁴` ≈ 0; the Polyglot scheme's published constants make this case structurally rare for the standard initial position and reachable derivatives), the consequence is benign: `store(0, data)` writes `key=0` to the slot; any subsequent `probe(0)` sees `entry.is_empty() == true` and returns `None`. Net effect: a silent TT skip for that one position — no crash, no soundness violation, just a tiny perf hit. Recording this here so a future maintainer doesn't have to re-derive it.

## 9. Risk register

1. **Bound classification regression (HIGH SEVERITY, MITIGATED).** Storing `Exact` for non-terminal qsearch results is the documented Stockfish-45e5e65 trap. Mitigation: helper `qsearch_tt_bound_for_completed_node` returns only Lower/Upper; the only Exact stores are at FIDE-definite terminal sites (stalemate=0, mate-at-horizon). The §6.3 helper test sweep over the "would-have-been-Exact" zone pins this structurally.

2. **GHI worsening from qsearch entries (LOW SEVERITY).** Marginal; ADR-0018 §10 already accepts the "live with it" stance. Bounded to within-qsearch subtrees because negamax probes reject depth=0 entries via the existing `entry.depth >= depth` test. No mitigation beyond the existing acceptance.

3. **TT-move chain problem in qsearch (MITIGATED BY DESIGN).** Filtering the TT move via `moves_vec` membership prevents quiet TT moves from entering not-in-check qsearch. In-check arm permits any legal move (correct behaviour). No additional gate needed.

4. **`is_empty()` semantic change breaks an existing test (LOW SEVERITY).** Tests T1, T9, T10, T13, T14 in `src/tt.rs::tests` exercise probe/store/replacement. All assume non-zero keys. Default-is-empty is preserved (default key=0). Mitigation: §6.1 tests pin both halves of the new discriminator (default-empty + nonzero-key-not-empty).

5. **Bench delta forecast (LOW SEVERITY).** Forecast: −5% to −15% bench nodes (qsearch saves on interior re-traversal). The fixed-depth bench may underrepresent the gain (qsearch is dominant in deep-leaf positions). SPRT carries the strength signal.

6. **SPRT inconclusive (MEDIUM SEVERITY).** Research §9 forecast: +5–15 Elo, mode +8–12. The fast classical eval tightens the tradeoff (Crafty's "wash" precedent). If SPRT is inconclusive at 400 games:
   - **No-regression criterion** (CI lower bound > −10) **DOES** apply (this is a strength feature, not a correctness fix like M5.E).
   - If `Δ Elo < 0` at 400 games **AND** CI lower bound is ≤ -10, do not land; investigate (likely culprit: bound-classification bug or insufficient TT-move filtering).
   - Acceptable outcomes: H1 fires, OR `Δ Elo > 0` and CI crosses 0 with lower bound > -10 (small-but-not-regression).

7. **Bench drift on M5.E corner cases (LOW SEVERITY).** M5.E's corner cases (queen-promo-stalemate, true qsearch stalemate, single-reply forced quiet) don't fire on the 16-position bench corpus (M5.E retro §"Bench unchanged"). M5.F fires on every qsearch frame at every position; bench WILL change. Update E51 accordingly.

8. **Probe overhead at fast TC (MEDIUM SEVERITY).** Research §11 / §10(a): probe adds one cache-resident lookup per qsearch frame. Most qsearch frames are leaves; per-leaf overhead is non-zero. SPRT at the 4-bucket mixed TC will surface a per-TC asymmetry if the overhead dominates at fast TC (e.g., 10+0.1 negative, 60+0.6 positive). Watch the per-TC breakdown; if bimodal, consider a bench-driven tuning of the probe-skip threshold (no obvious knob — direct probe-or-not is the only available decision).

- **M5.H (staged movegen refactor):** touches `order_moves` and the move-loop iterator surface. The qsearch TT-move-first reorder in M5.F is a small parallel reorder (same shape as negamax's step 12); the staged-movegen refactor will likely subsume it. ✓
- **M5.I (third aspiration tier):** isolated to the negamax outer loop; no interaction with qsearch's TT machinery. ✓

No M5.F decision creates a forward-compatibility hazard.
