# M6.E — King safety (plan)

Fifth M6 sub-phase. Adds a **king-safety eval term** (king-zone attacker
S-curve + pawn-shield + open/semi-open-file-toward-king, MG-heavy taper)
**shipped score-neutral from the start** — every king-safety weight zeroed in
`eval::data`, the entire weight set deferred to the M6.I joint-Texel reshape.
The M6.C/M6.D inert-landing disposition: no SPRT screen ladder.

- Research: [`docs/research/m6-king-safety.md`](../research/m6-king-safety.md).
- ADR: [`docs/decisions/0033-king-safety.md`](../decisions/0033-king-safety.md)
  (binds on M6.E per roadmap §M6; supersedes ADR-0032 §3's pawn-shield-cache
  note — §6).
- Precedent: M6.C/M6.D (score-neutral inert landing, ADR-0032 §7/§8),
  ADR-0032 §4 (eval-boundary rule), the M6.B→C→D three-phase
  "co-calibrated-elsewhere ≠ transfers here" law.
- Production HEAD / SPRT baseline tag: **`M6.D`**.

## 1. Goal & non-goals

- **Goal.** A white-perspective `(mg, eg)` king-safety term entering
  `evaluate_core`'s blend numerator, **all weights zeroed** (term ≡ `(0,0)` ⇒
  `evaluate` byte-identical to `M6.D`); full term math live + tested,
  M6.I-ready. Same pattern as M6.C/M6.D.
- **Non-goal (deferred by design — ADR-0033).**
  - **Weight calibration is M6.I's joint Texel pass.** M6.E ships literature
    defaults *zeroed* (research §8 transfer-risk verdict HIGH; no per-component
    SPRT screen — ADR-0033 §8).
  - **No pawn-storm term** (ADR-0033 §3; research §3/§9 q4 — documented gap).
  - **Not pawn-hash-cached.** Computed live in `evaluate_core`, never cached
    (ADR-0033 §6; supersedes ADR-0032 §3's reserved option). No
    `PawnHashEntry`/`PawnEval` change.
  - **No tactical/x-ray refinement** of attacker counting beyond pseudolegal
    `magic::*_attacks(sq, occ_all)` (the M6.D mobility precedent).
  - King's own square excluded from the zone (matches the cited CPW shape).

### `src/eval/king_safety.rs` — the term

```rust
//! King-safety eval term (M6.E). White-perspective (mg, eg); the side under
//! attack contributes ±sign symmetrically. Computed live in `evaluate_core`
//! (not pawn-only ⇒ never cached — ADR-0033 §6, supersedes ADR-0032 §3).
//! Zone = 3×3 ring + forward wedge; per-kind attacker units → SAFETY_TABLE;
//! castled-king pawn-shield; MG-only open/semi-open-file penalty. All weights
//! zeroed at ship (score-neutral, ADR-0033 §8) — term math live, M6.I-ready.

pub(crate) fn king_safety_term_white(pos: &Position) -> (i32, i32);
```

Algorithm (prescriptive — the coder transcribes; mirror `mobility.rs`'s
`for (side, sign) in [...]` + 4-explicit-loops style, **no** match-on-kind):

```rust
let occ_all = pos.occupied_all();
let wp = pos.pieces_colored(Color::White, PieceKind::Pawn);
let bp = pos.pieces_colored(Color::Black, PieceKind::Pawn);
let all_pawn_files = bitboard::file_fill(wp | bp);
let (mut mg, mut eg) = (0i32, 0i32);

for (side, sign) in [(Color::White, 1i32), (Color::Black, -1i32)] {
    let (enemy, own_pawns, own_pawn_files) = match side {
        Color::White => (Color::Black, wp, bitboard::file_fill(wp)),
        Color::Black => (Color::White, bp, bitboard::file_fill(bp)),
    };
    let ksq = pos.king_square(side);
    let ring = movegen::masks::king_attacks(ksq);
    // Zone = ring + the 3 squares one rank toward the enemy beyond the ring's
    // forward edge, king's own square excluded (ADR-0033 §1). The
    // `& !from_square(ksq)` is load-bearing: for a king NOT on its back rank a
    // ring square sits directly behind it, so the toward-enemy shift would
    // re-introduce the king square — mask it out. No-op for a back-rank king.
    let fwd = match side {
        Color::White => ring.shift_north(),
        Color::Black => ring.shift_south(),
    };
    let zone = ring | (fwd & !Bitboard::from_square(ksq));

    // king-safety from `side`'s OWN perspective (penalty = negative,
    // shield = positive); white-perspective contribution = sign * ks_*.
    let mut ks_mg = 0i32;
    let mut ks_eg = 0i32;

    // (a) attacker S-curve — enemy N/B/R/Q attacking `side`'s zone.
    let mut units = 0i32;
    let mut attackers = 0u32;
    for psq in pos.pieces_colored(enemy, PieceKind::Knight).iter() {
        let h = (movegen::masks::knight_attacks(psq) & zone).count() as i32;
        if h > 0 { attackers += 1; units += KING_ATTACK_WEIGHT_N * h; }
    }
    for psq in pos.pieces_colored(enemy, PieceKind::Bishop).iter() {
        let h = (magic::bishop_attacks(psq, occ_all) & zone).count() as i32;
        if h > 0 { attackers += 1; units += KING_ATTACK_WEIGHT_B * h; }
    }
    for psq in pos.pieces_colored(enemy, PieceKind::Rook).iter() {
        let h = (magic::rook_attacks(psq, occ_all) & zone).count() as i32;
        if h > 0 { attackers += 1; units += KING_ATTACK_WEIGHT_R * h; }
    }
    for psq in pos.pieces_colored(enemy, PieceKind::Queen).iter() {
        let h = (magic::queen_attacks(psq, occ_all) & zone).count() as i32;
        if h > 0 { attackers += 1; units += KING_ATTACK_WEIGHT_Q * h; }
    }
    let enemy_has_queen = pos.pieces_colored(enemy, PieceKind::Queen).any();
    if attackers < 2 || !enemy_has_queen { units = 0; }
    let idx = units.clamp(0, (KING_SAFETY_TABLE.len() - 1) as i32) as usize;
    ks_mg -= KING_SAFETY_TABLE[idx]; // MG-only (EG king-safety = 0, ADR-0033 §2/§5)

    // (b) pawn shield — only when `side`'s king is on a castled-side file.
    let kf = ksq.file();
    if kf >= 5 /* ≥ f */ || kf <= 2 /* ≤ c */ {
        let (r2, r3) = match side { Color::White => (1u8, 2u8),   // ranks 2,3
                                    Color::Black => (6u8, 5u8) }; // ranks 7,6
        let lo = kf.saturating_sub(1);
        let hi = (kf + 1).min(7);
        for f in lo..=hi {
            let on2 = Square::from_file_rank(f, r2).is_some_and(|s| own_pawns.contains(s));
            let on3 = Square::from_file_rank(f, r3).is_some_and(|s| own_pawns.contains(s));
            if on2 { ks_mg += SHIELD_1_MG; ks_eg += SHIELD_1_EG; }
            else if on3 { ks_mg += SHIELD_2_MG; ks_eg += SHIELD_2_EG; }
        }
    }

    // (c) open / semi-open files toward the king — MG-only.
    // file f "has own/any pawn" via the file_fill rank-0 projection.
    let has_own = |f: u8| Square::from_file_rank(f, 0)
        .is_some_and(|s| own_pawn_files.contains(s));
    let has_any = |f: u8| Square::from_file_rank(f, 0)
        .is_some_and(|s| all_pawn_files.contains(s));
    // king file: open (no pawn either color) takes precedence over semi-open.
    if !has_any(kf) { ks_mg += KS_KFILE_OPEN_MG; }
    else if !has_own(kf) { ks_mg += KS_KFILE_SEMI_OPEN_MG; }
    // adjacent files: count semi-open (no own pawn); both ⇒ amplify.
    let adj: [Option<u8>; 2] = [kf.checked_sub(1), if kf < 7 { Some(kf + 1) } else { None }];
    let mut semi_adj = 0u32;
    for f in adj.into_iter().flatten() {
        if !has_own(f) { ks_mg += KS_ADJ_SEMI_OPEN_MG; semi_adj += 1; }
    }
    if semi_adj == 2 { ks_mg += KS_BOTH_ADJ_SEMI_OPEN_MG; }

    mg += sign * ks_mg;
    eg += sign * ks_eg;
}
(mg, eg)
```

**Index-clamp invariant.** `units.clamp(0, 99)` is a real clamp (not a
`debug_assert!`-only invariant like M6.D): with live M6.I weights `units` can
exceed 99 (Q·4 × ≤11 zone squares + others), and the saturating tail of the
S-curve is part of its design (research §6 — flat 500 from index 61). Clamping
is correct behavior here, not defensive masking. At ship `units ≡ 0` (weights
zeroed) ⇒ `idx = 0` ⇒ `KING_SAFETY_TABLE[0] = 0`. Verify imports resolve:
`crate::magic`, `crate::movegen::masks`, `crate::bitboard`,
`Bitboard::{shift_north,shift_south,count,contains,any,from_square}` + the
`core::ops::Not` (`!Bitboard`) impl (already used by `mobility.rs`),
`Position::{occupied_all,pieces_colored,king_square}`, `Square::{file,
from_file_rank}`, the `eval::data` constants.

deliberately (the M6.D §4 rationale verbatim: a delta-equals-addend assertion
