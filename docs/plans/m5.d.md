# M5.D — Frontier futility pruning (FFP)

Fourth M5 sub-phase. Adds **frontier futility pruning** as a per-quiet-move skip inside the negamax move loop at shallow depth (`depth ≤ FFP_MAX_DEPTH`): before recursing into a quiet move, if `static_eval + margin(depth) ≤ alpha`, skip it. Composes with M5.A NMP, M5.B RFP, and M5.C LMR; layers next to LMR's reduce/skip choice.

Research synthesis: [`docs/research/m5-frontier-futility.md`](../research/m5-frontier-futility.md).

The roadmap row commits to the broad shape: skip quiet moves at `depth ≤ 2` when `static_eval + margin·depth < α`; per-depth margin table (CPW: 100/150/250 cp at d=1/2/3); layered into the per-quiet-move decision next to M5.C's reduce/skip choice. This plan narrows those commitments into clawfish's M5.C-shaped move loop.

## 0. Goals

- New constants `FFP_MAX_DEPTH = 2`, `FFP_MARGIN_D1 = 100`, `FFP_MARGIN_D2 = 150`, `FFP_MARGIN_D3 = 250` in `src/search.rs`. The depth-3 entry is defined for forward compatibility but **inactive** at v1 (`FFP_MAX_DEPTH = 2`).
- Compile-time invariant `const _: () = assert!(FFP_MAX_DEPTH < LMR_MIN_DEPTH)` adjacent to the constants in `src/search.rs` (production code, not test code; mirrors ADR-0025 §3's `LMR_HIGH_HISTORY_THRESHOLD <= MAX_HISTORY` precedent). At v1 this enforces that FFP and LMR have non-overlapping depth ranges; a future tuning that violates the invariant must remove the assert in the same patch that updates ADR-0026 §6.
- Pure helper `frontier_futility_margin(depth: u32) -> i32` returning the per-depth margin (0 outside the active range).
- Pure helper `ffp_pruned_bound(static_eval: i32, depth: u32, alpha: i32) -> Option<i32>` — single helper combining the gate test AND the proved fail-soft upper bound. Returns `Some(static_eval + margin)` (saturating) when the FFP gate fires; `None` otherwise. Helper-level domain guard returns `None` for `depth ∉ [1, FFP_MAX_DEPTH]` (M5.C `late_move_reduction` precedent). The single helper closes the gate/contribution overflow asymmetry that two separate helpers would create.
- Move-loop integration: per-quiet **FFP-prune-first**, then LMR. Five-condition node-level gate (`ply > 0`, `!is_pv`, `!in_check`, `depth ≤ FFP_MAX_DEPTH`, `alpha.abs() < MATE_IN_MAX_PLY`).
- A pruned quiet does NOT enter `quiets_searched` (no recursive evidence; mirrors M5.C reduced-only exclusion under ADR-0025 §7).
- A pruned quiet contributes its proved fail-soft upper bound `static_eval + margin` to the node's running `best`, **routed through `best_is_full_depth_after_score(..., move_is_full_depth = false)`** so the node-level `best_is_full_depth` flag is downgraded. This is load-bearing for TT-store correctness: an FFP-bound contribution that overwrites a previously full-depth-witnessed `best` would otherwise leave the flag at `true` and let `tt_bound_for_completed_node` store an inflated Upper bound at the current depth from coarse static-comparison evidence — the exact same failure mode ADR-0025 §6 worked out for reduced-only-LMR scores ("Upper would be false advertising").
- The pruned-bound contribution closes the "all quiets pruned, no captures" corner-case (research §13 Pitfall 6) without breaking fail-soft semantics: every searched move contributes its real score; every pruned move contributes a proved upper bound; their max is the tightest bound on the node's value. The flag downgrade ensures the bound only ever lives at the parent's recursion register, never propagates via the TT.
- No TT store on FFP fire per se (the proof is per-move + per-depth, not a node bound). The end-of-loop TT store path is unchanged in code, but its bound classification will return `None` (suppress) at any node whose `best_is_full_depth` was downgraded by FFP — see `tt_bound_for_completed_node_suppresses_when_reduced_only` precedent.
- `#[cfg(test)]` instrumentation so the suite can pin direct FFP behavior (firings + skipped-move trace) without depending on brittle global node-count deltas.
- ADR-0026 records the policy commitments.

Mutation testing follows the M5.A/M5.B/M5.C precedent: the per-unit `--in-diff` campaign is **deferred** to the project's overnight backlog (`docs/mutants-backlog.md`). The plan still prepares the diff-scope and the anticipated catchable surface for the campaign agent.

## 1. Out of scope

- **Gives-check exemption** — not detecting whether a quiet move gives check before pruning. Research §7 calls this the primary v1 open question; v1 punts because `gives_check(pos, mv)` infrastructure does not yet exist in the move loop and TalkChess t=74403 documented a major correctness bug from getting it wrong. SPRT-tunable post-v1.
- **Depth 3 activation.** The constant `FFP_MARGIN_D3 = 250` is defined for forward compatibility but `FFP_MAX_DEPTH = 2` keeps it inactive. Activation deferred to a post-landing SPRT-tune campaign (open question §6 row 1).
- **Linear formula alternative** (`k * depth`). The per-depth table is more SPRT-friendly (each depth tunable independently); deferred.
- **Eval-aware margin** (margin halved when STM's eval is improving across plies).
- **Per-move SEE-based capture futility.** Captures are non-quiet by `is_quiet`'s definition and implicitly exempt; full capture-futility is a separate technique (delta pruning).
- **Razoring** at depth 3.
- **Late move pruning** / move-count-based pruning.
- **Qsearch delta pruning.**
- **Adaptive margin** as a function of search depth or improving heuristic.
- Hoisting state into `Position` or adding new movegen annotations. M5.D consumes existing search-time signals only.

## 3. Type definitions and signatures

### 3.1 Constants and compile-time invariant

New constants in `src/search.rs`, adjacent to the existing M5 constants (next to `LMR_*`):

```rust
/// FFP node-level depth ceiling. At depth > FFP_MAX_DEPTH, FFP does not fire.
/// v1: 2 (frontier + pre-frontier per Heinz 1998). Depth 3 / pre-pre-frontier
/// is a post-landing SPRT-tune candidate (research §4 / open question §6).
pub(crate) const FFP_MAX_DEPTH: u32 = 2;

/// FFP margin at depth 1 (frontier nodes).
/// 100 cp ≈ one pawn. Conservative per research §3.
pub(crate) const FFP_MARGIN_D1: i32 = 100;

/// FFP margin at depth 2 (pre-frontier / Heinz "extended futility").
/// 150 cp. Roadmap CPW reference.
pub(crate) const FFP_MARGIN_D2: i32 = 150;

/// FFP margin at depth 3 (pre-pre-frontier / "limited razoring").
/// **Inactive at v1** (FFP_MAX_DEPTH = 2 keeps depth 3 from firing).
/// Defined here so post-landing `FFP_MAX_DEPTH = 3` SPRT can activate it
/// without a fresh constant churn.
pub(crate) const FFP_MARGIN_D3: i32 = 250;

/// Compile-time invariant: at v1, FFP fires at `depth ≤ 2` and LMR fires at
/// `depth ≥ 3`, so the two pruning paths cannot co-fire at any node. This
/// assertion is load-bearing as a tripwire — a future tuning that raises
/// `FFP_MAX_DEPTH` to overlap with `LMR_MIN_DEPTH` MUST update ADR-0026 §6
/// (the per-quiet ordinal semantics question) and remove this assertion in
/// the same patch. Mirrors ADR-0025 §3's `LMR_HIGH_HISTORY_THRESHOLD <=
/// MAX_HISTORY` invariant pattern.
const _: () = assert!(FFP_MAX_DEPTH < LMR_MIN_DEPTH);
```

### 3.2 Helper functions

```rust
/// Per-depth FFP margin. Returns 0 outside `[1, FFP_MAX_DEPTH]`.
/// Defining the depth-3 entry here (even though FFP_MAX_DEPTH = 2 disables it)
/// keeps the constant inventory consistent with research §3 and lets a future
/// SPRT raise the ceiling without revisiting the table.
pub(crate) fn frontier_futility_margin(depth: u32) -> i32;

/// FFP gate test combined with proved fail-soft upper bound.
///
/// `static_eval` and `alpha` are STM-relative centipawn scores at the
/// *parent* node (pre-move). Returns `Some(static_eval + margin)` iff
/// `depth ∈ [1, FFP_MAX_DEPTH]` AND `static_eval + margin <= alpha`.
/// Returns `None` otherwise.
///
/// The Some payload is the FFP-proved upper bound on the move's true
/// score — guaranteed `<= alpha` by the gate. The call site uses it to
/// floor `best` (fail-soft preservation; ADR-0026 §7) without a separate
/// recompute.
///
/// `saturating_add` defends against `i32` overflow when `static_eval` is
/// near `MATE`. The node-level gate's `alpha.abs() < MATE_IN_MAX_PLY`
/// check makes that case unreachable in production, but the helper is
/// `pub(crate)` and unit-tested independently.
///
/// The depth-range check is helper-level domain guard (M5.C
/// `late_move_reduction` precedent): the helper returns `None` at d=0 or
/// d > FFP_MAX_DEPTH even with mathematically passing margin/alpha —
/// defense-in-depth against a refactor that drops the call-site
/// `depth <= FFP_MAX_DEPTH` gate.
pub(crate) fn ffp_pruned_bound(
    static_eval: i32,
    depth: u32,
    alpha: i32,
) -> Option<i32>;
```

`frontier_futility_margin`:

```rust
pub(crate) fn frontier_futility_margin(depth: u32) -> i32 {
    match depth {
        1 => FFP_MARGIN_D1,
        2 => FFP_MARGIN_D2,
        3 => FFP_MARGIN_D3,  // inactive until FFP_MAX_DEPTH raised
        _ => 0,
    }
}
```

`ffp_pruned_bound`:

```rust
pub(crate) fn ffp_pruned_bound(
    static_eval: i32,
    depth: u32,
    alpha: i32,
) -> Option<i32> {
    if depth == 0 || depth > FFP_MAX_DEPTH {
        return None;
    }
    let bound = static_eval.saturating_add(frontier_futility_margin(depth));
    if bound <= alpha {
        Some(bound)
    } else {
        None
    }
}
```

**One helper, two responsibilities by design.** Separating the gate test (bool) from the bound calculation (i32) is the more direct mutation-killable surface, but it creates a saturation-overflow asymmetry: the gate must be saturating (else `+`-overflow could let the bound test pass when arithmetic says no), and the contribution must reuse the same saturated value (else the `+`-overflow could re-emerge at the call site). The single helper closes the asymmetry by computing the bound once. Mutation testing on the helper directly kills the gate and the bound together — `is_ffp_pruneable` style mutations land on the `bound <= alpha` branch and `ffp_proved_bound` style mutations land on the `Some(bound)` payload; both surfaces remain killable.

## 4. Planned production change in `negamax`

### 4.1 Node-level gate (computed before the move loop)

Inside the existing block that precomputes `lmr_node_eligible` (around `src/search.rs:1385`), compute a lazy STM-relative `static_eval` wrapped in an `Option` whose `Some/None` IS the FFP node-eligibility signal — no separate `ffp_node_eligible: bool`:

```rust
let lmr_node_eligible = ply > 0 && !is_pv && depth >= LMR_MIN_DEPTH && !in_check(pos);

// M5.D — Frontier futility pruning.
//
// Lazy-dup `static_eval` and lazy-dup `in_check(pos)` per the M5.B precedent
// (ADR-0024 §6): this block reads its own `static_eval` independently of NMP
// (step 9) and RFP (step 8), so the M5.A/B reads remain byte-identical and
// the M5.D SPRT signal is attributable to FFP alone. At v1 constants, FFP
// (depth ≤ 2) and LMR (depth ≥ 3) cannot fire at the same node, so any
// duplicated `in_check` evaluation is structural only — never per-frame.
//
// `ffp_static_eval == Some(_)` IS the eligibility predicate; the per-quiet
// branch in §4.2 matches on `Some(static_eval)` and skips otherwise. No
// separate `ffp_node_eligible: bool` to keep in sync.
let ffp_static_eval: Option<i32> = if ply > 0
    && !is_pv
    && depth >= 1
    && depth <= FFP_MAX_DEPTH
    && alpha.abs() < MATE_IN_MAX_PLY
    && !in_check(pos)
{
    let stm = pos.side_to_move();
    Some(if stm == Color::White {
        pos.static_eval_white()
    } else {
        -pos.static_eval_white()
    })
} else {
    None
};
```

The `depth >= 1` lower bound is a structural guard: `negamax` at `depth == 0` delegates to `qsearch` at the top of the function (step 2), so this branch is unreachable in production; the explicit bound makes the helper's domain match the call-site invariant.

### 4.2 Per-quiet branch in the move loop

Inside the `for (i, &mv) in moves_vec.iter().enumerate()` loop (around `src/search.rs:1387`), insert an FFP block AHEAD of the LMR decision but inside the quiet-move arm:

```rust
for (i, &mv) in moves_vec.iter().enumerate() {
    let child_is_pv = is_pv && i == 0;
    let quiet_move = is_quiet(mv);
    let mut move_is_full_depth = true;

    // M5.D — FFP skip (lands BEFORE LMR; research §9):
    //   - per-quiet, non-capture, non-promo (is_quiet excludes those)
    //   - alpha is the node's caller-tightened alpha at this point
    //   - the pruned bound is the move's fail-soft proved upper bound,
    //     guaranteed `<= alpha` by the gate; never improves alpha; never
    //     causes a beta cutoff — only floors the eventual return value
    //   - the contribution is routed through `best_is_full_depth_after_score`
    //     with `move_is_full_depth = false` so the flag is downgraded if
    //     the FFP bound overwrites a previously full-depth-witnessed `best`
    //     (load-bearing for TT-store correctness — ADR-0026 §7)
    if quiet_move
        && let Some(static_eval) = ffp_static_eval
        && let Some(pruned_bound) = ffp_pruned_bound(static_eval, depth, alpha)
    {
        #[cfg(test)]
        if self.lmr_trace_root_ply == Some(ply) {
            self.ffp_firings += 1;
            self.ffp_skipped_moves.push(mv);
        }

        best_is_full_depth = best_is_full_depth_after_score(
            best,
            best_is_full_depth,
            pruned_bound,
            /*move_is_full_depth=*/ false,
        );
        if pruned_bound > best {
            best = pruned_bound;
        }

        // Do NOT push onto `quiets_searched`: no recursion happened, no
        // evidentiary basis for history malus (research §10; mirrors
        // ADR-0025 §7 reduced-only exclusion).
        continue;
    }

    // M5.C — LMR (unchanged from M5.C v1).
    let lmr_reduction = if quiet_move {
        quiet_index += 1;
        ...
    } else {
        None
    };

    ...rest of body unchanged...
}
```

**`quiet_index` semantics.** FFP-skipped quiets DO NOT advance `quiet_index` — the increment lives inside the LMR branch and FFP `continue`s before reaching it. The semantic rationale: `quiet_index` is LMR's *considered-for-reduction* ordinal, not a *seen-in-ordering* ordinal. ADR-0025 §3 makes this explicit: the TT move (when quiet) is searched first via the step-12 reorder and counts as `quiet_index = 1` even though it is implicitly exempt from reduction; the floor at `LMR_MIN_QUIET_INDEX = 2` is what makes the exemption work. FFP-skipped quiets are *not considered* for either reduction or recursion — they are never searched at all — so they semantically should not advance the ordinal that drives reduction decisions for subsequent quiets. At v1 constants, FFP and LMR cannot co-fire (the §3.1 compile-time invariant pins `FFP_MAX_DEPTH < LMR_MIN_DEPTH`), so this rule has no observable behavioral effect; it is enforced *structurally* by the `continue` placement and *invariantly* by the compile-time assert. No behavioral test exists at v1 because the rule is unobservable while the invariant holds. If a future SPRT raises `FFP_MAX_DEPTH ≥ LMR_MIN_DEPTH`, ADR-0026 §6 must be amended jointly with the assert removal, and the per-quiet ordinal semantics question is reopened then.

### 4.3 TT-store interaction (load-bearing correctness)

The end-of-loop TT-store path at step 14 is unchanged in code. The behavior changes via the `best_is_full_depth` flag downgrade above:

- **All-quiets-FFP-pruned, no captures**: `best_is_full_depth = false` (initial; never set to `true` because no full-depth move ran). `best = max(pruned_bounds) <= alpha`. `tt_bound_for_completed_node` returns `None` → store suppressed. Sound: no full-depth witness, no TT entry.
- **Mixed: some captures, some FFP-pruned quiets, no full-depth alpha improver**: walk the loop:
  - Capture 1 (full-depth, `score = 50 <= alpha`): `best_is_full_depth_after_score(-INF, false, 50, true)` → `true`. `best = 50, flag = true`.
  - FFP-pruned quiet (`pruned_bound = 80 <= alpha`): contribution goes through `best_is_full_depth_after_score(50, true, 80, false)` → returns `false` (`80 > 50` strict-improvement arm with `move_is_full_depth = false`). `best = 80, flag = false`. **The downgrade is the load-bearing step.** End of loop: `flag = false` → `tt_bound_for_completed_node` returns `None` → store suppressed. Without the downgrade, the engine would store an inflated Upper at the current depth from coarse static-comparison evidence — exactly the failure mode ADR-0025 §6 worked out for reduced-only-LMR scores.
- **Full-depth alpha improver**: a capture or non-FFP quiet returns `score > alpha`. `flag = true`. FFP-pruned quiets contribute pruned bounds `<= alpha < score`, so the strict-improvement arm of `best_is_full_depth_after_score` is never re-entered with `move_is_full_depth = false` overwriting the flag. End of loop: `flag = true` → `tt_bound_for_completed_node` classifies as Lower or Exact, store fires with full-depth provenance. Sound.

The `best_is_full_depth_after_score` helper from ADR-0025 §6 is reused verbatim — no signature changes, no new helper. The strict-improvement arm `score > best → move_is_full_depth` and the equal-score arm `best_is_full_depth || (score == best && move_is_full_depth)` already encode the right semantics for FFP's `move_is_full_depth = false` contribution.

### 4.4 Terminal-node interaction

Step 11 (`moves_vec.is_empty()`) runs BEFORE the move loop. FFP cannot fire on a position with zero legal moves. The mate / stalemate detection is unaffected by FFP.

### 4.5 Lazy-dup discipline (ADR-0024 §6 precedent)

FFP's `static_eval` read is **independent** of RFP's (step 8) and NMP's (step 9). The lazy-dup design rejects a hoisted shared eager read at the top of `negamax` because:

- A shared hoist would change the read population on K+P endgame nodes (NMP's `has_non_pawn_material` gate currently prevents the eval read at step 9; a hoist would fire regardless).
- The NMP and RFP gates would silently change, muddying the M5.D SPRT against `M5.C`.

Each block reads independently. The depth-range overlap between the three gates:

- At `d ∈ {1, 2}`: RFP (`d ≤ 6`) and FFP (`d ≤ 2`) can both evaluate `static_eval`; NMP cannot fire (requires `d ≥ 3`).
- At `d ∈ {3, .., 6}`: RFP and NMP can both evaluate `static_eval`; FFP cannot fire.
- At `d ≥ 7`: only NMP can fire (RFP capped at 6, FFP capped at 2).

So the maximum number of independent `static_eval` reads at one physical position is two — never three. RFP's read happens at step 8 inside its own gate (cuts before reaching the move loop); FFP's read happens at the move loop's entry inside its own gate; NMP's read at step 9 is depth-disjoint from FFP. The cost is at most one additional `static_eval_white()` read per qualifying node — measured at the bench level by the M5.D SPRT.
