# M2.C — Engine I/O loop + position state

## Context

M2.A landed `Move::to_uci`/`from_uci`/`UciMoveError`. M2.B landed `parse_uci_line` and the `Command` enum. M2.C is the engine I/O layer that ties them together — an event loop reading lines from stdin, dispatching parsed `Command`s, owning `Position` state, and writing protocol replies to stdout.

This is the first phase that introduces threading. **ADR-0011 binds here** and codifies the model from `docs/research/m2-uci-threading.md`: reader thread → mpsc → main-as-orchestrator + per-`go` search worker + `Arc<AtomicBool>` cancellation. ADR-0011 has been drafted as the first step of this unit.

### Deliverable

- `src/search.rs` — `Search` trait + `SearchContext` + `SearchLimits` + `SearchResult` + a `Stub` `Search` impl (M2.C placeholder; M2.D replaces with the random-mover).
- `src/engine.rs` — `Engine` struct + handler methods + `reader_loop` + `run_stdio()` convenience.
- `src/main.rs` — calls `chess::run_stdio()`.
- New `tests/uci_integration.rs` — process-spawn integration test.
- Crate-root re-exports in `src/lib.rs`.
- Doc updates after commit (`docs/architecture.md`, `docs/roadmap.md`, `CLAUDE.md`).

### Bound ADRs

- **ADR-0011** — newly drafted, codifies the threading topology.
- **ADR-0012** (tournament harness) binds M2.E, not here.
- **ADR-0007** (legal-direct movegen) is consumed indirectly via `from_uci` and `generate_moves`.

### Research skip — justified

`docs/research/m2-uci-threading.md` is the dedicated pre-M2 research note. No new research needed.

### Not in M2.C

- **Random-mover.** The `Search` trait is defined and a deterministic `Stub` plugs in; M2.D replaces.
- **Time-management heuristics.** `wtime/btime/winc/binc/movestogo` are *parsed* but not used to compute a deadline — that's M2.D / M3. `go movetime <ms>` *is* honored as a hard deadline by the Stub (sleep-with-cancellation until the deadline, then emit a real bestmove).
- **`info` lines from search**, `score cp`, `pv`, multi-pv, `currmove`. Search is a stub.
- **fastchess integration / SPRT.** M2.E.
- **Benchmarks.** UCI dispatch is per-line, never on a search hot path. Skip per M2.A / M2.B precedent.

## Decisions baked into this plan

### 1. File layout

Two new files, no submodules:

- **`src/search.rs`** owns the `Search` trait + value types (`SearchContext`, `SearchLimits`, `SearchResult`) + the M2.C `Stub` impl. The trait is re-used unchanged across M2.D / M3 / M8.
- **`src/engine.rs`** owns the `Engine` struct, command handlers, the reader-thread function, and `run_stdio()`. Plus a `#[cfg(test)] InfoEmittingFake` Search impl for the info-ordering test (lives next to where it's used).

Inline `mod tests` per file as elsewhere.

### 2. Engine name and author

- `id name chess <CARGO_PKG_VERSION>` — read at compile time via `env!("CARGO_PKG_VERSION")`.
- `id author Alex Feldgendler` — string constant; trivial to change later.
- No `option` lines emitted (no options exposed in M2.C — `setoption` is silently accepted-and-ignored, with one forward-compat caveat in §11).

### 3. Generics over trait objects

Rationale: better stack traces, no virtual call per `write_line`, and we have only two callers (`run_stdio` and tests). Generics propagate to `Engine`'s type parameters but not to its consumers — `run_stdio` returns `!`; tests instantiate locally.

```rust
pub struct Engine<W: Write + Send + 'static, S: Search + Send + 'static> {
    position:      Position,
    debug:         bool,
    stop:          Arc<AtomicBool>,
    stdout:        Arc<Mutex<W>>,
    search:        Arc<Mutex<S>>,
    search_handle: Option<JoinHandle<()>>,
}
```

`Arc<Mutex<S>>` is the shape because `Search::go` takes `&mut self` — the worker needs an exclusive borrow, which a plain `Arc<S>` cannot provide, and `S` is not `Clone`. Back-to-back `go` joins the previous worker before starting the next (§7), so the Mutex is uncontended in normal flow; the Mutex is structural (gives `&mut` access from a thread) rather than synchronization. **Do not** attempt `Option::take` / `clone_box` / similar patterns — `Arc<Mutex<S>>` is the chosen idiom.

### 4. I/O abstraction for testability

- `Engine::run(&mut self, rx: mpsc::Receiver<Command>)` returns when `Quit` is dispatched. Drives unit tests directly.
- `Engine::new(stdout: W, search: S) -> Self` — generic constructor.
- `pub fn run_stdio() -> !` — production wrapper. Spawns the reader thread on `io::stdin().lock()`, constructs the Engine with `io::stdout()` and `Stub`, calls `run`, then `std::process::exit(0)`.
- `pub fn reader_loop(stdin: impl BufRead, tx: mpsc::Sender<Command>)` — reader-thread body, tested directly with `Cursor<&[u8]>`.
- Tests use `CapturedWriter(Arc<Mutex<Vec<u8>>>)` so the test holds a handle to the buffer after the engine takes ownership.
- `Engine` exposes `pub(crate) fn position(&self) -> &Position` so handler unit tests in the same crate can verify state mutation.

### 5. `position … moves` error handling — reset-on-error

Build a *fresh* `Position` from the spec (`startpos` or parsed FEN). Apply moves one at a time via `Move::from_uci` + `Position::make_move`. On any failure (FEN parse error, move parse error, illegal move):

- The engine's position is set to **the spec's base position with no moves applied** — *not* the prior position. This avoids both Stockfish's apply-prefix divergence and the strict reject-on-error stale-state hazard the v1 plan picked.
- Emit `info string position rejected: <one-line reason>` **regardless of the `debug` flag** — protocol-legal (`info string` is always allowed), and a silent rejection in tournament play is the worst possible failure mode.
- If the FEN itself fails to parse, the engine's position is **left unchanged** (we don't have a base to fall back to in that case). Same `info string` is emitted.

The asymmetry — FEN error keeps prior state; move error resets to base — is deliberate, not a bug: a move error has a known-good base position to fall back to (the parsed `startpos` or successfully-parsed FEN), while a FEN parse error has no such base, so reverting to "what was there before" is the only safe option.

Rationale: the GUI will resync on its next `position` command anyway; the engine staying at the new base position (even without moves) is closest to what the GUI asked for, and is at least as defensible as either of the alternatives.

### 6. `searchmoves` parsing in `go`

The parser hands us `searchmoves: Option<Vec<String>>`. The `handle_go` parses each via `Move::from_uci`:

- Bad entries (parse error / illegal for current position) are silently dropped from the filter.
- All-bad list → `searchmoves: Some(Vec::new())` → Stub generates no candidates → emits `bestmove 0000`.
- `None` (keyword absent) → no filter; Stub considers all legal moves.

This is more lenient than `position`'s reset-on-error because `searchmoves` is a *filter*, not state-mutation; dropping bad entries doesn't desynchronize engine state. Matches Stockfish.

### 7. Implicit-stop on back-to-back `go`

If a `go` arrives while a search is in flight, orchestrator flips the cancellation flag, joins the previous worker (which emits its `bestmove` on the way out), then starts the new search. Matches Stockfish.

**Flag-clear step (load-bearing for every `go`).** `handle_go`'s very first action is `self.stop.store(false, Ordering::Relaxed)`. Without this, the second-ever `go` (after any `stop` ever, or after a deadline-driven cancellation) would see the flag still set and exit immediately with `bestmove 0000`. The order inside `handle_go` is exactly: (1) join previous worker if `Some`; (2) `stop.store(false)`; (3) build `SearchContext`; (4) `thread::spawn` the new worker; (5) save the `JoinHandle`.

### 8. `Stub` Search impl semantics — honors `infinite` / `movetime`

- Generates legal moves at entry (filtered by `searchmoves` if non-`None`).
- Picks the lexicographically-first by UCI notation as the `bestmove` candidate. **The candidate is always computed first**, before any cancellation check — computing lex-first is essentially free, and the spec wants the best legal move on every `go` (line 211). `bestmove == None` (engine emits `bestmove 0000`) is reserved for the genuine "no legal move exists" case (mate / stalemate / empty `searchmoves` filter).
- If `infinite` is set, OR if `movetime` is set, OR if `ponder` is set: spin in `while !ctx.should_abort(0) { thread::sleep(Duration::from_millis(1)); }` until cancelled / deadline expires, then emit the candidate.
- Else: emit the candidate immediately.

**Race-free under quit-immediately-after-go.** The earlier "cancellation-before-enumeration ⇒ bestmove 0000" rule (v1/v2 of this plan) was removed because it created a race between worker scheduling and `handle_quit`'s flag-set: if `quit` arrived before the worker thread was scheduled, `should_abort` returned true at entry and the engine emitted `bestmove 0000` instead of the legitimate candidate. Always-compute-candidate eliminates the race deterministically.

This eliminates the `go infinite` spec deviation that v1 carried. M2.D's random-mover replaces only the candidate-picking step; the loop and `should_abort` invariants are preserved.

`ponder` is treated as `infinite` here (search keeps running until `stop`) per ADR-0011's "Ponder support deferred" note.

### 9. `quit` discipline — set flag, join worker, return

- `handle_quit`: `stop.store(true, Relaxed)`; if `search_handle.is_some()`, join it; then return from `run`.
- `run_stdio` calls `std::process::exit(0)` after `run` returns. The OS reaps the reader thread.
- The join is **bounded by the cancellation polling cadence** (1 ms in `Stub`, similar in M2.D's random-mover, configurable in M3+ alpha-beta). Worst case: the worker is mid-sleep in its `should_abort` polling loop and observes the flag on its next check ≤ 1 ms later. Total `quit`-to-`run`-return time is bounded by that one cadence cycle plus one stdout flush — well under the 1 s budget.
- Why join, when the original plan said don't? Because `Engine::run` is testable without `run_stdio`'s `process::exit(0)` safety net. Without the join, a unit test calling `run(rx)` directly would race the worker's `bestmove` write — `run` could return before the worker has flushed. The integration tests would similarly race the OS pipe-close against the worker's flush. Joining is the cheapest fix and the same primitive scales unchanged through M3 / M8.
- The reader thread is **not** joined — its blocking `read_line` is uncancellable, and on `quit` we call `process::exit` from `run_stdio` which terminates the process anyway; the OS reaps it.
- A pathological future `Search` impl that ignores the cancellation flag could hang `quit`. That's a contract violation by the impl, not the plumbing — the trait's contract requires obeying `should_abort`. Bug fixes happen at the impl layer.

### 10. EOF handling and reader-loop termination

- `reader_loop` translates `lines()`-iterator end (whether EOF or read error) into a synthetic `Command::Quit` send, then exits.
- **`reader_loop` exits as soon as it sends *any* `Command::Quit` — whether from a parsed `quit\n` line or from EOF synthesis.** A parsed `quit` line is **not** followed by an EOF-synthesized second `Quit`; the reader sends one `Command::Quit` total in either case. This avoids the "double-Quit" race where input `b"uci\nquit\n"` would otherwise yield `[Uci, Quit, Quit]`.
- Channel-disconnect on the orchestrator side is unreachable because the reader always sends `Quit` before dropping its `Sender`. The orchestrator's `rx.recv()` therefore always returns `Ok(Command::Quit)` as the terminating message; a `recv()` error is treated as an internal-invariant violation and `unreachable!()`'d. (If you ever see this fire, it means the reader thread panicked silently — a bug, not an expected path.)

### 11. Silent vs. info-string handlers — the rule

| Command | Default (debug off) | With `debug on` |
|---|---|---|
| `setoption` / `register` / `ponderhit` | silent | emit `info string <command-name> received: <details>` |
| `Unknown` | silent | emit `info string unknown command: <details>` |
| `debug on` / `debug off` | **always silent** | **always silent** (just toggles `self.debug`) |
| All other handlers | per spec (uci/isready emit replies; etc.) | same |

`handle_debug` is intentionally *not* in the info-string-when-debug-on group: it's the one command whose effect is observed by *what subsequent commands do*, not by its own output. Emitting an info string at the toggle would couple A12/A13's signal-detection with the toggle's own output, breaking the cleanest possible test of "is debug on?".

**Forward-compat caveat:** tests A14 / A15 / A16 pin *current* behavior — when the first real option lands (M2.D's `Random_Seed`, etc.), these tests are revised to allow option-acknowledgment output.

### 12. `isready` latency under shared `Mutex<Stdout>`

The lock is held only for one `writeln!` + `flush()` per protocol line. Worst-case wait: the search worker is mid-write when `isready` arrives — orchestrator blocks until the worker's single `writeln!` completes, which is tens of microseconds. Well under the 1 ms budget from ADR-0011. No special-case priority path is needed.

### `src/search.rs`

```rust
use std::sync::Arc;
use std::sync::atomic::{AtomicBool, Ordering};
use std::time::Instant;

use crate::{Move, Position};

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct SearchLimits {
    pub depth:    Option<u32>,
    pub nodes:    Option<u64>,
    pub movetime: Option<i64>,   // ms
    pub mate:     Option<u32>,
    pub infinite: bool,
    pub ponder:   bool,
    pub wtime:    Option<i64>,
    pub btime:    Option<i64>,
    pub winc:     Option<u64>,
    pub binc:     Option<u64>,
    pub movestogo: Option<u32>,
    /// Subset of legal moves the search is restricted to. Bad entries from
    /// the `go searchmoves …` parser are silently dropped (§6). `None` =
    /// no restriction.
    pub searchmoves: Option<Vec<Move>>,
}

#[derive(Clone)]
pub struct SearchContext {
    pub stop:     Arc<AtomicBool>,
    pub deadline: Option<Instant>,
    pub start:    Instant,
    pub limits:   SearchLimits,
}

impl SearchContext {
    /// `true` ⇒ cancel this iteration immediately. `nodes_searched` is the
    /// caller's running count, compared against `self.limits.nodes` (the
    /// cap from `go nodes <N>`). `Relaxed` is sufficient (§3 of ADR-0011).
    #[inline]
    pub fn should_abort(&self, nodes_searched: u64) -> bool {
        if self.stop.load(Ordering::Relaxed) { return true; }
        if let Some(d) = self.deadline {
            if Instant::now() >= d { return true; }
        }
        if let Some(cap) = self.limits.nodes {
            if nodes_searched >= cap { return true; }
        }
        false
    }
}

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct SearchResult {
    pub bestmove: Option<Move>,
    pub ponder:   Option<Move>,
    pub depth:    u32,
    pub score_cp: Option<i32>,
    pub nodes:    u64,
}

/// Implementations are spawned onto worker threads — `Send` is required so
/// the trait object / generic instance can be moved into `thread::spawn`.
pub trait Search: Send {
    /// Run a search. Must obey `ctx`: poll cancellation, respect deadline,
    /// emit `info` lines via `info_sink`, return cleanly on cancellation.
    /// Must not write to stdout directly. Must not read stdin.
    fn go(
        &mut self,
        position: &Position,
        ctx: &SearchContext,
        info_sink: &dyn Fn(&str),
    ) -> SearchResult;
}

/// M2.C placeholder. Picks the lexicographically-first legal move by UCI
/// notation; `bestmove 0000` if none. Honors `infinite`/`movetime`/`ponder`
/// by polling `should_abort` until cancelled / deadline expires.
/// Replaced in M2.D by the random-mover.
pub struct Stub;

impl Search for Stub { /* impl per §8 */ }
```

## Test plan

```rust

```

It builds an `Engine` with a `CapturedWriter` and `Stub`, sends each line through a channel as a parsed `Command` followed by `Quit`, runs to completion, returns captured stdout + a clone of the engine's position.

For threading tests, a separate harness that doesn't auto-send `Quit` and exposes the channel `Sender` so tests can interleave commands while the worker runs.

For the info-ordering test, a one-off `#[cfg(test)] InfoEmittingFake` Search impl in `src/engine.rs::tests` that emits 3 `info string thinking N` lines via `info_sink` then returns.

## Risks and mitigations

- **Reader thread blocks on stdin and can't be cleanly joined.** Abandoned on `quit` per §9, ADR-0011, and OS-reaping.
- **Race window between flag-clear and spawn in `handle_go`.** Orchestrator is single-threaded; the next channel `recv` cannot fire until `handle_go` returns. So the order is: clear flag → spawn → return → next recv. A `stop` already in the channel is read on the next recv and cancels the just-spawned worker before it has done meaningful work.
- **Test flakiness on threading tests.** Use generous (1 s) wallclock budgets; sleep cadence in `Stub`'s polling loop is 1 ms (good enough for cancellation responsiveness in tests).
- **Process-spawn integration test depends on the binary being built.** Cargo's `tests/` rebuild it; `env!("CARGO_BIN_EXE_chess")` resolves the path. Stdout reader is on its own thread; child is `kill()`'d if the test timeout fires.
- **Mutex<Stdout> contention with isready during search.** Single `writeln!`+`flush()` per line; tens of microseconds; under the 1 ms budget per §12.
