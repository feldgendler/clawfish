## 0. Goals

Insert an **intermediate widening tier** between M4.D's `±50 cp` first try and the existing `(L, +INF)` / `(-INF, L′)` asymmetric full-window fallback. The mechanism:

1. **Tier 1 (unchanged)** — `(prev − 50, prev + 50)` centered on the prior iteration's score, gated by `ASPIRATION_MIN_DEPTH = 6`.
2. **Tier 2 (new)** — on fail-high with fail-soft return `L`: `alpha = L, beta = prev + 150`. On fail-low with return `L′`: `alpha = prev − 150, beta = L′`. *Skipped entirely* when the tier-2 window would be inverted (`L ≥ prev + 150`) or when the tier-1 return is a mate score (`|L| ≥ MATE_IN_MAX_PLY`).
3. **Tier 3 (unchanged)** — on tier-2 fail-{high,low} with return `L₂` / `L₂′`: `(L₂, +INF)` / `(-INF, L₂′)`. Tier 3 also fires when tier 2 is skipped — i.e. on tier-1 fail with `L ≥ prev + 150` or mate-magnitude, tier 3 runs immediately as the existing `widen_after_fail` output.

Reason this is M5.I (not M4.x): the M4.D plan deferred it explicitly. The two-tier baseline has been stable for ~10 phase landings (M5.A through M5.H1); the engine's TT density and ordering quality (M4.A–C + M5.A NMP + M5.C LMR + M5.G SE) are now at a level where the literature's EV math (`c_intermediate < p · c_full ≈ 0.6 · c_full`) is plausibly satisfied.

**This plan acknowledges up front that SPRT may come back inconclusive** (roadmap §M5.I: "lands as a no-change retrospective rather than a failure"). Outcome paths are spelled out in §11.

## 3. Type definitions and signatures

### 3.1 New constant

```rust
/// M5.I intermediate-tier half-width in centipawns. Tier 2 widens the
/// *failing-side* bound from `prev ± 50` (tier 1) to `prev ± 150` while
/// keeping the proved-bound from tier 1 on the non-failing side.
/// Crafty-proportional starting value (research §7); post-landing
/// SPRT-tune candidate.
pub(crate) const ASPIRATION_INTERMEDIATE_HALF_WIDTH: i32 = 150;
```

Pin: a `const _: () = assert!(ASPIRATION_INTERMEDIATE_HALF_WIDTH > ASPIRATION_HALF_WIDTH)` compile-time invariant. If a future tune sets them equal or inverted, tier 2 degenerates to a no-op or worse (tier 2 narrower than tier 1) — surface that as a build error.

### 3.2 New pure helper

The helper takes ONLY the tier-1 window edges plus the fail-soft return — no separately-passed `prev`. This eliminates the invariant "caller must pass `prev` consistent with `prev_alpha = prev - W_SHORT, prev_beta = prev + W_SHORT`" by deriving tier-2's bounds directly from the tier-1 window. The intermediate-tier widening adds `(W_INT - W_SHORT) = 100 cp` to the failing-side bound, leaving the non-failing side at the proved tier-1 edge.

```rust
/// Intermediate widening tier (M5.I tier 2) on a tier-1 aspiration
/// failure. Computes the tier-2 re-search window from the failed try's
/// `(prev_alpha, prev_beta)` window and the fail-soft `returned` score.
///
/// **Returns** `None` when tier 2 should be **skipped** and the caller
/// should drop directly to tier 3 (the existing full-window fallback).
/// The skip fires when the proved bound from tier 1 already lies past
/// the intermediate cap, producing an inverted/empty window. This
/// subsumes the mate-magnitude case (mate-magnitude `returned` always
/// satisfies the inverted-window condition for any non-mate centered
/// tier-1 window).
///
/// Otherwise:
/// - **Fail-high** (`returned >= prev_beta`):
///   `(returned, prev_beta + ADDITIONAL_HALF_WIDTH)` — preserve the
///   proved lower bound from tier 1; widen beta by the additional
///   half-width. `ADDITIONAL_HALF_WIDTH = ASPIRATION_INTERMEDIATE_HALF_WIDTH
///   - ASPIRATION_HALF_WIDTH = 100`, so on a symmetric tier 1 the
///   tier-2 beta equals `prev + ASPIRATION_INTERMEDIATE_HALF_WIDTH`.
/// - **Fail-low** (`returned <= prev_alpha`):
///   `(prev_alpha - ADDITIONAL_HALF_WIDTH, returned)` — preserve the
///   proved upper bound from tier 1; widen alpha down by the
///   additional half-width.
///
/// **Caller contract**: only called when `(returned >= prev_beta) ||
/// (returned <= prev_alpha)`. The window-contained case is short-
/// circuited by the caller (same as `widen_after_fail`). Pinned by
/// AS33 (`debug_assert!` panic in debug builds on violation).
///
/// Pure function. Pinned by AS25–AS32.
fn widen_intermediate(
    returned: i32,
    prev_alpha: i32,
    prev_beta: i32,
) -> Option<(i32, i32)>;
```

**Why no `prev` parameter, no separate mate branch.** The reviewer's must-fix #3 + should-fix #9 are addressed by this signature: tier-2's failing-side cap is derived from `prev_beta + (W_INT - W_SHORT)` (which equals `prev + W_INT` for a symmetric tier 1, but is the structurally robust form if tier 1's symmetry is ever revisited). The inverted-window check (`returned >= intermediate_beta`) subsumes the mate case: for any non-mate tier-1 center (`|prev| < MATE_IN_MAX_PLY - W_INT`), a mate-magnitude `returned >= MATE_IN_MAX_PLY = 29936` satisfies `returned >= intermediate_beta < 30086 << 29936`-with-margin → skip via inverted-window. The explicit `|returned| >= MATE_IN_MAX_PLY` branch is structurally redundant and is omitted from the helper.

Returning `Option` for the skip case is deliberately preferred over producing an inverted window and relying on negamax to short-circuit it: the inverted window costs a function call and a `pos_clone` plumbing pass before negamax detects it, and the skip is a load-bearing correctness commitment (per the research note §2.3 — fixed-width tier 2 can invert if tier 1 fails by more than `W_int`).

### 3.3 Integration: `Search::go` aspiration loop — load-bearing semantic commitments

The canonical diff is in **§4.3**. This section captures the load-bearing semantic commitments only (§3.3 and §4.3 are kept distinct: §3.3 is the *contract*, §4.3 is the *code*).

- **Cap raised**: `tries >= 2` → `tries >= 3`. Up to two re-searches per ID iteration (tier-1 fail → tier-2 → tier-3).
- **Cap-after-success rule preserved**: the cap check stays AFTER the window-contained check, so a tier-3 search whose new wider window contains the final score returns through the success path on the next iteration.
- **No `prior_score` reads at the call site**: per §3.2 the helper takes `(returned, alpha, beta)` directly — these locals still hold the tier-1 window at the failure point because the widen hasn't fired yet. No `prior_score.unwrap_or` / no `.expect()`.
- **Tier-2 skipped → tier-3 fires same iteration**: when `widen_intermediate` returns `None`, the `.unwrap_or_else(|| widen_after_fail(returned, alpha, beta))` fold produces tier-3's window from the tier-1 fail-soft return, exactly as the two-tier code path would. Maximum negamax calls per ID iteration: 3 (tier 1 + tier 2 + tier 3); when tier 2 is skipped, 2 (tier 1 + tier 3).
- **Single `info_sink` emission preserved**: the existing M4.D code emits one info line per re-search; under M5.I, the same single emission fires for whichever tier ran.

### 3.4 Test-only instrumentation

No new instrumentation; the existing `info string aspiration_re_search depth={d} alpha={a} beta={b}` line is reused. Test-side parsing uses the M4.D `parse_aspiration_line` helper (already in `tests` module) and discriminates tier 2 vs tier 3 by INF-edge detection on `alpha`/`beta`:

- Tier 2 (fail-high): `beta < INF` (finite intermediate cap).
- Tier 2 (fail-low): `alpha > -INF` (finite intermediate floor).
- Tier 3 (fail-high): `beta == INF`.
- Tier 3 (fail-low): `alpha == -INF`.

The implicit contract on the info-line schema is stable across M4.D → M5.I. A future change to add an explicit `tier=N` field would be an improvement but isn't required at this scope.

This means **AS19** (the M4.D `fail-high → beta == INF` test) and **AS20** (`fail-low → alpha == -INF`) need a docstring update: on a fail-{high,low} fixture under M5.I, the FIRST emitted aspiration_re_search line may be tier 2 (finite cap), and tier 3 (INF-edge) only fires if tier 2 also fails or is skipped. The AS19/AS20 update is documented in §5.3 "Disturbed pre-existing pins."

### 4.2 New `widen_intermediate` helper

Place immediately after `widen_after_fail` to group the aspiration helpers. Signature and semantics per §3.2.

```rust
fn widen_intermediate(
    returned: i32,
    prev_alpha: i32,
    prev_beta: i32,
) -> Option<(i32, i32)> {
    debug_assert!(
        returned >= prev_beta || returned <= prev_alpha,
        "widen_intermediate called with window-contained score: \
         returned={returned} prev_alpha={prev_alpha} prev_beta={prev_beta}"
    );

    const ADDITIONAL_HALF_WIDTH: i32 =
        ASPIRATION_INTERMEDIATE_HALF_WIDTH - ASPIRATION_HALF_WIDTH;
    // The compile-time assert ASPIRATION_INTERMEDIATE_HALF_WIDTH >
    // ASPIRATION_HALF_WIDTH guarantees ADDITIONAL_HALF_WIDTH > 0.

    if returned >= prev_beta {
        // Fail-high: proved lower bound is `returned`; widen beta by
        // ADDITIONAL_HALF_WIDTH. Skip if the proved bound is already
        // past the intermediate beta (would invert window). For tier 1
        // symmetric around `prev`, `prev_beta + ADDITIONAL_HALF_WIDTH ==
        // prev + ASPIRATION_INTERMEDIATE_HALF_WIDTH`.
        let intermediate_beta = prev_beta + ADDITIONAL_HALF_WIDTH;
        if returned >= intermediate_beta {
            return None;
        }
        Some((returned, intermediate_beta))
    } else {
        // Fail-low: proved upper bound is `returned`; widen alpha down
        // by ADDITIONAL_HALF_WIDTH. Skip if the proved bound is already
        // past the intermediate alpha.
        let intermediate_alpha = prev_alpha - ADDITIONAL_HALF_WIDTH;
        if returned <= intermediate_alpha {
            return None;
        }
        Some((intermediate_alpha, returned))
    }
}
```

**Correctness notes**:

1. The skip on inverted-window is `returned >= intermediate_beta` (NOT `>`). At exact equality `returned == intermediate_beta`, the tier-2 window is `(returned, returned)` which is empty: fail-soft would immediately fail-high with no new information. Skipping is the right call. Symmetric for fail-low.

2. **Mate-magnitude subsumption** (single-line invariant): for any tier-1 window with `prev_beta < MATE_IN_MAX_PLY - ADDITIONAL_HALF_WIDTH = 29836`, mate-magnitude `returned >= MATE_IN_MAX_PLY = 29936` satisfies `returned >= intermediate_beta = prev_beta + 100 ≤ 29936`, so the inverted-window check fires → `None`. This is always true for non-mate tier-1 centers, where the typical bound is `|prev_beta| ≤ a few hundred cp`. Even for tier-1 centers themselves near mate (`prev_beta` ∈ `[29836, MATE_IN_MAX_PLY)`), the inverted-window check fires on any `returned` that confirms or extends the mate (proved bound ≥ intermediate cap). The explicit `|returned| >= MATE_IN_MAX_PLY` branch would be dead code.

3. The helper is agnostic to `prev`; it derives the intermediate cap from the tier-1 window edges. If a future tune makes tier 1 asymmetric (e.g., separate `ASPIRATION_FAIL_HIGH_HALF_WIDTH` vs `ASPIRATION_FAIL_LOW_HALF_WIDTH`), this helper still works: the additional widening is applied symmetrically on whichever side failed.

### 4.3 Aspiration-loop wiring in `Search::go`

Inside the `for depth in 1..=max_depth` body, replace the M4.D inner aspiration loop's `tries >= 2` cap + single widen step with the three-tier dispatch from §3.3.

Concretely, in pseudo-diff form:

```diff
-                if tries >= 2 {
+                if tries >= 3 {
                     break;
                 }

-                let (na, nb) = widen_after_fail(returned, alpha, beta);
+                let (na, nb) = if tries == 1 {
+                    widen_intermediate(returned, alpha, beta)
+                        .unwrap_or_else(|| widen_after_fail(returned, alpha, beta))
+                } else {
+                    widen_after_fail(returned, alpha, beta)
+                };
                 alpha = na;
                 beta = nb;

                 info_sink(&format!(
                     "info string aspiration_re_search depth={depth} alpha={alpha} beta={beta}"
                 ));
```

This is the minimal diff: ONE line changed for the cap, FIVE lines added for the tier-1/tier-2 dispatch, ZERO new `info_sink` calls. The reviewer's should-fix #7 (single info_sink emission) is preserved by structure.

**No `prior_score` reads at this call site.** Per §3.2 the helper takes only `(returned, prev_alpha, prev_beta)` — these are the existing `alpha, beta` locals which still hold the tier-1 window at the failure point (they haven't been updated yet). No `prior_score.expect("...")` is needed because the helper doesn't need `prev`.

**Loop cap discipline**: the existing M4.D `tries >= 2` becomes `tries >= 3`. The check stays AFTER the window-contained check, preserving M4.D's invariant that a re-search whose new wider window contains the score returns through the success path. With three tiers, this means a tier-3 search whose window contains the final score still terminates the loop via the success path on the next iteration.

**Tier-2 skipped → tier-3 fires same iteration.** When `widen_intermediate` returns `None`, `.unwrap_or_else(|| widen_after_fail(returned, alpha, beta))` immediately produces tier-3's window. The closure's `returned, alpha, beta` are the captured tier-1 locals, so tier 3 fires on the tier-1 fail-soft return exactly as it would in the two-tier code path. `tries` increments past 2 on the next iteration, capping at 3 total tries.

### 4.4 No changes to other steps

- `aspiration_window` (tier-1 helper) — unchanged.
- `widen_after_fail` (tier-3 helper) — unchanged signature and semantics. Tier 3 is still "asymmetric full-window on fail."
- Per-try reset (aborted / root_score / pv.lengths) — unchanged.
- Killer persistence — unchanged. Killers persist across all three tries; no per-try clear.
- `extract_bestmove_or_tt_fallback` — unchanged.

### 5.2 Integration tests for `Search::go` (AS34–AS37)

All in `src/search.rs::tests` using the same `fail_low_fixture` / `fail_high_fixture` / `stable_fixture` helpers as AS10–AS23. The existing helpers `aspiration_lines`, `parse_aspiration_line`, `parse_int_field` are reused.

**AS34 — Three-tier cap respected (anti-stub against `tries >= 4`)**

Run the depth-6 search on a fixture that triggers tier 1 fail. Assert that **at most 2 aspiration_re_search lines per depth** are emitted (one for tier 2, one for tier 3). A future regression that raised the cap to `tries >= 4` would emit 3 lines per depth on the same fixture.

The fixture must produce both a tier-1 fail AND a tier-2 fail (so tier 3 fires). Constructing such a fixture is non-trivial because tier 2 has a wide window (`±150 cp`). Candidate approach: use the existing `fail_high_fixture` (KP-vs-K, queen-promo discovery) — iter-6 first try `(93, 193)` fails high with `returned >> 193` (the post-promo queen score is ~+1000 cp). Tier 2 would then attempt `(returned, prev + 150)` = `(returned, 293)` — but if `returned >= 293`, tier 2 is **skipped via inverted-window** and tier 3 runs immediately. **So this fixture triggers exactly 1 re-search line at depth 6 (tier 3 only) under the new design — not 2.**

This means AS34 may need a fixture where tier 2 DOES fire (returned in range `[prev + 50, prev + 150]`) AND tier 2 also fails — producing 2 lines. This is harder to construct deterministically because it requires the depth-6 true score to be in the `[prev + 150, +INF)` range while the tier-1 return at `(prev − 50, prev + 50)` is in `[prev + 50, prev + 150)`. **This is a real concern**: the load-bearing tier-2-fail fixture may not exist for the engine's actual score curves. The fallback test design:

- **AS34a**: tier-2-fires-not-tier-3. Use any fail-{high,low} fixture where tier-1's `returned` is in the `[prev + 50, prev + 150)` range. Assert **exactly 1** re-search line at the failing depth AND that line's `beta` matches `prev + 150` (not INF). This pins the tier-2 path.

- **AS34b**: tier-2-skipped-via-inverted-window. Use `fail_high_fixture` (large fail-high gap, queen-promo at depth 6+). Assert exactly 1 re-search line at the failing depth AND that line's `beta == INF` (tier 3). This pins the inverted-window skip path.

- **AS34c (optional, conditional on fixture availability)**: tier-2-fires-then-tier-3-fires. Search a constructed position where tier-1 fails AND tier-2 also fails. If such a fixture exists, assert exactly 2 re-search lines, first with finite-beta (tier 2), second with `beta == INF` (tier 3).

**Residual cap-pin gap (reviewer should-fix #5).** Without AS34c, the integration-level cap pin `tries >= 3` is structurally pinned only by (a) code-reading + (b) the AS33 `debug_assert!` (which fires only on window-contained input, not on cap violation). A mutation `tries >= 3` → `tries >= 4` would survive on fixtures where tier-2 never re-fails. **The plan accepts this as a documented residual mutation-survivor concern** — surfaced in the mutation-triage step (workflow §9) for the final-reviewer's judgment. If AS34c CAN be constructed during impl, it closes this gap; if not, the survivor is justified-deferred (the cap-bump cost on a no-fixture-reachable fail-low fail-high cascade is bounded: one extra `widen_after_fail` + negamax call per ID iteration, the second of which is the same window the first call produced — functionally idempotent under fail-soft).

The fixture-availability question is empirical. The plan commits to **AS34a + AS34b as load-bearing**; AS34c is *attempted but optional*.

**AS35 — Tier-2 window has proved-bound preservation (anti-stub against `alpha = prev - 50` instead of `alpha = returned`)**

Mirrors AS19 for tier 2 specifically. Use a fail-high fixture where tier 2 fires (per AS34a's fixture). Assert that the re-search line's `alpha` equals the tier-1 returned score (read from `info depth ...` line at the failing depth's iter-(d−1) snapshot or from a `#[cfg(test)]` instrumentation hook). The literal anti-stub: `widen_intermediate` returning `(prev_alpha, intermediate_beta)` instead of `(returned, intermediate_beta)` would set `alpha = prev - 50` here. Symmetric AS36 for fail-low.

If the tier-1 returned score isn't directly observable from `info` lines (M4.D's existing AS19 reads the post-re-search `alpha` from the re-search info line itself, which is the post-widen value — this is sufficient for the M4.D test). For M5.I, the same approach works: AS35 reads `alpha` from the tier-2 info line and asserts `alpha >= prev + 50` (the proved lower bound from tier 1's fail-high — since `returned >= prev + 50` always). The exact value isn't required; the inequality `alpha >= prev + 50` directly pins proved-bound preservation.

**AS36 — Tier-2 fail-low symmetry of AS35**

Mirror of AS35 for the fail-low side. Use the existing `fail_low_fixture`. The depth-6 fail-low returned score is ≤ -935 cp (queen-down regime); `prev` (iter-5) is around -885. Tier 1 (-935, -835) → fail-low with `returned ≤ -935`. Tier 2 attempts `(prev - 150, returned)` = `(-1035, returned)`. Is the inverted-window check triggered? `returned ≤ prev - 150 = -1035` would skip tier 2. The fixture's actual tier-1 returned score is around -939 (per AS21's documentation), so `returned = -939 > -1035` → tier 2 fires. AS36 asserts the tier-2 info line's `alpha == -1035` (= `prev - 150`) and `beta == -939` (= `returned`, fail-soft proved upper bound).

**Risk**: the iter-5 score depends on M5.G + M5.H1 search state, which may have shifted from M4.D's recorded values. The plan accepts this as an empirical anchor: at test-authoring time, run the fixture once, record the actual prior score, encode the expected tier-2 alpha/beta. The AS21 fixture has been stable across multiple M5 phases (re-search continues to fire at depth 6), so prior-score drift within ±50 cp is plausible. Test assertion uses inequalities (`alpha < prev`, `beta > prev_alpha`) rather than exact values where possible.

**AS37 — Mate-prior at threshold falls through to tier 3 cleanly**

Reuse the Bogoljubow mate-in-3 fixture from AS22. Construct a sequence where iter-(N−1) reports a mate score and iter-N first try fails high with a mate return. Assert that **exactly one** re-search line fires at the failing depth (tier 2 was skipped via the inverted-window check, which subsumes the mate case; tier 3 ran). The line's `beta == INF` (tier 3) confirms the skip went through to the existing widen_after_fail path.

Caveat: similar to AS22, the integration-level anti-stub for the mate skip is hard to construct (a mate-prior iteration that fails high is rare with threshold=6 + window=±50 cp — the iter-(N−1) mate score typically remains visible at iter-N within ±50 cp, so window-contained). AS37 is best-effort; **AS29b** (the mate-magnitude inverted-window smoke test in §5.1) is the load-bearing mate-skip pin (it directly asserts the inverted-window check fires for mate-magnitude `returned` on a non-mate tier-1 center, which is the exact subsumption proof).

## 10. Risks and what could go wrong

### 10.1 Risk: SPRT comes back inconclusive (expected)

The literature has no positive SPRT for three-tier vs. two-tier aspiration. MadChess (the only published three-tier data point) regressed. The roadmap explicitly says: "SPRT may come back inconclusive; that's an expected outcome and lands as a no-change retrospective rather than a failure."

**Mitigation**: §11 outcome paths cover both lands and no-lands. The implementation is reversible (revert the `widen_intermediate` helper + the loop wiring); no architectural lock-in.

### 10.2 Risk: tier-2 fixture inconstructable (AS34c)

A fixture where tier 1 AND tier 2 both fail (so tier 3 fires) is hard to construct deterministically because tier 2's window is wide (±150 cp). The fail-soft proof: if tier-1 returns `L < prev + 150`, tier 2 fires with window `(L, prev + 150)`. For tier 2 to fail, the true score must be `< L` (fail-low) or `≥ prev + 150` (fail-high). The fail-low case contradicts tier-1's lower bound proof (`L ≥ prev + 50`, and tier-2 would need true score `< L < prev + 150` while tier-1 first try fail-high required true score `> prev + 50` — these are consistent only with search instability between tier-1 and tier-2 trees). The fail-high case requires `true_score ≥ prev + 150` AND `tier-1 returned L < prev + 150` — both conditions are possible with search instability or with a true score exactly at the boundary.

**Mitigation**: AS34c is best-effort. AS34a (tier 2 fires) + AS34b (tier 2 skipped) are the load-bearing integration pins. If AS34c can't be constructed, the cap pin relies on the loop structure being readable (no hidden 4-tier path) plus the AS33 debug-assert.

### 10.3 Risk: AS19/AS20 disturbance reveals a bug

If AS20 (fail-low) currently relies on tier-2's failure path firing, and the new code's tier-2 actually succeeds (window-contained), AS20's old assertion (`alpha == -INF`) becomes false. This isn't a bug — it's the new behavior. But the test will fail loudly at step 2, and the **test-suite review loop** must accept the updated assertion as correct.

**Mitigation**: documented in §5.3 as expected disturbance. Test-suite reviewer is briefed via the plan.

### 10.4 Risk: bench signature change suggests the implementation is wrong

A change in bench `nodes` from `1147614` means depth-7 startpos now has a different node count. Three plausible causes:
- Real algorithmic difference: tier 2 fires (or doesn't) at depth 7 on the startpos, changing the search tree size. **Expected behavior**, not a bug.
- An incorrect tier-1 / tier-2 interaction that changes nodes spuriously. **Mitigation**: the `widen_intermediate` helper's unit tests (AS25–AS33) verify the helper's logic; the integration tests (AS34) verify the loop wiring. If both are green and bench changes, the change is real.
- Drift from another path. **Mitigation**: no other code path changes in M5.I — only the aspiration loop's widen step. A bench-signature shift implies the aspiration path changed.

The bench delta is informational; not a gate.

### 10.5 Risk: TC-bimodal regression at SPRT (per M5.H2 / M5.G v1 precedent)

The research note §4.4 flagged this. If SPRT shows positive at slow TC and negative at fast TC (e.g., 40+0.4 positive but 10+0.1 negative), the outcome path is "inconclusive lands as no-change retrospective" per the roadmap.

**Mitigation**: mixed-TC SPRT (4-bucket uniform `10+0.1:1, 20+0.2:1, 40+0.4:1, 60+0.6:1`) is the explicit gate. A TC-bimodal pattern triggers §11 outcome 3 or 4.
