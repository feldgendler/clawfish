# M5.A — Null-move pruning (NMP)

First M5 sub-phase. Adds a null-move sub-search to the negamax prologue: at non-PV interior nodes that pass a seven-condition gate, search a "passed turn" position to reduced depth (`R = 2 + depth/6`); on `null_score >= beta`, return a fail-high without entering the move loop.

Slots into the negamax prologue **after** the TT probe + cutoff check (ADR-0018 §13's pinned ordering) and **before** move generation. Adds the first static-eval consumer in negamax (read inside the NMP gate; M5.B/RFP may hoist when its plan lands). New ADR-0023 records the parameter choices and the zugzwang policy.

Per the user's standing instructions: **mutation testing prepared but not run** at landing. SPRT vs `baseline/alpha-beta-tt-killer-history-aspiration` runs at landing per the roadmap's mixed-TC adoption rule; result is recorded post-merge. The ELOH overnight cargo-mutants campaign covers M5.A jointly with the existing M4.B+M4.C+M4.D entry — append the M5.A diff range to that backlog entry.

Research synthesis: `docs/research/m5-null-move-pruning.md`.

## 0. Goals

- **`NullUndo` struct** (`src/mov.rs`) — `prior_ep: Option<Square>`, `prior_halfmove: u8`, `prior_zobrist: u64`. No `prior_fullmove`: `unmake_null_move` derives the fullmove restore from the post-make side-to-move, mirroring `unmake_move`'s pattern at `src/mov.rs:803` (`us == Black ⇒ decrement; else leave`). No piece data, no castling — null move touches neither.
- **`make_null_move(pos: &mut Position) -> NullUndo`** + **`unmake_null_move(pos: &mut Position, undo: NullUndo)`** in `src/mov.rs`. Delegation methods `Position::make_null_move` / `Position::unmake_null_move` per the M1.E `make_move`/`unmake_move` precedent. State changes: STM flips, EP target clears, halfmove clock increments by 1, fullmove number increments iff Black-was-to-move, Zobrist XOR turn key + XOR ep_file_key when Polyglot-active before the null. Pieces / mailbox / castling / king squares / `static_eval_white` untouched.
- **`has_non_pawn_material(pos: &Position, side: Color) -> bool`** pure helper (`src/search.rs`). Returns `true` iff `side` has at least one non-pawn, non-king piece. Used as the NMP zugzwang guard. Implemented as `(pos.pieces_colored(side, Knight) | pos.pieces_colored(side, Bishop) | pos.pieces_colored(side, Rook) | pos.pieces_colored(side, Queen)) != Bitboard::EMPTY`.
- **`null_move_reduction(depth: u32) -> u32`** pure helper (`src/search.rs`). Returns `NMP_BASE_R + depth / NMP_DEPTH_DIVISOR` (= `2 + depth/6`). Extracted as a named function so mutations on the formula are directly unit-testable (M3.D `negate_window` precedent, M3.E `aborted_fallback_result` precedent).
- **`AlphaBetaMover::negamax` signature gains `allow_null: bool`** parameter, threaded through alongside `is_pv`. Top-level call from `Search::go` passes `allow_null = true`. Recursive calls in the move loop pass `allow_null = true`. The NMP null-search recursive call passes `allow_null = false` (stacked-null prevention).
- **NMP block in negamax**, between step 7 (TT probe) and step 9 (move generation). **Seven-condition gate** with `ply > 0` first as a structural-root guard (defense-in-depth against a future PVS refactor that would change `is_pv`'s semantics — research §12 "NMP at ply=0" row). Static-eval read is **lazy**: pulled inside the gate after the cheap predicates and `in_check`, so the read fires only when the other gates are likely to pass. Zero-window null-search at `(-beta, -beta+1)` with `allow_null = false`; on `null_score >= beta` returns the cutoff with mate-cap; otherwise falls through to the move loop. This is the **first static-eval consumer in negamax** (read inside the NMP gate); M5.B/RFP may hoist the read to a shared location when its plan lands and a second consumer exists.
- **Mate-score cap on NMP cutoff**: when `null_score >= beta` AND `null_score >= MATE_IN_MAX_PLY`, define `cutoff_score = beta` (the mate-capped value); otherwise `cutoff_score = null_score`. NMP doesn't prove mate; returning a mate score from the null branch would mis-rank the position in the parent's search.
- **TT store on NMP cutoff**: `Bound::Lower` at the **current depth** (not `depth - 1 - R` — the cutoff proves a lower bound at the current node, not at the reduced child; ADR-0018 §3 "depth at which entry was stored" semantic + §1 depth-preferred replacement) with `best_move = 0` and `score = score_to_tt(cutoff_score, ply)` (the mate-capped value, NOT the raw `null_score` — a mate-magnitude score in TT would later be returned by a probe as a real mate proof at a different ply). ADR-0018 §7's preservation rule keeps any prior `best_move` for the same key.
- **No verification search** in v1 (deferred — `has_non_pawn_material` is the primary protection; verification doubles work on the uncertain branch for marginal gain per Hyatt/Crafty testing).
- **No eval-aware R bonus** in v1 (deferred — adds a tuning parameter; v1 ships the simpler smooth-linear formula).
- **Bench signature expected to change** (NMP cuts ~30–50% of nodes at fixed depth). Determinism within a run preserved (re-pin via the existing E47 pattern). `bench/m5.md` opened with the new signature.
- SPRT against `baseline/alpha-beta-tt-killer-history-aspiration` per the roadmap's mixed-TC rule (`elo0=0, elo1=10`; `--tc-sample 10+0.1:1,20+0.2:1,40+0.4:1,60+0.6:1`). User-scheduled long-wallclock run; commit lands ahead of it.
- ADR-0023 records the formula `R = 2 + depth/6`, the gate set, the zugzwang policy (non-pawn material ≥ 1), the deferred verification-search and eval-aware-R-bonus surface, and the open SPRT-tunable parameters.

## 1. Out of scope

- **Verification search** (Tabibi & Netanyahu 2002). Deferred. Material guard alone is the v1 safety net.
- **Eval-aware R bonus** (`R += min((static_eval - beta) / 200, 3)`). Deferred. Adds a tuning parameter; not a v1 win.
- **TT-driven threat-extraction after NMP fail** (CPW: extract refutation move from null-search TT entry, give ordering boost to escape-from-target-square). Deferred refinement.
- **RFP / reverse-futility pruning** — that's M5.B. M5.A's NMP block is structured so M5.B can land an adjacent `if` block at the same prologue location, sharing only the `static_eval` variable. The roadmap's "fold M5.B into M5.A?" question resolves to **keep separate** per research §13: independent SPRT signals, no code entanglement, and depth-3 overlap is sequential-`if`-blocks not interaction.
- **Adaptive R as f(eval, depth)**. M5+ tuning surface. v1 ships the smooth-linear formula.
- **Static-eval-stm helper method** on `Position`. Inline sign-flip for v1; helper added later if call sites proliferate.

## 3. Type definitions and signatures

### 3.1 `NullUndo` + `make_null_move` / `unmake_null_move`

```rust
// src/mov.rs (alongside the existing Undo struct).

/// Reversal token for a previous `make_null_move` call. Records only the
/// fields a null move mutates and that aren't trivially derivable from the
/// post-make state. Side-to-move is recoverable (XOR-flip); fullmove
/// number is recoverable from the post-make side via the same pattern as
/// `unmake_move` at `src/mov.rs:803` (`us == Black ⇒ decrement; else leave`).
///
/// Separate from `Undo` (which carries piece-capture + castling deltas)
/// because no pieces move and no castling rights change — reusing `Undo`
/// would carry irrelevant zeroed state and blur the call-site semantics.
#[derive(Copy, Clone, PartialEq, Eq, Debug)]
pub struct NullUndo {
    pub prior_ep: Option<Square>,
    pub prior_halfmove: u8,
    pub prior_zobrist: u64,
}

/// Apply a null move (pass the turn) to `pos`, returning a `NullUndo`
/// sufficient to reverse the change.
///
/// State changes:
/// - `side_to_move` flips.
/// - `ep_target` clears (a null move forfeits any pending EP capture).
/// - `halfmove_clock` increments by 1 (null is not a capture or pawn push).
/// - `fullmove_number` increments iff `prior_side == Black`.
/// - `zobrist` updates incrementally: XOR `turn_key()` AND XOR
///   `ep_file_key(file)` for each `Some(file)` in
///   `zobrist::ep_file_to_hash(pos)` BEFORE the EP clear.
/// - `static_eval_white`, pieces, mailbox, king squares, castling: untouched.
///
/// **Trusts the caller** that `pos` is not in check — searching a null-move
/// position when in check is undefined; NMP's gate must screen this out.
/// Debug builds add a `from_scratch` Zobrist round-trip assert.
pub fn make_null_move(pos: &mut Position) -> NullUndo;

/// Reverse a previous `make_null_move`. Restores all fields the make
/// mutated; debug builds assert the post-unmake position equals
/// `pos_before_make` byte-for-byte.
pub fn unmake_null_move(pos: &mut Position, undo: NullUndo);
```

`Position::make_null_move(&mut self) -> NullUndo` and `Position::unmake_null_move(&mut self, undo: NullUndo)` are thin delegators in `src/position.rs`, mirroring the existing `Position::make_move` / `Position::unmake_move` methods.

### 3.3 NMP block placement and pseudocode

Inserted between current step 7 (TT probe) and current step 8 (movegen). Numbering bumps: NMP becomes new step 8, movegen becomes 9, etc. The renumbered prologue (per ADR-0018 §13 + M5.A insertion):

```
1. clear PV slot at this ply
2. depth == 0 → qsearch
3. nodes increment + cancellation poll
4. capture original_alpha
5. ply > 0: repetition + 50-move draw checks
6. mate-distance pruning (may tighten alpha/beta)
7. TT probe (cutoffs at non-PV; ordering hint at PV)
8. *** NEW: NMP block (M5.A) — see pseudocode below ***
9. generate moves + terminal check
10. order moves
11. move loop + recursive negamax
12. TT store on completion
```

NMP block pseudocode:

```rust
// 8. Null-move pruning (M5.A). Seven-condition gate (ply > 0 first as
//    structural-root guard, defense-in-depth against future PVS refactor;
//    static-eval read pulled into the gate as a lazy late predicate so it
//    fires only when the other cheap gates have already passed). Null
//    sub-search at zero window; mate-cap on cutoff; TT store on cutoff.
//    Falls through on any gate miss or null-score < beta.
if ply > 0
    && allow_null
    && !is_pv
    && depth >= NMP_MIN_DEPTH
    && !in_check(pos)
{
    let stm = pos.side_to_move();
    if has_non_pawn_material(pos, stm) {
        let static_eval = if stm == Color::White {
            pos.static_eval_white()
        } else {
            -pos.static_eval_white()
        };
        if static_eval >= beta {
            let r = null_move_reduction(depth);
            let null_undo = pos.make_null_move();
            self.history.push(pos.zobrist());
            let null_score = -self.negamax(
                pos,
                depth - 1 - r,
                ply + 1,
                -beta,
                -beta + 1,
                false,            // is_pv
                false,            // allow_null (stacked-null prevention)
                ctx,
                clock,
            );
            self.history.pop();
            pos.unmake_null_move(null_undo);

            // Abort discipline matches the move loop: unmake before
            // checking aborted, so balanced-make/unmake debug-assert holds
            // even on the abort path. (NMP introduces a new abort site
            // that flows through the existing abort discipline unchanged
            // — see §12 Risk 2.)
            if self.aborted {
                return 0;
            }

            if null_score >= beta {
                // Mate-cap: NMP doesn't prove mate. If the null branch
                // returned a mate score, it means the opponent mates after
                // we pass — that indicates a dangerous position but is not
                // a real mate proof.
                let cutoff_score = if null_score >= MATE_IN_MAX_PLY {
                    beta
                } else {
                    null_score
                };
                // TT store as Lower-bound at the CURRENT depth (the cutoff
                // proves a lower bound at this node, not at the reduced
                // child — ADR-0018 §3 "depth at which entry was stored"),
                // no best move (NMP didn't pick one). ADR-0018 §7
                // preserves any prior best_move for the key. Score stored
                // is the mate-CAPPED value (cutoff_score), not raw
                // null_score — a mate-magnitude score in TT would
                // later be returned as a real mate proof at a different ply.
                if let Some(tt) = &self.tt {
                    let adjusted = score_to_tt(cutoff_score, ply as i32);
                    tt.store(
                        pos.zobrist(),
                        TtData {
                            score: adjusted as i16,
                            depth: depth as u8,
                            bound: TtBound::Lower,
                            best_move: 0,
                        },
                    );
                }
                return cutoff_score;
            }
        }
    }
}
```

The `static_eval` variable is **scoped to the NMP block** (read inside the gate). M5.B's RFP plan will decide the static-eval read location once both consumers exist (M5.B may hoist to a shared prologue location, may keep two reads, or may unify via a helper); M5.A does not pre-commit M5.B's design. v1's lazy-read avoids paying the static-eval read at every PV node, every in-check node, every shallow node where NMP doesn't fire.

### 3.4 Helper functions

```rust
// src/search.rs

/// True iff `side` has at least one non-pawn, non-king piece on the board.
/// NMP zugzwang guard: zugzwang is dominantly a K+P-ending phenomenon, so
/// the presence of any minor or major piece reduces zugzwang risk to
/// near-zero. (Residual K+R+P / K+B+P zugzwang is rare and not screened.)
///
/// Implemented as a union of `pieces_colored` bitboards rather than four
/// `count() > 0` calls; the union short-circuits at the first set bit.
pub(crate) fn has_non_pawn_material(pos: &Position, side: Color) -> bool {
    let pieces = pos.pieces_colored(side, PieceKind::Knight)
        | pos.pieces_colored(side, PieceKind::Bishop)
        | pos.pieces_colored(side, PieceKind::Rook)
        | pos.pieces_colored(side, PieceKind::Queen);
    !pieces.is_empty()
}

/// NMP depth reduction. Returns `NMP_BASE_R + depth / NMP_DEPTH_DIVISOR`
/// (= `2 + depth/6`). Pure function. Extracted as a named helper so
/// mutations on the formula constants are directly unit-testable
/// (M3.D `negate_window` precedent).
pub(crate) fn null_move_reduction(depth: u32) -> u32 {
    NMP_BASE_R + depth / NMP_DEPTH_DIVISOR
}
```

If `Bitboard::is_empty()` does not exist on the existing API, the function uses `pieces != Bitboard::EMPTY`. Confirmed in impl.

### 3.5 Constants

```rust
// src/search.rs (near the existing ASPIRATION_MIN_DEPTH / ASPIRATION_HALF_WIDTH block).

/// Minimum depth at which NMP is attempted. Below this, the null-search's
/// `depth - 1 - R` would be ≤ 0, which dispatches to qsearch — defeating
/// the cost/benefit calculation. ADR-0023.
pub(crate) const NMP_MIN_DEPTH: u32 = 3;

/// NMP base reduction: `R = NMP_BASE_R + depth / NMP_DEPTH_DIVISOR`.

pub(crate) const NMP_BASE_R: u32 = 2;

/// NMP depth divisor in the reduction formula.
pub(crate) const NMP_DEPTH_DIVISOR: u32 = 6;
```

`pub(crate)` so tests outside the `negamax` body can reference them.

### 5.3 `src/search.rs` — NMP behavior in negamax (~12 tests)

**Test pattern: every gate-skip test pairs with a sister positive fixture and asserts a node-count delta.** A no-op NMP impl trivially "skips NMP" everywhere; the gate-skip tests therefore must compare against a fixture where the gate's *opposite* condition fires and demonstrate observable behavior change. Mechanism: run `negamax_for_test` twice from the same parent setup — once at the gate-skip fixture, once at the gate-pass sister fixture — and assert (`nodes_skip > nodes_pass`) or (`returned_skip != returned_pass`). The delta is the discriminator.

NMP-behavior tests use `negamax_for_test` directly (not via `Search::go`) so the test author controls `is_pv`, `allow_null`, depth, and the `(alpha, beta)` window precisely.

| Test | Assertion |
|---|---|
| `negamax_skips_nmp_at_ply_zero_even_when_is_pv_false` | Direct `negamax_for_test` call with `ply = 0` and synthetic `is_pv = false` (defending against future PVS refactor). Sister fixture: same position, same arguments, called with `ply = 1` instead of `ply = 0` — the `ply > 0` gate passes there and NMP fires. Assert node-count or score delta. |
| `negamax_skips_nmp_when_in_check` | Setup: position where STM is in check, depth ≥ 3. Sister fixture: a near-identical non-check position. **Construction note**: changing piece placement to remove the check perturbs `static_eval`; the test author must verify both fixtures pass `static_eval >= beta` independently (e.g., by setting `beta` per-fixture to compensate, or picking positions where the eval delta is smaller than the gate margin). The sister-fixture comparison's discriminator is **node count**: the in-check version visits more nodes (full evasion move-loop) than the not-in-check version (NMP cutoff). |
| `negamax_skips_nmp_at_pv_node` | Setup: `is_pv = true` at a non-root ply with NMP-firing-eligible position. Sister fixture: same position with `is_pv = false`. **Primary assertion: distinct node counts** (PV node runs the full move loop; non-PV node fires NMP). Score equality is permitted — both can return scores ≥ beta via different paths under fail-soft. |
| `negamax_skips_nmp_when_allow_null_false` | Two negamax calls on the same fixture: `(allow_null = true, depth = 6)` vs `(allow_null = false, depth = 6)`. Assert distinct node counts; the `false` run visits more nodes (move loop unconditional). |
| `negamax_skips_nmp_when_static_eval_below_beta` | Setup: middlegame position; pick `beta = static_eval + 100` so the gate fails. Sister fixture: same position with `beta = static_eval - 50` so the gate passes. Assert distinct node counts. |
| `negamax_skips_nmp_when_no_non_pawn_material` | Setup: K+P-only endgame (FEN `8/4p3/8/8/4k3/8/4P3/4K3 w - - 0 1`). Sister fixture: same K+P position with one white knight added (`8/4p3/8/8/4k3/3N4/4P3/4K3 w - - 0 1`). Assert distinct node counts at depth ≥ 3 with matching `(alpha, beta)` windows. |
| `negamax_skips_nmp_when_depth_below_3` | At `depth = 2`, NMP must not fire. Sister fixture: same position at `depth = 4`. Assert distinct node counts; the depth-2 run has no NMP saving. |
| `negamax_returns_beta_cutoff_on_successful_nmp` | Setup: a quiet middlegame position where the side-to-move has clear material advantage. Drive `negamax_for_test` with `(alpha = -INF, beta = static_eval - 100)` to guarantee `static_eval >= beta`. Assert returned score >= beta (fail-soft cutoff observed). |
| `negamax_caps_mate_score_to_beta_when_null_score_is_mate` | **Hand-driven, three-step** to avoid fixture flakiness: (1) **sanity step** — directly call `make_null_move` on a known mate-in-1-after-pass position; manually drive `negamax_for_test` from the resulting position with depth 2; assert the returned score `>= MATE_IN_MAX_PLY` (sanity-checks that the fixture actually triggers the mate-cap path; without it, a trivial fixture could pass step 3 for the wrong reason — e.g., NMP didn't fire and the search returned 0). (2) **set up parent** — call `negamax_for_test` at depth 3 with `(alpha = -INF, beta = 500)` (finite, non-mate-magnitude). (3) **assert** returned score == `beta` (mate-capped), NOT mate-magnitude. Specific fixture suggestion: STM has winning material edge but opponent has a back-rank mate-in-1 if STM passes. |
| `negamax_passes_allow_null_false_in_null_subsearch` | **Direct kill via debug-build NMP firing counter**. Add a `#[cfg(test)] nmp_firings: u32` field on `AlphaBetaMover`, increment in the NMP block before the null-search recursive call, expose a `pub(super) fn nmp_firings_for_test(&self) -> u32` accessor (mirrors the existing `killers_for_test` accessor). The test fixture: a position where stacked-NMP could in principle fire ≥ 2 times in a path (depth ≥ 6 with strong eval surplus). Run `negamax_for_test` once; assert `nmp_firings == K` for some specific K observed empirically at impl time. Mutating the inner `allow_null = false` to `true` would let the inner NMP fire, increasing the count past K. The counter is `#[cfg(test)]`-gated so production code is unaffected. |
| `negamax_stores_lower_bound_in_tt_after_nmp_cutoff` | After an NMP cutoff at a known position, `tt.probe(pos.zobrist())` returns an entry with `bound == Lower`, `best_move == 0`, `depth == current_depth`, and `score` matching the expected `score_to_tt(cutoff_score, ply)` value (post-mate-cap). |
| `negamax_with_nmp_preserves_existing_tt_best_move` | Pre-populate the TT at a key with `bound = Exact` and a non-zero `best_move`. Run negamax such that NMP fires at that key. Re-probe; assert the entry has `bound = Lower` (NMP overwrote) BUT `best_move` is the original non-zero move (ADR-0018 §7's preservation rule). |
| `negamax_with_nmp_clears_history_correctly_on_unmake` | Push-and-pop discipline: after the null-search recursive call returns, `self.history.len()` matches the pre-NMP length. (Catches a forgotten `pop` or a doubled `push`.) |

## 7. ADR-0023 — null-move pruning

`docs/decisions/0023-null-move-pruning.md`. **Scope: terse decision + rationale**, ~30–50 lines following the ADR-0018 / ADR-0019 / ADR-0022 pattern. Re-derivation lives in the research note (`docs/research/m5-null-move-pruning.md`) and the plan; the ADR commits the decisions only.

Sections (each ≤ 5 lines):

- **Status**: Accepted, 2026-05-DD.
- **Context**: One paragraph naming the decision surface (NMP parameters + zugzwang policy) and pointing to the research note + plan for the re-derivation.
- **Decision** (parameters fixed at landing):
  - Reduction formula: `R = 2 + depth/6` (integer division). Constants `NMP_BASE_R = 2`, `NMP_DEPTH_DIVISOR = 6`.
  - Minimum depth: `NMP_MIN_DEPTH = 3`.
  - Gate set: `ply > 0`, `allow_null`, `!is_pv`, `depth >= NMP_MIN_DEPTH`, `!in_check(pos)`, `has_non_pawn_material(pos, stm)`, `static_eval >= beta`. Order is meaningful (cheap predicates first; `static_eval` read lazy after `has_non_pawn_material`).
  - Zugzwang policy: non-pawn material ≥ 1 (`has_non_pawn_material` returns true iff side has any knight/bishop/rook/queen).
  - Mate-cap on cutoff: when `null_score >= MATE_IN_MAX_PLY`, return `beta` (not `null_score`).
  - TT store policy: `Bound::Lower` at the **current depth** (not reduced), `best_move = 0`, `score = score_to_tt(cutoff_score, ply)` (the mate-capped value).
  - Stacked-null discipline: `allow_null: bool` parameter on `negamax`; `false` only in the NMP null-search recursive call.
- **Deferred** (one bullet each, no re-derivation):
  - Verification search (Tabibi & Netanyahu 2002).
  - Eval-aware R bonus (`R += min((static_eval - beta)/SCALE, CAP)`).
  - TT-driven threat-move extraction post-NMP-fail.
  - Adaptive R as f(eval, depth).
  - Bundling with M5.B/RFP — explicit decision: keep separate.
- **Open SPRT-tunable parameters**: (a) linear-vs-step `R` formula; (b) static-eval gate margin (`+ delta` instead of plain `>=`). Both as post-M5.A campaigns, not blocking M5.B.
- **References**: research note + plan + ADR-0018 §3/§7 (TT store interaction).

## 9. SPRT methodology

Per ELOH.D's mixed-TC adoption rule + the M4.D precedent.

- **Baseline tag**: `baseline/alpha-beta-tt-killer-history-aspiration` (M4.D end).
- **SPRT bounds**: `elo0=0, elo1=10`. NMP is meaty enough; lower to `elo1=5` only if a v1-design retry surprisingly underperforms.
- **TC sampling**: `--tc-sample 10+0.1:1,20+0.2:1,40+0.4:1,60+0.6:1` (mixed-TC, ~150 games per TC; total ~600 games at ~10h wallclock).
- **Acceptance**: mixed-game SPRT crosses upper Wald bound (H1) AND per-TC Δ ≥ 0 with 95% CI at every sampled TC.
- **Per-TC regression**: a width that fails the per-TC floor at fast TC but passes mixed-game H1 is adoptable with a "helps deep but not fast" flag in the retrospective (M4.C precedent).
- **Width-tune follow-up** (deferred): compare `R = 2 + depth/6` vs `depth > 6 ? 3 : 2`; compare static-eval gate vs no-gate. Recorded in `bench/m5.md` post-merge as an optional follow-up campaign, not blocking M5.B.

## 10. Mutation testing prep

**Pre-review run** (`cargo mutants --in-diff /tmp/m5.a.diff`). Diff scope: `src/mov.rs`, `src/position.rs`, `src/search.rs`, plus the new `docs/decisions/0023-...md` (excluded by the existing mutants config — docs aren't mutated).

Anticipated mutant-survivor surface:
- **`null_move_reduction` formula constants**: `+ → -`, `* → /`, `1 → 2` etc. Killed by §5.2 boundary tests.
- **Stacked-null flag inversion**: changing `allow_null = false` to `allow_null = true` in the null-search recursive call — direct test in §5.3 `negamax_passes_allow_null_false_in_null_subsearch`.
- **NMP gate inversion**: any `&&` → `||` or `>=` → `>` in the gate. Killed by §5.3 gate-skip tests.
- **Mate-cap inversion**: `null_score >= MATE_IN_MAX_PLY` → `null_score > MATE_IN_MAX_PLY`. The §5.3 `negamax_caps_mate_score_to_beta_when_null_score_is_mate` fixture produces `null_score = MATE - small_ply` (well above `MATE_IN_MAX_PLY = 29936`), which kills `>=` → `<` and `>=` → `==` mutants but **does not kill the `>=` → `>` boundary mutant** (since `MATE - small_ply > MATE_IN_MAX_PLY` is true under both forms). Killing the boundary mutant requires `null_score == MATE_IN_MAX_PLY` exactly, which is contrived and not directly achievable from a chess fixture (`MATE_IN_MAX_PLY` corresponds to a mate-in-MAX_PLY which can't be searched). Acknowledged: this mutant likely survives in `cargo mutants` and is documented as a deferred / structurally-undetectable survivor in `docs/mutants-backlog.md` jointly with the M4 entries.
- **TT store bound inversion**: `Bound::Lower` → `Bound::Upper` or `Bound::Exact`. Killed by §5.3 `negamax_stores_lower_bound_in_tt_after_nmp_cutoff`.
- **Halfmove-clock increment in `make_null_move`**: `+ 1` → `+ 0` or `+ 2`. Killed by §5.1 `null_move_increments_halfmove_clock`.
- **Fullmove conditional**: `if prior_side == Black` → `if prior_side == White`. Killed by §5.1 `null_move_increments_fullmove_when_black_was_to_move` + the negative case.
- **EP clear**: `pos.set_aux_state(..., None, ...)` → reuse prior EP. Killed by §5.1 `null_move_clears_ep_target`.

## 11. Bench signature expectation

NMP cuts ~30–50% of nodes at fixed depth (literature; clawfish has strong M4 ordering, expect upper end). Current M4.D bench: `bench: 15863206 nodes <NPS> nps`. Predicted M5.A bench: somewhere in the `7M – 11M nodes` range. Final pinned value lands in the impl pass at step 6.

**Fixed-depth bench vs fixed-time SPRT**: `bench` is fixed-depth (default `go depth 7`), so the 30–50% node-reduction figure applies directly to the bench-signature delta. SPRT is fixed-time per the time-control specs (`tc=10+0.1`, etc.); under fixed-time, NMP's node-reduction is partially recovered as +1–2 plies of additional depth at the same wallclock, so the SPRT Elo delta is NOT proportional to the bench-node delta. The two metrics measure different things: bench pins a deterministic regression check; SPRT measures playing strength. Don't expect the bench-percentage to match the SPRT-Elo when comparing.

## 12. Risks and mitigations

- **Risk**: zugzwang false positive in K+R+P (or similar) endgame produces a wrong score that ripples up the search.
  - **Mitigation**: `has_non_pawn_material` guard catches K+P-only; the K+R+P residual is acknowledged in ADR-0023 + research §4. SPRT is the gate; per-TC regression check catches a global regression.
- **Risk**: a missing `pos.unmake_null_move` (e.g., on the abort path) leaves the position state corrupted, triggering the `debug_assert_eq!(pos_clone, *position)` at the end of `Search::go`. NMP introduces a new abort site (the null-search recursive call into `negamax` can poll `should_abort` at the 4096-node cadence and set `self.aborted`).
  - **Mitigation**: the pseudocode places `unmake_null_move` (and the matching `self.history.pop()`) BEFORE the abort check, matching the existing move-loop discipline of unmaking before checking `self.aborted`. The new abort site flows through the existing M3.E abort discipline unchanged: `self.aborted = true` propagates up through the parent's `if self.aborted { return 0; }` after each recursive call. Test §5.3 `negamax_with_nmp_clears_history_correctly_on_unmake` covers the history-stack discipline; the existing `Search::go` post-search `debug_assert_eq!(pos_clone, *position)` covers the position-balance discipline.
- **Risk**: `allow_null` flag forgotten in one of the multiple recursive-call sites (move-loop call passes wrong value), enabling stacked nulls.
  - **Mitigation**: only one call site passes `false` (the NMP null-search itself); all others pass `true`. Visible as a one-line discipline in the code; tests §5.3 `negamax_passes_allow_null_false_in_null_subsearch` (direct kill via the `nmp_firings` `#[cfg(test)]` counter — fires-count assertion is the most direct catch for stacked-nulls-enabled-by-mis-threaded-flag) and `negamax_skips_nmp_when_allow_null_false` (parameter-skip case) catch the regression independently.
- **Risk**: `is_pv` gate confused with `allow_null` gate; one accidentally substituted for the other.
  - **Mitigation**: research §6.1 + ADR-0023 explicitly enumerate both. Code uses both names without abbreviation. Tests §5.3 `negamax_skips_nmp_at_pv_node` and `negamax_skips_nmp_when_allow_null_false` cover each independently.
- **Risk**: NMP fires at the root despite the non-PV gate (e.g., aspiration fail-soft re-search at root with `is_pv = true` correctly suppresses NMP, but a bug in `is_pv` propagation could let it through).
  - **Mitigation (two layers)**: (1) **primary, structural** — the `ply > 0` gate (added per the pass-1 review's must-fix #1) blocks NMP at the root regardless of `is_pv`. This is defense-in-depth against a future PVS refactor that would change `is_pv`'s semantics (research §12). (2) **secondary backstop** — `Search::go` passes `is_pv = true` at the top-level call, and the `!is_pv` gate continues to block NMP there. M5.A doesn't change either. Tests §5.3 `negamax_skips_nmp_at_ply_zero_even_when_is_pv_false` (layer 1) and `negamax_skips_nmp_at_pv_node` (layer 2) pin both invariants independently.
