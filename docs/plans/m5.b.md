# M5.B — Reverse futility pruning (RFP)

Second M5 sub-phase. Adds **Reverse Futility Pruning** (also called Static Null-Move Pruning, Beta Pruning) to the negamax prologue: at non-PV shallow non-check non-mate-beta interior nodes whose static eval beats beta by a depth-scaled margin, return immediately with a fail-soft proved lower bound, without generating a single move.

Slots into the negamax prologue **between the TT probe + cutoff (step 7) and the M5.A NMP block (which becomes new step 9)**, as new step 8. **The M5.A NMP block is structurally untouched**: its existing seven-condition gate (incl. lazy `static_eval` read inside `has_non_pawn_material`) is preserved verbatim. RFP is cheaper than NMP (no sub-search at all — pure static comparison), so RFP fires first on the depth=3..6 overlap; if RFP cuts off, NMP's sub-search is skipped entirely. Both blocks read `static_eval` independently inside their own gates (lazy duplication, **not** a shared eager hoist) — design choice locked at plan-review pass 1 to keep M5.B's SPRT signal cleanly attributable to RFP alone, with no NMP-side behavior change.

Per the user's standing instructions: **mutation testing prepared but not run** at landing. SPRT vs `M5.A` (commit `e63eb15`) runs at landing per the roadmap's mixed-TC adoption rule; result is recorded post-merge. The ELOH overnight `cargo mutants` campaign covers M5.B jointly with the existing M4.B+M4.C+M4.D+M5.A entry — extend that backlog entry's diff range to include the M5.B SHA.

Research synthesis: [`docs/research/m5-reverse-futility.md`](../research/m5-reverse-futility.md) (15-section survey of the design space, including the §13 v1 recommendation table this plan consumes).

## 1. Out of scope

- **NMP-side mate-beta gate change.** Considered at plan-review pass 1 as part of a "shared static_eval hoist + shared cheap-gate" refactor; rejected because (a) it bundled an NMP behavior change with M5.B's SPRT, blurring attribution against `M5.A`, (b) the equivalence argument vs. ADR-0023 §6's mate-cap-on-cutoff was not airtight (mate-magnitude `beta` is not the same node set as mate-magnitude `null_score`), and (c) hoisting the read out from behind `has_non_pawn_material` enlarged the read population on K+P endgame nodes. M5.A NMP semantics preserved verbatim. Future "share static_eval and shared cheap-gate" refactor can land as a standalone refactor commit with its own SPRT vs `M5.B` if the cost-vs-correctness tradeoff is later judged worth re-opening.
- **Eval-aware margin** (margin shrinks when position is well-above-beta). Documented post-M5.B SPRT-tune candidate (research §13).
- **Per-depth margin table** (e.g., 100/150/250 cp at d=1/2/3 — MadChess-style). v1 ships the simpler linear formula. Per-depth-table is a tuning surface, not a v1 commitment.
- **`(static_eval + beta) / 2` smoothed return**. Lynx/Ciekce recommendation; a documented post-M5.B tuning candidate. v1 ships the simpler `static_eval - margin*depth` proved lower bound.
- **Improving heuristic** (margin halves when STM's eval is improving across plies — i.e., `static_eval` at the current ply exceeds `static_eval` at ply-2). Adds a search-stack field and a tuning parameter. Deferred.
- **M5.D forward / frontier futility pruning** — that's a separate phase. RFP and forward futility are complementary (research §8): RFP cuts at fail-high in the prologue; forward futility skips individual quiet moves at fail-low inside the move loop. They target opposite tails of the position-value distribution and don't interact at the same node.
- **Static-eval-stm helper method on `Position`** (still inline sign-flip — same call as M5.A's NMP block). Once a third negamax static-eval consumer appears (LMR move-skip at M5.C, frontier futility at M5.D), the helper extraction becomes worthwhile; not yet.
- **Verification search for RFP** — the literature does not propose one. Static check is its own verification; nothing to verify.

## 3. Type definitions and signatures

### 3.1 No `negamax` signature change

The M5.A signature `negamax(&mut self, pos, depth, ply, alpha, beta, is_pv, allow_null, ctx, clock) -> i32` is preserved verbatim.

### 3.2 Constants

```rust
// src/search.rs (immediately after the existing NMP_DEPTH_DIVISOR block at line 438).

/// Upper depth bound for reverse-futility pruning. At depths above this,
/// `static_eval - margin*depth >= beta` is rarely true (the margin grows
/// faster than realistic eval surplus), and the tactical-blindness risk
/// from a depth-7+ refutation grows. Stockfish DD historical: `depth < 7`
/// (i.e., depth ≤ 6); ADR-0024 §1.
pub(crate) const RFP_MAX_DEPTH: u32 = 6;

/// Linear coefficient for reverse-futility pruning's depth-scaled margin.
/// `margin = RFP_MARGIN_PER_DEPTH * depth`. At depth=1, 100 cp (≈ one
/// pawn); at depth=6, 600 cp (≈ a rook). Conservative v1 starting value;
/// CPW workhorse alternative is 150 (post-landing SPRT-tune candidate).
/// ADR-0024 §1.
pub(crate) const RFP_MARGIN_PER_DEPTH: i32 = 100;
```

`pub(crate)` so test-module call sites can reference them.

### 3.3 Helper function

```rust
// src/search.rs (immediately after `null_move_reduction` at line 558).

/// RFP depth-scaled margin. Returns `RFP_MARGIN_PER_DEPTH * depth as i32`.
/// Pure function. Extracted as a named helper so mutations on the formula
/// constants are directly unit-testable (M3.D `negate_window` /
/// M3.E `aborted_fallback_result` / M5.A `null_move_reduction` precedent).
///
/// `RFP_MARGIN_PER_DEPTH * depth as i32` cannot overflow `i32` at any depth
/// below ~21M; the `depth <= RFP_MAX_DEPTH = 6` gate makes this trivially safe.
pub(crate) fn reverse_futility_margin(depth: u32) -> i32 {
    RFP_MARGIN_PER_DEPTH * depth as i32
}
```

### 3.4 `#[cfg(test)] rfp_firings` field

Added on `AlphaBetaMover` immediately after the existing `nmp_firings`. Increment site is inside the RFP cutoff branch, before the `return`. Accessor `pub(super) fn rfp_firings_for_test(&self) -> u32` mirrors `nmp_firings_for_test`.

### 3.5 Renumbered prologue + RFP block pseudocode

The renumbered prologue (M5.A's was 1–13 with NMP at step 8; M5.B inserts the RFP block at step 8 and renumbers M5.A's 8–13 to 9–14):

```text
1. clear PV slot at this ply
2. depth == 0 → delegate to qsearch
3. nodes increment + 4096-cadence cancellation poll
4. capture original_alpha = alpha
5. ply > 0: repetition + 50-move draw checks
6. mate-distance pruning (may tighten alpha/beta)
7. TT probe (cutoffs at non-PV; ordering hint at PV)
8. *** NEW: RFP block (M5.B — ADR-0024) ***
9. NMP block (M5.A — ADR-0023, unchanged)
10. generate moves + terminal check
11. order moves
12. move loop + recursive negamax
13. TT store on completion
```

RFP block pseudocode:

```rust
// 8. Reverse futility pruning (M5.B — ADR-0024). Independent of NMP: own
//    cheap-gate, own lazy `static_eval` read, own cutoff. M5.A's NMP block
//    at step 9 is byte-identical (it has its own static_eval read inside
//    its own gate; the duplicated read is a deliberate plan choice over a
//    shared eager hoist — see plan §1 "Out of scope" for the rationale).
//    Order: RFP fires before NMP because it's cheaper (no sub-search). On
//    the d=3..6 overlap, an RFP cutoff skips NMP's sub-search entirely.
if ply > 0
    && !is_pv
    && !in_check(pos)
    && depth <= RFP_MAX_DEPTH
    && beta.abs() < MATE_IN_MAX_PLY
{
    let stm = pos.side_to_move();
    let static_eval = if stm == Color::White {
        pos.static_eval_white()
    } else {
        -pos.static_eval_white()
    };
    let margin = reverse_futility_margin(depth);
    if static_eval - margin >= beta {
        #[cfg(test)]
        {
            self.rfp_firings += 1;
        }
        // Fail-soft proved lower bound: even after discounting `margin*
        // depth` cp from `static_eval`, we still beat beta. No TT store
        // (research §6 / §7): the proof is depth-specific to the margin,
        // not a search-quality bound.
        return static_eval - margin;
    }
}

// 9. Null-move pruning (M5.A — ADR-0023). UNCHANGED FROM M5.A. The block
//    keeps its own `static_eval` read inside its own seven-condition gate;
//    no read is shared with the M5.B RFP block above. (The duplicated read
//    is paid only at non-PV non-check non-mate-beta nodes that pass the
//    RFP-shallow-depth screen but proceed on to the NMP-deep-depth tier; in
//    practice a small fraction of negamax frames.)
//
// (M5.A's existing NMP block goes here verbatim — no edits.)
```

Notes on the shape:

- **No shared cheap-gate, no shared static_eval hoist, no NMP changes.** RFP and NMP each operate inside their own gates with their own lazy `static_eval` reads. This is a deliberate plan-review pass-1 choice over the shared-hoist alternative (rejected because it bundled an NMP behavior change with M5.B's SPRT and enlarged the read population on K+P endgame nodes — see §1).
- **The duplicated `static_eval` read is paid at most twice per negamax frame** (once inside RFP's gate at d≤6, once inside NMP's gate at d≥3, overlap at d∈{3,4,5,6}). At those overlap depths the cost is one extra eval read per frame; `Position::static_eval_white` is a single field load (incremental eval, ADR-0014), so the cost is negligible. Outside the overlap (RFP at d∈{1,2}; NMP at d≥7) only one of the two reads happens.
- **The NMP-internal `has_non_pawn_material` lazy-screen is preserved** because the NMP block is byte-identical to M5.A. K+P-only endgame nodes still skip the NMP `static_eval` read (and now also skip the RFP `static_eval` read, because RFP's gate has no `has_non_pawn_material` check — but RFP's check is even cheaper because it's purely gated on depth/check/PV/mate-beta, all O(1) field reads).
- **RFP-before-NMP ordering**: RFP's static check is cheaper than NMP's null sub-search (zero recursive calls vs one recursive call to depth `depth - 1 - R`). On the d=3..6 overlap, if RFP cuts off, NMP is skipped entirely. The two cutoffs are correctness-equivalent (both produce valid lower bounds at the node), so the ordering choice is a perf optimization. **Caveat**: the two orderings produce different TT contents (NMP stores `Bound::Lower` on cutoff per ADR-0023 §7; RFP doesn't store), so future sibling/transposition probes pick up an entry from NMP-cutoff but not from RFP-cutoff. Both bounds are valid, but the search tree shape diverges. SPRT measures the net Elo of the ordering choice; the cheaper-first ordering is the standard CPW recommendation (research §7).
- **No mate-beta gate added to NMP.** ADR-0023 §3 / §6 are unchanged; ADR-0023 §6's mate-cap-on-cutoff still defends against mate-magnitude `null_score` propagation. The RFP-only mate-beta gate is internal to the RFP block.

## 5. Test coverage strategy

Mirrors M5.A §5's sister-fixture pattern: every gate-skip test pairs with a sister positive fixture and asserts a node-count or score delta. A no-op RFP impl trivially "skips RFP" everywhere; gate-skip tests therefore must compare against a fixture where the gate's *opposite* condition fires and demonstrate observable behavior change.

RFP-behavior tests use `negamax_for_test` directly (not via `Search::go`) so the test author controls `is_pv`, `allow_null`, depth, and the `(alpha, beta)` window precisely. The `rfp_firings` `#[cfg(test)]` counter is the direct discriminator for the cutoff path; node-count delta is the discriminator for the gate-skip paths.

**M5.A retrospective lesson — test fragility under future search modifications.** M5.A retro §"Lessons" (line 50) flags that node-count discriminators at depth ≥ 4 inside chess fixtures depend on the search tree's branching, which M5.C's LMR will modify. Where possible this plan preferences direct counter assertions (`rfp_firings`/`nmp_firings`) and prologue-level fixtures (TT seeds, sister fixtures with clean discriminators) over move-loop-shape-dependent node-count deltas. Each §5.2 row's "Discriminator" column calls out the future-survivability of that test's pin.

### 5.2 RFP-behavior tests in negamax (~12 tests, `src/search.rs::tests`)

Sister-fixture pattern throughout. Discriminator column distinguishes `nodes`-delta (move-loop counts differ; **fragile under M5.C's LMR**), from `score`-delta (cutoff vs no-cutoff returns differ; **stable**), from `rfp_firings`/`nmp_firings`-counter assertion (**stable** under prologue invariants).

## 7. ADR-0024 — reverse futility pruning

`docs/decisions/0024-reverse-futility-pruning.md`. **Scope: terse decision + rationale**, ~60–80 lines following the ADR-0018 / ADR-0019 / ADR-0023 pattern. Re-derivation lives in research note + plan; ADR commits the decisions only.

Sections (each ≤ 5 lines):

- **Status**: Accepted, 2026-05-DD.
- **Context**: One paragraph naming the decision surface (RFP parameters + ordering vs NMP + lazy-dup design choice). References ADR-0023 (NMP) for the prologue ordering interaction and ADR-0018 (TT) for the no-store policy. **Notes that ADR-0023 is unchanged**: M5.A NMP semantics preserved verbatim.
- **Decision** (parameters fixed at landing):
  - **Margin formula**: linear, `RFP_MARGIN_PER_DEPTH = 100`. Margin function: `reverse_futility_margin(depth) = RFP_MARGIN_PER_DEPTH * depth`.
  - **Max depth**: `RFP_MAX_DEPTH = 6`.
  - **Gate set**: `ply > 0`, `!is_pv`, `!in_check(pos)`, `depth <= RFP_MAX_DEPTH`, `abs(beta) < MATE_IN_MAX_PLY`, `static_eval - reverse_futility_margin(depth) >= beta`. Order: cheap structural predicates first; `static_eval` read lazily inside the gate (own read, not shared with NMP).
  - **Return value on RFP cutoff**: `static_eval - reverse_futility_margin(depth)` (fail-soft proved lower bound).
  - **TT store policy on RFP cutoff**: NONE. Proof is depth-specific to the margin and not reusable as a search result (research §6).
  - **Order vs NMP**: RFP fires BEFORE NMP. Rationale: RFP is cheaper (no sub-search); on the d=3..6 overlap, an RFP cutoff skips NMP's null-search entirely.
  - **`static_eval` read**: each block reads independently (lazy-dup); no shared eager hoist. Plan-review pass-1 rejected the shared-hoist alternative because it bundled an NMP behavior change with M5.B's SPRT and enlarged the read population on K+P endgame nodes.
- **Deferred**: see research §13 (eval-aware margin; per-depth margin table; smoothed return; improving heuristic).
- **Open SPRT-tunable parameters**: (a) `RFP_MARGIN_PER_DEPTH` — compare 100 / 120 / 150; (b) `RFP_MAX_DEPTH` — compare 6 / 7 / 8.
- **References**: research note `docs/research/m5-reverse-futility.md` + plan `docs/plans/m5.b.md` + ADR-0023 (NMP, unchanged) + ADR-0018 (TT, no-store rationale).

## 9. SPRT methodology

Per ELOH.D's mixed-TC adoption rule + the M5.A precedent.

- **Baseline tag**: `M5.A` (commit `e63eb15`, M5.A landing).
- **SPRT bounds**: `elo0=0, elo1=5`. RFP is smaller than NMP per literature: standalone RFP gain is +20–50 Elo (research §11), and the marginal gain on top of NMP is a fraction of that. `elo1=5` is the appropriate floor.
- **TC sampling**: `--tc-sample 10+0.1:1,20+0.2:1,40+0.4:1,60+0.6:1` (mixed-TC, ~150 games per TC; total ~600 games at ~10h wallclock budget).
- **Acceptance**: mixed-game SPRT crosses upper Wald bound (H1) AND per-TC Δ ≥ 0 with 95% CI at every sampled TC.
- **Per-TC regression**: a width that fails the per-TC floor at fast TC but passes mixed-game H1 is adoptable with a "helps deep but not fast" flag (M4.C precedent).
- **Width-tune follow-up** (deferred): post-merge SPRT campaign comparing `RFP_MARGIN_PER_DEPTH = 100` vs `120` vs `150`; `RFP_MAX_DEPTH = 6` vs `7` vs `8`.

## 12. Risks and mitigations

- **Risk 1 (no-op bundled refactor risk — RESOLVED)**: the original plan-pass-0 design bundled an NMP-side mate-beta gate change with M5.B's SPRT, blurring attribution. Plan-review pass 1 surfaced this; resolved by **lazy-dup design**: RFP and NMP each keep their own gates and `static_eval` reads. ADR-0023 is unchanged; M5.A NMP semantics preserved verbatim. M5.B's SPRT signal vs `M5.A` is a clean RFP-only attribution.
- **Risk 2 (read-population enlargement on K+P endgame nodes — RESOLVED)**: the original shared-eager-hoist design read `static_eval` at K+P-only endgame nodes that M5.A's lazy-read screened behind `has_non_pawn_material`. Plan-review pass 1 surfaced this; resolved by lazy-dup. NMP block byte-identical to M5.A — `has_non_pawn_material` screen preserved. RFP block has no equivalent screen but adds a `depth <= RFP_MAX_DEPTH` screen first (cheap O(1) compare; cheaper than `has_non_pawn_material`'s 4-bitboard OR), and the additional read is paid only at non-PV non-check non-mate-beta shallow-depth nodes.
- **Risk 3 (tactical blindness from RFP at depth 6 missing a depth-7 tactic)**: RFP's static check at depth 6 uses a 600 cp margin. A depth-7 forcing sequence netting 700+ cp would refute the static lead.
  - **Mitigation**: depth bound (≤ 6) + non-PV gate. Conservative `100 * depth` margin (vs CPW workhorse 150) further reduces risk. SPRT is the gate; per-TC regression catches a global blindness regression.
- **Risk 4 (RFP-before-NMP ordering causes some M5.A NMP-fixture tests to fail)**: M5.A's NMP-behavior tests in §5.3 may have fixtures where RFP intercepts before NMP fires. Specifically, `negamax_returns_beta_cutoff_on_successful_nmp` and the `nmp_firings`-counter-asserting `negamax_passes_allow_null_false_in_null_subsearch` (M5.A K=34 pin) are at risk.
  - **Mitigation**: classify in §5.4. Tests where RFP genuinely better handles the position need fixture updates (construct fixtures that fail RFP's gate but pass NMP's). Tests where the assertion is "node-count delta vs sister fixture" may not need changes if both fixtures see RFP intercept symmetrically. The impl pass enumerates failures and updates each per the classification.
- **Risk 5 (return-value off-by-one or sign error)**: returning `static_eval - margin*depth` is the proved lower bound; returning `static_eval` overstates by `margin*depth`; returning `beta` understates.
  - **Mitigation**: §5.2 `negamax_returns_proved_lower_bound_on_successful_rfp` exact-equality assertion catches all three return-value mutations.
- **Risk 6 (counter-pin maintenance tax)**: `rfp_firings`/`nmp_firings` empirical pins shift at every M5.x landing. M5.A's K=34 pin is fragile per its retrospective; M5.B doubles the surface (both pins).
  - **Mitigation**: counter-pin policy in §5.2 (single-ply discriminators only; exact-K assertions on `negamax_for_test` calls where the test's negamax frame is the only RFP/NMP firing site). Tests fail loudly with a clear message ("RFP firings count must match pinned K=N; got M") on drift; re-pin is a one-line update at M5.C+ landing. Acknowledged maintenance tax; alternative (synthetic-fixture event-trace assertions) is a future tooling refactor, not an M5.B blocker.
- **Risk 7 (TT-store ordering interaction)**: NMP stores `Bound::Lower` on cutoff (ADR-0023 §7); RFP doesn't store. The two orderings produce different TT contents at the same Zobrist key — future sibling/transposition probes pick up an entry from NMP-cutoff but not from RFP-cutoff. Both bounds are valid lower bounds; the search tree shape diverges.
  - **Mitigation**: SPRT measures the net Elo of the cheaper-first ordering; literature consensus (research §7) recommends RFP-before-NMP. The M5.B SPRT is the gate.
