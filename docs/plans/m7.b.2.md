# M7.B.2 — depth-conditioned qsearch SEE-prune threshold (slow-TC fix)

**Status:** PLAN (2026-06-16). Designed while the M7.B.1 flat-sweep seed-2 confirm
runs; SPRT deferred until the confirm completes (no engine-spawning during a live
SPRT — M5.G lesson).

## 1. Problem

M7.B shipped a **flat** `QS_SEE_PRUNE_THRESHOLD = 0` (prune every non-promo
`see < 0` capture in qsearch when not in check). SPRT vs `M5.K`: aggregate
**+40.13**, but an **inverse depth profile** — strongly positive at fast/mid TC
(10+0.1 +109, 20+0.2 +73, 40+0.4 +109) and **≈−104 at 60+0.6** (the
strength-relevant slow TC). Mechanism (ADR-0040 caveat): at slow TC the engine
has the depth budget to *refute* a statically-losing capture that is actually a
real tactical sacrifice, so pruning it costs accuracy; at fast TC the node saving
buys depth and the prune wins.

M7.B.1 (flat negative-threshold sweep) seed-1: `−50` recovers 60+0.6 (−104 → +28)
but collapses 20+0.2 (+73 → −66) and gives back fast-TC gains; aggregate +26.11
[−0.29, +52.81]. A flat threshold can buy back the slow TC only by paying at the
faster TCs — it cannot separate them.

## 2. Insight — the conditioning variable is *search depth*, not nominal TC

The engine experiences TC only **through the ID depth it reaches** (fast TC ⇒
ID stops ~d9; slow TC ⇒ ~d15). So the prune's harm is a function of depth, not of
the clock. Condition the threshold on the **current ID-iteration (root) depth**:
prune aggressively (threshold 0) at shallow iterations, relax toward a negative
margin (prune only clearly-losing) at deep iterations.

qsearch runs at the leaves of **every** ID iteration. Therefore:
- **Fast TC** runs only shallow iterations (d ≤ ~9) → threshold stays 0 → full
  M7.B fast-TC node-saving benefit retained.
- **Slow TC** runs iterations 1…~15; the shallow ones prune hard (cheap), but the
  **deep iterations — which burn most of the clock and produce the played move —
  prune conservatively** → slow-TC accuracy restored exactly where it matters.
  (Caveat, per plan-review: a hard-pruned shallow iteration leaves mildly-biased
  TT entries and an aspiration `score(d-1)` baseline that the deep iteration
  *consumes* — it is not a clean overwrite. Second-order; the SPRT is the arbiter.)

## 3. Mechanism — a *smooth* ramp on root depth

```
qs_see_prune_threshold(root_depth) = clamp(-SLOPE * max(0, root_depth - D0), FLOOR, 0)
```
First-cut defaults (data-derived, see §4):
- `QS_SEE_RAMP_D0    = 12`  (flat 0 at/below d12)
- `QS_SEE_RAMP_SLOPE = 16`  (cp per ply beyond D0)
- `QS_SEE_RAMP_FLOOR = -64` (most-conservative deep threshold; reached at d16)

| root_depth | 1–12 | 13 | 14 | 15 | 16+ |
|---|---|---|---|---|---|
| threshold | 0 | −16 | −32 | −48 | −64 |

**Smooth ramp, NOT a hard band** — this is the explicit defense against the
M5.K aspiration depth-gate failure (`[8,12]` band scored −34.9 Elo, the
regression landing in the very 20+0.2 bucket it meant to protect, attributed to a
**band-edge discontinuity** at the mid-TC median depth ~11.5 ≈ band-max 12). The
ramp has no cliff: consecutive depths differ by `SLOPE` cp, so there is no
discontinuity for 20+0.2 to fall into.

## 4. Why these defaults (per-TC targeting)

Measured median ID depths: 20+0.2 ≈ 11.5 (backlog `scripts/depth-probe.sh`),
60+0.6 deeper (~15). The flat M7.B/M7.B.1 per-TC tells us what each depth band
"wants":
- 10+0.1 (~d9): thr-0 +109, thr-50 +69 → forgiving; 0 best. Ramp gives 0. ✓
- 20+0.2 (~d11.5): thr-0 **+73**, thr-50 **−66** → wants **aggressive** (≈0).
  Ramp at d≤12 = 0. ✓ (this is the bucket flat-−50 broke; the ramp avoids it.)
- 40+0.4 (~d13): thr-0 +109, thr-50 +87 → ~0/slightly-neg fine. Ramp d13 = −16. ✓
- 60+0.6 (~d15): thr-0 **−104**, thr-50 **+28** → wants **conservative** (≈−50).
  Ramp d15 = −48 ≈ thr-50. ✓

`D0=12` sits just above the 20+0.2 median (11.5), so 20+0.2 searches stay in the
flat-0 region (preserving +73), while 60+0.6's deeper iterations get the relaxed
margin. The 20+0.2/60+0.6 median gap (~3.5 plies) is what the ramp exploits.

**Predicted profile (the testable hypothesis):** the ramp reproduces M7.B's
fast/mid per-TC almost exactly (those TCs rarely exceed d12, where the ramp ≡
flat-0) and differs only at 60+0.6, which it lifts from −104 toward ≥0. If the
flat-−50 20+0.2 collapse was *real*, the ramp specifically avoids it by keeping
20+0.2 at ≈0. If it was noise, the ramp loses nothing there either.

**Behavioral surface is a sparse marginal band (plan-review).** Only captures
whose true SEE lands in `(FLOOR, 0)` ever change disposition vs M7.B (clearly-
winning captures hit the `victim ≥ attacker` fast-out and are never pruned;
clearly-losing ones sit below any FLOOR and are always pruned). With the coarse
`SEE_VALUE = [82, 337, 365, 477, 1025, 30000]` (P,N,B,R,Q,K), single-piece losing
trades are mostly far below −64 (e.g. minor×defended-pawn = −255); the smallest is
**B×N-defended = 337−365 = −28**. So at the single-capture level the band is thin.
But it is **empirically Elo-relevant**: the flat thr-0↔thr-50 delta (which is
*exactly* the `[−50,0)` band) produced huge per-TC swings, proving the band is
populated (multi-piece exchange sequences resolve to intermediate SEE values) and
strength-bearing. The ramp keeps that band pruned at shallow depth (like thr-0)
and unpruned at deep depth (like thr-50) — i.e. its effect lives precisely in the
band the flat sweep already showed matters.

## 5. Strong structural property — superset of M7.B at shallow depth

`qs_see_prune_threshold(d) == 0` for all `d ≤ D0`. Therefore the engine is
**byte-identical to M7.B (flat-0) at every iteration ≤ D0**, and the ramp can
*only* change behavior at d ≥ 13 — precisely where M7.B regressed. Consequences:
- **Standard bench (d4, d7) is byte-identical** to M7.B (`45788` / `662085`):
  bench never reaches d13, so the ramp is inert there. (⇒ bench is NOT a canary
  for this change; §7 adds a depth-driven unit test instead.)
- vs M7.B, the ramp differs only in deep iterations ⇒ low regression risk at the
  TCs M7.B already won.

## 6. Implementation (lean; named consts, no UCI options in v1)

`src/search.rs`:
1. Add field `root_depth: u32` to `AlphaBetaMover` (init `0` in the constructor
   alongside `nodes: 0`).
2. At the top of the ID loop (`for depth in 1..=max_depth`, ~L1416) set
   `self.root_depth = depth;`.
3. Add `const QS_SEE_RAMP_{D0,SLOPE,FLOOR}` and
   `fn qs_see_prune_threshold(root_depth: u32) -> i32` (the §3 clamp). Replace the
   scalar `QS_SEE_PRUNE_THRESHOLD` const. Add a **compile-time** guarantee at the
   const site that the function can only ever produce ≤0 (strongest form of the
   fast-out invariant, free): `const _: () = assert!(QS_SEE_RAMP_FLOOR <= 0 &&
   QS_SEE_RAMP_SLOPE >= 0);`.
4. Change `qsearch_see_pruneable(pos, mv)` → `qsearch_see_pruneable(pos, mv,
   threshold: i32)`. Replace the compile-time `assert!(THRESHOLD <= 0)` (no longer
   const) with a `debug_assert!(threshold <= 0)` guarding the `victim >= attacker`
   fast-out (belt-and-suspenders; the real guarantee is the §6.3 const-assert +
   the function clamp). Update the §3 fast-out doc-comment to reference the ramp
   clamp, not the deleted scalar const.
5. In `qsearch`, compute `let see_threshold = qs_see_prune_threshold(self.root_depth);`
   once before the move loop; pass to the helper at the call site (~L2779).
6. **Code-back the default-0 safety (plan-review MEDIUM):** `root_depth` is set at
   the ID loop top but never reset per-`go` (like `nodes`/`aborted` are). Production
   is safe (the loop always runs from `depth=1`, overwriting it before any qsearch
   leaf), and the reused `eval_white` `inner` mover never runs the loop (stays 0).
   But to make the "default 0" guarantee code-backed rather than invariant-backed,
   reset `self.root_depth = 0` inside `qsearch_for_test` alongside its existing
   per-entry counter resets. For the depth-driving tests (§7), add a sibling
   test-only helper `qsearch_at_root_depth_for_test(pos, alpha, beta, ply,
   root_depth)` that sets `self.root_depth` *then* calls `self.qsearch(...)` (so
   it isn't clobbered by the `qsearch_for_test` reset).

**Default root_depth = 0 ⇒ threshold 0** for any path that does not run the ID loop
(`qsearch_for_test`, the eval/bench `stm_score` helper at ~L3617) — i.e. exactly
M7.B behavior, so those paths and their tests are unaffected.

**UCI tunability deferred:** v1 ships hand-picked consts. If the ramp SPRTs
positive, a follow-up can expose `D0/SLOPE/FLOOR` as UCI spins (aspiration
precedent) for a sweep — but per the M5.K lesson SPSA is low-signal for this knob
class, so a small manual SPRT sweep would be the tool, and v1 doesn't need the
option surface to test the core hypothesis.

## 7. Tests (TDD — written + reviewed before implementation)

1. `qs_see_prune_threshold` value table: `d∈{1,11,12,13,14,15,16,32}` →
   `{0,0,0,−16,−32,−48,−64,−64}` (pins D0 onset, slope, floor; kills
   off-by-one / sign / clamp mutants).
2. `qs_see_prune_threshold` monotonic non-increasing in depth; always in
   `[FLOOR, 0]` (fast-out invariant `≤ 0` holds for all depths).
3. Pruning **backs off at deep root_depth** (the live-qsearch-path discriminator —
   pins that `qsearch` actually *reads* `self.root_depth`, which the §7.1 pure-
   function table cannot). Exact fixture (per plan-review, given `SEE_VALUE`
   granularity): a **B×N capture onto a defended knight**, `see = 337−365 = −28`
   (in the marginal band `(−64, 0)`; attacker bishop 365 > victim knight 337 so
   the fast-out does not short-circuit and the full `see()` runs). Assert via
   `qsearch_at_root_depth_for_test` + the `qsearch_see_prune_firings_for_test`
   counter: the −28 capture **is pruned at `root_depth = 12`** (threshold 0,
   −28<0) and **is NOT pruned at `root_depth = 16`** (threshold −64, −28≮−64).
   Robust to SLOPE retuning as long as `FLOOR < −28`. Pin the exact FEN + asserted
   SEE = −28 in the test (the test-suite reviewer needs both).
4. A clearly-losing capture (QxP onto a defended pawn, `see ≈ −943` per the
   existing M7.B fixture) is pruned at **all** depths (still `< FLOOR`) — the ramp
   relaxes marginal prunes, not gross ones.
5. **`go`-driven assignment coverage:** one integration test that runs `go` to a
   deep-enough fixed depth (≥ D0+1) and asserts the ramp engaged (e.g. a position
   with a marginal `see∈(FLOOR,0)` capture survives into the deep PV that flat-0
   would have pruned), OR — simpler — asserts the prune-firing rate drops vs a
   shallow `go`. This covers the `self.root_depth = depth` ID-loop assignment,
   which bench (inert, ≤ d7) does NOT exercise. Without it the assignment is only
   covered indirectly.
6. Existing M7.B prune tests (`qsearch_see_prune_*`, the `< vs <=` boundary
   mutant test at ~L21471, the QxP/Rd8 test at ~L21124) run with default
   `root_depth = 0` ⇒ threshold 0 ⇒ unchanged. Verify they still pass; update the
   `=0` comment wording where it references the old const.
7. Update `.cargo/mutants.toml` skip note for the boundary if the function shape
   changed the mutant surface.

## 10. Risks

- **M5.K precedent (primary):** depth-gating a TC-sensitive search mechanism
  backfired. Mitigation: smooth ramp (no band edge), `D0` above the 20+0.2 median
  so that bucket stays flat-0, and the superset-of-M7.B property bounds downside
  at the TCs M7.B won.
- **Median-depth overlap:** if 20+0.2 and 60+0.6 ID depths overlap more than the
  ~3.5-ply estimate, the ramp can't separate them and reduces to a flat
  intermediate threshold. The SPRT per-TC will show this (20+0.2 would dip).
  Fallback: raise `D0` / steepen `SLOPE`.
- **Tactical-shot pruning is not purely depth-monotone:** the "engine can refute
  given depth" story is a hypothesis; the SPRT is the arbiter.
