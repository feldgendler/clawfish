# M7.B — qsearch SEE-pruning

**Status:** Plan (drafted 2026-06-16). Workflow: research → plan → tests → implement → review → bench → SPRT.
**Baseline tag for SPRT:** current production HEAD (`M6.J` eval / `M5.K` search; bench d4 `112020` / d7 `1326598`).
**Milestone scope:** roadmap §M7.B — "Skip SEE < 0 captures in quiescence. Small; own SPRT." Wires the **first production consumer** of the SEE evaluator that landed inert in M7.A (`src/see.rs`; ADR-0039). This is the milestone where SEE's strength payoff is finally claimed, after the M7.A *ordering* split was explored and shelved as neutral (reordering captures by SEE added nothing; **pruning** is a different mechanism — it removes work rather than reorders it).

---

## 1. Goal & success criteria

Add a single pruning gate to the qsearch capture loop: when not in check, skip a non-promotion capture whose static exchange evaluation is losing (`see(pos, mv) < 0`). Gated by:

1. **Correctness / soundness (mechanical gate).** The change must:
   - Never prune when in check (evasions, incl. quiet evasions, are searched in full).
   - Never affect the terminal mate/stalemate/single-reply/under-promo logic (those run on the *unpruned* move list before the loop, or on promotions we exclude).
   - Preserve the fail-soft floor: stand-pat remains the node's lower bound, so pruning all captures returns the (sound) stand-pat Upper bound — exactly as a captureless quiet node already does.
   - Pass the full existing suite (with the audited, expected fixture churn — §5.4).
2. **No NPS regression / a measurable node reduction.** SEE-pruning *adds* a per-capture `see()` call but *removes* subtrees; the net must be neutral-or-faster wall-clock. The ADR-0030 §10 scar (bench's 16-position snapshot hid a per-node regression) applies — a **sustained-go NPS check on a capture-dense tactical position** is a hard gate (§6).
3. **SPRT (strength confirmation).** Mixed-TC + virtual-clock vs HEAD, standard ADR-0037 verdict ladder. This is the gate that decides ship/no-ship. Marginal-but-positive lands per the M5.F precedent; a clear regression reverts. Unlike the M7.A ordering split (node reduction that did *not* convert to Elo), pruning is expected to convert because it deepens the effective search by spending fewer nodes on losing tactical noise.

## 2. The pruning rule — spec (pin the gates before coding)

Inside qsearch's main move loop (search.rs step 8, currently `for mv in moves_vec`), before `make_move`, prune iff **all** of:

1. **Not in check** (`!in_chk`). When in check, `moves_vec` holds evasions (which include quiet king moves and blocks); pruning any of them is unsound (the position demands a response). The `in_chk` flag is already computed at step 3. This is the load-bearing guard — mirrors the ADR-0026 FFP `!in_check` gate.
2. **The move is a non-promotion capture** (`mv.is_capture() && !mv.is_promotion()`), i.e. flag ∈ {`Capture`, `EnPassant`}. Rationale:
   - **Non-captures** (the non-capture queen-promo `QueenPromo`, which `qsearch_move_filter` admits) are not captures — `see()` is undefined on them, and a queen-promo is a ~+940 cp material event we always want to search (ADR-0016 §ordering). Excluded.
   - **Promotion-captures** (`*PromoCapture`) are excluded to keep the M5.E #3 queen-promo-stalemate / under-promo-extension logic (search.rs step 10b) fully intact: that logic keys off a `QueenPromoCapture` move actually entering the loop body. A promo-capture is also a large material event (gains a queen) and is essentially never SEE-negative, so excluding it costs ~nothing while removing all risk of perturbing the M5.E extension. Excluded.
3. **`see(pos, mv) < QS_SEE_PRUNE_THRESHOLD`** with `const QS_SEE_PRUNE_THRESHOLD: i32 = 0` (prune strictly-losing captures). The threshold is the SPRT/SPSA tuning lever (§10): if the `< 0` cut SPRTs flat, a small positive margin (prune slightly-losing-or-worse) or a small negative margin (prune only clearly-losing) is the next probe. v1 ships `0`.

When the predicate holds: `continue` (skip the move entirely — no make/unmake, no `best`/`alpha` update, no counter beyond the per-move-skip diagnostic in §5.5). No TT special-casing: the TT move sits at index 0 but is pruned on the same predicate as any other move — see §4 for why that is safe and what test pins it.

**Helper guard discipline (decided, not deferred).** The three cheap gates (`!in_chk`, `is_capture`, `!is_promotion`) live at the **call site** (§3.2); the helper `qsearch_see_pruneable` does **not** re-assert them with `debug_assert!`. The call-site guards are directly pinned by the §5.2 in-check and queen-promo-capture tests (and the §5.3 mutants), so a defense-in-depth re-guard inside the helper would be an untestable duplicate (a mutant removing it cannot be discriminated). This deliberately diverges from the ADR-0026 §5 defense-in-depth-helper precedent because here the guard is a *correctness* gate with a unique behavioral test, not a hard-to-mutate structural predicate.

### Soundness argument (why pruning losing captures in qsearch is sound *enough*)

Qsearch's job is to resolve tactical noise to a quiet evaluation; its floor is stand-pat. A capture with `see < 0` is *statically* expected to lose material. Searching it can only raise `best` above stand-pat if the recursive line refutes the static SEE verdict (a real but rare tactical exception — e.g. the "losing" capture sets up a bigger threat). Pruning it accepts that small accuracy loss for a large node saving — the textbook qsearch SEE-prune. The accuracy loss is bounded: we never prune evasions (in check), never prune promotions, and never go below the stand-pat floor. Net effect is validated by SPRT, not asserted. This is exactly the ADR-0016 §162 deferral ("SEE-based capture filter … M5+") and the ADR-0026-class fail-soft-pruning discipline, now realized.

## 3. Implementation site & shape (`src/search.rs`)

Single new free function + one gate line in `qsearch`.

### 3.1 The predicate helper (with fast-out)

```rust
/// Centipawn SEE threshold for qsearch capture pruning. A non-promotion
/// capture with `see < QS_SEE_PRUNE_THRESHOLD` is skipped in quiescence
/// (statically losing). `0` prunes strictly-losing captures; this is the
/// SPRT/SPSA tuning lever (docs/plans/m7.b.md §10).
const QS_SEE_PRUNE_THRESHOLD: i32 = 0;

/// True iff `mv` (a non-promotion capture: `Capture` | `EnPassant`) should be
/// pruned from quiescence as statically losing. Caller guarantees `!in_check`
/// and `mv.is_capture() && !mv.is_promotion()`.
///
/// Fast-out: a capture whose victim is worth >= the attacker can never be
/// SEE-negative (worst case the attacker is traded off, netting >= 0), so the
/// full `see()` resolver is skipped for the common winning/equal captures
/// (PxN, RxQ, equal trades, all EP PxP). Only `attacker > victim` captures
/// (QxP-class) — exactly the prune candidates — pay for the resolver. The
/// fast-out is only valid while `QS_SEE_PRUNE_THRESHOLD <= 0` (victim>=attacker
/// ⇒ see>=0 ⇒ not < threshold); pinned by a compile-time assert.
fn qsearch_see_pruneable(pos: &Position, mv: Move) -> bool {
    use crate::mov::MoveFlag;
    use crate::piece::PieceKind;
    const _: () = assert!(QS_SEE_PRUNE_THRESHOLD <= 0); // fast-out validity
    let attacker = SEE_VALUE[pos
        .piece_at(mv.from_square())
        .expect("qsearch_see_pruneable: capture from-square occupied")
        .kind as usize];
    let victim = match mv.flag() {
        MoveFlag::EnPassant => SEE_VALUE[PieceKind::Pawn as usize],
        _ => SEE_VALUE[pos
            .piece_at(mv.to_square())
            .expect("qsearch_see_pruneable: capture to-square occupied")
            .kind as usize],
    };
    if victim >= attacker {
        return false; // SEE >= 0; never prune
    }
    see(pos, mv) < QS_SEE_PRUNE_THRESHOLD
}
```

`SEE_VALUE` and `see` are imported from `crate::see` (the M7.A evaluator). The fast-out mirrors the M7.A §4.3 `see_nonneg_fastout` semantics but lives here in `search.rs` (the M7.A ordering-hook version was reverted with the shelved split; this is a fresh, prune-scoped re-introduction).

**Dead-code transition (named §8 step, per ADR-0039 disposition).** `src/see.rs:28` carries a module-wide `#![allow(dead_code)]` because the evaluator landed inert. ADR-0039 committed to removing it "when M7.B wires the first production caller." Once `see` has a live consumer, `see` / `SEE_VALUE` / `attackers_to` are all reachable (the latter two via `see`/`slow_see`), and `slow_see` + curated-test helpers are already `#[cfg(test)]`. So the module-wide allow should be **removed** and *not* replaced (verify with `cargo clippy --all-targets -- -D warnings`; add a narrowly-scoped `#[allow(dead_code)]` only on a specific item if — and only if — clippy flags one). Leaving the blanket allow on a now-live module is the stale-allow anti-pattern the project's clippy discipline targets. This is step 0 of the implementation, gated by §8.

### 3.2 The gate in the loop

```rust
for mv in moves_vec {
    // M7.B: qsearch SEE-pruning — skip statically-losing captures when not in
    // check. Promotions and (when in check) evasions are exempt by predicate.
    if !in_chk && mv.is_capture() && !mv.is_promotion() && qsearch_see_pruneable(pos, mv) {
        continue;
    }
    let undo = pos.make_move(mv);
    // … unchanged …
}
```

Placement: the very top of the loop body, before `make_move` (cheapest skip; no state to unwind). It composes cleanly with the existing per-move logic — a pruned move advances no accumulator (`best`/`alpha`/`cutoff_move` untouched), so the post-loop bound classification (`qsearch_tt_bound_for_completed_node`) sees exactly the state it would see if the pruned moves had never been generated.

### 3.3 What is deliberately NOT changed

- **Move ordering** is untouched (still MVV-LVA + TT-first). We prune, we do not reorder — the M7.A lesson is that reordering is neutral.
- **Negamax** is untouched (M7.C territory: SEE capture-futility at frontier nodes).
- **The terminal block** (step 6: mate / stalemate / single-reply / false-stalemate) runs on `moves_vec` *before* the loop and is unaffected — we never prune a move into emptiness that would flip a terminal verdict, because pruning happens inside the loop, after the emptiness checks.
- **The M5.E #3 under-promo extension** (step 10b) — untouched (we exclude all promotions from pruning).

## 4. TT-move interaction (made explicit)

The TT move is promoted to `moves_vec[0]` (step 7). Under this design it is pruned on the **same predicate** as any other move — there is no TT exemption. This is safe:

- A TT move that is a winning/equal capture (`victim >= attacker`) hits the fast-out and is never pruned.
- A TT move that is a *losing* capture (`attacker > victim`, `see < 0`) at a depth-0 qsearch entry is low-confidence (qsearch TT entries are depth 0; ADR-0028) and statically losing — pruning it is consistent with pruning any other losing capture, and the stand-pat floor still bounds the node.
- **`qsearch_tt_move_promoted_to_index_0_when_capture` (search.rs:16802) WILL churn — this is not contingent.** Verified: its fixture `4k3/8/8/8/3b1q2/8/3Q4/4K3 w - - 0 1` stores **Qxd4** (`d2d4`, QxB) as the TT move; Bd4 is defended by Qf4 along rank 4, so `see(Qxd4) = 365 − 1025 = −660` — strictly losing. Under M7.B this TT move is pruned in the loop, so the test's load-bearing `assert_ne!(nodes_a, nodes_b)` (which is meant to prove *ordering* changes the search shape) would still differ but for the wrong reason (Qxd4 vanishes from run (b) entirely). **Required fix, both parts:** (a) re-point the fixture to a SEE-non-negative capture TT move (e.g. an equal/winning capture) so the ordering assertion measures ordering again; **and** (b) add a **sibling test** `qsearch_tt_move_pruned_when_see_losing_capture` pinning "a SEE-losing capture promoted to index 0 by TT is still pruned in the loop" — this is the *only* direct behavioral pin for the §3/§4 no-TT-exemption decision; without it that decision has no test backstop.

> **Design note — why no TT exemption.** Exempting the TT move is a defensible alternative (some engines trust the TT move). We choose *no* exemption for v1 because (a) it is simpler and matches the textbook minimal qsearch SEE-prune, (b) a depth-0 qsearch TT entry is weak evidence, and (c) it avoids a special case in the hot loop. If SPRT shows a regression traceable to over-pruning trusted moves, a TT exemption is the first remediation to try (§11).

## 5. Test surface (authored before implementation — TDD)

All tests live in `src/search.rs` `#[cfg(test)]`, using the existing qsearch test harness (`qsearch_for_test`, the `Search` builder, FEN fixtures).

### 5.1 Predicate unit tests — `qsearch_see_pruneable`

- **Fast-out: winning capture not pruned.** PxN (victim>attacker) → `false` without needing the resolver verdict. (Assert `false`.)
- **Fast-out: equal capture not pruned.** A defended equal trade RxR where `victim == attacker` → `false`.
- **Fast-out: EP PxP not pruned.** En-passant (victim Pawn, attacker Pawn) → `false`. Pins the EP victim-square special case (we must NOT read `piece_at(to)` for EP — `to` is empty).
- **Losing capture pruneable.** QxP defended by a pawn (attacker Queen ≫ victim Pawn, `see < 0`) → `true`.
- **Losing-looking but actually safe capture not pruned.** QxP where the pawn is *undefended* (`see = +82 ≥ 0`) → `false` (fast-out does not fire — attacker>victim — so the full `see()` runs and returns ≥ 0).

### 5.2 qsearch behavioral tests — pruning fires / does not fire

- **Pruning skips a losing capture (node-count / result).** A position where the only non-stand-pat candidate is a SEE-losing capture; assert qsearch returns the stand-pat value (the losing capture is not searched, so it cannot lower/raise `best` off stand-pat) and/or assert a node-count drop vs a SEE-disabled reference. (Use a deterministic node-count assertion if a disable-hook exists; otherwise assert the returned score equals stand-pat.)
- **A winning capture is still searched.** Position with a clearly winning capture (PxQ): qsearch returns a score reflecting the capture (above stand-pat), proving the gate did not prune it.
- **In check: losing captures NOT pruned.** A position in check whose only evasion is a SEE-losing capture (e.g. king or piece must capture the checker at a loss): assert the evasion is searched (qsearch does not return a spurious mate/stand-pat). This is the load-bearing soundness test for the `!in_chk` gate — a mutant that drops the `!in_chk` guard must fail here.
- **Queen-promo-capture NOT pruned.** A position with a `QueenPromoCapture` that is (contrived) SEE-non-positive: assert it is still searched (promotion exclusion holds). Guards the `!mv.is_promotion()` gate.
- **All captures pruned → clean stand-pat Upper.** Position where every capture is SEE-losing: qsearch returns stand-pat, stores an Upper bound (reuse the existing bound-classification assertion style). Confirms the empty-effective-loop path is sound.

### 5.3 Mutation-resistance targets (author tests so these mutants die)

- Drop `!in_chk` → §5.2 in-check test fails.
- Drop `!mv.is_promotion()` → §5.2 queen-promo-capture test fails.
- Flip `victim >= attacker` fast-out to `>` or `<` → §5.1 equal-capture test fails.
- Change `< QS_SEE_PRUNE_THRESHOLD` to `<=` → a `see == 0` capture must NOT be pruned at threshold 0. **The fixture must reach the `see()` path**: an exactly-even RxR has `victim == attacker` → it hits the fast-out (`victim >= attacker` returns `false`) and never reaches the threshold comparison, so it *cannot* kill this mutant. Use a fixture with `attacker > victim` (fast-out does not fire) whose full `see()` resolves to exactly `0` — e.g. a higher-value attacker initiating an exchange that nets exactly even via defenders/x-ray (the B≠N divergence in `SEE_VALUE` makes a precise-0 construction non-trivial but feasible; do not reach for the RxR case).
- Negate the whole predicate → §5.2 winning-capture-still-searched test fails.

### 5.4 Existing-fixture audit (bound the churn up front)

Move-loop pruning changes node counts and can change which qsearch fixtures search which moves. Enumerate and reconcile before implementing:
- **`qsearch_tt_move_promoted_to_index_0_when_capture`** — §4: re-point fixture + add the sibling prune test (non-contingent, per §4).
- **`qsearch_extends_capture_to_resolve_material`**, **`qsearch_beta_cutoff_in_capture_loop`**, **`qsearch_alpha_improvement_from_stand_pat_then_capture`** — confirm their driving captures are SEE-non-negative (winning/equal), else the prune changes the asserted score. Most tactical fixtures use winning captures (PxQ-class), which the fast-out exempts, so churn is expected to be small — but verify each.
- **`qsearch_in_check_*`** — must be unaffected (in-check exempt); spot-confirm.
- The **bench signature** (`bench: <N>`) and the **depth-4 determinism pin** will change (node counts drop). Update to the measured post-prune counts (§6); this is expected, not a regression (the M7.A §5.4 precedent).

### 5.5 Diagnostic counter (optional, mirrors M5.E `*_firings` convention)

Add a `#[cfg(test)]` `qsearch_see_prune_firings: u32` counter incremented at each prune, with a `*_for_test` accessor and per-`go` reset, mirroring `qsearch_single_reply_firings`. Lets the §5.2 "pruning fires" tests assert the gate actually ran (not just that the score happened to match). Reset in the same sites as the other qsearch counters: the `new()` field-init (~1330) plus **both** `*_for_test` reset blocks — `negamax_for_test` (~2354) and `qsearch_for_test` (~2925). Missing the 2925 per-entry reset breaks back-to-back test determinism.

## 6. Performance gate — the ADR-0030 §10 scar (hard, not optional)

SEE-pruning changes the per-node cost/benefit balance: `+` one `see()` per `attacker>victim` capture, `−` the subtrees of pruned losing captures. `bench`'s 16-position fresh-allocator snapshot is a weak probe for hot-loop cost (the ADR-0030 scar). Before committing:

1. **`see()` is allocation-free** (M7.A: stack `[i32; 32]`, no `Vec`) — re-confirmed by reading, noted in review. The fast-out keeps `see()` off the hot path for the common winning/equal captures.
2. **Sustained-go check:** 20× sequential `go depth 10` HEAD-with-prune vs HEAD-without, wall-clock + NPS ratio, **on a capture-dense tactical position** **in addition to** startpos. Pin the fixture to the **Kiwipete** position `r3k2r/p1ppqpb1/bn2pnp1/3PN3/1p2P3/2N2Q1p/PPPBBPPP/R3K2R w KQkq - 0 1` (heavy piece contact, many `attacker>victim` captures that bypass the fast-out and run the full resolver) so the `bench/m7.md` record is reproducible across sessions. Plus a single `go depth 14`. Target: **NPS parity-or-better** after accounting for the (legitimate, beneficial) node-count *drop*. We expect *fewer* nodes and *equal-or-higher* NPS → net faster; if NPS drops materially the fast-out / threshold needs tuning before proceeding.
3. **Defensive short SPRT** (50–100 pairs, mixed-TC) folded into the main SPRT launch — the first checkpoint must not be a sharp negative.

Record the new bench signature + the sustained-go numbers in `bench/m7.md`.

## 9. SPRT (strength confirmation, post-implementation)

Mixed-TC + virtual-clock vs HEAD per ADR-0037 verdict ladder, `--tc-sample` per the ELOH.D mandate. Long-running (overnight class) — launched after §8 passes and the implementation commits; ship decision follows the verdict ladder (marginal-but-positive lands per M5.F; clear regression reverts). Watch: pruning should help at **every** TC (fewer nodes per depth → deeper effective search), and possibly more at fast TC (where node budget is tightest) — the inverse of the M6 depth-amplifying terms.

## 10. Threshold tuning (the lever if v1 is flat)

If the `< 0` cut SPRTs flat (not a clear regression), the threshold `QS_SEE_PRUNE_THRESHOLD` is the knob:
- A **positive** margin (e.g. prune `see < +50`) prunes *more* (also skips marginally-even captures) — more aggressive, risks accuracy. Note: a positive threshold **breaks the fast-out validity assert** (§3.1) and requires reworking the fast-out (`victim >= attacker` no longer implies "not pruned"). Reopen §3.1 then.
- A **negative** margin (e.g. prune `see < −50`) prunes *less* (only clearly-losing) — safer, smaller gain. Fast-out stays valid.
- The SPSA harness (`docs/plans/spsa-harness.md`) can tune it, but per the M5.K lesson SPSA is low-signal for node-efficiency knobs; a 2–3 point manual SPRT sweep is likely the right tool. Backlog to `docs/tuning-backlog.md` if v1 ships marginal.

## 11. Risks & open items

- **Over-pruning trusted/tactical captures (primary strength risk).** SEE is static; a "losing" capture can be a real sacrifice. Mitigated by: pruning only in qsearch (the horizon, where sacrifices are negamax's job), never in check, never promotions, stand-pat floor preserved. If SPRT regresses, first remediation is a TT-move exemption (§4), then a negative threshold (§10).
- **Per-node cost (secondary).** Mitigated by the fast-out (keeps `see()` off the common-capture path) + allocation-free resolver + the §6 NPS gate.
- **Fixture churn** in qsearch tests / bench — expected; bounded by the §5.4 audit.
- **ADR:** allocate **ADR-0040** at landing for the qsearch SEE-prune mechanism (rule, threshold, gate set, TT no-exemption, fast-out). This follows the one-ADR-per-pruning-mechanism precedent (ADR-0024 RFP / ADR-0025 LMR / ADR-0026 FFP); M7.B is a new search *behavior*, not just a tuning of ADR-0039's evaluator. Cross-reference ADR-0039 (the consumed evaluator) from it.
