# M2.D — Random-mover `Search` impl + `Random_Seed` UCI option

## Context

M2.C landed `Engine<W, S>` + reader thread + per-`go` worker + `Search` trait + a deterministic `Stub`. M2.D replaces `Stub` with a SplitMix64-seeded random mover and adds the engine's first real UCI option, `Random_Seed`, so games are reproducible from a known seed.

Plug-in point per ADR-0011 §"`Search` trait": orchestrator unchanged; only the `Search::go` body changes. The `setoption` plumbing is the only orchestrator-touching addition (case-insensitive option-name matching, advertise the option in `uci` reply, reset PRNG on `ucinewgame`).

## Decisions baked into this plan

### 1. `Random_Seed` option declaration

```
option name Random_Seed type spin default 0 min 0 max 2147483647
```

- `max 2147483647` (= `i32::MAX`) is load-bearing per research §1.4: Stockfish 18 crashes on `stoi` overflow above this, and GUIs likely behave the same. A 64-bit seed cannot be expressed as `spin` safely.
- `min 0`: seeds are non-negative by convention; sign carries no extra meaning when the internal PRNG state is `u64`.
- `default 0`: the spec literal value `0` (a valid SplitMix64 seed). Not "system entropy" — that would defeat reproducibility's-purpose, and a non-deterministic default would leak through tests.
- Single underscore-joined token `Random_Seed` per research §5.3 — unambiguous against the spec's "value" / "name" delimiter trap.
- Internal storage is `u64` (the PRNG state width), but parsing accepts at most 31 bits. 2.1 billion seeds is ample for tournament-style reproducibility.

### 2. PRNG semantics — continuous state, `ucinewgame` resets

Per research §4.3–§4.4 and reviewer brief §10:

All seed/state lives in `RandomMover` fields `seed: u64` and `state: u64`.

| Event | Action |
|---|---|
| Engine startup | `run_stdio` builds `RandomMover::new(0)` → `seed = 0; state = 0` |
| `setoption name Random_Seed value N` (valid N) | `RandomMover::set_seed(N)` → `seed = N; state = N` immediately (§2.1) |
| `setoption name Random_Seed value N` (invalid N) | No state change; debug-mode `info string` |
| `ucinewgame` | `RandomMover::reset()` → `state = self.seed` |
| Each `go` call | Pick legal move via one SplitMix64 step; `state` advances |
| `stop` / cancellation | No PRNG effect (state already advanced from the pick) |

#### 2.1 Decision: `setoption` resets `state`, not just `seed`

The research note's §4.4 left this as an open question (defer-to-`ucinewgame` vs. reset-on-`setoption`). I'm choosing **reset on `setoption`** because:

- A user setting the seed mid-session almost always means "start a reproducible run *now*." Defer-on-`setoption` requires sending `ucinewgame` afterward to take effect — surprising and easy to forget.
- Symmetric with the test invariant "same seed + same sequence of `go` = same bestmoves" — easier to test, and the test reads more naturally (set the seed, then play).
- No reachable correctness regression: changing the seed mid-game already breaks reproducibility against any prior run; resetting state too just makes the new seed deterministic from this point forward.
- Defer-to-`ucinewgame` is also defensible; this is a tie-broken design call, surfaced in §10 for the reviewer.

### 3. SplitMix64 implementation — inline, no dep

Per research §3.1, vendor the public-domain reference verbatim into `src/search.rs`:

```rust
#[inline]
fn splitmix64_next(state: &mut u64) -> u64 {
    *state = state.wrapping_add(0x9E3779B97F4A7C15);
    let mut z = *state;
    z = (z ^ (z >> 30)).wrapping_mul(0xBF58476D1CE4E5B9);
    z = (z ^ (z >> 27)).wrapping_mul(0x94D049BB133111EB);
    z ^ (z >> 31)
}
```

- Constants vendored verbatim from prng.di.unimi.it (research §3.1). Public-domain; same provenance as our Polyglot Zobrist table.
- `wrapping_*` is required — overflow is intentional in this PRNG.
- `pub(crate) fn` — exercised directly by a unit test pinning the first ~8 outputs from seed 0 against a hand-computed reference (catches a constant typo in code review).

#### 3.1 Modulo bias — none worth handling

Per research §3.4: bias for any N ≤ 218 (`MoveList` cap is 256, but legal-move max is 218) is < 4×10⁻¹⁸. `rng_output % n_moves` is correct without rejection sampling. The proptest in §6.E pins the empirical uniformity within chi-square tolerance; we do not implement rejection sampling.

### 4. `Search` trait extension

The orchestrator needs to push two lifecycle events into the search impl:

- "Seed changed via `setoption`" — update `RandomMover.seed` + reset `RandomMover.state` to it.
- "`ucinewgame` arrived" — reset `RandomMover.state` to `RandomMover.seed`.

Three options were considered:

| Option | Pros | Cons |
|---|---|---|
| **A. Add methods to `Search` trait** | Type-safe; works for any `S: Search`; no downcast | Adds two trait methods; non-RandomMover impls must provide a default body |
| B. `Box<dyn Any>` downcast | Zero trait churn | Loses generics' static-dispatch benefit; ergonomically awful; defeats ADR-0011's choice of generics over trait objects |
| C. Generic `set_option(&str, &str)` on trait | Forward-compatible to many options | Stringly-typed; pushes parsing into impls; M2.D has exactly one option |

**Choice: A.** Add two trait methods with default-no-op bodies:

```rust
pub trait Search: Send {
    fn go(&mut self, position: &Position, ctx: &SearchContext, info_sink: &dyn Fn(&str)) -> SearchResult;

    /// Notify the search of a new `Random_Seed` value. Default: no-op
    /// (most search impls don't have configurable seeds). M3+ alpha-beta
    /// will not implement this; it stays a no-op.
    fn set_seed(&mut self, _seed: u64) {}

    /// Notify the search that a new game has started (`ucinewgame`). Default:
    /// no-op. RandomMover resets `state` to `seed` here. M3+ alpha-beta
    /// will eventually clear killer/history/TT here.
    fn reset(&mut self) {}
}
```

Default-empty bodies preserve M3+'s freedom to ignore both methods until they need them. The `InfoEmittingFake` test fixture inherits the no-op defaults — no test-fixture churn.

### 5. `RandomMover` struct

```rust
pub(crate) struct RandomMover {
    /// The seed configured via `Random_Seed` (or the default, 0). Reset
    /// target for `reset()`.
    seed: u64,
    /// PRNG state. Initially equal to `seed`; advances by one SplitMix64
    /// step per `go` call.
    state: u64,
}

impl RandomMover {
    pub(crate) fn new(seed: u64) -> Self {
        Self { seed, state: seed }
    }
}

impl Search for RandomMover {
    fn go(&mut self, position: &Position, ctx: &SearchContext, _info_sink: &dyn Fn(&str)) -> SearchResult {
        // Always compute the candidate before checking cancellation
        // (preserves the M2.C race-free invariant — see plan §8 of m2.c.md).
        let mut moves = {
            let mut ml = crate::movegen::MoveList::new();
            crate::movegen::generate_moves(position, &mut ml);
            ml.iter().collect::<Vec<_>>()
        };
        if let Some(ref filter) = ctx.limits.searchmoves {
            moves.retain(|mv| filter.contains(mv));
        }

        let candidate = if moves.is_empty() {
            None
        } else {
            let r = splitmix64_next(&mut self.state);
            // Modulo bias for N ≤ 218 is < 4×10⁻¹⁸ (research §3.4) — no
            // rejection sampling.
            let idx = (r as usize) % moves.len();
            Some(moves[idx])
        };

        let wait = ctx.limits.infinite || ctx.limits.movetime.is_some() || ctx.limits.ponder;
        if wait {
            while !ctx.should_abort(0) {
                std::thread::sleep(std::time::Duration::from_millis(1));
            }
        }

        SearchResult { bestmove: candidate, ..Default::default() }
    }

    fn set_seed(&mut self, seed: u64) {
        self.seed = seed;
        self.state = seed;
    }

    fn reset(&mut self) {
        self.state = self.seed;
    }
}
```

Key invariants pinned by tests:
- `bestmove == None` iff `moves.is_empty()` after filtering — covers mate / stalemate / empty `searchmoves`.
- The PRNG step happens *only* when `moves.is_empty()` is false. Empty filters do not consume PRNG state.
- The candidate is always computed before any cancellation check (race-free under quit-immediately-after-go, M2.C precedent).
- The wait loop uses the same 1 ms sleep cadence as `Stub`, satisfying ADR-0011's "≤ 1 ms" cancellation cadence promise.

### 6. Engine changes

#### 6.1 `Engine` field — none added

**Decision (revised pass-2): do not add a `seed_value` field to `Engine`.** The seed lives solely in `RandomMover.seed` (or whatever the search impl chooses to store internally). Justification:

- `Engine` would only ever write `seed_value` (in `handle_setoption`) and read it indirectly through `RandomMover::set_seed` and `RandomMover::reset`. Both of those operations already use `RandomMover.seed` internally — the engine field would be a dead store.
- Eliminating the field eliminates the drift risk the previous draft of this plan enumerated.
- Future need (e.g. echoing the current seed in an `info` line, or implementing `setoption name Random_Seed` *without* a value to query) would require a `Search::seed() -> u64` accessor, not a duplicated field on `Engine`.

`Engine`'s field set therefore stays exactly as M2.C left it. Only `handle_uci`, `handle_setoption`, `handle_ucinewgame`, and `run_stdio` change.

The contract on `Engine::new(stdout, search)` is unchanged: callers pass an `S` already initialized to whatever seed they want. `run_stdio` builds `RandomMover::new(0)` (matching the protocol-declared `default 0`); tests that need a non-zero seed either build `RandomMover::new(N)` and skip `setoption` (direct-construction path), or build `RandomMover::new(0)` and send `setoption name Random_Seed value N` (protocol path). The end-to-end E36 test uses the protocol path; unit tests in `search.rs::tests` use the direct-construction path.

#### 6.2 `handle_uci` — advertise the option

Order is `id name`, `id author`, `option …`, `uciok`:

```rust
fn handle_uci(&mut self) {
    self.write_line(&format!("id name clawfish {}", env!("CARGO_PKG_VERSION")));
    self.write_line("id author Alex Feldgendler");
    self.write_line("option name Random_Seed type spin default 0 min 0 max 2147483647");
    self.write_line("uciok");
}
```

The `default` literal in the protocol-level option line is `0`, hard-coded — the spec-defined `default` is the engine's factory default, not the current seed value.

#### 6.3 `handle_setoption` — case-insensitive matching

The `MAX_RANDOM_SEED` constant matches the declared `max` from §1: `2147483647` (i32::MAX).

```rust
// Type is u32; value is 2^31 - 1 (the protocol-declared `max`). Not i32 —
// the comparison band [0, MAX_RANDOM_SEED] is unsigned by construction.
const MAX_RANDOM_SEED: u32 = 2_147_483_647;

fn handle_setoption(&mut self, name: String, value: Option<String>) {
    if name.eq_ignore_ascii_case("random_seed") {
        // Strict: parse as u32, then reject if above declared max.
        // Honors the protocol contract that values fall in [min, max].
        let parsed: Option<u32> = value
            .as_deref()
            .and_then(|s| s.parse::<u32>().ok())
            .filter(|&n| n <= MAX_RANDOM_SEED);
        match parsed {
            Some(n) => {
                self.search.lock().unwrap().set_seed(n as u64);
                // Silent on success — even under `debug on`. Same convention
                // as `handle_debug`: state-mutating commands without a
                // protocol response do not echo themselves.
            }
            None => {
                // Bad parse, out-of-range, or missing value — silent if
                // debug off; info string if debug on. The engine's
                // existing seed value is unchanged.
                let msg = match value.as_deref() {
                    Some(v) => format!("Random_Seed: rejected value '{v}'"),
                    None => "Random_Seed: rejected (no value given)".to_string(),
                };
                self.info_string_debug(&msg);
            }
        }
        return;
    }

    // Unknown option — preserve M2.C behavior: silent if debug off, info
    // string if debug on. Do NOT emit Stockfish's bare "No such option:"
    // line (research §1.4, §2.5). Idiom mirrors existing M2.C handler:
    // the `if self.debug` guard wraps the whole format-and-write because
    // `details` allocation is conditional too.
    if self.debug {
        let details = match value {
            Some(ref v) => format!("name {name} value {v}"),
            None => format!("name {name}"),
        };
        self.info_string_always(&format!("setoption received: {details}"));
    }
}
```

Decisions baked in (resolves §10 O3 strict):
- **Parse as `u32`, then validate `n <= MAX_RANDOM_SEED`.** Two-step: `parse::<u32>()` excludes negatives and non-numerics; the `<= MAX_RANDOM_SEED` filter excludes the band `[2147483648, 4294967295]` that `u32` would otherwise accept. Honors the protocol contract that the GUI declared `max 2147483647`; rejecting above-`max` values matches the spec's `[min, max]` semantics regardless of what Stockfish does internally.
- **`2147483647` accepted; `2147483648` rejected.** Boundary test pins both values explicitly (B.2.b accepted, B.2.c rejected).
- **Negative numbers** (e.g. `-1`) fail `parse::<u32>()` cleanly → rejected.
- **Non-numeric** (e.g. `abc`) fails `parse::<u32>()` cleanly → rejected.
- **Missing value** (`setoption name Random_Seed`) → rejected; `info_string_debug` notes the absence (debug-on only).
- **Empty value** (`setoption name Random_Seed value `) → `parse::<u32>("")` fails → rejected. Same path as non-numeric.
- **Case-insensitive matching** via `eq_ignore_ascii_case` — the spec's case-insensitivity (research §2.1) is ASCII-scoped; option names are conventionally ASCII, and `eq_ignore_ascii_case` is allocation-free.
- **Success is silent under `debug on`** (different from M2.C's behavior for *unknown* setoptions, which DO echo under `debug on`). Justification: the `Random_Seed` line is a state mutation with no protocol return value; echoing on success would create noise during reproducible test runs. Same convention as `handle_debug`. The unknown-option echo behavior is preserved for diagnosability of GUI/engine name mismatches.

#### 6.4 `handle_ucinewgame` — reset PRNG too

```rust
fn handle_ucinewgame(&mut self) {
    self.position = Position::starting_position();
    self.search.lock().unwrap().reset();
}
```

The lock is uncontended in normal flow — `ucinewgame` arrives between games, with no in-flight `go`. (If a future GUI sends `ucinewgame` mid-search, the orchestrator's `handle_ucinewgame` would block on the search-mutex lock until the worker finishes its current `go`. Acceptable: spec says `ucinewgame` arrives before `position`, not during `go`.)

#### 6.5 `run_stdio` — switch to `RandomMover`

```rust
pub fn run_stdio() -> ! {
    let (tx, rx) = mpsc::channel::<Command>();
    std::thread::spawn(move || reader_loop(BufReader::new(io::stdin()), tx));
    let mut engine = Engine::new(io::stdout(), RandomMover::new(0));
    engine.run(rx);
    process::exit(0);
}
```

### C. End-to-end self-play integration test in `tests/uci_integration.rs`

| # | Test | Detail |
|---|---|---|
| E36 | `integration_self_play_game_with_seed_0_terminates_legally` | Spawn the binary; set `Random_Seed value 0`; loop: `position startpos moves <accumulated>` + `go movetime 10`; on each `bestmove`, parse with `Move::from_uci` against a parallel `Position` and `make_move` it; track ply count. Loop terminates when `generate_moves` returns empty (mate or stalemate). Assertions: (a) every bestmove was legal in its position (already enforced by `Move::from_uci` round-trip); (b) total ply ≤ MAX_PLY (deadlock detector — random play should terminate well within 100–200 ply on average); (c) the terminal position is mate or stalemate (not a 50-move-rule or threefold artifact, since we don't implement those yet); (d) **with seed 0 specifically, the final ply count and last bestmove are pinned to specific values** (full reproducibility — values determined empirically during Phase 4 implementation and embedded as constants). Wallclock budget: ≤ MAX_PLY × 10 ms + overhead. **Empirical pre-check: in Phase 4, before embedding the constants, run the seed-0 self-play game once to (i) confirm it terminates within MAX_PLY without cycling, (ii) capture the actual final ply count and last bestmove. If seed 0 cycles or runs >300 ply, surface to the user before picking a different seed (a non-terminating random game is a strong signal of a movegen bug worth investigating).** Failure modes: if MAX_PLY is reached, the test panics with a message including the last 10 moves played, the current FEN, and `cycled-or-runaway: did not terminate within MAX_PLY plies`. The 10 s wallclock timeout with `child.kill()` fallback panics with `engine did not respond within timeout: <last bestmove>; <accumulated>`. **MAX_PLY = 300** (≈ tournament limit, safely larger than the ≈60–120 ply random self-play would normally run before mate/stalemate). |

### D. Random-uniformity proptest (`src/search.rs::tests`)

| # | Test | Detail |
|---|---|---|
| D12 | `prop_random_mover_chi_square_within_tolerance_for_uniform_pick` | Given a position with K legal moves (use a chosen mid-game position with K=20), draw M=2000 samples from `RandomMover` with seed s (proptest strategy: `s in 0u32..=10`). Compute chi-square against expected uniform 1/K. Assert χ² < critical value at α=0.001 with K-1 degrees of freedom (very loose tolerance to avoid flakiness; tightening would risk per-seed false-fails). Bound: 10 seeds × 2000 picks × ~20 candidates ≈ 400k movegen calls — well under 1 s on M4. |

### E. Test-reviewer dimensions to flag

- **B.2.e flakiness** must be pre-empted at fixture-build time (find a known-different seed pair, embed as constant). The seed search itself is deterministic and reproducible.
- **D12 chi-square tolerance** is intentionally loose to absorb statistical noise; tightening to α=0.05 would yield ~1-in-20 false-fail per seed across the proptest's seed range.
- **E36 (self-play game)** must pin specific final ply count and last bestmove for seed 0 — without this anchor, "the game terminated" is too weak (it would pass even on a regression that always picked the same move and stalemated immediately).
- **B.3 audit** is load-bearing — every existing test that pinned `bestmove a2a3` must be reviewed; a swap to RandomMover with default seed 0 will *not* pick `a2a3` first.

| Risk | Mitigation |
|---|---|
| Bestmove-pinning tests fail after Stub→RandomMover swap | §B.3 audit: rewrite to "any legal move" or use a pre-determined seed that produces the previously-pinned move. The audit is enumerated, not discovered at runtime. |

## Open questions

- **O1. Resolved → reject + debug-mode echo.** `setoption name Random_Seed` (no `value` clause) is treated as a bad value: silent if debug off, `info string Random_Seed: rejected (no value given)` if debug on. Pinned by B.2.c (silent path) and B.2.d (debug-on echo).
- **O2. Resolved → reset immediately on `setoption`.** §2.1 chose reset-on-`setoption` over defer-to-`ucinewgame`. Pinned by B.2.g.
- **O3. Resolved → strict.** §6.3 rejects `n > MAX_RANDOM_SEED` (= 2147483647). The implementation parses as `u32` then validates against the declared max. Pinned by B.2.b (boundary acceptance at `2147483647`) and B.2.c (boundary rejection at `2147483648`).
- **O4. Resolved → `pub(crate)`.** Only the engine constructs `RandomMover`; in-crate tests access via `crate::search::RandomMover`. The end-to-end self-play test drives via UCI bytes only. Easy to re-export later if M2.E or M3 needs it.
- **O5. Open (informational only — not blocking).** Whether GUIs parse `2147483647` differently from `2147483648` is empirically untested for non-Stockfish GUIs. Research §1.4 confirms Stockfish 18 crashes on `> i32::MAX`; we adopt that as the de facto standard. M2.E (fastchess integration) will surface any GUI-side disagreement, at which point the declared `max` can be lowered if needed.
