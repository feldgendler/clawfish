# M4.D — Aspiration windows

Fourth and final M4 phase. Wraps M3.E's iterative-deepening outer loop with **two-tier asymmetric aspiration windows**: at depth ≥ threshold, the next-iteration window is centered on the prior iteration's score with half-width ±50 cp; on fail-high or fail-low, exactly one re-search runs with the proved bound preserved on the unfailed side and `±INF` on the failed side. No third tier (deferred to M5 per roadmap §M5). No PVS / negascout (M5+). No adaptive width (M5+).

The roadmap §M4.D row, refined during the 2026-04-30 walkthrough, names every load-bearing parameter; this plan transcribes them, names the helper signatures and tests that pin them, and identifies the SPRT campaign structure.

Per the user's standing instructions for this branch: **mutation testing is prepared but not run**. The unit's diff range is appended to the joint M4.B+M4.C entry in `docs/mutants-backlog.md` for the overnight campaign. SPRT runs at landing per the roadmap's mixed-TC adoption rule; **width-tune SPRTs are documented and queued but not blocking M4.D's commit**.

Research synthesis: `docs/research/m4-aspiration-windows.md` (lands jointly with this plan; see §13 if reviewer convergence requires research-side refinement).

## 0. Goals

- `aspiration_window(prior_score, depth) -> (i32, i32)` pure function in `src/search.rs`: returns `(-INF, INF)` for `depth < ASPIRATION_MIN_DEPTH` or for `prior_score == None`; else `(prior - HALF_WIDTH, prior + HALF_WIDTH)`. **No mate-score skip** — research §7.2 + §10's "Tested-and-rejected variants" recommend not special-casing mate detection in the aspiration loop; the asymmetric widening handles mate scores correctly via the second-tier full-window path.
- `ASPIRATION_MIN_DEPTH: u32 = 4` (CPW workhorse default — depth 1–3 scores are too volatile to seed a tight window; research §4 + §13.2).
- `ASPIRATION_HALF_WIDTH: i32 = 50` (CPW workhorse default; roadmap pinned; research §3 + §13.4).
- `widen_after_fail(returned, prev_alpha, prev_beta) -> (i32, i32)` pure function: asymmetric fallback per the roadmap and research §3. `returned >= prev_beta` → `(returned, INF)`; `returned <= prev_alpha` → `(-INF, returned)`. The proved fail-soft bound is preserved on the unfailed side; only the failing side widens to `±INF`. This matches the literature's unanimous recommendation (CPW, Beowulf, TalkChess t=46624 et al.; research §3 + §12.2).
- `Search::go`'s ID outer loop body restructures around an inner "aspiration loop" that runs up to **two** negamax calls per iteration (first try + at most one re-search). Two-tier means exactly two calls in the worst case; window-contained returns fall through after one.
- M4.B's per-iteration `clear_killers` continues to fire **once at the top of each ID iteration**, BEFORE the first aspiration try. **NOT** between aspiration tries within the same iteration — the failed try's killer slots are valuable ordering hints for the re-search, and clearing would discard them. (M4.B's plan flagged this revisit point at "M4.D may revisit for aspiration re-search persistence" — this plan resolves it: preserve. Research §12.7 confirms.)
- M3.E's per-iteration reset of `aborted` / `root_score` / `pv.lengths[..]` is split: `aborted` and `root_score` reset **per aspiration try** (so the re-search starts clean); `pv.lengths[..]` reset **per aspiration try** (each negamax frame's `clear_ply(0)` already does this for ply 0 via the existing prologue, but the iteration-level mass-clear is preserved for safety on plies > 0 in case a prior search left state there).
- **Empty-PV-after-re-search recovery via TT fallback (NOT a snapshot field).** The fail-soft re-search at `(L, +∞)` can — in the rare edge case where the position's true value equals `L` exactly — return with `pv.lengths[0] == 0`. The first try's TT store (bound=Lower, best_move=cutter) survives the re-search's overwrite via ADR-0018 §7's best-move-on-overwrite preservation rule, so the root's TT entry retains the failed-try bestmove. A new helper `extract_bestmove_or_tt_fallback(pv, tt, root_key) -> Option<Move>` returns `pv[0][0]` when populated, else probes the TT for the root entry's `best_move`. Helper is direct-unit-testable (M3.D `negate_window` + M3.E `aborted_fallback_result` precedent); no new field on `AlphaBetaMover` is added. See §3.3 + §3.7.
- **No stop-flag check between aspiration tries** beyond what the existing post-call `self.aborted` check already catches — research §12.4 says "no additional code needed." A `stop` flipped between try-1's negamax-return and try-2's first 4096-cadence poll is observed within sub-millisecond of the re-search start; that latency is consistent with the existing `should_abort` cancellation contract. Adding an explicit between-tries probe creates a contract surface that doesn't exist anywhere else in the codebase.
- Bench signature **expected to change** (different windows produce different cutoff patterns → different leaf set). Determinism within a run preserved (E47 re-pins).
- SPRT against `baseline/alpha-beta-tt-killer-history` per the roadmap's **mixed-TC adoption rule** (§9): four fixed-TC fastchess matches at `tc=10+0.1`, `tc=20+0.2`, `tc=40+0.4`, `tc=60+0.6`, ~150 games each; aggregate union → SPRT, per-TC outcome → "doesn't regress anywhere" floor. Wallclock ~10 hours unattended. **Width-tune campaigns** (±25, ±75, possibly ±100) at the same methodology run **after** M4.D lands; the M4.D commit ships ±50 cp as the documented default. Width-tune outcomes recorded in `bench/m4.md`'s M4.D section as a follow-up, not blocking the commit.
- Mutation testing **prepared** (diff command appended to the joint M4.B+M4.C entry in `docs/mutants-backlog.md` so the overnight campaign covers M4.B → M4.C → M4.D as one batch); **not run** in this loop.

## 1. Out of scope

- **PVS / NegaScout.** M5. Aspiration introduces an explicit PV vs non-PV window distinction (`beta - alpha == 1` is non-PV under PVS). M4.D's first-try window has `beta - alpha = 100` cp, NOT `1` — so the synthetic `is_pv: bool` parameter from M4.A continues to govern PV/non-PV classification. PVS at M5 swaps `is_pv` to the window-based predicate.
- **Adaptive width as a function of depth or PV-stability.** M5+. M4.D ships fixed ±50 cp at the comparator default. Width as `f(depth)` (tighter at deeper iterations) and width as `f(prior_PV_change)` (wider after PV instability) are recorded in `docs/tooling-backlog.md` as future tuning surface. M4.D's mixed-TC SPRT curve is the reference baseline future adaptive variants will be measured against.
- **Third intermediate widening tier.** M5. The roadmap's 2026-04-30 sensitivity analysis showed the EV margin is too narrow to justify in M4.D. Defer.
- **Aspiration-aware TT semantics.** M4.A's TT store discipline is unchanged. A failed-aspiration try's negamax call returns at end-of-loop on a fail bound (Lower or Upper) and stores normally per ADR-0018 §13. The re-search's TT probe at the root sees the failed try's entry as an ordering hint (TT-move-first) and as a cutoff candidate (Lower bound at the same depth → may cut the re-search if the new alpha allows; in practice the re-search's wider beta means Lower-bound cutoffs at the root are exactly the proved-bound cuts that motivated aspiration). No new TT discipline is introduced.
- **Per-iteration window-state tracking** (logging, telemetry, info-string fail-high/low markers). Future debugging tooling; not in M4.D scope.
- **Mate-score special-casing.** Per research §7.2 + §10, the asymmetric widening already handles mate scores correctly: a centered window around `prior = MATE - K` would fail-high in iter N if a faster mate is found, and `widen_after_fail` re-searches at `(L, +∞)` which finds the deeper mate or stays at L. The cost is one fail-high + one re-search ≈ two searches at the same depth — exactly what aspiration is designed for. The first-try cost is bounded and the asymmetric path is correct. **No mate-score skip in `aspiration_window`.**

## 3. Type definitions and signatures

### 3.1 Constants and `aspiration_window`

```rust
// src/search.rs (near the existing MAX_PLY / MATE / INF / MATE_IN_MAX_PLY block).

/// Minimum depth at which aspiration narrows the window. Below this, the
/// outer loop passes `(-INF, INF)` to negamax — same as M3.E behavior.
/// CPW workhorse default; depths 1–3 have prior-iteration scores that are
/// too volatile to seed a tight window (research §4).
const ASPIRATION_MIN_DEPTH: u32 = 4;

/// First-try aspiration half-width in centipawns. Window is
/// `(prior - HALF_WIDTH, prior + HALF_WIDTH)`. CPW workhorse default;
/// roadmap §M4.D pins ±50 with a documented post-merge width-tune campaign
/// over ±25 / ±75 / ±100.
const ASPIRATION_HALF_WIDTH: i32 = 50;
```

```rust
/// First-try aspiration window. Returns `(-INF, INF)` (equivalent to no
/// aspiration) when:
///
/// 1. `depth < ASPIRATION_MIN_DEPTH` — too-shallow iteration; prior
///    score is unstable.
/// 2. `prior_score == None` — no prior iteration to seed from (the first
///    ID iteration of the **current `go`**; `last_complete` resets at the
///    top of each `Search::go` invocation per ADR-0017 §2 and search.rs:
///    333. A prior `go`'s final score is NOT carried across — each `go`
///    is independent. This is intentional: cross-`go` carryover would
///    couple aspiration to GUI-side time control and `position` resets,
///    invalidating the deterministic-bench contract from M3.F).
///
/// Otherwise returns `(prior - HALF_WIDTH, prior + HALF_WIDTH)`. Mate-score
/// `prior_score` values produce a window with `prior ± HALF_WIDTH` that
/// straddles the mate boundary; this is fine — `widen_after_fail` handles
/// the resulting first-try fail correctly via the asymmetric full-window
/// re-search (research §7.2: "do not special-case mate detection in the
/// aspiration loop").
///
/// Pure function. Unit-testable in isolation; pinned by AS1–AS5.
fn aspiration_window(prior_score: Option<i32>, depth: u32) -> (i32, i32) {
    if depth < ASPIRATION_MIN_DEPTH {
        return (-INF, INF);
    }
    let Some(prior) = prior_score else {
        return (-INF, INF);
    };
    (prior - ASPIRATION_HALF_WIDTH, prior + ASPIRATION_HALF_WIDTH)
}
```

### 3.2 `widen_after_fail`

```rust
/// Two-tier asymmetric widening on aspiration failure. Computes the
/// re-search window from the failed-try's returned score and the failed
/// try's `(prev_alpha, prev_beta)` window.
///
/// **Fail-high path** (`returned >= prev_beta`): re-search `(returned,
/// +INF)` — keep the proved lower bound `L = returned` as the new alpha;
/// widen the upper side to full. Per research §3 and §12.2, this is the
/// unanimous literature recommendation (CPW, Beowulf, TalkChess t=46624,
/// Crafty's `[g − 1/4, g + 1]` form). Symmetric widening (re-opening the
/// already-disproved range below `L`) is universally noted as suboptimal.
///
/// **Fail-low path** (`returned <= prev_alpha`): re-search `(-INF,
/// returned)` for the symmetric reason — keep the proved upper bound,
/// widen the lower side to full.
///
/// **Edge case: empty PV after re-search.** The fail-soft alpha-beta at
/// the root updates PV at `score > alpha` strictly. With `alpha = L`
/// (the proved bound) and a re-search where every root move scores
/// exactly `L`, no move improves alpha, and the re-search's PV[0] stays
/// empty. The recovery is **TT-driven, not snapshot-driven**: the failed
/// try's TT store (bound=Lower, best_move=cutter) survives the re-search's
/// overwrite via ADR-0018 §7's best-move-on-overwrite preservation rule
/// (when the new entry has `best_move == 0` and the slot's existing entry
/// has the same key with non-zero `best_move`, the old `best_move` is
/// preserved). The bestmove-extraction site falls back to `tt.probe(root)
/// .best_move` via the §3.7 helper. No new state on `AlphaBetaMover`.
///
/// **Caller contract**: `widen_after_fail` is only called when
/// `(returned >= prev_beta) || (returned <= prev_alpha)`. The
/// window-contained case (`prev_alpha < returned < prev_beta`) is
/// short-circuited by the caller before this helper runs. Pinned by AS9b
/// (panic in debug if invariant violated).
///
/// Pure function. Unit-testable in isolation; pinned by AS6–AS9b.
fn widen_after_fail(returned: i32, prev_alpha: i32, prev_beta: i32) -> (i32, i32) {
    debug_assert!(
        returned >= prev_beta || returned <= prev_alpha,
        "widen_after_fail called with window-contained score: \
         returned={returned} prev_alpha={prev_alpha} prev_beta={prev_beta}"
    );
    if returned >= prev_beta {
        (returned, INF)
    } else {
        // returned <= prev_alpha by the debug_assert
        (-INF, returned)
    }
}
```

### 3.3 `Search::go` ID outer loop body restructure

The existing M3.E body (search.rs:328–393, between `let max_depth = …` and the `debug_assert_eq!(pos_clone, *position, …)`) is replaced. The new shape, with M4.D-introduced sites highlighted:

```rust
let max_depth = max_depth_from_limits(&ctx.limits);
let mut pos_clone = *position;
let mut last_complete: Option<(u32, Option<Move>, i32)> = None;

for depth in 1..=max_depth {
    // Per-iteration reset (UNCHANGED from M3.E + M4.B):
    //   `nodes` not reset — accumulates across iterations
    //   killer table cleared per the M4.B inter-iteration policy
    clear_killers(&mut self.killers);

    // M4.D: aspiration loop body — at most TWO calls to negamax per
    // iteration (first try + at most one re-search). The re-search
    // is gated by an explicit `tries < 2` cap (the "two-tier" rule).
    let prior_score = last_complete.map(|(_, _, s)| s);
    let (mut alpha, mut beta) = aspiration_window(prior_score, depth);

    // The score eventually accepted as this iteration's result. Set inside
    // the loop; mid-iteration abort breaks before assignment.
    let mut returned: i32;

    let mut tries: u32 = 0;
    loop {
        // Per-aspiration-try reset (NOT killers — preserve cross-try ordering):
        //   `aborted` cleared so a prior try's abort doesn't bleed
        //   `root_score` cleared so the lockstep is correct for this try
        //   `pv.lengths[..]` cleared so a prior try's stale state on plies > 0
        //                    doesn't make the parent's pv.update copy stale
        self.aborted = false;
        self.root_score = None;
        for i in 0..MAX_PLY {
            self.pv.lengths[i] = 0;
        }

        returned = self.negamax(&mut pos_clone, depth, 0, alpha, beta, true, ctx);

        if self.aborted {
            // Mid-try abort: discard partial PV/score; the outer ID loop's
            // existing post-iteration handling preserves last_complete.
            break;
        }

        tries += 1;

        // Window-contained: no re-search needed. Common case (>~70%
        // first-try success per literature when ordering is good).
        if returned > alpha && returned < beta {
            break;
        }

        // Two-tier cap: after one re-search, accept the score regardless.
        // (This is what makes the design "two-tier": full search after at
        //  most one widening step.)
        if tries >= 2 {
            break;
        }

        // Re-search: asymmetric widening based on which side failed.
        let (na, nb) = widen_after_fail(returned, alpha, beta);
        alpha = na;
        beta = nb;

        // §3.8 test-instrumentation: emit one info string per re-search
        // exposing the new (alpha, beta) window. AS19/AS20/AS22 parse this.
        info_sink(&format!(
            "info string aspiration_re_search depth={depth} alpha={alpha} beta={beta}"
        ));
    }

    if self.aborted {
        // Mid-iteration abort: discard partial PV/score; preserve prior
        // last_complete snapshot.
        break;
    }

    // Iteration completed (window-contained OR re-search accepted).
    // M4.D: TT-fallback on empty PV (§3.7 helper) handles the rare
    // edge case where a re-search at `(L, +INF)` finds true_value
    // exactly L and fails to update PV in fail-soft.
    let bestmove = extract_bestmove_or_tt_fallback(
        &self.pv,
        self.tt.as_deref(),
        pos_clone.zobrist(),
    );
    last_complete = Some((depth, bestmove, returned));

    // Existing M3.E info emit + soft-cap check (UNCHANGED).
    let now = Instant::now();
    let elapsed_ms = (now - ctx.start).as_millis();
    let pv_str = if self.pv.lengths[0] == 0 {
        "0000".to_string()
    } else {
        self.pv.moves[0][..self.pv.lengths[0]]
            .iter()
            .map(|m| m.to_uci())
            .collect::<Vec<_>>()
            .join(" ")
    };
    info_sink(&format!(
        "info depth {depth} score {} nodes {} time {elapsed_ms} pv {pv_str}",
        score_to_uci(returned),
        self.nodes,
    ));

    if depth >= max_depth {
        break;
    }
    if ctx.stop.load(Ordering::Relaxed) {
        break;
    }
    if let Some(soft) = ctx.soft_deadline
        && now >= soft
    {
        break;
    }
}
```

**The `for` → `for { let prior_score = …; … }` restructure is additive**: the per-iteration reset, info emit, soft-cap break, and depth-cap break all stay. The only structural change is replacing the single `negamax(…, -INF, INF, …)` call with the aspiration loop. M3.E's post-iteration semantics (`last_complete` snapshot; mid-iteration-abort discards partial state) are unchanged.

**Per-try PV-clear discipline.** The per-try `for i in 0..MAX_PLY { pv.lengths[i] = 0; }` is intentionally per-try, not per-iteration. The first negamax call's frame-prologue `clear_ply(0)` would zero `lengths[0]` for the second try too, but it would NOT clear plies > 0 from the first try. Without the per-try mass-clear, a deep PV from the failed try might leak into the re-search's parent-side `pv.update` calls (which copy child state from `lengths[ply+1]`), corrupting the displayed PV. Pinned by AS12.

**Two-tier cap location.** `if tries >= 2 { break; }` lands AFTER the `returned > alpha && returned < beta` window-contained check, so a window-contained re-search returns through the success path. It lands BEFORE the stop-check + widen — so once two tries have run, we never widen for a third. Pinned by AS10 (3rd-tier-suppression) + AS11 (window-contained re-search returns clean).

### 3.4 No `SearchContext` / `SearchLimits` changes

`Search::go`'s signature is unchanged. `SearchContext` carries no aspiration state — the prior score is local to `Search::go` (via `last_complete`). The `Search::reset` body (which clears killers + history + game-history Zobrist Vec) is unchanged.

### 3.5 No new UCI option

Width and threshold are private constants in `src/search.rs`, not user-tunable. The width-tune campaign (post-M4.D) iterates by editing the constant and rebuilding the baseline binary; if the campaign reveals a strongly-preferred width different from ±50, the constant changes and a new SPRT-validated commit replaces the M4.D default. **No `AspirationWidth` UCI option** — exposing search-tuning knobs to GUIs invites mistuning; the CCRL/Fishtest convention is private constants tuned via SPRT.

### 3.6 No interaction with `prior_root_move`

`prior_root_move` was removed in M4.A (TT subsumes). Aspiration windows do not re-introduce it. The TT entry for the root position from the prior iteration carries the bestmove, ordering it first via the M4.A TT-move-first bubble.

### 3.7 `extract_bestmove_or_tt_fallback` helper

```rust
/// Return the root bestmove for the iteration's `last_complete` snapshot.
/// Prefers `pv[0][0]` when populated; falls back to the root TT entry's
/// `best_move` field when PV[0] is empty (M4.D rare empty-PV-after-
/// aspiration-re-search edge case — see §3.2 + §3.3).
///
/// **Why the fallback works (fail-high path only).** The empty-PV-after-
/// re-search edge case is only reachable on the fail-high path: the
/// fail-low re-search at `(-INF, L')` always populates PV[0] because any
/// finite root-move score satisfies `score > -INF`, improving alpha and
/// firing `pv.update`. So PV[0] is empty post-re-search ONLY when try-1
/// fail-high'd AND the re-search at `(L, +INF)` returned with
/// `true_value == L` exactly (no move improves alpha=L). On fail-high,
/// try-1 stored `(bound=Lower, best_move=cutter)` in TT (search.rs:680
/// `cutoff_move.map(|m| m.bits()).unwrap_or(0)` returns the cutter's
/// non-zero bits). The re-search stores `(bound=Upper, best_move=0)`. ADR-
/// 0018 §7's preservation rule fires (new `best_move == 0`, old key
/// matches, old `best_move != 0`), preserving the cutter. The fallback
/// retrieves the preserved cutter at the bestmove-extraction site.
///
/// **Fail-low + empty-PV is theoretically unreachable.** If a future
/// refactor breaks fail-low's PV-population invariant (e.g., changes the
/// `score > alpha` strictness or the `-INF` sentinel), the helper still
/// behaves correctly: a fail-low TT entry has `bound=Upper, best_move=0`
/// (no cutter to preserve), so the helper's `entry.best_move == 0` guard
/// returns `None` — UCI then emits `bestmove 0000`, which is the spec-
/// compliant "no legal move / null" signal. No correctness gap.
///
/// **Helper extraction precedent.** Same pattern as M3.D's `negate_window`,
/// M3.E's `aborted_fallback_result`, M3.F's `compute_bench_nps`. Direct
/// unit-testability for mutation-test surface; the inline expression
/// `(pv.lengths[0] > 0).then(|| pv.moves[0][0])` was the M3.E line whose
/// mutations (`> → >=`, `> → <`, `then → then_some`) were structurally
/// undetectable at the integration-test level.
///
/// Pinned by AS24a–AS24d (synthetic `PvTable` + synthetic TT).
fn extract_bestmove_or_tt_fallback(
    pv: &PvTable,
    tt: Option<&TranspositionTable>,
    root_key: u64,
) -> Option<Move> {
    if pv.lengths[0] > 0 {
        return Some(pv.moves[0][0]);
    }
    let entry = tt?.probe(root_key)?;
    if entry.best_move == 0 {
        return None;
    }
    Some(Move::from_bits(entry.best_move))
}
```

The `.as_deref()` at the call site (§3.3) converts `Option<&Arc<TranspositionTable>>` → `Option<&TranspositionTable>`. `Move::from_bits` is **added to `src/mov.rs` by this plan** (§2 row 2) — `pub(crate) const fn from_bits(bits: u16) -> Move { Move(bits) }`. The `Move(u16)` tuple constructor is private to `mov.rs`; the new `from_bits` is the canonical raw-bits decode entry point, mirroring `MoveFlag::from_bits` at the type one level up. Sentinel `best_move == 0` (`Move::default()` bits) → guarded explicitly in the helper body to return `None` rather than decode to a useless `a1-a1-Quiet` move.

### 3.8 Test-instrumentation hook: `info string aspiration_re_search` line

`AS19`, `AS20`, `AS22` need to verify the re-search's `(alpha, beta)` window. Rather than thread a test-only counter or capture-channel through `Search::go`, the simpler mechanism is to **emit a single `info string` line on each re-search** via the existing `info_sink` callback:

```rust
// At the top of the inner aspiration loop's "re-search" branch (i.e.,
// AFTER widen_after_fail produces (alpha, beta) and BEFORE the per-try
// reset of the next loop iteration):
info_sink(&format!(
    "info string aspiration_re_search depth={depth} alpha={alpha} beta={beta}"
));
```

Tests parse the captured `info_sink` lines via the existing `RefCell<Vec<String>>` pattern (used by `alphabeta_emits_info_line_with_score_and_pv` at search.rs:2257). The line is informational only — UCI GUIs ignore unrecognized `info string` content; the production cost is one `format!` per fail (rare). This is the same pattern fastchess + Cute Chess use to expose engine-internal state (`info string nps`, `info string hashfull`).

If a future user requests a "no debug strings" mode (e.g., for tournament play), the `info string` can be gated behind a UCI option (`option name DebugAspiration type check default false`); not in M4.D scope.

`AS19` parses the `info_sink` lines for the `aspiration_re_search` token after a fail-high fixture; asserts the next `alpha` field equals the prior `info depth N score X` line's score (i.e., `widen_after_fail`'s output's alpha equals the prior return). `AS20` does the symmetric check for fail-low. `AS22` parses iter-(N+1)'s first try (NOT a re-search line) — by absence of an `aspiration_re_search` line for iter-(N+1), or by inference from the `info depth N` score being the mate score (centered window worked first try).

## 4. Order of operations inside `Search::go`

```text
Per-go reset (UNCHANGED from M3.E):
  history clone, nodes=0, aborted=false, root_score=None, tt install,
  pv.lengths[..] = 0, clear_killers.

ID outer loop, for depth in 1..=max_depth:
  Per-iteration reset (UNCHANGED from M4.B):
    clear_killers (M4.B inter-iteration policy)

  M4.D NEW: aspiration loop, for tries in 0..2:
    Per-try reset:
      aborted=false, root_score=None, pv.lengths[..] = 0
    Compute or carry-over (alpha, beta) from prior step
    negamax(..., depth, 0, alpha, beta, true, ctx) → returned
    if aborted: break to ID loop's mid-iteration-abort handler
    if returned in (alpha, beta) exclusive: break — window-contained
    if tries == 1: break — two-tier cap reached (re-search done)
    (alpha, beta) = widen_after_fail(returned, alpha, beta)

  Post-iteration: last_complete snapshot via extract_bestmove_or_tt_fallback,
                  info emit, depth/stop/soft-cap checks (UNCHANGED from M3.E
                  except for the bestmove-extraction helper at the snapshot
                  line)
```

**Lockstep with M3.E `last_complete`.** `last_complete` is set at the END of each iteration, after the aspiration loop accepts a score. Mid-iteration aborts (in either try) preserve the prior iteration's snapshot — same as M3.E.

**Mid-aspiration aborts vs. mid-iteration aborts.** From the outer ID loop's perspective they are the same: the inner aspiration loop sets `self.aborted = true` and breaks; the outer loop's `if self.aborted { break; }` catches it. No explicit between-tries stop check — the post-call `self.aborted` check fires in both tries; a `stop` flipped between tries is observed at the re-search's first 4096-cadence poll (sub-millisecond), consistent with the existing `should_abort` cancellation contract.

**Anti-stub defenses (cross-cutting):**

- AS6 + AS7 use **specific arithmetic values** (`(200, INF)`, `(-INF, -200)`) that depend on the proved-bound-preserved form. A stub that drops the proved bound and uses `(prev_alpha, INF)` instead would produce `(50, INF)` ≠ `(200, INF)` and fail.

- AS22 inverts the v1 anti-stub direction: catches a future maintainer who *re-introduces* a mate-score skip in `aspiration_window` (the v1 design that was dropped in v2 per research §7.2). With a mate-score prior, the assertion is that the window IS centered on the mate score (NOT widened to full); a re-introduced skip would produce `(-INF, INF)` and fail the assertion.

### 5.7 Confirmation-bias defense

- **AS3–AS5 use specific arithmetic values** (`(73, 173)` for `prior=123, depth=5, half=50`) that depend on the exact `±HALF_WIDTH` formula. A stub that does `prior + 0` (drops half-width) or `0 ± HALF_WIDTH` (drops prior) produces different numbers.

A future maintainer who "improves" the per-try reset by also clearing killers (consistent with the per-iteration clear) would silently degrade re-search ordering quality. AS23 catches that.

## 7. Dependencies on other units

- **Hard:** M3.E `last_complete: Option<(u32, Option<Move>, i32)>` plumbing in `Search::go`. The score field of this snapshot is the ASPIRATION_WINDOW input. M3.E ships the snapshot already; M4.D consumes it without further plumbing changes.
- **Hard:** M3.E mid-iteration-abort discipline. M4.D's mid-aspiration-abort treats abort identically to mid-iteration abort (outer ID loop breaks; `last_complete` is the reported result).
- **Hard:** M4.A TT store-on-completion + skip-on-abort discipline. A failed-aspiration try's negamax stores at end-of-loop on its fail bound; the re-search's TT probe extracts the stored move for ordering-first. No change to TT discipline.
- **Hard:** M4.B inter-iteration `clear_killers` policy (clear at start of each ID iteration). M4.D's per-try reset preserves M4.B's per-iteration clear (still fires once at the top of the iteration) AND adds NO new `clear_killers` call between aspiration tries.
- **Hard:** M4.C `quiets_searched` per-frame state + history bonus/malus. The per-frame `MoveList` lives inside `negamax`'s stack frame and is reset on each negamax call — so each aspiration try gets a fresh accumulator. No special handling needed; any history updates from a failed try persist (the `history_table` on `AlphaBetaMover` is across-iteration / across-go state).
- **Soft:** M5 PVS / NegaScout. M5 will replace the synthetic `is_pv: bool` with the window-based `beta - alpha == 1` predicate. M4.D's first-try window has `beta - alpha = 100`, far from the PVS zero-window — `is_pv` continues to govern. When M5 lands, both helpers (`aspiration_window` and `widen_after_fail`) compose with PVS without changes.
- **Soft:** M5 third-tier exploration. The two-tier cap (`tries >= 2 { break; }`) sits at the aspiration-loop's exit point; M5 gains a third tier by relaxing the cap and adding an intermediate widening step in `widen_after_fail`. The body restructure of M4.D anticipates this (the loop is already a `loop {}` with explicit breaks, not a hardcoded 2-iteration `for`).
- **Soft:** M6 eval improvements. Tighter eval → smaller iteration-to-iteration score variance → higher first-try success rate → more aspiration EV. The width-tune is independent of eval changes; the SPRT methodology naturally re-validates.

## 10. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Aspiration loses Elo when first-move ordering is unstable (fluctuating scores → repeated re-searches) | M4.A–C delivered ordering quality (TT-move-first, killers, history). The M4.C SPRT at tc=60+0.6 shows ordering is stable enough at deep iterations. M4.D's mixed-TC SPRT ensures we don't ship a width that regresses at any TC. |
| Re-search window deviates from literature | Plan v1's earlier `(L-1, +INF)` form was reverted to `(L, +INF)` per research §3 + §12.2; AS6+AS7+AS8+AS9 anchor the explicit numbers. Empty-PV edge case handled via §3.7 TT-fallback helper. |
| Future maintainer adds back a mate-score skip in `aspiration_window` | AS5b explicitly asserts NO skip on mate-magnitude priors. AS22 verifies the integration-level mate-iteration behavior under aspiration. |
| Killer-table cross-try persistence introduces non-determinism in `bench` | The killer state is deterministic given the same search trajectory. A failed try's killers are populated by the same negamax body that will run the re-search. E47 pins bench determinism end-to-end. |
| Per-try PV mass-clear costs measurable NPS at high iteration counts | The `for i in 0..MAX_PLY { pv.lengths[i] = 0 }` is `MAX_PLY = 64` writes per try; ~128 ns at modern memory speeds. Per-iter overhead is below the 1ms per-iteration sleep granularity in `Search::go`'s wait loop; bench may show <0.1% NPS shift. |
| First aspiration call's window narrower → child-side cutoffs dominate → unfair fixture in tests | AS19+AS20 directly assert the re-search window numerically. AS21's "re-search succeeds with stable PV" is the integration check that fail-high recovery actually finds the right move. |
| The `tries >= 2` cap fires before window-contained check on a re-search whose returned score WAS in-window | The `if returned > alpha && returned < beta { break; }` runs FIRST (line above the `tries >= 2` cap). A re-search whose new wider window contains the score returns through the success path. AS11 directly pins this. |
| Mid-iteration `negamax` returning 0 for an aborted call interpreted as a window-contained score | The post-call `if self.aborted { break; }` runs FIRST (line above the window-contained check). An aborted call with `returned = 0` (the abort sentinel) cannot reach the window-contained check. AS16 + AS17 pin this. |
| Bench signature changes confuse "is this an M4.D regression?" | Expected. Recorded explicitly in `bench/m4.md` with the M4.C → M4.D node-count delta. The signature is deterministic across runs (E47 pins it). |
| Width-tune campaigns introduce a width different from ±50 that requires re-running M4.D's SPRT | The width-tune is a follow-up commit, not a re-run of M4.D. If a winning width emerges, the constant change + SPRT-validate lands as a separate "M4.D follow-up: aspiration width tune" commit. The M4.D commit itself is not retired. |

## 13. Research-note synchronization

The research note `docs/research/m4-aspiration-windows.md` landed in parallel with this plan, and the plan-review pass-1 feedback prompted a v2 alignment with both the research and ADR-0018 §7. Convergence outcome:

- **First-try half-width** (research §3 + §13.4 / plan §0) — converged on ±50 cp.
- **Threshold depth** (research §4 + §13.2 / plan §0) — converged on `ASPIRATION_MIN_DEPTH = 4`.
- **Re-search window form** (research §3 + §12.2 / plan §3.2) — converged on `(L, +∞)` and `(−∞, L′)`. Plan v1's earlier `(L − 1, +∞)` deviation was reverted post-research/post-review to match the literature consensus exactly. The empty-PV edge case is handled via the §3.7 TT-fallback helper, NOT via a 1-cp wider window.
- **Killer persistence across re-searches** (research §12.7 + §13.1 / plan §3.3 + §0) — converged: preserve killers across aspiration tries within the same depth; clear only between depth steps.
- **PV clear discipline** (research §12.1 + §13.3 / plan §3.3 + AS12) — converged: per-try `for i in 0..MAX_PLY { pv.lengths[i] = 0; }` is explicit in §3.3; AS12 pins it.
- **Mate score handling** (research §7.2 + §10 / plan §0, §3.1) — converged on **no special-casing** in `aspiration_window`. Plan v1 had a `prior.abs() > MATE_IN_MAX_PLY → full window` skip; v2 drops it per research §7.2's "do not special-case mate detection" recommendation. AS5b + AS22 explicitly assert no skip.
- **TT entries from failed try** (research §6 + §12.3 / plan §1) — converged: keep them; bound type is correct. ADR-0018 §7's best-move-on-overwrite rule is the load-bearing mechanism that makes the §3.7 TT-fallback work.
- **Stop-flag check between tries** (research §12.4) — converged: **no explicit between-tries probe**. Plan v1 had a defensive check; v2 drops it per research and reviewer feedback. The existing post-call `self.aborted` check + the re-search's own 4096-cadence poll cover the cancellation contract.
- **Empty-PV after re-search** (plan §3.2 + §3.3 + §3.7 + AS24a–d) — converged on **TT fallback via `extract_bestmove_or_tt_fallback` helper**, NOT a `failed_root_move` snapshot field. The TT entry from the failed first try preserves the cutoff move via ADR-0018 §7's preservation rule. The helper follows the M3.D / M3.E / M3.F precedent for direct-unit-testable extracted helpers.

The research is the authoritative reference for plan-reviewer cross-check. Open questions §13.1–§13.7 in the research note are all resolved by this plan.
