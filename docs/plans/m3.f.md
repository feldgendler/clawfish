# M3.F — `bench` UCI command + SPRT validation

Closes M3. Adds (a) a deterministic `bench` UCI command for node-count regression baselines; (b) a `scripts/sprt.sh` wrapper using historical-commit baselines per `docs/workflow.md` SPRT methodology; (c) the first SPRT match validating the M3 exit criterion ("beats RandomMover ~100%"); (d) a first rating estimate vs Stockfish `UCI_Elo=1320`.

Research synthesis: `docs/research/m3.f-bench-and-sprt.md`. No new ADR — `scripts/sprt.sh` is concrete, not architectural.

## 0. Goals

- `Command::Bench { depth: Option<u32> }` added to the UCI parser; `bench` (default depth) and `bench <N>` accepted.
- `Engine::handle_bench` iterates a vendored fixed-position corpus, drives `Search::go` at fixed depth on each, sums node counts, emits per-position `info string bench position <i>/<N>: <fen> nodes <N> time <ms>` info lines + an `info string Nodes searched: <N>` summary + an `info string bench: <N> nodes <NPS> nps` signature line. All output through `info string` per ADR-0011 discipline.
- Position corpus: 16 vendored FENs covering opening / middlegame / endgame phases, in `src/bench.rs::BENCH_POSITIONS`.
- Default depth: **7** — empirically calibrated sub-10 s wall on Apple M4 at M3.E's nps. Probe (M3.E end binary, 2026-04-29): startpos D7 = 9.23 M nodes / 640 ms; Kiwipete D7 = 9.13 M nodes / 795 ms; Canonical-6 #5 D7 = 2.79 M nodes / 151 ms; Canonical-6 #3 (endgame) D7 = 0.18 M nodes / 19 ms. Linear extrapolation across 16 positions (4 opening, 8 middlegame, 4 endgame) ≈ 9 s. Sub-30 s budget holds even with 3× CI slowdown. Doubling to depth 8 would push a Kiwipete-class position to ~5–8 s alone (× 8 mid positions ≈ 40–60 s), too slow for routine use; depth 7 is the sweet spot. Tens of millions of total nodes give low-ppm change-resolution.
- `scripts/sprt.sh` wrapper: builds baseline binary in a `git worktree`, runs fastchess SPRT, captures result.
- SPRT match vs `baseline/random-mover`: bounds `elo0=0, elo1=10, alpha=0.05, beta=0.05`; tc `10+0.1`; concurrency 6; up to 400 games; `-report penta=true`.
- First rating estimate match vs Stockfish 18 `UCI_Elo=1320`: 200 games, tc `10+0.1`, logistic-Elo formula.
- `bench/m3.md` final M3.F summary section + `bench/sprt/2026-04-29-vs-random.md` SPRT log.
- Annotated tag `baseline/alpha-beta-no-tt` at the M3.F commit.

## 1. Out of scope

- `bench` CLI subcommand (`./clawfish bench`) — defer; pipe `bench\nquit\n` over stdin instead. Adding a CLI dispatcher complicates `main.rs` for marginal gain at M3.F.
- Variable-`hash` / variable-`threads` `bench` arguments — n/a until M4 (TT) and M8 (parallelism).
- Pre-commit hook validating commit-message bench signature — defer to M4. We adopt the convention manually in M3.F's commit body; the hook is the next slot.
- Custom opening books for SPRT — vs RandomMover, no book is the right call (research §2). Books matter for SPRT between similar-strength engines (M4+).
- BayesElo / Ordo for rigorous Elo estimation — defer; logistic formula is sufficient for the first estimate.
- OpenBench integration — defer; the `Bench: <N>` commit-message convention we adopt is forward-compatible.
- M4 baseline tag — `baseline/alpha-beta-tt` lands at M4.A end, not here.

### 3.3 `BENCH_DEFAULT_DEPTH`

```rust
/// Default depth for `bench` when no argument given. Empirically calibrated
/// to ~9 s wall on Apple M4 (M3.E binary, 2026-04-29) at the engine's
/// ~7–11 Mnps; sub-30 s on 3× slower CI runners. Raise as TT (M4) and
/// parallelism (M8) cut per-depth wallclock; revisit at each milestone where
/// nps changes materially.
pub(crate) const BENCH_DEFAULT_DEPTH: u32 = 7;
```

Range guard in parser: depth must be 1..=63 (`MAX_PLY - 1` clamping). Parser-level `parse::<u32>()` failure → `Command::Unknown`, mirrors `parse_setoption` discipline. Out-of-range integers (0, ≥64) also → `Command::Unknown` so the engine reports the same protocol behavior as for any malformed body.

## 4. `parse_bench` body

```rust
"bench" => parse_bench(rest),
// ...

fn parse_bench(rest: &[&str]) -> Command {
    if rest.is_empty() {
        return Command::Bench { depth: None };
    }
    if rest.len() != 1 {
        return Command::Unknown;
    }
    match rest[0].parse::<u32>() {
        Ok(d) if (1..=63).contains(&d) => Command::Bench { depth: Some(d) },
        _ => Command::Unknown,
    }
}
```

**Subtleties:**

- `bench` (no arg) → `Bench { depth: None }`. The handler picks `BENCH_DEFAULT_DEPTH`.
- `bench 7` → `Bench { depth: Some(7) }`.
- `bench 0` / `bench 64` / `bench foo` / `bench 7 extra` → `Command::Unknown`. Strict-on-extra-tokens matches `debug` (which is `parse_debug`'s strict-exact-2-tokens contract) more than `position` (which is lenient on trailing junk). `bench` is closer in shape to `debug`: a single optional argument with a tightly-typed value.

## 5. `handle_bench` body

```rust
fn handle_bench(&mut self, depth_override: Option<u32>) {
    use crate::bench::{BENCH_DEFAULT_DEPTH, BENCH_POSITIONS};

    // Defensive: signal + join any in-flight worker. `bench` is a
    // synchronous-orchestrator-thread command and should not race with a
    // pre-existing `go infinite`; mirrors `handle_ucinewgame`'s discipline.
    self.join_in_flight_worker();

    let depth = depth_override.unwrap_or(BENCH_DEFAULT_DEPTH);

    let start = Instant::now();
    let mut total_nodes: u64 = 0;

    for (idx, fen) in BENCH_POSITIONS.iter().enumerate() {
        // FEN parse failure is unreachable for the vendored corpus
        // (anchor-tested by `bench_positions_all_parse_via_from_fen`), but a
        // defensive return keeps `bench` total over arbitrary corpora — useful
        // when M4+ extends the corpus and a typo slips through code review.
        let pos = match Position::from_fen(fen) {
            Ok(p) => p,
            Err(e) => {
                self.info_string_always(&format!(
                    "bench: skipping position {} (FEN parse error: {e})",
                    idx + 1,
                ));
                continue;
            }
        };

        // No per-position `reset()` call needed. `AlphaBetaMover::reset()` only
        // clears `self.history` (see `src/search.rs::reset`); cross-position
        // `prior_root_move` contamination is in fact prevented by `Search::go`'s
        // own top-of-go reset (line 321 of `src/search.rs`: `self.prior_root_move
        // = None`). Calling `reset()` here would do nothing for prior_root_move,
        // and would zero `history` redundantly with the per-go clone of
        // `ctx.history` we do anyway. Dropped to keep the loop body honest about
        // what's load-bearing.

        let limits = SearchLimits {
            depth: Some(depth),
            ..SearchLimits::default()
        };
        let pos_start = Instant::now();
        let ctx = SearchContext {
            stop: Arc::clone(&self.stop),
            deadline: None,
            soft_deadline: None,
            start: pos_start,
            limits,
            history: vec![pos.zobrist()],
        };

        // Synchronous-on-orchestrator-thread invocation. No worker thread —
        // `bench` is expected to run to completion without `stop` interrupting,
        // and the orchestrator's stdin reader thread keeps consuming during
        // bench (an `isready` mid-bench would queue and be served after bench
        // returns; consistent with Stockfish behavior).
        let result: SearchResult = {
            let mut s = self.search.lock().unwrap();
            // info_sink is a no-op closure — per-iteration ID info lines are
            // suppressed during bench (would flood stdout for 16 positions ×
            // depth iterations).
            let sink = |_: &str| {};
            s.go(&pos, &ctx, &sink)
        };
        let elapsed_ms = pos_start.elapsed().as_millis();

        total_nodes += result.nodes;

        // Per-position summary line. Format mirrors Stockfish's per-position
        // bench output: `bench position N/16: <fen> nodes <N> time <ms>`.
        // Routed through `info_string_always` so it conforms to ADR-0011's
        // discipline (all non-spec engine output goes through `info string`).
        self.info_string_always(&format!(
            "bench position {}/{}: {} nodes {} time {}",
            idx + 1,
            BENCH_POSITIONS.len(),
            fen,
            result.nodes,
            elapsed_ms,
        ));
    }

    let total_ms = start.elapsed().as_millis().max(1);
    let nps = (total_nodes as u128 * 1000) / total_ms;

    // Final summary lines. Two lines, both routed through `info string` to
    // honor ADR-0011's discipline that all non-spec engine output goes through
    // the `info string …` channel:
    //   1. `info string Nodes searched: <N>` — human-readable summary.
    //   2. `info string bench: <N> nodes <NPS> nps` — OpenBench-grep-compatible
    //      signature. Strict OpenBench-format expects the bare-prefix line
    //      `bench: <N> nodes <NPS> nps`; clawfish's `info string`-prefixed form
    //      is *substring-grep-compatible* with the OpenBench scraper regex
    //      `bench: [0-9]+ nodes [0-9]+ nps` (matches the substring inside the
    //      prefixed line) but not bytewise-OpenBench-format. Acceptable
    //      tradeoff: clawfish's bench is exclusively stdin-driven (no CLI
    //      subcommand at M3.F), so OpenBench couldn't scrape directly anyway.
    //      M4+ CLI-bench would need to emit the bare-prefix form.
    self.info_string_always(&format!("Nodes searched: {total_nodes}"));
    self.info_string_always(&format!("bench: {total_nodes} nodes {nps} nps"));

    // No post-bench `reset()`. By the same argument as the per-position case
    // (lines 163-170 above), `AlphaBetaMover::reset()` would only clear
    // `history`, which `Search::go` re-clones from `ctx.history` on every next
    // `go` anyway. Unlike `ucinewgame`, `bench` does NOT mutate `Engine::position`
    // or `Engine::game_history`, so there is no engine-side state to clean up.
}
```

**Subtleties:**

- **Synchronous, not threaded**: `bench` runs on the orchestrator thread. Holds the search mutex for the duration; `isready` / `stop` arriving mid-bench queue and are processed after bench returns. Acceptable for `bench` — it's a developer-tool command, not a long-running game-time operation. (Threaded bench would force `bestmove` emission semantics that don't apply.)
- **`stop` mid-bench**: NOT supported in M3.F. `stop` flips the atomic, but the bench loop doesn't poll it between positions; the per-position `Search::go` will see `stop=true` and abort the current iteration, but the loop continues to the next position. Acceptable — `bench` is short-lived; a developer who wants to abort can `kill` the process. Documented in handler comments.
- **`info_sink` is no-op**: per-iteration ID `info depth N …` lines are suppressed during bench. Otherwise `bench` would emit ~7 × 16 = 112 info lines, which is noise.
- **`history = vec![pos.zobrist()]`**: each position is a fresh game-history; no repetition concerns from prior bench positions. The single-entry vec is the M3.B+M3.E invariant.
- **No per-position `reset()`**: `AlphaBetaMover::reset()` only clears `self.history`; it does NOT clear `prior_root_move`. Cross-position `prior_root_move` contamination is prevented by `Search::go`'s own top-of-go reset (clear at line 321: `self.prior_root_move = None`), which fires unconditionally on every `go` invocation. The bench loop relies on this; no extra reset is needed. **Note**: even if `prior_root_move` were not cleared, the `position()` lookup inside `negamax`'s ply==0 reorder (line 534) gracefully returns `None` for a move not in the current movelist, so the leak would be silent rather than crashing — but the lookup is fast and correctness comes from the per-go reset, which is the load-bearing invariant.
- **`pos_start = Instant::now()` separate from `start`**: enables per-position `time <ms>` reporting. Not load-bearing but matches Stockfish's per-position output format.
- **NPS arithmetic uses u128**: `(total_nodes as u128 * 1000) / total_ms` avoids u64 overflow at billion-scale node counts (depth 13 + 32 positions could exceed u64 / 1000 boundary but not u128 / 1000). Match the M3.E `info time` precedent's safety.
- **`max(1)` on `total_ms`**: sub-millisecond bench (tiny corpora) doesn't divide-by-zero.

## 8. `scripts/sprt.sh` body

```bash
#!/usr/bin/env bash
# SPRT match runner using historical-commit baselines per docs/workflow.md.
#
# Subcommands:
#   sprt <baseline-tag>      — SPRT match: HEAD vs baseline-tag (clawfish-vs-clawfish)
#   match <baseline-tag>     — fixed-game-count match HEAD vs baseline-tag; 200 games default
#   rating-estimate          — fixed-game-count match HEAD vs Stockfish UCI_Elo=1320; 200 games
#                              default. No tag arg — Stockfish from PATH (brew install stockfish)
#                              capped at the known-Elo setting (ADR-0012 reference point).
#
# Usage: scripts/sprt.sh sprt baseline/random-mover
#        scripts/sprt.sh match baseline/random-mover
#        scripts/sprt.sh rating-estimate
#        SPRT_GAMES=400 scripts/sprt.sh sprt baseline/random-mover  (override)
#        SPRT_TC=10+0.1 scripts/sprt.sh sprt baseline/random-mover  (override)
#        SPRT_CONCURRENCY=6 scripts/sprt.sh sprt baseline/random-mover
#        SPRT_REBUILD=1 scripts/sprt.sh sprt baseline/random-mover  (force rebuild
#                                                                    of cached baseline)

set -euo pipefail

if [[ "${SPRT_DEBUG:-0}" == "1" ]]; then set -x; fi

ulimit -n 4096 2>/dev/null || true

EXPECTED_VERSION_LINE="alpha 1.8.0"
REPO_ROOT="$(cd "$(dirname "$0")/.." && pwd)"
SUBCMD="${1:-}"
BASELINE_TAG="${2:-}"

usage() {
    echo "Usage: scripts/sprt.sh <sprt|match|rating-estimate> [baseline-tag]"
    echo ""
    echo "  sprt <tag>           SPRT match (elo0=0, elo1=10, alpha=0.05, beta=0.05; up to 400 games)"
    echo "  match <tag>          fixed-game-count match (200 games default)"
    echo "  rating-estimate      fixed-game-count match HEAD vs Stockfish UCI_Elo=1320 (200 games)"
    echo ""
    echo "Env vars:"
    echo "  SPRT_GAMES           default sprt=400, match=200, rating-estimate=200"
    echo "  SPRT_TC              default '10+0.1'"
    echo "  SPRT_CONCURRENCY     default '6'"
    echo "  SPRT_REBUILD=1       force rebuild of cached baseline worktree"
    echo "  SPRT_DEBUG=1         enable set -x"
    echo ""
    echo "Output: target/matches/sprt/<dated>-<baseline-slug>-<subcmd>.{pgn,log}"
}

if [[ -z "$SUBCMD" ]] || [[ "$SUBCMD" == "--help" ]] || [[ "$SUBCMD" == "-h" ]]; then
    usage
    exit 0
fi
# `rating-estimate` takes no tag arg; sprt/match require one.
if [[ "$SUBCMD" != "rating-estimate" ]] && [[ -z "$BASELINE_TAG" ]]; then
    usage
    exit 1
fi

# fastchess locator (mirror match.sh).
VENDOR_BINARY="$REPO_ROOT/vendor/fastchess/fastchess"
if [[ -x "$VENDOR_BINARY" ]]; then
    FASTCHESS="$VENDOR_BINARY"
elif command -v fastchess >/dev/null 2>&1; then
    FASTCHESS="$(command -v fastchess)"
else
    echo "ERROR: fastchess not found. Run scripts/install-fastchess.sh." >&2
    exit 1
fi
actual_ver="$("$FASTCHESS" --version 2>&1 || true)"
if ! echo "$actual_ver" | grep -q "$EXPECTED_VERSION_LINE"; then
    echo "ERROR: fastchess version mismatch. Expected to contain '$EXPECTED_VERSION_LINE'; got: $actual_ver" >&2
    exit 1
fi

# Build current-tree binary (always rebuild — cheap on incremental).
echo "Building HEAD binary..."
cargo build --release --manifest-path "$REPO_ROOT/Cargo.toml" --quiet
CURRENT_BINARY="$REPO_ROOT/target/release/clawfish"

# Resolve baseline (clawfish-tag-from-worktree, or stockfish-1320 sentinel).
if [[ "$SUBCMD" == "rating-estimate" ]]; then
    if ! command -v stockfish >/dev/null 2>&1; then
        echo "ERROR: stockfish not on PATH." >&2
        echo "  Run: brew install stockfish" >&2
        exit 1
    fi
    STOCKFISH="$(command -v stockfish)"
    BASELINE_BINARY="$STOCKFISH"
    BASELINE_LABEL="stockfish-1320"
    BASELINE_SLUG="$BASELINE_LABEL"
    # Stockfish-specific UCI options injected into the engine def below; cap at
    # UCI_Elo=1320 (ADR-0012's known-strength reference point).
else
    # Verify baseline tag exists.
    if ! git -C "$REPO_ROOT" rev-parse --verify --quiet "refs/tags/$BASELINE_TAG" >/dev/null; then
        echo "ERROR: baseline tag '$BASELINE_TAG' not found." >&2
        echo "  Available tags: $(git -C "$REPO_ROOT" tag -l 'baseline/*' | tr '\n' ' ')" >&2
        exit 1
    fi

    # Sanitize tag name → filesystem-safe slug.
    BASELINE_SLUG="${BASELINE_TAG//\//-}"
    BASELINE_LABEL="clawfish-${BASELINE_SLUG}"

    # Build baseline binary in worktree (cached after first run, unless SPRT_REBUILD=1).
    BASELINE_DIR="$REPO_ROOT/target/sprt-baselines/$BASELINE_SLUG"
    BASELINE_BINARY="$BASELINE_DIR/target/release/clawfish"
    if [[ "${SPRT_REBUILD:-0}" == "1" ]] && [[ -d "$BASELINE_DIR" ]]; then
        echo "SPRT_REBUILD=1: removing cached worktree at $BASELINE_DIR..."
        git -C "$REPO_ROOT" worktree remove --force "$BASELINE_DIR" 2>/dev/null || rm -rf "$BASELINE_DIR"
    fi
    if [[ ! -x "$BASELINE_BINARY" ]]; then
        echo "Setting up baseline worktree at $BASELINE_DIR..."
        mkdir -p "$REPO_ROOT/target/sprt-baselines"
        if [[ -d "$BASELINE_DIR" ]]; then
            # Stale worktree without a built binary — remove and re-add.
            git -C "$REPO_ROOT" worktree remove --force "$BASELINE_DIR" 2>/dev/null || rm -rf "$BASELINE_DIR"
        fi
        git -C "$REPO_ROOT" worktree add "$BASELINE_DIR" "$BASELINE_TAG"
        echo "Building baseline binary at $BASELINE_BINARY..."
        cargo build --release --manifest-path "$BASELINE_DIR/Cargo.toml" --quiet
    else
        echo "Baseline binary cached at $BASELINE_BINARY"
    fi

    # Sanity-check the baseline binary speaks UCI before fastchess starts.
    # Catches "binary built with stale toolchain / corrupt cache" cases up front,
    # mirroring match.sh's fastchess version-line gate.
    if ! printf 'uci\nquit\n' | "$BASELINE_BINARY" 2>/dev/null | grep -q '^uciok$'; then
        echo "ERROR: baseline binary at $BASELINE_BINARY did not emit 'uciok' on a basic uci probe." >&2
        echo "  Try: SPRT_REBUILD=1 scripts/sprt.sh $SUBCMD $BASELINE_TAG" >&2
        exit 1
    fi
fi

# Output paths.
SPRT_DIR="$REPO_ROOT/target/matches/sprt"
mkdir -p "$SPRT_DIR"
TS="$(date +%Y%m%dT%H%M%S)"
PGN="$SPRT_DIR/${TS}-${BASELINE_SLUG}-${SUBCMD}.pgn"
LOG="$SPRT_DIR/${TS}-${BASELINE_SLUG}-${SUBCMD}.log"

# Match parameters.
TC="${SPRT_TC:-10+0.1}"
CONCURRENCY="${SPRT_CONCURRENCY:-6}"
ADJUDICATION=(-maxmoves 200 -resign movecount=3 score=600 -draw movenumber=34 movecount=8 score=20)

# Per-engine line for the BASELINE side. For clawfish baselines: just `cmd name`.
# For Stockfish rating-estimate: append the UCI_LimitStrength + UCI_Elo options.
if [[ "$SUBCMD" == "rating-estimate" ]]; then
    BASELINE_ENGINE_ARGS=(
        -engine cmd="$BASELINE_BINARY" name="$BASELINE_LABEL"
              option.UCI_LimitStrength=true option.UCI_Elo=1320
    )
else
    BASELINE_ENGINE_ARGS=(-engine cmd="$BASELINE_BINARY" name="$BASELINE_LABEL")
fi

COMMON=(
    -engine cmd="$CURRENT_BINARY" name=clawfish-head
    "${BASELINE_ENGINE_ARGS[@]}"
    -each proto=uci tc="$TC"
    -concurrency "$CONCURRENCY"
    -repeat
    "${ADJUDICATION[@]}"
    -pgnout file="$PGN" notation=san
    -log file="$LOG" level=info engine=true
    -report penta=true
)

case "$SUBCMD" in
    sprt)
        GAMES="${SPRT_GAMES:-400}"
        ROUNDS=$((GAMES / 2))
        echo "Running SPRT: tc=$TC, up to $GAMES games, elo0=0 elo1=10"
        echo "  HEAD vs $BASELINE_LABEL"
        "$FASTCHESS" \
            "${COMMON[@]}" \
            -rounds "$ROUNDS" \
            -sprt elo0=0 elo1=10 alpha=0.05 beta=0.05
        ;;
    match)
        GAMES="${SPRT_GAMES:-200}"
        ROUNDS=$((GAMES / 2))
        echo "Running fixed-game match: tc=$TC, $GAMES games"
        echo "  HEAD vs $BASELINE_LABEL"
        "$FASTCHESS" \
            "${COMMON[@]}" \
            -rounds "$ROUNDS"
        ;;
    rating-estimate)
        GAMES="${SPRT_GAMES:-200}"
        ROUNDS=$((GAMES / 2))
        echo "Running rating-estimate match: tc=$TC, $GAMES games"
        echo "  HEAD vs $BASELINE_LABEL (Stockfish UCI_Elo=1320)"
        "$FASTCHESS" \
            "${COMMON[@]}" \
            -rounds "$ROUNDS"
        ;;
    *)
        echo "ERROR: unknown subcommand '$SUBCMD'" >&2
        usage >&2
        exit 1
        ;;
esac

echo ""
echo "PGN: $PGN"
echo "Log: $LOG"
```

**Subtleties:**

- **Worktree cache invalidation**: if `$BASELINE_DIR` exists but `$BASELINE_BINARY` does not (e.g. partial build, or someone deleted `target/` inside the worktree), the script removes the worktree and re-adds. `git worktree remove --force` handles the case where the worktree's `.git` link is corrupt.
- **`-rounds` is half of `-games`**: fastchess plays 2 games per round (one each color). 400 games = 200 rounds.
- **No `-sprt` flag for `match` subcommand**: that subcommand is for fixed-game-count matches (rating estimate via logistic Elo; not statistical termination).
- **fastchess result-parsing**: not handled in the script. The user reads the final fastchess stdout line (which names which hypothesis was accepted) or inspects the log. M3.F's open-question item is whether to add programmatic exit-code parsing; deferred to M4.A for now (research §3 noted this as an open empirical question).
- **`-report penta=true`**: pentanomial statistics; faster SPRT termination than trinomial.
- **No opening book**: vs RandomMover, no book is the right call (research §2). Future SPRTs against equal-strength engines will add `-openings file=<book>`.

**Two genuinely-independent slices** can run on parallel coding agents:

| Slice | Scope | Files | LOC |
|---|---|---|---|
| **Slice A** (Sonnet) | `src/bench.rs` (corpus + const + tests §9.1); `Command::Bench` variant + `parse_bench` + tests §9.2; `src/lib.rs` export | `src/bench.rs` (new); `src/uci.rs` (variant + parser + tests); `src/lib.rs` | ~140 |

**Dependency**: Slice B's `handle_bench` calls `BENCH_POSITIONS` and `BENCH_DEFAULT_DEPTH` from `src/bench.rs`; uses `Command::Bench` variant from `src/uci.rs`. Slice B can stub `BENCH_POSITIONS` as `["startpos-fen-here"; 16]` to compile/test in parallel; the orchestrator merges Slice A's real corpus at the merge step.

**Synchronization point**: orchestrator confirms both slices report green (test + clippy + fmt), then merges. Step 11+ (smoke + SPRT + docs + commit) is sequential on the orchestrator.

**File-level disjointness**: Slice A's `src/uci.rs` edits add a new variant + sub-parser + tests at the end. Slice B's `src/engine.rs` edits add a new handler + dispatch arm at the existing match-arm position. Both append to `tests/uci_integration.rs` (E43 in Slice B; Slice A doesn't add integration tests). No textual conflicts expected.

**Rationale for two slices**: M3.F's surface is small (~330 LOC of new code) and the parser/handler are textbook-independent. Slice A (~140 LOC) and Slice B (~190 LOC) are unbalanced; parallel wallclock is `max(A, B) = B`'s budget, saving Slice A's ~140 LOC of transcription from the critical path (~40% wall reduction over a fully sequential single slice). **Both Sonnet** per the model assignment table — neither slice has tricky-lifetime / novel-invariant / parallel-precedent work that warrants Opus.

**No SPRT slice**: `scripts/sprt.sh` (§8) is authored by the orchestrator after both slices land — it depends on a working `bench` (for the bench-signature recording step) and the SPRT script's parameter choices need Slice B's bench output to validate.

## 13. Risks and gotchas

- **Bench depth too high → CI timeout.** Default depth 7 should keep wall under 30 s on Apple M4. CI runners are slower (sometimes 3-5× slower); E43's 60s budget absorbs this. If E43 flakes on CI, lower test-only depth to `bench 4` (already what E43 uses).
- **Bench depth too low → noisy regression signal.** Depth 1 evaluates only a handful of nodes per position; a 1-node delta could be a 5% regression signal. Depth 7 → tens of millions of nodes total → 1-node delta is sub-ppm. Default depth 7 is the right band.
- **`prior_root_move` cross-position contamination.** Prevented by `Search::go`'s top-of-go reset (line 321: `self.prior_root_move = None`); the bench loop does NOT call `reset()` per position because `AlphaBetaMover::reset()` only clears `history`. The reproducibility test (`bench_node_count_is_reproducible_across_invocations`) catches *non-deterministic* drift across runs but not *deterministic* cross-position leakage within a single run; the latter is a `Search::go` invariant already pinned by M3.E's ID tests (per-go reset is part of that test surface). Two complementary defenses: per-go reset (correctness) + reproducibility test (regression baseline integrity).
- **`stop` mid-bench**: not supported. A user `stop`-ing mid-bench will see the current position's iteration abort, but the next position will start. Acceptable; documented.
- **Worktree corruption**: if `target/sprt-baselines/<tag>` exists with a stale `.git` link, `git worktree remove --force` may fail. Script falls through to `rm -rf` as a defensive last resort. Comment in script explains.
- **fastchess SPRT exit code**: not parsed by the script. User reads stdout. Open question deferred per research §3.
- **`Bench: <N>` commit-message format strictness**: M3.F's commit message body MUST contain `Bench: <N>` on a line by itself (or as the last line). The convention is informational at M3.F (no pre-commit hook enforces it yet); the discipline is for forward-compatibility with OpenBench/Fishtest patterns.
- **Stockfish vs-1320 rating estimate is TC-dependent and a point estimate**: the resulting Elo is at `tc=10+0.1`, not at "infinite TC". `bench/m3.md` must label this explicitly. Additionally, the logistic Elo formula yields a *point estimate*, not a confidence interval — at 200 games the estimate is ±~100 Elo per research §4. `bench/m3.md` must label both axes explicitly: TC (`tc=10+0.1`) AND uncertainty (`200 games → ±100 Elo`). Future readers reading "Elo: 1450" without those qualifiers would over-interpret. M4+ may switch to BayesElo or Ordo for a CI-bearing estimate.
- **Determinism scope**: the **node-count signature** is deterministic across runs — `AlphaBetaMover` is deterministic by construction (alpha-beta + MVV-LVA + prior-PV hint, all functions of position state alone — no floating point, no time-dependent decisions inside the search recursion). Per-position `time {ms}` fields and the aggregate `<NPS>` value are wallclock-dependent and explicitly **excluded from the signature**; greppers extract only the `<N> nodes` field. Two `bench` invocations from the same binary MUST produce identical node-count totals (and per-position node counts); flakiness in those would expose a real determinism bug. Pinned by `bench_node_count_is_reproducible_across_invocations`.
- **Worktree creation at `baseline/random-mover` may fail** if the user's git config has `worktree.guessRemote = true` or similar. Defensive: `git worktree add` accepts any tag/SHA reference.
