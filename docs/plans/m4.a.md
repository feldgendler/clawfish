# M4.A — Transposition table

First M4 phase. Adds a Zobrist-keyed transposition table with bound-aware probe + cutoffs at non-PV nodes, store at every completed-bound negamax node, mate-score depth-adjustment on store/probe, the `Hash` UCI option, and TT-move-first move ordering. Closes M4.A → opens M4.B.

Research synthesis: `docs/research/m4-transposition-table.md`. Lands ADR-0018 (TT layout + replacement + mate-score adjustment + GHI stance + bench-reset inventory).

## 0. Goals

- New `tt` module with `TtEntry` (16-byte packed), `TtBound { Exact, Lower, Upper }`, `TranspositionTable` ({ `UnsafeCell<Vec<TtEntry>>`, `mask: usize`, `generation: AtomicU8` }) + `probe` / `store` / `clear` / `resize` / `new_search` / `index_for` API.
- **Backing storage is `UnsafeCell<Vec<TtEntry>>`, not `Mutex<Vec<TtEntry>>`.** TT is single-threaded by ADR-0011 invariant: only the per-`go` worker thread probes/stores during a search; the orchestrator mutates only after `join_in_flight_worker()`. Mutex overhead at ~10 ns × ~23M lock-acquisitions/sec ≈ 23% CPU at M3.F's 11.5 Mnps — load-bearing. Discipline: `unsafe impl Sync for TranspositionTable {}` with a `// SAFETY:` comment citing the ADR-0011 single-mutator invariant; resize/clear paths must run after `join_in_flight_worker()` returns. Migration to lockless XOR-trick at M11 replaces `UnsafeCell` with `Vec<AtomicU64>`-pair entries — same surgery either way.
- `score_to_tt(score: i32, ply: i32) -> i32` and `score_from_tt(score: i32, ply: i32) -> i32` pure helpers in `tt.rs`, mate-aware via the existing `MATE_IN_MAX_PLY = MATE - MAX_PLY = 29936` constant (re-exported `pub(crate)` from `search.rs`). The helpers operate on `i32` so they match the negamax score type; the i16 narrowing happens at the **store call site** with a `debug_assert!(adjusted == adjusted as i16 as i32, "TT score overflow")` guard. The bound holds: `|negamax score| ≤ MATE + MAX_PLY = 30064 < i16::MAX = 32767`.
- `AlphaBetaMover` gains a `tt: Arc<TranspositionTable>` field (cheap-clone, shared with `Engine` for ucinewgame / Hash resize / bench-reset).
- `negamax` body restructured: rep/50-move check → MDP tighten → TT probe (with bound comparison and TT-move extraction at non-PV nodes) → fall-through with TT move pre-ordered → existing recursion → store on completed bound (not on aborted return).
- `is_pv: bool` parameter threaded through `negamax` (no PVS yet — root and first-child-of-PV-parent only).
- `Hash spin default 16 min 1 max 4096` UCI option emitted in `handle_uci`; `setoption name Hash value <N>` resizes the TT (rebuild-and-clear).
- `Engine::reset_for_new_game()` private helper clears TT + game_history + position; called from `handle_ucinewgame` AND per-position inside `handle_bench`. Mirrors the M3.F `Search::go` per-go reset discipline at the engine level.
- `prior_root_move` removed: TT entry at root subsumes the ordering hint. Safety property: stores are gated by **two** invariants — (a) end-of-move-loop only (no mid-loop write); (b) skip on `self.aborted`. Together: an aborted iter N never overwrites iter (N-1)'s root entry, so iter (N+1)'s probe still finds the iter (N-1) bestmove. Both halves pinned by S3 (abort-skip) and S3b (mid-loop-no-store). Full rationale: ADR-0018 §11. M4.D revisits if SPRT shows a regression localized to aspiration-window re-search.

- SPRT vs `M3.F` accepts at `elo0=0, elo1=10` (per `docs/workflow.md` §SPRT M4 entry).
- New annotated tag `M4.A` at the M4.A commit.
- `bench/m4.md` new file with M4.A row (bench signature, SPRT result, depth-7 corpus deltas).

## 1. Out of scope

- Killer / history / aspiration: M4.B / M4.C / M4.D respectively.
- Qsearch participation in TT: deferred to M5 (per M4.A scope detail in roadmap; intermediate "probe-but-don't-store at depth==0 horizon" considered and deferred — adds complexity without composable upside until full qsearch-in-TT lands).
- Lockless TT / XOR-trick: M11 concern. Full 64-bit key in entry; clean migration path documented in ADR-0018.
- TT-move legality check beyond "is in legal-move list": structural pseudo-legality fast-path is a later optimization (profile first).
- `Hash` resize while a search is in flight: defenchess-style "resize on next ucinewgame only" is acceptable; we do the simple thing — `setoption name Hash` joins any in-flight worker (existing helper) before swapping the table, mirroring `handle_setoption(Random_Seed)`'s discipline.
- TT debug counters (hits, misses, fills, depth-distribution): nice-to-have; `info hashfull` is the only externally-visible piece, and even that is deferred to a later refinement (calculation requires sampling 1000 entries, not a free op).
- 50-move-boundary GHI guard: deferred per ADR-0018 §10. Repetition pre-TT-probe is sufficient for the common case.

## 3. Type definitions and signatures

### 3.1 `TtBound`

```rust
/// Bound type for the stored score.
/// - `Exact`: score is the position's true value (fail-high *and* fail-low both ruled out).
/// - `Lower`: returned by a beta-cutoff. Stored score is a lower bound on the true value.
/// - `Upper`: returned by a fail-low (no move beat alpha). Stored score is an upper bound.
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
#[repr(u8)]
pub(crate) enum TtBound {
    Exact = 0,
    Lower = 1,
    Upper = 2,
}
```

`#[repr(u8)]` so the bound packs into 2 bits of the entry's `age_and_bound` byte without `unsafe` casts.

### 3.2 `TtEntry`

```rust
/// 16-byte transposition-table entry. Packed for cache-line cleanliness:
/// 4 entries fit in a 64-byte cache line.
#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
#[repr(C)]
pub(crate) struct TtEntry {
    pub key: u64,             // full Zobrist key (single-threaded; M11 may shrink to 32-bit + xor-trick)
    pub score: i16,           // ply-adjusted on store (mate scores), un-adjusted on probe
    pub depth: u8,            // 0..=63 (MAX_PLY); u8 leaves headroom for future qsearch entries
    pub age_and_bound: u8,    // bits [7..2] = age (6 bits, wraps at 64); bits [1..0] = TtBound
    pub best_move: u16,       // packed Move; `Move::default()` (0u16) means "no move stored"
    pub _pad: u16,            // align to 16 bytes
}
```

Helpers (associated fns):
```rust
impl TtEntry {
    pub fn empty() -> Self;            // all zero; key == 0, best_move == 0u16
    pub fn is_empty(&self) -> bool;    // key == 0 AND depth == 0 AND age_and_bound == 0
    pub fn bound(&self) -> TtBound;    // (age_and_bound & 0b11) → TtBound
    pub fn age(&self) -> u8;           // age_and_bound >> 2
    pub fn pack_age_bound(age: u8, bound: TtBound) -> u8; // (age << 2) | (bound as u8)
}
```

### 3.3 `TranspositionTable`

```rust
/// Power-of-two-sized direct-mapped TT. Indexing is `key & mask`.
/// Single-threaded for M4–M10 by ADR-0011 invariant; lockless concurrent
/// variant for Lazy SMP deferred to M11.
pub(crate) struct TranspositionTable {
    entries: UnsafeCell<Vec<TtEntry>>,
    /// Mask = entries.len() − 1. Fixed for the lifetime of `entries`;
    /// recomputed on resize. Storing it outside the UnsafeCell lets
    /// `entry_count()` and `index_for()` skip the cell entirely.
    mask: usize,
    /// 6-bit search generation. Range `[0, 63]`; advanced once per `go`
    /// via `new_search()` as `(gen + 1) & 0x3F`. AtomicU8 lets the orchestrator
    /// observe it under `Sync` without unsafe; reads/writes are Relaxed.
    /// Reset to 0 by `clear()`.
    generation: AtomicU8,
}

// SAFETY: ADR-0011 + ADR-0018 §2 invariant — only the per-`go` worker thread
// touches `entries` during a search; the orchestrator mutates `entries` only
// after `Engine::join_in_flight_worker()` returns. No cross-thread access to
// `entries` ever overlaps. `mask` is set on construction/resize and read
// without aliasing concerns. `generation` is AtomicU8.
unsafe impl Sync for TranspositionTable {}
```

**API:**
```rust
impl TranspositionTable {
    pub fn new(size_mib: usize) -> Self;                        // panics if size_mib == 0
    pub fn resize(&self, size_mib: usize);                      // rebuild-and-clear
    pub fn clear(&self);                                        // zero all entries; resets generation to 0
    pub fn new_search(&self);                                   // gen = (gen + 1) & 0x3F
    pub fn probe(&self, key: u64) -> Option<TtEntry>;           // None on key mismatch or empty
    pub fn store(&self, key: u64, entry_data: TtData);          // applies replacement scheme
    pub fn entry_count(&self) -> usize { self.mask + 1 }        // derived; never locks
    pub fn generation(&self) -> u8;                             // returns Relaxed-loaded gen ∈ [0, 63]
    pub fn index_for(&self, key: u64) -> usize { (key as usize) & self.mask }
}

/// Inputs to `store` — bundle so the call site doesn't pass 5 positional args.
pub(crate) struct TtData {
    pub score: i16,
    pub depth: u8,
    pub bound: TtBound,
    pub best_move: u16,  // packed; 0 means "no move"
}
```

**Replacement scheme** (applied inside `store`):

```text
let idx = self.index_for(key);
let old = (*self.entries.get())[idx];          // unsafe deref; single-mutator
let new_age_bound = TtEntry::pack_age_bound(self.generation(), data.bound);
let replace = old.is_empty()
    || old.age() != self.generation()              // old generation: free to replace
    || old.depth <= data.depth;                    // depth-preferred at same gen
if replace {
    // Best-move preservation: if new entry has no best_move and slot has the SAME
    // position (same key) with a best_move from a prior store, copy it over.
    let preserved_move = if data.best_move == 0 && old.key == key && old.best_move != 0 {
        old.best_move
    } else {
        data.best_move
    };
    (*self.entries.get())[idx] = TtEntry {
        key, score: data.score, depth: data.depth,
        age_and_bound: new_age_bound,
        best_move: preserved_move,
        _pad: 0,
    };
}
```

**Why `<=` not `<` on the depth check.** Equal-depth re-search of the same position with a tighter window can produce a more useful entry (Exact replacing Lower, e.g.); biased toward freshness on ties. Anti-stub: T11 catches a stub that uses `<` (would fail the same-depth-replaces sub-case).

### 3.4 `score_to_tt` / `score_from_tt`

```rust
/// Mate-score adjustment on store. `score` is the negamax return at the
/// node's ply; `ply` is that node's distance from root.
pub(crate) fn score_to_tt(score: i32, ply: i32) -> i32 {
    if score > MATE_IN_MAX_PLY {
        score + ply
    } else if score < -MATE_IN_MAX_PLY {
        score - ply
    } else {
        score
    }
}

/// Inverse: probe-side adjustment.
pub(crate) fn score_from_tt(score: i32, ply: i32) -> i32 {
    if score > MATE_IN_MAX_PLY {
        score - ply
    } else if score < -MATE_IN_MAX_PLY {
        score + ply
    } else {
        score
    }
}
```

`MATE_IN_MAX_PLY` is currently a private constant in `search.rs`; promote to `pub(crate)` (single-line change). Pinned by §5 round-trip property test.

### 3.6 `negamax` signature change

```rust
fn negamax(
    &mut self,
    pos: &mut Position,
    depth: u32,
    ply: u32,
    mut alpha: i32,
    mut beta: i32,
    is_pv: bool,
    ctx: &SearchContext,
) -> i32;
```

`is_pv` plumbed: `true` at the root call from `Search::go`; in the recursion, `is_pv = parent_is_pv && i == 0` where `i` is the **move-loop recursion-order index** (i.e., index into the post-ordered `moves_vec` after step 9's TT-move-first reorder). The first child by recursion order is the PV child; all others are non-PV — regardless of whether they later improve alpha. Under fail-soft pure alpha-beta there is no window-based PV/non-PV distinction (every node has the same window type semantically); `is_pv` is a **synthetic ordering predicate** governing whether TT cutoffs fire. PVS at M4.D will replace it with the window-based `beta - alpha == 1` predicate. Tests S5/S6/S13 must assert the synthetic semantics ("the i==0 child sees `is_pv=true`"), not any window invariant.

### 3.8 `Hash` UCI option

Emit in `handle_uci`:
```
option name Hash type spin default 16 min 1 max 4096
```

Parse in `handle_setoption`: case-insensitive `"hash"` match (mirrors `random_seed` / `moveoverhead` discipline). Parse value as `usize`, clamp to `[1, MAX_HASH_MIB]`. On valid value:
1. `join_in_flight_worker()` (mirrors `random_seed`).
2. `self.tt.resize(value);` (rebuild-and-clear).
3. `self.hash_mib = value;`.

Out-of-range / parse-fail: `info_string_debug` rejection (mirrors existing setoption discipline).

## 4. Order of operations inside `negamax` (post-M4.A)

```text
1. clear PV slot at this ply
2. depth == 0 → delegate to qsearch (UNCHANGED — qsearch does not consult TT in M4.A)
3. nodes increment + 4096-cadence cancellation poll (non-leaf only)
4. **CAPTURE original_alpha = alpha** (BEFORE MDP, BEFORE TT probe; load-bearing for bound classification at step 11).
5. ply > 0:
   a. is_fifty_move_draw(halfmove_clock) → return 0
   b. is_repetition(history, halfmove_clock) → return 0
6. mate-distance pruning: tighten alpha/beta against MATE-ply / -(MATE-ply); short-circuit if collapsed
7. TT probe with key = pos.zobrist():
   a. Probe returns Option<TtEntry>; on None or empty fall through.
   b. If hit: extract `tt_move = entry.best_move` (validate at move-list scan §step 10).
   c. Score: `tt_score = score_from_tt(entry.score as i32, ply as i32)`.
   d. If !is_pv AND entry.depth >= depth:
      - Exact: return tt_score
      - Lower AND tt_score >= beta: return tt_score
      - Upper AND tt_score <= alpha: return tt_score
   e. Otherwise: keep `tt_move` as the ordering hint; fall through to search.
   (PV nodes: never return early, even on Exact. Use `tt_move` for ordering only.)
8. generate_moves; root searchmoves filter (UNCHANGED)
9. terminal: empty move list → MDP-tightened mate / stalemate / 0 (UNCHANGED)
10. order: MVV-LVA descending, THEN if `tt_move != 0u16` and `tt_move` is in moves_vec, move it to index 0. This subsumes M3.E's `prior_root_move` reorder (which is removed entirely). `Move::default() == 0u16` encodes a1-a1-Quiet, never produced by movegen, so the `is in moves_vec` scan rejects the sentinel by construction. S12 covers garbage 0xFFFF.
11. recurse fail-soft (UNCHANGED structure, BUT pass `is_pv` correctly):
    - For move at recursion-order index `i` (after the step-10 reorder): child_is_pv = is_pv && i == 0.
    - score = -self.negamax(pos, depth-1, ply+1, -beta, -alpha, child_is_pv, ctx)
    - existing post-call abort check + alpha update + PV update + beta cutoff
12. NEW — store on completion (END of move loop, never mid-loop):
    - **Skip if self.aborted** — partial scores are not real bounds.
    - bound =
        if best >= beta { TtBound::Lower }
        else if best > original_alpha { TtBound::Exact }    // uses pre-MDP original_alpha (step 4)
        else { TtBound::Upper }
    - best_move:
        Lower → the move that caused the cutoff (the breaking move at break-time).
        Exact → pv.moves[ply][0] if pv.lengths[ply] > 0 else 0.
        Upper → 0 (no move beat alpha; preservation logic in `store` reuses old.best_move when slot's key matches).
    - score: `let adjusted = score_to_tt(best, ply as i32); debug_assert!(adjusted == adjusted as i16 as i32, "TT score overflow"); let stored_score = adjusted as i16;`
    - depth: `depth as u8` (MAX_PLY = 64 fits in u8).
    - tt.store(key, TtData { score: stored_score, depth: depth as u8, bound, best_move })
```

**Why `original_alpha` is captured before MDP.** MDP can mutate `alpha` upward (via `alpha = mated_value` when `mated_value > alpha`). Bound classification compares `best > original_alpha` to decide Exact vs Upper. Capturing after MDP would make a fail-low against the *MDP-tightened* alpha look like an Exact bound at a different ply (where MDP would tighten differently). CPW Mate-Distance-Pruning + ADR-0017 §M3.E preserve the pre-MDP alpha for this reason. S1 / S2 pin the pre-MDP capture.

**Store-at-end-of-loop discipline.** The store fires after the move loop returns. The abort path (`if self.aborted { return 0; }` inside the loop) returns *without* storing — correct. There is **no mid-loop store**. Together: aborted iterations never overwrite a prior iteration's entry, so iter (N+1)'s probe still finds iter (N-1)'s root bestmove when iter N aborted. S3 pins the abort-skip half; S3b pins the no-mid-loop-store half.

### 5.6 Confirmation-bias defense

For S4–S6, the explicit anti-stub assertion: the test counts node visits via the `nodes` field. A stub TT-probe-returning-None would force full recursion; a real TT cutoff returns immediately. The expected node count differs by at least 10× between these two paths.

For S8 (mate-score round-trip), the assertion includes both the stored value and the probed value separately, not just `score_to_tt(score_from_tt(x))` — this catches a buggy implementation where store and probe both return the input unchanged.

For T13 (best-move preservation), the assertion explicitly distinguishes "old best_move preserved (M1)" from "new best_move written (M2)": the test stores M1 first, then stores with `best_move=0`, asserts M1 is preserved; a separate sub-test stores M1, then M2 with a real best_move, asserts M2 is written. Catches a stub that always preserves or always overwrites.

## 6. Order of work / parallelization map

**Sequential dependencies:**
1. ADR-0018 written → 2. tests for `tt` module written → 3. `tt` module impl → 4. tests for `search` changes → 5. `search` impl → 6. tests for engine wiring → 7. engine wiring impl → 8. integration tests → 9. pre-review → 10. final review → 11. SPRT.

**Parallelization opportunities:**

- **Slice A (chess-coder Sonnet, prescriptive):** `src/tt.rs` module + tests T1–T22. Self-contained — no dependency on `search.rs` or `engine.rs` changes. `MATE_IN_MAX_PLY` is exported from `search.rs` as a `pub(crate) const`; this single-line export is the dependency, hand-applied by the orchestrator at start-of-implementation.
- **Slice B (chess-coder Opus, structural — flagged because it reshapes negamax body and threads `is_pv`):** `src/search.rs` changes + tests S1–S13.
- **Slice C (chess-coder Sonnet, prescriptive):** `src/engine.rs` Hash option + reset_for_new_game + handle_bench wiring + tests E_a–E_f. Depends on slice A's TT API surface. After slice A lands.
- **Slice D (orchestrator):** integration tests E44–E45, doc updates, ADR finalize. After A+B+C.

A and B can run concurrently if A's `pub(crate)` API is committed to a header-style stub first (signatures only, no bodies). C runs after A. D runs after all.

In practice we'll likely run A first (smallest, lowest risk, surfaces API quirks), then B+C in parallel, then D. The orchestrator stitches the slices.

**Slice B Opus flag rationale.** Falls under "novel invariants" + "qualitative behavior shifts that break existing tests" criteria from `docs/workflow.md` "When to flag a coder slice for Opus": (a) the `is_pv` invariant is invented during impl (no prior carrier in the codebase); (b) removing `prior_root_move` breaks the M3.E tests pinning that field — Slice B's coder must update those tests atomically; (c) the negamax store-on-completion discipline is the kind of cross-call-site invariant where a simple-pattern-match impl can slip up (e.g. forgetting to skip on `aborted`).

## 7. Dependencies on other units

- **Hard:** M3.E `Search::go` ID outer loop — TT entries are populated per ID iteration; we rely on the ID structure for the prior-iteration-bestmove ordering benefit.
- **Hard:** M3.F `Engine::handle_bench` per-position TT clear — without it, bench determinism breaks.
- **Soft:** M4.B Killer + M4.C History — both use `is_pv` and the new node-prologue ordering; M4.A landing the discipline lowers M4.B/M4.C surface.

## 10. Risks and mitigations

| Risk | Mitigation |
|---|---|
| TT introduces non-determinism in bench | `Engine::reset_for_new_game()` called per bench position; T_e + S11 + E45 pin it. |
| `is_pv` plumbing wrong → search returns wrong score | S5 + S6 pin PV cutoff suppression; S4 pins non-PV cutoff. The test count-difference is the load-bearing assertion. |
| Mate-score adjustment has a sign error | T17 / T18 / T19 (proptest round-trip) / T20 (worked example with concrete plies) — covers all four sign quadrants. S8 is the integration version. |
| Best-move preservation causes stale moves to surface | T13 pins same-key preservation; T14 pins different-key non-preservation; S12 pins legality filter on collision garbage. |
| SPRT fails (no Elo gain or worse) | Most likely cause: TT-move not actually moving to front (`tt_move == 0u16` or `tt_move not in moves_vec`). Diagnostic: add debug `info string tt-hit-rate` log temporarily; expect ~10–30% probe-hit rate at depth ≥ 4. Second-most-likely cause: aborted-store discipline broken — search storing partial bounds that taint subsequent probes. Diagnostic: pin `if self.aborted { skip store }` per S3. Third: PV-node discipline broken (PV nodes returning early on TT score) — diagnostic via S5. |
| `Hash` resize while bench in flight | bench is synchronous on the orchestrator thread; commands queue. `setoption name Hash` after `bench` waits; before `bench` resizes first. No mid-bench race. |
| Mutex contention on TT under future M11 Lazy SMP | Documented as the M11 swap-out point; not M4.A's concern. |
| Removing `prior_root_move` breaks M3.E tests | Slice B's coder updates the M3.E tests atomically; the test surface that asserts the field exists or is set is replaced with TT-based equivalents (S7). |
