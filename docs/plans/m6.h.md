# M6.H — Robust on-demand Lichess/CCRL ingestion (plan)

**Status:** plan v1. Unit: M6 sub-phase H (data-acquisition layer). Gate:
**functional, not SPRT** — no `evaluate`/`Position`/search touch ⇒ bench
byte-identical to `M6.F`/`M6.G` (`1213649` / d4 `90591`) by construction; no
Elo claim. Binding scope: `docs/roadmap.md` §M6 "M6.H scope detail" + the
"Sub-protocol — robustness gates" table (gates 1–7). Binding research:
`docs/research/m6-network-fetch.md`. Extends ADR-0035 (corpus infra); ADR-0036
allocated at landing.

This plan does **not** re-derive the roadmap scope detail — read it first. It
fixes the module layout, signatures, the three load-bearing mechanisms
(early-termination / stall watchdog / resume), the dependency + license +
feature-gating decisions, and the test surface.

## 1. Scope / non-scope

In: a `corpus::fetch` library module + a `corpus fetch` CLI subcommand that
streams a compressed PGN dump over HTTPS, decompresses, and feeds the existing
M6.G ingest path (`pgn::stream_pgn` → `filter::game_admitted` →
`store::append_block` into `pgn-shard.bin`). Robust: in-attempt Range-resume,
games-parsed stall watchdog, infinite outer backoff, 7 robustness gates, a URL
catalog, a per-URL state file.

Out: 7z; on-disk `.partial` checkpoint (in-RAM resume + shard dedup cover it);
any change to `stream_pgn`/`append_block`/`filter`/the store format (reused
verbatim); any `evaluate`/search touch. M6.I's bi-level driver is **not** built
here — M6.H only delivers the synchronous primitive it will call.

**Amendment (2026-05-22, DECIDED, not yet implemented).** The "filter … (reused
verbatim)" non-scope above is relaxed: `filter::game_admitted` is *extended* (not
rewritten) with three game-level gates — drop `Termination "Rules infraction"`;
minimum game length `≥ 20 plies` (10 full moves, the `--minmoves 10` literature
default); and a universal non-standard-start gate rejecting `[SetUp "1"]` /
non-startpos `[FEN]` (which also requires the PGN parser to read those two tags).
Recorded non-gates: no Elo-gap cap, no CCRL strength floor; resignations + agreed
draws are kept. Full spec + rationale: ADR-0036 amendment "(2026-05-22, game-level
+ variant filter spec)". No code lands with this note.

## 2. Dependencies, licensing, feature-gating (load-bearing infra decision)

New deps, **all gated behind a non-default `corpus-fetch` Cargo feature** so
the engine binary / its `cargo audit`+`cargo deny`+build stay unaffected (the
project is deliberately lean — only `libc` today; `corpus` is `pub mod` in
`lib.rs`, so unconditional deps would link rustls/ring/zstd/zip into the engine
binary for zero benefit). Rejected alternative: unconditional deps (simpler
build matrix, but bloats the engine's supply-chain surface — contrary to the
"no engine touch" ethos extended to dependencies).

```toml
[features]
corpus-fetch = ["dep:ureq", "dep:zstd", "dep:zip"]

[dependencies]
ureq = { version = "3.3", default-features = false,
         features = ["rustls", "platform-verifier"], optional = true }
zstd = { version = "0.13", optional = true }
zip  = { version = "<verified at impl time>", default-features = false,
         features = ["deflate"], optional = true }
```

- **`ureq` 3.3 + `platform-verifier`** — OS trust store (macOS Security
  framework) for gate-1 channel identity; the better mechanism for the
  roadmap's "OS trust store / `rustls-native-certs`" intent (research §1–2).
  `default-features=false` + explicit `rustls` to drop the static Mozilla
  `webpki-roots` we don't use. **No `gzip` feature** — Lichess `.pgn.zst` and
  CCRL `.zip` are *payloads* (we decompress them ourselves), not
  `Content-Encoding` transport; enabling ureq transport-gzip would double-handle
  a gzip-wrapped body and confuse gate 5's sniff. (research dependency table.)
- **`zstd` 0.13** (C-binding, vendors libzstd, ~3× faster decode than `ruzstd`;
  build-time C compiler only, no runtime system dep — research §3).
- **`zip`** — verify exact version with `cargo add zip` (research §4 flagged a
  version-string ambiguity); `deflate`-only (CCRL uses deflate). Used via
  `ZipArchive::new(File)` on a downloaded temp file (§7), not the streaming
  reader.
- **No** `rustls-native-certs` (subsumed), **no** `fs2`/`fs4` (use
  `libc::statvfs`, already a dep — research §7).

**License gate (`cargo deny check`, mandatory on dep change).** Plan commits to
two `deny.toml` edits, both consistent with CLAUDE.md's stated permissive set:
(a) add `Unicode-3.0` + `Zlib` to `licenses.allow` (proc-macro `unicode-ident`
/ `miniz_oxide` transitives); (b) add a `[[licenses.clarify]]` for `ring` if
flagged (it ships `license-file`, no SPDX field — standard cargo-deny
friction). `zstd-sys` is `BSD-3-Clause OR GPL-2.0` → cargo-deny resolves to
BSD-3-Clause (**already in the allowlist** — the GPL-2.0 string in the OR is
expected and needs no action; noted so the dep-change reviewer isn't surprised).
Exact `ring` clarify entry determined empirically at impl. `cargo audit` +
`cargo deny check` run after `Cargo.lock` changes; any advisory surfaced in
chat. The transitive expansion (~+80–120 crates) is surfaced to the user as a
supply-chain note.

## 5. The three load-bearing mechanisms (control flow)

**(A) Two-level resume.**
- *Within an attempt (`ResumableHttpReader`)*: on a transient `inner` error or a
  recv-body timeout (below), reopen `GET … Range: bytes={consumed}-`, **keep the
  same `zstd` decoder alive** (the lichess streaming path; decoder reads from the
  reader; byte-level reconnect of the raw compressed body is transparent —
  research §3). Zero re-decompression. A `206` continues; a `200` (server ignored
  Range) ⇒ `RangeIgnored` (can't feed byte-0 into a mid-stream decoder); a `416`
  ⇒ clean EOS (`Ok(0)`, `EofReason::InnerEof`). **CCRL does not use in-stream
  resume** — it Range-resumes a temp-file download (§7), so its resume is
  file-offset-based and trivially correct (per research §4/§5).
- *Across attempts (`stream_to_ingest` outer loop)*: on any non-terminal failure
  (incl. `RangeIgnored`, escalated stall, reconnect that can't re-establish),
  sleep (exponential backoff 1s→…→5 min cap), then start a **fresh attempt from
  byte 0** with a fresh decoder. This is also the "wait until network resolves"
  loop; honors `stop` (SIGINT) for clean exit; logs the next retry in **absolute
  local clock time** (CLAUDE.md); bounded by `cfg.max_attempts` only in tests.

**Idempotence + accounting across byte-0 restarts (the roadmap "dedup absorbs
as no-ops" claim, made precise).** `target` means **N new positions appended
this call**. `CallState` (incl. `positions_ingested`, `max_appended_game_id`)
**persists across the call's attempts**; `AttemptState` (incl. `consumed`, the
Range byte-offset) is **fresh per attempt**. `base_game_id =
max_existing_game_id(out)+1` is pinned **once at entry**; `stream_pgn` assigns
ids sequentially from it in deterministic parse order (`pgn.rs:553`), so a
byte-0 restart re-derives the *same* id per physical game. The `on_game`
closure:
- bumps `last_game_at` + `games_since_resume` on **every** yielded game
  (liveness — a re-seen game still proves the stream is healthy);
- if `gp.game_id <= max_appended_game_id` ⇒ **skip** (no `append_block`, and
  **does NOT bump `positions_ingested`** — those positions were counted on
  first append) ⇒ in-process byte-0 restart is a **true no-op append**, and the
  counter keeps measuring true progress toward `target` (no reset, no
  double-count);
- else ⇒ `append_block`, `positions_ingested += recs.len()`, `games_emitted +=
  1`, `max_appended_game_id = gp.game_id`.

*Across separate processes* (reboot → new `stream_to_ingest`, `base_game_id`
recomputed from the grown shard) the same games get *new* ids ⇒ duplicate FENs
land in `pgn-shard.bin`, removed only by the later `corpus build` FEN-dedup
(NOT a no-op at append time — the documented weaker cross-process guarantee,
consistent with ADR-0035 §8's "external sources: re-derivable, not byte-exact").
Acceptable because byte-0 restarts are *rare* (escalation / reboot only;
in-attempt resume is the primary recovery path and never re-ingests).

**(B) Stall watchdog — games parsed, not bytes.** ureq owns the socket; the
reader never calls `set_read_timeout`. The heartbeat is the agent-level
**`timeout_recv_body = stall_timeout`** (research §6): a hung socket makes
`inner.read` return a timeout error within `stall_timeout`, handing control
back to the reader. The reader's `read()` loop checks the watchdog at the **top
of every call** (so the bytes-but-no-games case is caught even while reads keep
succeeding — `stream_pgn`/decoder pull frequently): if `now − last_game_at >
stall_timeout`, it is a stall. `last_game_at` is bumped by the `on_game` closure
per yielded game (keyed on **games parsed**, not positions — the filter is
legitimately selective), initialized to attempt start so warm-up gets the full
window. A stall (or a recv-body timeout / transient `inner` error) triggers a
Range reconnect; `games_since_resume` gates escalation — a reconnect that
yields no new game increments `noprogress_resumes`, and exceeding
`max_noprogress_resumes` (default 3) bubbles `AttemptFailure::Stall` ⇒ outer
byte-0 restart (defeats the byte-alive-but-semantically-dead stream and any
livelock on a legitimately-slow-but-gameless connection). (CCRL temp-download
sets `bytes_are_progress=true` so raw bytes count as progress during the
download phase, where bytes *are* the goal; the games-watchdog applies during
the post-download local parse, which needs no network.)

**(C) Early-termination — decoder-agnostic, via counter + `EofReason`.** The
`on_game` closure bumps `call.positions_ingested` (on a real append only —
§5A); once `>= target` the reader returns `Ok(0)` recording `eof_reason =
Target`. A real stream end records `eof_reason = InnerEof`. **Classification
after `stream_pgn` returns** (order):
`stop` set → `Stopped`; `eof_reason == InnerEof` → `Eos` (so a true-EOS that
coincided with hitting target is correctly reported as drained, not early —
matters for `fetch-state.json`'s "has more to give" signal to M6.I); else
`positions_ingested >= target` → `EarlyTarget` (true even if the decoder
errored on a mid-frame truncation — the counter, not the decoder's terminal
`Ok(0)`-vs-`Err`, is truth); else inspect `AttemptState.failure`
(`Stall`/`Transient`/`RangeIgnored` → backoff+restart; `Permanent` → return
`Err`). **No `stream_pgn` change is needed** — the counter-as-truth design fully
handles early termination, preserving the §1 "reused verbatim" invariant. (The
earlier "O2 early-stop predicate on `stream_pgn`" fallback is dropped: it would
breach that invariant and is unnecessary.)

## 6. Robustness gates (mapping to roadmap gates 1–7)

1. **Connect** — `timeout_connect`; `RootCerts::PlatformVerifier` (chain +
   hostname). 2. **Stall watchdog** — §5(B). 3. **HTTP error split** —
   `classify_http_status` (transient 408/429/5xx → backoff; permanent other 4xx
   → `CorpusError` nonzero exit). 4. **Redirect cap** — `max_redirects(5)`;
   gates 5/6 apply to the final response.

**Gates 5+6 — single decompressed-prefix pre-flight (nothing committed before
validation).** Both content-sanity gates run on **one buffered prefix** of the
decompressed stream, *before* any `append_block`: read up to `preflight_bytes`
(~256 KiB, enough for ≫100 games) into a RAM buffer; run a **throwaway
`stream_pgn`** over the buffer (`Cursor`, throwaway base id + `PgnStats`) to get
`(games_seen, parse_failures)`. **Gate 5 (magic-byte sniff)** —
`sniff_is_pgn(prefix)`: the first non-whitespace bytes must be a PGN tag pair
(`[` + a known tag token `Event`/`Site`/`White`/`Result` + `"`); a **prefix
anchor, not `contains`** (so HTML that merely embeds a `[Event ` substring
mid-body is rejected). **Gate 6 (parse-sanity)** — `games_seen > 0 ∧
parse_failures/games_seen ≤ 0.10`. On either failure → discard + backoff +
retry (a soft-404/CDN-HTML 200 is thus rejected without ingesting a byte). On
pass → **chain the prefix back** (`Cursor::new(prefix).chain(rest_of_decoder)`)
and run the *real* `stream_pgn` over the full stream (the prefix games are
re-parsed — ~256 KiB, negligible — and appended for real under the pinned
`base_game_id`). This is the only place gate 5/6 logic lives; it removes the
"can't read `PgnStats` mid-stream / garbage already committed" problem (the
verdict precedes the first real append). 7. **Disk pre-check** — `disk_precheck`
before connecting, using `cfg.disk_floor_bytes` (2 GiB floor); for the CCRL
temp-file path the check is *refined* once the GET response `Content-Length` is
known to `max(floor, 3×Content-Length)` and aborts before the temp write if
insufficient (the streaming lichess path needs only the floor — it never writes
the whole file to disk, only the bounded `pgn-shard.bin` growth).

## 7. CLI + decompress dispatch

`corpus fetch --source {ccrl|lichess} --out <dir> --target-positions <N>
[--url <u>] [--lichess-month YYYY-MM]`. Mirrors `cmd_ingest_pgn`: `source`,
`GameFilter::default()`, `base_game_id = max_existing_game_id(out)+1`, the
`on_game` closure (game_admitted → records → `append_block` into
`pgn-shard.bin`), then calls `stream_to_ingest`. URL resolution: explicit
`--url`; else lichess → `lichess_url` from `--lichess-month` (default a pinned
recent month); ccrl → first `CCRL_CATALOG` entry. Without the feature the arm
prints "built without the corpus-fetch feature; rebuild with
`--features corpus-fetch`". Updates `fetch-state.json` on completion.

Decompress dispatch (in `stream_to_ingest`/attempt), **two structurally
distinct pipelines** (per research §4 — temp-file for CCRL):

- **Lichess `.pgn.zst` (streaming, multi-GB → early-terminate).**
  `zstd::stream::read::Decoder::new(resumable)` (`bytes_are_progress=false`,
  games-parsed watchdog, in-RAM Range-resume below the live decoder). Gates 5+6
  pre-flight → `BufReader` → `stream_pgn`. Early-termination via the counter
  (§5C) downloads only ~5–10% of the dump.
- **CCRL `.zip` (download-to-temp, tens of MB).** Stream the raw zip body
  through `ResumableHttpReader` (`bytes_are_progress=true`) into a temp file in
  `out_dir` (gate-7 disk-checked; Range-resumes the temp download on a blip);
  then `zip::ZipArchive::new(File)`, pick the first `*.pgn` entry → its `impl
  Read` → gates 5+6 pre-flight → `BufReader` → `stream_pgn`. The whole (small)
  archive is downloaded — early-termination applies at the *parse* stage (the
  counter stops appends at target), not the download. Temp file unlinked after
  ingest and on error (RAII guard). This sidesteps the streaming-zip mid-entry
  Range-resume footgun research §4 flagged; CCRL's small size makes the
  full-download cost negligible.

## 8. Test strategy + names

Reviewer dimensions: correctness, confirmation-bias resistance, corner cases.
The `ResumableHttpReader<R,F>` generic-over-reconnect design makes the resume
state machine **fully unit-testable without ureq** (inject in-memory `R` +
scripted reconnect `F`). All tests compile under `--features corpus-fetch`.

**Unit — reader.rs** (`fetch::reader::tests`):
- `resume_continues_from_consumed_offset` — inject a transient `inner` error
  mid-stream; assert the reconnect closure is called with the exact `consumed`
  offset and the bytes the caller sees are the unbroken concatenation.
- `target_reached_returns_eof_with_reason_target` — counter ≥ target ⇒ `Ok(0)`
  + `eof_reason == Target`.
- `inner_eof_returns_eof_with_reason_inner` — real `Ok(0)` from `inner` ⇒
  `eof_reason == InnerEof` (the EOS-at-target tie-break).
- `recv_body_timeout_triggers_reconnect_not_failure` — an injected
  `TimedOut`/`WouldBlock`/ureq-`Timeout` from `inner`, while `now − last_game_at
  ≤ stall_timeout`, triggers a Range reconnect and continues (not a hard fail).
- `stall_window_then_noprogress_escalates` — no game for > `stall_timeout`
  reconnects; N consecutive no-game resumes ⇒ `AttemptFailure::Stall` + `Err`.
- `range_ignored_200_sets_failure` — reconnect returns `RangeIgnored` ⇒
  `AttemptFailure::RangeIgnored` + bubble (drives outer byte-0 restart).
- `stop_flag_returns_eof_clean` — `stop` set mid-read ⇒ `Ok(0)` (→ `Stopped`).
- `games_parsed_resets_noprogress_and_bumps_last_game_at` — closure-side bump
  visible to the reader's watchdog; resets the escalation counter.

**Unit — gates.rs**: `classify_http_status_split` (404/403/410 permanent;
408/429/500/503 transient; 200/206 ok); `sniff_is_pgn_prefix_anchored`
(`[Event "X"]` accepted; `<!DOCTYPE html>` rejected; **the adversarial
`<html>…[Event ]…</html>` mid-body-substring case rejected** because the
*first* non-whitespace bytes aren't a PGN tag — asserts the real prefix-anchor
predicate, not a stronger one); `parse_sanity_threshold` (≤10% fail over the
prefix passes, 11% fails, `games_seen==0` fails — the empty/garbage guard);
`preflight_accepts_pgn_prefix_rejects_html_prefix` (the combined gate-5+6 entry
over a buffered prefix); `available_disk_bytes_positive_for_tmp` +
`disk_precheck_rejects_when_below_floor` (floor = `u64::MAX` forces rejection —
no real full disk needed).

**Unit — catalog.rs**: `lichess_url_pattern_golden` (exact
`https://database.lichess.org/standard/lichess_db_standard_rated_2024-01.pgn.zst`,
zero-padded month); `ccrl_catalog_nonempty_https_only`;
`fetch_state_json_roundtrip` (hand-rolled JSON load/save/merge stable;
malformed → empty, never panic).

**Integration — `tests/corpus_fetch.rs`** (`#![cfg(feature = "corpus-fetch")]`,
localhost `std::net::TcpListener` in a thread, **no real network**):
- `fetch_zst_early_termination_bounds_bytes` — serve a hand-built `.pgn.zst`
  (built at test time via the `zstd` encoder) over HTTP/1.1 with `Accept-Ranges:
  bytes` + `Range`/`206`; set `target` to ~10% of the file's positions; assert
  `Termination::EarlyTarget`, `positions_ingested ≈ target`, `pgn-shard.bin`
  scans to valid blocks (`store::scan_valid_blocks`), and **`bytes_received` is
  bounded well below the full file** (e.g. `< 50%` of `Content-Length`) — proves
  early-termination actually limited the download, not merely "stopped
  somewhere." **Decoder-error-forwarding canary for §5(C).**
- `fetch_resumes_after_injected_connection_drop_zst` — server drops once at a
  fixed offset; client reconnects via `Range` (same live decoder); final shard
  multiset equals the no-drop reference.
- `fetch_eos_when_target_exceeds_file` — target huge ⇒ `Termination::Eos`,
  ingest = whole file's admitted positions, `eof_reason == InnerEof`.
- `fetch_eos_at_target_reports_eos_not_early` — target == exactly the file's
  admitted-position count ⇒ `Eos` (the tie-break, so `fetch-state` says
  drained).
- `fetch_permanent_404_returns_err_no_infinite_loop` — server 404s ⇒ `Err`
  quickly (`max_attempts=Some(1)`), not a hang.
- `fetch_rejects_html_body_no_ingest` — server returns a zst-wrapped HTML page;
  gate 5/6 pre-flight rejects ⇒ **zero records appended** (`pgn-shard.bin`
  absent/empty) before the `max_attempts` cap exhausts.
- `fetch_idempotent_byte0_restart_no_duplicate` — force one escalation
  (no-progress restall) so the outer loop restarts from byte 0; assert the
  shard has **no duplicate game blocks** (the pinned-`base_game_id` +
  skip-re-seen-ids no-op).
- `fetch_ccrl_zip_temp_file_parity` — serve a small `.zip` (one `.pgn` entry)
  with Range support; assert ingest parity with the same PGN via `ingest-pgn`,
  and that the temp file is unlinked afterward.
- `fetch_ccrl_zip_resumes_after_drop` — drop the connection mid temp-download;
  the temp-file Range-resume completes; ingest parity with the no-drop case.

Determinism / no-CI-hang: tests bind `127.0.0.1:0` (ephemeral port), join the
server thread on drop, use short `stall_timeout` + a low `backoff_max` + a
**bounded `cfg.max_attempts = Some(k)`** so the permanent/garbage/escalation
paths terminate. No real network. (`bench` unchanged is asserted by the absence
of any `evaluate`/`search` edit — no engine touch.)

## 9. Order of operations + parallelization

Per the workflow, **the entire test suite (§8 unit + integration) is written
and passes test-suite review BEFORE any implementation** (steps 2–5 below are
the *implementation* order, gated on the test-suite-review pass). Step 1 is a
prerequisite for *compiling* tests (the deps must resolve).

1. Cargo.toml feature + deps; `cargo add zip` to pin; deny.toml + .gitignore;
   `cargo build --features corpus-fetch` + `cargo deny check` + `cargo audit`
   (resolve `ring` clarify empirically). **Gate before any code or tests.**
   *(Write all §8 tests next; test-suite review; then implement:)*
2. **[parallel A]** `gates.rs` + `catalog.rs` (pure, independent).
   **[parallel B]** `reader.rs` (`AttemptState` + `ResumableHttpReader` +
   state machine; production ureq opener last).
3. `fetch/mod.rs` (`stream_to_ingest` + the two decompress pipelines + on_game) —
   depends on A+B.
4. `cmd_fetch` + dispatch arm.
5. docs: `data-catalog.md`, ADR-0036, `m6.h.md`, roadmap/architecture/CLAUDE.

**Parallelization map.** Impl step 2 A and B are genuinely independent (shared
types are only `CorpusError`/`Source`, already in `corpus::mod`). Step 3 is
sequential on A+B; step 4 on 3. The test suite is authored up-front (workflow
gate), with the `ResumableHttpReader<R,F>` generic-over-reconnect design making
the reader's state machine fully testable without ureq — so reader tests don't
block on the production ureq opener.

## 10. Dependencies on other units / risks

- Reuses M6.G `stream_pgn`, `filter::game_admitted`, `store::append_block`,
  `max_existing_game_id` **unchanged** ⇒ R1 atomic-block / dedup for free; the
  §1 "verbatim reuse" invariant holds (no `stream_pgn` change — §5C).
- **Risk: `zstd` decoder error on mid-frame early-EOF.** Mitigated by §5(C)
  counter+`EofReason` classification (decoder terminal state is not consulted)
  + the `fetch_zst_early_termination_bounds_bytes` canary.
- **Risk: `zip` version / API drift.** Pin via `cargo add` (step 1); CCRL uses
  the stable `ZipArchive::new(File)` temp-file path (not the streaming reader);
  `fetch_ccrl_zip_temp_file_parity` pins behavior.
- **Risk: ureq 3.x recv-body-timeout body re-drive semantics.** §5(B) treats a
  recv-body timeout as "Range-reconnect" (the safe assumption — research §6
  flagged the re-drive question); empirically confirmed by
  `fetch_resumes_after_injected_connection_drop_zst`. If ureq turns out to
  permit cheap in-place re-reads, that's a future optimization, not a
  correctness dependency.
- **Risk: license/`cargo deny`.** Handled in §2 as a step-1 gate.
- **Risk: supply-chain expansion (~+80–120 transitive crates).**
  Feature-gated (§2) so the engine binary / its audit are unaffected; surfaced
  to the user as a note at landing.
- No SPRT; functional gate per roadmap. Bench unchanged by construction.
