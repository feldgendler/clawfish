# M6.G — Corpus construction (plan)

Binding research: [`docs/research/m6-corpus-construction.md`](../research/m6-corpus-construction.md).
Roadmap: `docs/roadmap.md` §M6 "M6.G scope detail" + operational-robustness R1–R7 + R-TC + Verification.
ADR (allocated at landing): **ADR-0035** — corpus construction; runs the ADR-0003 label-provenance audit.

## 1. Goal & non-goals

**Goal.** A reusable, reproducible, game-result-labeled quiet-position corpus + the held-out
validation set + the stratified selection objective + the selection harness scaffold +
a data-quality gate. Consumed by M6.I, the tuning-backlog "PST co-tuning" Arm B, future
SPSA campaigns, M10 NNUE data-prep.

**Non-goals.**
- No `evaluate` / `Position` / negamax / qsearch **behavior** change → no bench, no SPRT, no Elo claim. Gate = data-quality checks (M5.E correctness-only-gate precedent applied to data).
- No mixture *selection* (bi-level inner-Texel; that is M6.I). M6.G delivers the objective + harness; M6.I runs it.
- No new third-party Rust crate. Decompression of external sources (`.pgn.zst`, `.7z`) is an **operator/script** step (system `zstd`/`7z`), not a Rust dep — dependency-hygiene-clean, R5-aligned (staged pre-crunch).

**Scoping decision (the committed frozen artifact = the *full filtered corpus bytes*).** Lichess monthly = ~20 GB, CCRL ≈ 0.5 GB — git-vendoring *raw* DBs is wrong; but the *filtered* corpus is just FEN+label records (compact). Therefore:
- **The vendored frozen artifact is the full filtered+self-play corpus bytes** (compressed, bounded, `bench/corpus/corpus.<ext>.zst`), **offline-reproducible-as-bytes** — all four downstream consumers (M6.I, PST-co-tuning Arm B, future SPSA, M10 NNUE) freeze on **these committed bytes**, never on a re-download. This is the strong R5 / reproducibility-mandate guarantee.
- The **self-play slice** of those bytes is additionally reproducible from {seed + clawfish binary} with **no network** (deterministic fixed-depth — §3.5).
- The **CCRL/Lichess slice** of those bytes is reproducible from raw sources via `re-run.sh` *given source availability* — the **weaker** "re-derivable" guarantee (CCRL is continuously updated; a pinned Lichess year-month is stable but not perpetually guaranteed downloadable). `re-run.sh` stages raw DBs into git-ignored `target/corpus-raw/` (R5: pre-crunch) and re-emits the identical filtered slice; the manifest pins source URLs + SHA-256 + the year-month + filter params.
- **Committed-artifact size ceiling:** target 1.5–3 M records (research §8.3); ≤ ~150 MB compressed is the documented ceiling (`--target-positions` knob). If an external-source acquisition is infeasible within the landing budget, the artifact is self-play-dominant **with the gap recorded as a coverage stat in the data-quality gate** (an honest recorded shortfall, not a hidden descope — the parser+filter+`re-run.sh` infra is complete and the manifest pins how to extend it).
- **Zurichess `quiet-labeled.epd`: REJECTED** by the ADR-0003 audit — research §3 found its `c9` labels are Stockfish-080916 *played-game results*, not original outcomes. The audit *passing* = it correctly produces this documented rejection. Corpus = CCRL + Lichess + clawfish self-play, all original game-result labels.

### 3.2 `pgn.rs`

```rust
pub struct PgnTags { result: Option<Label>, termination: Option<String>,
                     white_elo: Option<u32>, black_elo: Option<u32>,
                     time_control: Option<String> }
pub struct PgnGame { tags: PgnTags, game_id: u64 }
// Streaming: yields (Position, ply, &PgnTags) per game; one game at a time (R6).
pub fn stream_pgn<R: BufRead>(r: R, base_game_id: u64,
    on_game: &mut dyn FnMut(GamePositions), stats: &mut PgnStats) -> Result<u64, CorpusError>;
fn parse_san(token: &str, pos: &Position, legal: &MoveList) -> Result<Move, CorpusError>;
```
- **Disambiguation resolves against the LEGAL move set.** `generate_moves` is legal-direct (M1.F — `docs/decisions/0007-legal-direct-movegen.md`), so `parse_san` matches the SAN target/piece/disambiguator against `generate_moves(pos)` directly. This makes the **pinned-piece case** correct: standard SAN omits the disambiguator when only one move is *legal* even if two pieces pseudo-legally reach the square — matching legal moves resolves it; a pseudo-legal match would mis-parse and silently mislabel.
- **Parse failure ⇒ the WHOLE game is dropped, counted in `PgnStats.parse_failures`** (surfaced in `corpus_stats.txt` + the quality gate). A SAN token that resolves to ≠1 legal move (ambiguous or illegal) **must not** "skip the move and continue" — that desynchronizes the position stream and mislabels every later position (the Texel-poisoning the roadmap warns of). `on_game` is called only for a game parsed end-to-end with a `Result`/non-`*`; otherwise the game contributes **zero** records.
- SAN coverage: piece/pawn moves, file/rank/both disambiguation, `O-O`/`O-O-O`, `=Q/R/B/N`, `x`, e.p., `+`/`#`/`?!` suffixes stripped; comments `{…}` (incl. nested), NAGs `$n`, RAV `(…)` recursively skipped, `*`/no-`Result` ⇒ game dropped (not mislabeled). Streaming, one game buffered = R6.

### 3.5 `selfplay.rs` (R1–R7, R-TC)

```rust
pub struct SelfPlayConfig { seed: u64, games: u64, workers: usize,
    depth_ladder: Vec<(u8,u32)>, opening_random_plies: u32, max_plies: u32,
    out_dir: PathBuf, val_fraction: f64 }
pub fn run(cfg: &SelfPlayConfig, stop: &AtomicBool) -> Result<SelfPlayStats, CorpusError>;
fn play_one_game(seed: u64, game_id: u64, depth: u8, rng: &mut Prng) -> GameRecord; // pure-ish, deterministic
fn game_result(pos: &Position, hist: &[u64]) -> Option<Label>; // mate/stalemate/3fold/50mv/insufficient/max-plies
```
- **Determinism (R3/R4) — stated precondition, not asserted.** A `Search::go(SearchLimits{ depth: Some(d), nodes: None, movetime: None, infinite: false, .. })` with `SearchClock` caps = MAX (the §`src/bench.rs` in-process pattern) makes `clock.should_abort(&ctx.stop, ctx.limits.nodes, self.nodes)` (negamax/qsearch, every 4096 nodes) **only** reachable via `ctx.stop`. The recorded game **never** uses a `stop`-interrupted search's output (a SIGTERM/SIGINT-aborted in-flight game is *dropped*, R2). ⇒ each completed game's move sequence is a pure deterministic function of `(start_pos, depth)` — load-, suspend-, renice-independent ⇒ R3 resumed run bit-identical modulo the one dropped in-flight game; **no `VirtualClock`, no suspend-discard surface**.
- **R4-literal deviation — reasoned exception (ADR-0035 records the full argument, not "moot").** R4 literally says "mandate `VirtualClock` for M6.G self-play." VirtualClock exists to make *wall-clock* play load-independent. Fixed-depth gen is load-independent **without** a clock at all, so VirtualClock is *unnecessary here*, not merely moot. ADR-0021 §4 rejects node/implementation-coupled TC because it "shifts what N nodes means … across runtime settings / versions" — that objection is scoped to **cross-version SPRT comparability**; M6.G is **one frozen build**, so §4's reasoning does not bite, and roadmap R-TC **explicitly carves out** "fixed-shallow-depth stratified across their effective depths … (ADR-0021 §4's node-TC rejection is scoped to cross-version SPRT comparability and does NOT forbid fixed-depth/fixed-nodes for corpus generation — one fixed build, not a version comparison)." VirtualClock still binds the **M6.I SPRT** (M6.I's concern, not M6.G's).
- **R-TC depth ladder — empirically anchored, not guessed (closes the descope).** A one-shot `corpus calibrate-ladder` step runs `Search::go` at each deployment movetime budget `{10+0.1,20+0.2,40+0.4,60+0.6}` (the canonical mixed-TC SPRT buckets) over the 16-FEN `bench::BENCH_POSITIONS` corpus on the dev machine and records the **median completed iterative-deepening depth** per bucket. The ladder rungs are *set from those measured medians* (not literals in the plan) and written to `filter_spec.txt` + `manifest.json` with the calibration table. Per-game rung sampled via seeded `Prng` cumulative draw with the **deployment-profile weights** (R-TC: "prior-pinned to the deployment mixed-TC SPRT profile"); `CorpusRecord.depth_rung` records it. The held-out objective (§3.8) is then stratified by this *measured-effective-depth* rung ⇒ the R-TC precondition ("the held-out objective must itself be TC-stratified to the deployment profile") is **genuinely met**. **Residual caveat owned in ADR-0035:** depth is a *proxy* for TC; the rung↔bucket correspondence is the measured median (with run-to-run depth variance ±1 ply at fast buckets) — a validated proxy, not an exact identity. The calibration is re-runnable (recorded methodology + seed). **Cross-machine:** the *vendored* corpus freezes the dev-machine-calibrated ladder (in `manifest.json`); the reproducibility gate verifies against **that frozen ladder** (the committed bytes), not a re-calibration — a re-run on a slower machine recalibrates to its own medians (methodology fixed, rung values machine-local) and is a *separate* corpus, not a gate failure on the frozen one.
- **Openings:** play `opening_random_plies` (default 8) seeded-random legal moves from startpos (research §5.2 Integral/Minic random-ply); reject seeds reaching early game-over; opening-skip still drops first `OPENING_SKIP_PLIES`.
- **Two-pass design (decouples `selfplay` from `quiet`).** `selfplay.rs` emits **every** post-opening-skip position with the game label + `depth_rung`, transactionally per game — it does **not** apply the quiet predicate (so `selfplay.rs`/`store.rs` do **not** import `quiet.rs`; the §7 map edge is genuinely absent). Quiet-filtering + `|eval|` cutoff + dedup + cap + split run in the separate `corpus build` pass over the union of self-play + ingested-PGN records. (Cheap to defer: qsearch is run once per surviving position in `build`, on a per-worker-reused searcher per §3.6.)
- **R7 striping:** game `i` → worker `i % workers`, worker stream seed = `splitmix(base_seed, i)` so the union is **scheduler-independent deterministic**. Workers → bounded channel → single writer thread (no priority inversion; no spinlock). `stop` (SIGTERM/SIGINT) = stop dispatch, drain or drop in-flight, flush checkpoint, exit. SIGKILL/power-loss safe via R1 alone.
- **R5/R6 bounded resources.** R5: self-play has zero network; `ingest-pgn`/`build` read only pre-staged local files; `re-run.sh` does all network (staging) as a separate pre-crunch step. R6: PGN ingestion streams one game at a time; self-play buffers one game at a time; `dedup_fen` is external sort-merge with a **documented dual ceiling** — RAM `--max-mem-mb` (default 512) *and* a disk spill ceiling `--max-spill-gb` (default 8) for spill runs under **`target/corpus-spill/`** (git-ignored, *not* `bench/`), cleaned on success, surfaced in `corpus_stats.txt`. Peak RAM and peak spill are bounded and do not scale with corpus size; both ceilings + knobs documented in `--help` and ADR-0035.
- **R1/R2 transactional emit — per-game atomic block (the correctness gate, specified to verifiable level).** A game's positions buffer in RAM; on a **natural terminal result** the writer appends the whole game as **one length-and-CRC-framed block** (§3.6 frame: `MAGIC | game_id:u64 | rec_count:u32 | payload_len:u32 | payload | crc32(header‖payload):u32`) followed by `fsync`. Resume (§3.6) scans the shard and accepts **only** blocks whose magic+lengths+CRC fully validate; a torn final block (partial write / missing-or-bad CRC from a SIGKILL mid-append, even *after* a prior game's fsync) is discarded **as a whole game**, never line-by-line. Crash mid-game (before the game's own block `fsync`) ⇒ buffer lost or torn-block-rejected ⇒ **zero partial-game labels**. Ordering: game-block `fsync` **then** checkpoint `fsync`+rename ⇒ a crash between them re-emits one already-durable game whose block is valid; resume skips any `game_id` already present (idempotent — never partial, never double).

### 3.6 `store.rs` + the qsearch interface

- **Shard = append-only game-block log** (binary). Block frame (per §3.5): `MAGIC:u32 | game_id:u64 | rec_count:u32 | payload_len:u32 | payload | crc32:u32`. `payload` = `rec_count` records, each `fen_len:u16 | fen | label:u8 | source:u8 | ply:u32 | depth_rung:u8`. Append = single `write` of the whole block + `fsync` (R1). **No `.tmp`/rename for the append-log** (append is the atomic unit; the CRC frame makes a torn tail self-detecting); `.tmp`→`fsync`→rename is used for the **checkpoint** and **manifest** (whole-file replace) only.
- `scan_valid_blocks(path) -> (Vec<Block>, valid_byte_len)`: walk frames; stop at the first frame that fails magic/length/CRC; truncate the shard to `valid_byte_len` on resume (drops a torn final block wholesale). A human-greppable `corpus export` subcommand converts the binary log → `fen\tlabel\tsource\tgame_id\tply\tdepth_rung` TSV for inspection (not the on-disk format — keeps the crash-safe frame).
- `Checkpoint{ games_completed: u64, prng_state: u64, ladder_cursor, per_worker_next_game_id }` written `.tmp`→`fsync`→rename→`fsync(dir)`, **after** the game block's `fsync` (the §3.5 ordering).
- **qsearch_score interface (decision, pinned in Slice 0).** Add `pub fn quiescence_eval_white(pos: &Position) -> i32` to `src/search.rs`: calls the **existing** `qsearch` with a full window `(−INF, +INF)` at ply 0 on a **caller-supplied reusable** `&mut AlphaBetaMover` + throwaway `SearchContext` (one per worker, **not per position** — R6/R7: avoids per-position searcher/TT/pawn-hash allocation across millions of positions; the public signature wraps a `quiescence_eval_white_with(&mut searcher, &mut ctx, pos)` worker-reused inner). Introduces **no new search/eval logic**, touches **no existing code path** ⇒ `evaluate`/negamax/qsearch/**bench signature byte-identical** (bench drives `handle_bench`→`Search::go`, never this fn) ⇒ the roadmap "no engine build / no bench" clause (which targets *strength/bench-affecting* change) is honored. The `depth: Some(0)` route (negamax `depth==0` delegates to qsearch, `src/search.rs:1480`) is **not a lighter fallback** — it needs the same full `SearchContext` — so it is used **only** as the oracle in the equivalence test `quiescence_eval_white_eq_depth0_path` (pins the two to the same qsearch value). The added `pub fn` widens `search.rs`'s public surface deliberately as a data-infra seam; documented as such (not `#[doc(hidden)]` — M6.I/Arm-B/SPSA all consume it).

### 3.8 `dedup.rs`, `split.rs`, `objective.rs`, `manifest.rs`, `quality_gate.rs`

**Pinned pipeline order (correctness- and reproducibility-load-bearing): `dedup_fen` → `per_game_cap` → `split_by_game`** (research §2.5/§7.2: "FEN dedup before the cap"; split last so it sees the final record set).

```rust
// dedup — deterministic survivor rule, independent of shard/merge order
pub fn dedup_fen(stream, spill_dir, max_mem_mb) -> impl Iterator;
//   external sort-merge keyed on FEN; among duplicates keep the record with the
//   lexicographically-smallest (source, game_id, ply) → a deterministic function
//   of the input *multiset* (NOT of worker striping / ingestion order) ⇒ the
//   reproducibility_rerun_byte_identical gate genuinely verifies it.
pub fn per_game_cap(records, cap: usize, seed: u64) -> Vec<CorpusRecord>; // seeded reservoir, ≤ cap/game
// split — game-level (research §6.3); dedup-removal can't make a game straddle
//   splits because the split key is game_id, not position
pub fn split_by_game(records, val_fraction, seed) -> (Train, Val);
pub fn split_integrity(&Train, &Val) -> SplitReport; // game-disjoint (HARD must-PASS) + post-split FEN-leakage ratio (reported, ≤ τ; research §6.2: opening-transposition leakage is unavoidable, bounded not zero)
// objective (research §1.2/§6.4; mixture *selection* is M6.I)
pub fn fit_k(recs, score: impl Fn(&CorpusRecord)->i32) -> f64;  // 1-D MSE-min over K
pub fn logistic_loss(recs, k, score) -> f64;                    // σ(K·s) clamped, finite (no exp overflow)
pub fn stratified_objective(val, k, score) -> StratObjective;   // aggregate + per depth-rung + outpost/endgame strata
// manifest / gate
pub fn write_manifest(&Manifest, dir); pub fn sha256_file(path) -> String;
pub fn run_quality_gate(dir) -> QualityReport;   // §6, 3 must-PASS
```

**The Texel score the objective consumes (resolves research §2.5 open question — this IS the M6.G↔M6.I interface).** Records are **quiet-certified** (§3.4: `static_eval == qsearch` within `QUIET_MARGIN_CP`). The pinned interface contract is: **M6.I scores a quiet-certified position by `static_eval_white` (= `evaluate`) directly** — qsearch is *not* re-run at tune time. Rationale: the quiet certificate makes `static_eval ≈ qsearch` by construction (±30 cp), so static-eval is the cheap, correct tuning score (research §2.5: "If M6.I uses static_eval directly … Predicate B is mandatory" — we pinned Predicate B precisely so this holds). `fit_k`/`logistic_loss` take a `score: Fn(&CorpusRecord)->i32` closure; the **default and pinned** closure is `|r| static_eval_white(&Position::from_fen(&r.fen))`. Stated here so `objective.rs` is *semantically* pinned in Slice 0 (compile-time independence via the closure stays; the contract does not float).

**Blind-spot strata — the faithful M6.G-context analogue of the M6.A STS sub-gate, argued (not dismissed).** The M6.A per-theme STS sub-gate scores the engine's *move-choice* accuracy on the curated STS theme suite — that is a **move-choice test, not a labeled-result corpus**, so it *cannot* be a logistic-loss stratum directly. The faithful corpus-context analogue of "reuse the M6.A per-theme STS sub-gate discipline" is: a held-out **logistic-loss stratum over positions exhibiting the blind-spot feature** — it answers "does the eval's score track game result on outpost-bearing / endgame positions," the corpus analogue of "does the engine play these themes well." Strata: `STRATUM_OUTPOST` (STS theme #3 — roadmap-named), `STRATUM_ENDGAME` (roadmap-named), plus depth-rung (R-TC). **Frozen-snapshot, not live-call (closes the circularity):** `STRATUM_OUTPOST` membership is computed **once at corpus-build time** from a *frozen copy* of the outpost predicate (the `eval::tier1::outpost_squares` logic snapshotted into `corpus::objective`, its spec echoed in `filter_spec.txt`) and stored as a bit in `CorpusRecord` — **never a live call** to the M6.F seam (which M6.I is about to re-tune; a live call would let the stratum definition drift under M6.I). `STRATUM_ENDGAME` = phase-tag below the mop-up threshold (a structural constant, not a tuned weight). Full 15-theme STS classification is out of scope; the two roadmap-named strata + depth-rung are in.

## 4. Test coverage strategy

Function-level TDD (project's broad-TDD norm) + proptest where the invariant is compact.

- **pgn**: `san_parse_<piecemove|capture|file_disambig|rank_disambig|both_disambig|castle_short|castle_long|promo|promo_capture|ep|check_mate_suffix_stripped>`; `san_disambig_resolves_against_legal_not_pseudolegal` (pinned-piece fixture: two pieces pseudo-legally reach the square, one is pinned, SAN omits the disambiguator — must pick the legal one); `result_tag_maps_label`; `no_result_or_star_game_dropped_not_mislabeled`; `parse_failure_drops_whole_game_and_counts_stat` (a bad SAN token mid-game ⇒ zero records from that game ∧ `PgnStats.parse_failures += 1`); `comments_nags_rav_ignored`; `truncated_game_errors_clean`; **golden full-game final-FEN** `replay_known_ccrl_game_reaches_expected_fen` + `replay_known_lichess_game_reaches_expected_fen` (asserts the *correctness* of disambiguation, not just internal consistency); **proptest** `parsed_move_is_in_legal_set` (internal-consistency complement, not a substitute for the golden-FEN test).

## 7. Parallelization map
