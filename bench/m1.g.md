# M1.G benchmark baseline

Captured **2026-04-27** on **Apple M4 / macOS 26.4.1**, **Rust 1.95.0**, **criterion 0.7**.

Per ADR-0010, this is the committed regression-tracking artifact. Raw criterion data is gitignored under `target/criterion/`. Cross-machine comparisons read this table; same-machine cross-commit comparisons use `cargo bench -- --baseline m1.g`.

## perft throughput (`benches/perft.rs`)

| Bench | Position | Depth | Path | Median ns/iter | Throughput | Leaves |
|---|---|---|---|---|---|---|
| `perft_starting_d4_plain/plain` | starting | 4 | `perft` (plain) | 5.97 ms | **33.1 Mnps** | 197,281 |
| `perft_starting_d4_bulk/bulk` | starting | 4 | `perft_bulk` | 1.66 ms | **118.7 Mnps** | 197,281 |
| `perft_kiwipete_d3/bulk` | Kiwipete | 3 | `perft_bulk` | 581 µs | **168.3 Mnps** | 97,862 |

**Bulk-counting speedup over plain at the same depth/position:** ~3.6× (5.97 ms → 1.66 ms). Larger than the ~20–30% community estimate because the leaf-skip avoids both make/unmake AND another `generate_moves` call per leaf — at depth 4 from start, leaves dominate (8,902 + 197,281 ≈ 206k inner-or-leaf nodes; ~95% are leaves).

**M1 exit criterion** (`docs/roadmap.md` §M1: ≥100 Mnps single-threaded perft on Apple Silicon, ≥200 excellent): **met on the bulk path** (119 Mnps starting D4, 168 Mnps Kiwipete D3). Plain path at 33 Mnps lags by ~3× — this matches the bulk-path's ~3.6× speedup over plain at the same depth/position, so plain is implementation-correct, just lacks the leaf-skip optimization. Bulk is the conventional headline per CPW; plain is a candidate for a future M1.H optimization unit if a use case for plain throughput emerges (per the M1.G plan §"What if numbers miss the target").

## generate_moves throughput (`benches/movegen.rs`)

Six benches, one per canonical-6 starting position. Measured by reusing a single stack-allocated `MoveList` across iterations.

| Position | Median ns/call |
|---|---|
| `generate_moves/starting`  | 168.6 |
| `generate_moves/kiwipete`  | 276.9 |
| `generate_moves/position_3` | 80.9 |
| `generate_moves/position_4` | 95.4 |
| `generate_moves/position_5` | 237.6 |
| `generate_moves/position_6` | 234.8 |

Range 81–277 ns/call across the canonical 6, centered around ~200 ns/call. Replaces (and supersedes) the M1.F-era `bench_generate_moves_throughput` smoke test, which is deleted in M1.G.

## Most-aggressive validation gate (informational)

`cargo test --release -- --ignored canonical_six_d6_slow` ran in **117.93 s** (~2 minutes). All six canonical positions validated against Stockfish-generated D6 fixture totals (~22B leaves combined → ~187 Mnps end-to-end).

## Notes

- Hardware: Apple M4 P-core scheduling. No background load attempted to be controlled — criterion's outlier detection caught minor cache-line wobble (1 high-severe outlier on `perft_starting_d4_bulk/bulk`, 10 low-mild outliers on `generate_moves/kiwipete`, 14 high-mild on `generate_moves/position_5`); none of these shifted the median by more than a few percent.
- `criterion 0.7` ran with the `html_reports` feature enabled but `gnuplot` not installed, so it fell back to the `plotters` backend (informational warning, not a defect).
- `[profile.release] panic = "abort"` did not interfere with criterion's measurement-thread accounting; no `[profile.bench] panic = "unwind"` override needed (per plan §6 contingent path).
