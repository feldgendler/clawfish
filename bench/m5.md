# M5 — Search advanced

Per ADR-0010 milestone-summary format. Per-phase entries; final summary lands when M5 closes (M5.H end).

## M5.A (2026-05-01) — Null-move pruning

First M5 sub-phase. Adds a null-move sub-search to the negamax prologue: at non-PV interior nodes that pass a seven-condition gate, search a "passed turn" position to reduced depth (`R = 2 + depth/6`); on `null_score >= beta`, return a fail-high without entering the move loop.

Slots into the negamax prologue **after** the TT probe + cutoff check (ADR-0018 §13's pinned ordering) and **before** move generation. The first static-eval consumer in `negamax`; M5.B/RFP will share the read.

ADR-0023 codifies the formula (`R = 2 + depth/6`), gate set (seven conditions including `ply > 0` as defense-in-depth against future PVS refactor), zugzwang policy (`has_non_pawn_material ≥ 1`), mate-cap on cutoff, TT-store discipline (Lower bound at current depth with `best_move=0`, score = mate-capped value), and the deferred surface (verification search; eval-aware R bonus; threat extraction; bundling with M5.B/RFP — explicit "keep separate" decision).

### Bench signature

| Phase | Bench signature | Node count vs M4.D |
|---|---|---|
| M4.D end | `bench: 15863206 nodes <NPS> nps` | baseline |
| M5.A end | `bench: 5345534 nodes 11136529 nps` | **−66.3%** (10.5M fewer nodes from NMP cuts) |

NPS varies wallclock-to-wallclock and is excluded from the regression signature. The 66.3% node reduction is at the high end of the literature's 30–50% range; clawfish's M4.A→D ordering (TT-move-first + killers + history + aspiration) is the upper-end conditioning factor — NMP is most effective when first-move ordering quality is high.

**Fixed-depth bench vs fixed-time SPRT.** Bench is fixed-depth (`go depth 7`); the 66% node-count delta applies directly. SPRT is fixed-time (`tc=10+0.1`, etc.); under fixed-time NMP's node-reduction is partially recovered as +1–2 plies of additional depth at the same wallclock, so the SPRT Elo delta is NOT proportional to the bench-node delta. The two metrics measure different things; don't expect the bench-percentage to match the SPRT-Elo when comparing.

### Qualitative behavior shift from M4.D

| Feature | M4.D (TT + killers + history + aspiration) | M5.A (+ NMP) |
|---|---|---|
| Negamax prologue | rep/50-move → MDP → TT-probe → movegen → ordering → recurse → store | + NMP block between TT-probe and movegen (gates → null-search → mate-cap → TT-store-on-cutoff) |
| Static-eval read in negamax | not consumed | consumed inside the NMP block (lazy; only after cheap gates pass + `has_non_pawn_material`) |
| Per-node overhead at non-PV interior nodes | TT-probe + ordering + recurse | + ~6 ns gate evaluation; on gate-pass, one zero-window null sub-search at `(depth - 1 - R)` |
| `negamax` signature | 9 args | 10 args (`allow_null: bool` added after `is_pv`) |
| `negamax` recursive call sites | 1 (move loop) | 2 (move loop + NMP null-search) |
| Stacked-null prevention | n/a | `allow_null = false` in NMP null-search; all other recursive calls pass `true` |
| TT-store on NMP cutoff | n/a | `Bound::Lower` at current depth with `best_move = 0` and mate-capped score; ADR-0018 §7 preserves any prior best_move for the key |
| Mate-cap | n/a | `null_score >= MATE_IN_MAX_PLY` → return `beta` (not `null_score`) — NMP doesn't prove mate |
| `make_null_move` / `unmake_null_move` | n/a | new in `src/mov.rs`; flips STM, clears EP, increments halfmove, conditionally increments fullmove (Black-was-to-move), Zobrist XOR turn key + EP file key (when Polyglot-active); `NullUndo` is 16-ish bytes (excluding padding); `prior_fullmove` derived from post-make STM (mirrors `unmake_move`'s pattern at `mov.rs:803`) |
| Test instrumentation | `info string aspiration_re_search` | + `#[cfg(test)] nmp_firings: u32` counter on `AlphaBetaMover` for the stacked-null direct-kill test |

### Plumbing / process highlights

- **Three plan-review passes converged**: pass 1 raised 3 must-fix + 7 should-fix (`ply > 0` gate added as defense-in-depth against future PVS refactor; `cutoff_score` vs raw `null_score` for TT store; depth-field rationale; `NullUndo` byte-count claim dropped; lazy static-eval read; `negamax_for_test` migration enumerated; sister-fixture pattern for §5.3 tests; proptest required not optional; Slice C dependency explicit; bench fixed-depth vs SPRT fixed-time clarification; ADR-0023 scope tightened to ~30–50 lines per ADR-0018/0019/0022 pattern). Pass 2 raised 9 should-fixes (test-description precision; sister-fixture mechanics for in-check / PV-node / stacked-null tests; mate-cap test sanity step; `nmp_firings` `#[cfg(test)]` counter for direct stacked-null kill). Pass 3 returned 4 nits (cosmetic staleness in opener and cross-references); applied inline. Final verdict: `no further substantive issues`.
- **Verified via existing code before writing**: `Undo` does NOT carry `prior_fullmove` — `unmake_move` derives it from `us` at `mov.rs:803`; `NullUndo` follows the same pattern (drop `prior_fullmove`, derive from post-make STM). `arb_position` proptest strategy already exists at `src/movegen.rs:126`; lifted to `pub(crate) mod test_strategies` rather than duplicated for the null-move round-trip property test.
- **Coder slicing per plan §8** worked cleanly: Slice A (Sonnet) shipped `src/mov.rs` NullUndo + make/unmake + `src/position.rs` delegators + `src/movegen.rs` `arb_position` lift + 13 tests; Slice B (Sonnet) shipped `src/search.rs` constants + `null_move_reduction` + `has_non_pawn_material` + 10 tests; Slice C (Opus, flagged for novel `allow_null` invariant + 34-call-site `negamax_for_test` migration + first prologue static-eval consumer + `nmp_firings` test instrumentation) shipped the negamax body change + 13 NMP-behavior tests + E48 bench-determinism integration test.
- **Two test-fixture course-corrections during impl**:
  1. Slice A's initial `EP_AFTER_E4` FEN had no adjacent black pawn capturer; the FEN parser's phantom-EP sanitization (ADR-0015) stripped the EP target → `null_move_clears_ep_target` precondition failed. Fixed by switching to a fixture with a black pawn on d4 or f4 (pseudo-legally adjacent to e4 EP) — consistent with the existing `double_push_with_capturer` test-fixture pattern.
  2. Slice C's mate-cap test seeded TT with `Bound::Lower` and a positive mate score; the sign-direction analysis in plan §3.3 (null_score is parent-perspective; child returns child-perspective score; for parent's `null_score >= MATE_IN_MAX_PLY` the child must return `<= -MATE_IN_MAX_PLY`) shows it should be `Bound::Upper` with a negative mate score. Slice C's stacked-null test pinned `K=0` initially; the empirical NMP firing count for the chosen fixture (8-ply on a kingside-symmetric Italian) is 34. Both course-corrected to passing tests.
- **Bench result better than predicted**: 66.3% node reduction vs the plan's 30–50% prediction. Conditioning factor: M4 ordering quality is at the upper end of what the literature samples; with TT-move-first + killers + history + aspiration all active, NMP's first-move ordering is high enough that the null-search's success rate drives the upper-end of the gain.
- **No existing-test re-pins required**. M4.D's 901 lib + 11 uci-integration tests all pass under M5.A without modification. No `bestmove`-asserting tests changed; no `nodes`-asserting tests broke. The new bench signature is the only impl-driven number-pin update.
