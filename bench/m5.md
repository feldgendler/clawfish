## M5.A (2026-05-01) — Null-move pruning

First M5 sub-phase. Adds a null-move sub-search to the negamax prologue: at non-PV interior nodes that pass a seven-condition gate, search a "passed turn" position to reduced depth (`R = 2 + depth/6`); on `null_score >= beta`, return a fail-high without entering the move loop.

Slots into the negamax prologue **after** the TT probe + cutoff check (ADR-0018 §13's pinned ordering) and **before** move generation. The first static-eval consumer in `negamax`; M5.B/RFP will share the read.

ADR-0023 codifies the formula (`R = 2 + depth/6`), gate set (seven conditions including `ply > 0` as defense-in-depth against future PVS refactor), zugzwang policy (`has_non_pawn_material ≥ 1`), mate-cap on cutoff, TT-store discipline (Lower bound at current depth with `best_move=0`, score = mate-capped value), and the deferred surface (verification search; eval-aware R bonus; threat extraction; bundling with M5.B/RFP — explicit "keep separate" decision).

**Fixed-depth bench vs fixed-time SPRT.** Bench is fixed-depth (`go depth 7`); the 66% node-count delta applies directly. SPRT is fixed-time (`tc=10+0.1`, etc.); under fixed-time NMP's node-reduction is partially recovered as +1–2 plies of additional depth at the same wallclock, so the SPRT Elo delta is NOT proportional to the bench-node delta. The two metrics measure different things; don't expect the bench-percentage to match the SPRT-Elo when comparing.

## M5.B (2026-05-02) — Reverse futility pruning

Second M5 sub-phase. Adds a purely static β-cutoff to the negamax prologue at new step 8 (between TT probe at step 7 and NMP at step 9): at non-PV shallow non-check non-mate-beta interior nodes when `static_eval − margin·depth ≥ β`, return `static_eval − margin` immediately without generating a single move.

No null move. No sub-search. No TT store. Cheaper than NMP by construction; ordered before NMP so an RFP cutoff skips NMP's null-search on the `d=3..6` depth overlap. ADR-0024 codifies the gate set, margin formula (`100 * depth` cp), return value (`static_eval - margin`), TT-store policy (none), lazy-dup design (own `static_eval` read inside own gate, not shared with NMP), and RFP-before-NMP ordering rationale.

- RFP fires extensively at depths 1–2 (the leaf/near-leaf population that dominates default-depth-7 bench), well within the 25%-upper-bound estimate before applying the 1.5× M4-ordering conditioning factor. The observed magnitude is consistent with literature priors.

## M5.D (2026-05-06) — Frontier futility pruning

Fourth M5 sub-phase. Adds **frontier futility pruning (FFP)** as a per-quiet-move skip inside the negamax move loop at shallow depth (`depth ≤ FFP_MAX_DEPTH = 2`): before recursing into a quiet move, if `static_eval + margin(depth) ≤ alpha`, skip it. The pruned move's proved fail-soft upper bound `static_eval + margin` is contributed to the node's running `best`, routed through `best_is_full_depth_after_score` with `move_is_full_depth = false` to suppress an inflated TT-Upper store from coarse static-comparison evidence (ADR-0026 §7 — load-bearing TT-store correctness commitment). Layered next to M5.C's reduce/skip decision in the per-quiet branch; FFP fires before LMR. At v1 constants (FFP_MAX_DEPTH = 2 < LMR_MIN_DEPTH = 3), FFP and LMR have non-overlapping depth ranges — pinned by a compile-time `const _: () = assert!(FFP_MAX_DEPTH < LMR_MIN_DEPTH)` invariant.

### v1 → v2 thin-wrapper retune

The v1 implementation (per-stage state machine + per-stage Vecs + per-stage sorts) was bench-equivalent at depth 7 but introduced ~3× per-node allocation pressure invisible to bench. Defensive 100-game SPRT vs `baseline/m5g-singular` (seed `_00E`) returned **Δ Elo −110.48 [−207.37, −28.06]** at 26 games (verdict=H0); 300-game continuation tracked the regression to **~−44 Elo at 222 games** (W=46 L=74 D=102, sigma 8.65). Manual `go depth 14` from startpos: HEAD/baseline byte-equivalent on the 14201938-node tree but HEAD 6426ms vs baseline 6206ms — a 3.5% per-node overhead. Sustained-load test (20-sequential-`go-depth-10`) showed HEAD 5–9% slower across 3 runs.

v2 fix: collapse the stage state machine into a single `Vec<Move>` sorted once by `negamax_move_order_score` with TT promotion to index 0 — literally M5.G's `order_moves` algorithm wrapped in the M5.H1 `MoveStager` API. Public API preserved verbatim. v2 verification: bench parity exact (`1147614 nodes`); sustained-load test post-v2 shows HEAD avg ratio 0.974 vs baseline (slightly faster); 1481/1481 tests pass; defensive 200-game SPRT confirmation match (seed `_010`) pending. ADR-0030 §10 documents the retune in detail.

### Implementation highlights

- **Plan-review took 2 passes to converge.** Pass 1 had 6 must-fix items (most-load-bearing: undefined order-of-operations on the `searchmoves` filter; missing per-case bench-equivalence proof in §4.1; missing ADR-0030 outline). Pass 2 had 3 should-fix bracketing-tightness items + 4 nits, all "acceptable as-is."
- **Test-suite review took 3 passes to converge.** Pass 1 found 5 must-fix vacuous-pass items (H1-S5/S13/S15b/c/I5/I4-I4b each passed against the empty-stub for the wrong reason). Pass 2 caught a kingless FEN at H1-S5b (would have panicked at runtime). Pass 3 verdict `no further substantive issues`.
- **Final review converged at pass 1** with verdict `no further substantive issues` and 3 explicitly-acceptable nits.
- **Bench parity confirmed at the v1 implementation's first test run** — no drift-investigation needed for v1; the per-case proof was sufficient for the v1 implementation agent to produce byte-equivalent output on the first try. The v2 retune preserved bench parity by construction.
- **Implementation deviation from plan §5**: a third `i == 0` site at the `#[cfg(test)] se_tt_move_search_depth` recorder (`src/search.rs:~1975`) was not enumerated in plan §5's "exactly two sites" claim (which referred to production code). The agent caught and updated it correctly.

### Notable behavior shifts

- **Bench, E51 pin, and PV all unchanged.** First M5 sub-phase that's empirically zero-Elo by construction. The architectural value lands now; the Elo signal lands at H2.
- **`order_moves` demoted to `#[cfg(test)]`** preserves all 14+ existing test call sites (S20-S26/HS9/HS12) without churn. `negamax_move_order_score` stays as the score-tier discipline pin (`KILLER0_SCORE > KILLER1_SCORE > MAX_HISTORY` compile-time invariant).
- **`MoveStager` does NOT impl `Iterator`** — explicit decision per plan §3.1. Type-level block on `ExactSizeIterator::len()` decrement intuition; preserves the `len()` temporal contract (pre-iteration count, no decrement; pinned by H1-S17).
- **Position-counter pattern** (`let cur_i = i; i += 1; if Some(mv) == excluded_move { continue; }`) preserves M5.G's `enumerate()`+`continue` semantics byte-for-byte; H1-I3/I4 pin the SE-frame `cur_i==0` invariant; H1-B1 (bench parity) is the strongest fail-fast for any subtle position-counter divergence.
