# SPRT — Hash 128 MiB vs 64 MiB self-SPRT (M5.K binary)

**Campaign:** side-backlog micro-check 2026-06-13 (the optional M5.F item-8 Hash-interaction probe, "available on request").
**Binary:** one clean `M5.K` binary on both sides (bench d7 `1326598`); the only difference is the UCI `Hash` option.
**Candidate:** `--engine-option Hash=128`. **Baseline:** `--opponent-option Hash=64`.
**Harness:** mixed-TC `10+0.1:1,20+0.2:1,40+0.4:1,60+0.6:1` + `--virtual-clock`, conc 6, elo1=10, 400-game cap. Seed `…F0128`.

## Result — single-seed positive, NOT actioned

```
sprt: verdict=continue llr=1.32 pairs=200 ptnml=[14,37,74,53,22]
ci:   elo=+27.85 [+2.04, +53.98] pairs=200    (W133-L100-D166 ≈ 54.1%)
```

**Δ Elo +27.85 [+2.04, +53.98]** — Hash=128 modestly beats Hash=64 at these mixed TCs. CI-lower (+2.04) is barely above 0 on a single seed.

Mildly depth-amplifying (the gain concentrates at the slower TCs where more search → more TT pressure → a bigger table helps), which is the mechanistically-expected shape.

## Disposition — documented signal, not a config change

This confirms 128 > 64 *as a self-SPRT*, but it does **not** by itself motivate changing the engine's default `Hash`, which is **16 MiB**:
- The CI-lower is barely positive on a single seed → a confirmation seed would be required before treating +27.85 as real.
- The default-`Hash` decision is a **separate config tradeoff** (mobile-footprint vs desktop strength — ADR-noted under the M5.F item-8 close). Bumping the default raises the memory floor on the downstream mobile target.
- GUIs/match harnesses override `Hash` anyway (this very campaign ran the *real* item3 SPRTs at the engine default), so the default only matters for bare-CLI/embedded use.

Left as a documented single-seed signal in `docs/tooling-backlog.md`. No engine change.
