## Reading

- **The central design claim held: no 60+0.6 regression** (+3 / −2, flat) — the
  opposite of M7.B's −104 collapse. Alpha-relative capture futility *is*
  self-regulating in TC, as argued (research §4 / ADR-0042 §7). The no-ramp v1 was
  the right risk posture; M7.C.1 (the root-depth ramp) is **not** needed.
- **But the mechanism is Elo-neutral here.** The conservative v1 (two-layer, with the
  `victim ≥ attacker` exemption on branch (b)) is too thin to convert — consistent
  with the rarity of frontier nodes (bench only −5.8% d4 / −11.1% d7; M7.B's qsearch
  prune was −59% / −50%). Only the 40+0.4 bucket shows a stable (+3/+3) lean.
- **Same outcome class as M7.A's capture-ordering split** (neutral, shelved): for this
  engine SEE's Elo is concentrated in the *qsearch* prune (M7.B/M7.B.2, +92–124),
  not in the negamax-frontier extension.

M5.G item-6 "signal unambiguous, no full re-run" precedent.

## Disposition — M7.C SHELVED (close M7)

Both forms of the mechanism failed: **v1 (conservative) flat (≈−1.7), v2 (broad)
clearly negative (−49, 60+0.6 collapse).** There is no productive operating point at
current strength — too thin converts nothing, too broad over-prunes the saving
tactics. **No ship; production HEAD stays `M6.J` + `M7.B.2`.** Same outcome class as
M7.A's capture-ordering split: for this engine SEE's Elo is fully captured by the
*qsearch* prune (M7.B/M7.B.2, +92–124). The M7.C code (v1+v2) is retained on the
branch `m7c-see-capture-futility` for reference, **not** merged. M7 closes.

The margin sweep (CFP_MARGIN_D1) is the only untried lever, but it is weak-prior:
lowering it prunes *more* (toward v2's over-pruning regression), raising it prunes
*less* (toward v1's inert flatness) — the same too-thin/too-broad axis with no reason
to expect a sweet spot the two endpoints bracket. Not pursued. See
`docs/milestones/m7.c.md`.
