### Post-tag follow-up commits (operator-workflow extensions)

The `M6.G` tag remains at the original landing commit (`a45c6de`); the architectural extensions below are subsequent commits on `main`. They are operator-workflow improvements, not new milestones — M6.I's SPRT baseline is still `M6.F`.

1. **`corpus`: make `--games` optional, default unbounded.** Operator runs `scripts/corpus.sh` then Ctrl-Cs when satisfied; the next run resumes from the durable shard. Manifest records the *actual* durable game count at exit (`scan_valid_blocks`-derived), so `re-run.sh` reproduces what's on disk, not a fake target.
2. **`corpus`: inline per-position filter in selfplay.** Moves quiet/cutoff/in-check/strata-tag from `cmd_build` into `play_one_game`. The shard is build-ready at write time; `cmd_build` just does cross-game work (dedup→cap→split). Every overnight run directly contributes to the usable, prepared, labeled corpus. Also fixes a latent qsearch-TT-cross-game non-determinism by allocating a fresh `QSearcher` per game (R3-analog).
3. **`corpus`: vendored opening book + `book_fraction` meta-tunable.** `bench/data/openings.epd` (CC0 `2moves_v1.epd`, 40,457 positions) seeded-mixed with random-walk openings at a configurable per-game ratio. Each book-seeded record carries `STRATUM_BOOK_OPENING` in its strata bitset; `objective::stratified_objective` returns a per-stratum loss; the M6.I outer simplex can move `book_fraction` as another meta-axis (alongside source mix and depth-rung weights — ADR-0035 §9 / plan §3.8).
4. **`corpus`: per-source loss in `StratObjective` (source-mix meta-tunable axis).** `StratObjective.per_source: Vec<(u8, f64)>` reports held-out logistic loss per `Source` enum byte (SelfPlay / Ccrl / LichessOpen). The per-record `Source` field always supported source distinction; the missing piece was per-source loss reporting in the held-out objective so the outer simplex can read the per-stratum signal and move the corpus-mix ratio (self-play vs CCRL vs Lichess) accordingly — the same meta-tunable shape as `book_fraction`, just on a different axis (ADR-0035 §9).
5. **`bench/corpus/`: bytes gitignored; manifest-driven contract (ADR-0035 §8 post-tag amendment).** At M6.I production scale (100–300 MB filtered, multi-GB raw external) git is the wrong tool — GitHub's 100 MB hard cap, pack-inflation across nightly regenerations, useless diff/blame on binary. Resolution: `bench/corpus/{shard,val,checkpoint,pgn-shard}.bin` are `.gitignore`d; the committed contract is the manifest + filter_spec + corpus_stats + re-run.sh + the vendored opening book. The bytes are operator-materialized via `sh bench/corpus/re-run.sh` from the manifest's pinned knobs. Consumers freeze on the manifest, not the bytes. Future hosting (GitHub release asset / S3 / sister-repo) deferred — see ADR-0035 §8 "Future hosting" paragraph.
6. **`corpus`: four-source taxonomy + `OpeningMode` per-campaign (ADR-0035 §10 post-tag amendment, 2026-05-21).** **Supersedes follow-up #3 (`book_fraction` meta-tunable).** `Source::SelfPlay` split into `Source::SelfPlayOnBook` (book-seeded games) + `Source::SelfPlayOffBook` (startpos + random plies). The per-game `book_fraction` coin-flip is replaced by a per-campaign `OpeningMode::{Book, Random}` — every record carries the campaign's source variant. The book / off-book proportion becomes a training-time per-source reweighting axis at M6.I (mechanically identical to the CCRL / Lichess proportion via `StratObjective::per_source`), no longer a corpus-generation knob. ADR-0003 audit accept-list grows from 3 to 4: `{SelfPlayOnBook, SelfPlayOffBook, Ccrl, LichessOpen}`; the cardinality pin in `check_adr0003_audit` is bumped accordingly. `STRATUM_BOOK_OPENING` removed as redundant (bit 2 reserved). Manifest field `book_fraction: f64` replaced by `opening_mode: Option<String>`; the generated `bench/corpus/re-run.sh` dispatches on it. Wire-format change: source-byte assignment is now `SelfPlayOnBook=0, SelfPlayOffBook=1, Ccrl=2, LichessOpen=3`; shards committed under the prior numbering are not migrated, and the committed `bench/corpus/{shard,val}.bin` were deleted ahead of M6.I regeneration under the new taxonomy. Engine bench unchanged (`1213649` / d4 `90591`); 1848 lib + 8 crash-safety + 2 reproducibility tests pass; `cargo fmt --check` + `cargo clippy --release --all-targets -- -D warnings` clean.
