# M3 — Alpha-beta + material eval

Per ADR-0010 milestone-summary format. Per-phase entries; final summary lands when M3 closes.

## M3.A (2026-04-28) — material + PST eval + GreedyMover

First playing-engine phase: depth-1 best-eval with reservoir-sampled tie-break replaces M2.E's RandomMover as production search. PeSTO middlegame material + PST tables vendored verbatim. Incremental `static_eval_white` field on `Position` maintained through `make_move`/`unmake_move`. Insufficient-material draw detection in eval (KvK / KvN / KvB).

ADR-0014 codifies eval composition. No microbenchmark — UCI dispatch + depth-1 single-pass evaluate are not search-hot-path; M3.C alpha-beta will be the first phase with a meaningful nps figure.

## M3.C (2026-04-29) — negamax alpha-beta core

First *searching* phase: replaces M3.A's depth-1 GreedyMover with full alpha-beta recursion at fixed depth (set via `go depth N`; default 4). Single-iteration; no iterative deepening, no qsearch (deferred to M3.D / M3.E). Calls `evaluate(pos)` at depth==0 (horizon effect accepted). Fail-soft negamax with `i32` scores, `MATE = 30000`, ply-adjusted mate-in-N, mate-distance pruning, triangular PV table (8 KiB inline on AlphaBetaMover), MVV-LVA capture ordering, M3.B repetition/50-move helper integration at `ply > 0`, 4096-node cancellation cadence with sentinel-return + post-call abort check + parallel root-score lockstep update. **ADR-0013** codifies the search structure.

### nps headline figure: 8.55 Mnps

Apple M4, single-threaded, release build, depth-8 search from startpos, pure alpha-beta with MVV-LVA only (no killer/history/TT/qsearch). Within Sonnet research §11.1's 5–20 Mnps estimate (which assumed the eval is M3.A's PeSTO MG); above Opus research §11.1's 0.5–2 Mnps estimate (which assumed qsearch dominated leaf cost). The qsearch-not-yet-landed factor explains the high end — leaf eval is the cheap PeSTO PSQT lookup, not a recursive capture-resolution.

### Plumbing / process highlights

- **Three review loops all converged**: plan-review (3 passes; 5 must-fix → addressed), test-suite review (3 passes; 3 must-fix incl. the empty-searchmoves-in-check correctness regression → addressed), final-review (2 passes; 2 must-fix incl. score contamination under abort → addressed via root_score field per ADR-0013 §5).
- **Sonnet+Opus chess-coder calibration deferred to M3.D**. The plan §11 trigger fired but the worktree-isolation A/B was incompatible with the uncommitted-test-slice state at impl time. The standalone Sonnet impl pass needed two final-review-prescribed iterations (debug-mode timeouts, root score contamination) — both subtle bugs the test suite did not pre-pin. M3.D is a clean post-M3.C-commit slice with similar novel-invariant character; the calibration pass will land there.
- **Mate-in-2 fixture verification miss**: orchestrator + test-suite reviewer + initial impl all missed that the position `6k1/4Q3/5K2/8/8/8/8/8 w - - 0 1` is mate-in-1 (Qg7 covers f8 via diagonal — verifiable but easy to skip). Caught at impl time when the depth-4 search returned MATE-1 instead of MATE-3. Test renamed to `alphabeta_finds_forced_mate_from_dominating_position`; assertion relaxed to `score >= MATE_IN_MAX_PLY`. Recorded as a calibration data point for the chess-coder workflow's "verify chess geometry first-principles" discipline.
- **No baseline tag at M3.C commit**. Plan §10 step 13 deferred the `baseline/alpha-beta-no-tt` tag to M3 end / M4.A start (the tag's "without TT but with qsearch + ID + time-management" semantic only matches the M3.F-end commit, not the bare M3.C alpha-beta).
