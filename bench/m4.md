## M4.A (2026-04-29) — Transposition table

First M4 phase. Adds a Zobrist-keyed transposition table layered over M3.E's iterative-deepening alpha-beta. Depth-preferred + age-bias replacement; bound-aware probe with cutoffs at non-PV nodes only; mate-score depth-adjustment on store/probe; `Hash` UCI option (default 16 MiB, range 1–4096); `Engine::reset_for_new_game()` consolidated for both `ucinewgame` and per-bench-position lifecycle. `prior_root_move` (M3.E) removed — TT subsumes the M3.E ordering hint.

ADR-0018 codifies the TT layout, replacement scheme, mate-score discipline, GHI stance, and per-game state inventory.

### Plumbing / process highlights

- **Three review loops** all converged: plan-review (2 passes; 4 must-fix + 12 should-fix → addressed); final-review _(populated post-run)_.
- **`prior_root_move` removed** in favor of TT-driven ordering. Plan §0 weighed all three roadmap-suggested options; option (1) "Remove" chosen because the M4.A replacement scheme + abort-skip + end-of-loop-only store discipline together preserve the iter-(N-1) root entry across an aborted iter N. Pinned by S3 + S3b.
- **`Mutex<Vec<TtEntry>>` perf trap caught at plan-review pass 1.** Initial draft used `Mutex` for safety; pass-1 reviewer flagged ~23% CPU overhead at 11.5 Mnps × 23M lock acquisitions/sec. Revised to `UnsafeCell<Vec<TtEntry>>` + `unsafe impl Sync` with single-mutator discipline anchored to ADR-0011's threading model. Avoided shipping a known-suboptimal scheme.
- **Coder slicing** per plan §6 worked cleanly: Slice A (Sonnet) shipped `src/tt.rs` self-contained with 23 tests; Slice B (Opus, flagged for novel `is_pv` invariant + cross-call-site store discipline + breaking M3.E test surface) shipped the negamax restructure + 15 search tests; Slice C (Sonnet) wired the engine + 7 tests.
- **Plan-review caught `original_alpha` capture-after-MDP bug** before implementation. Initial plan §4 captured `original_alpha` after MDP tightening; pass-1 reviewer noted MDP can mutate alpha, causing fail-low against MDP-tightened-alpha to mis-classify as Exact. Fixed in pass 1 revision; pinned by S1/S2.
- **Pre-existing test infrastructure flake.** The M2.D-era `engine::tests::greedy_mover_determinism_across_repeated_runs_with_fixed_seed` test has ~20% failure rate when run as part of the full suite, 0% in isolation. Confirmed pre-existing (reproduces on main pre-Slice-B). Likely a `position`-after-`go` interleaving race in the M2.D test fixture, not an M4.A regression. Tracked for cleanup but not blocking.

### Mutation-survivor analysis

`cargo mutants --in-diff /tmp/m4.a.diff` against the M4.A primary commit produced 140 mutations: **127 caught + 3 timeout (caught-via-hang) + 6 unviable + 3 initially missed**. The three survivors (per workflow §"Triaging a single survivor"):

1. **`src/search.rs:568:42` `==` → `!=` in `child_is_pv = is_pv && i == 0`.** Real coverage gap. S13 (`negamax_is_pv_only_first_recursion_index_propagates`) used a node-count differential assertion (`nodes_with_tt < nodes_ref` + `savings >= n_children - 1`) that the mutation passed because under `i != 0`, savings still exceed `n_children - 1` by far (a single TT cutoff saves an entire subtree). **Fix in follow-up:** tightened the assertion to `nodes_with_tt < nodes_ref / 2` — under correct behavior savings are ≥95% of `nodes_ref`; under the mutation savings are ~5%. The /2 threshold cleanly separates the two regimes. Verified via manual mutation: original passes (`238 < 1089`); mutated fails (`2045 > 1089`).

2. **`src/tt.rs:96:27` `|` → `^` in `TtEntry::pack_age_bound`.** Equivalent mutant. The expression `(age & 0x3F) << 2 | bound as u8` has disjoint operand bit positions: left operand lives in bits [7..2], right operand in bits [1..0]. For disjoint operands, `|` and `^` produce identical results for every input. **Fix in follow-up:** documented and excluded via `.cargo/mutants.toml`.

3. **`src/tt.rs:297:14` `>` → `>=` in `score_from_tt`.** Boundary case at `score == MATE_IN_MAX_PLY = 29936` exactly. The mutated predicate fires at the boundary (where the original does not), causing a ply adjustment on a non-mate centipawn score. T17/T18/T20/T20b use mate scores strictly above the boundary; T19 proptest's i32 sampling has ~1/2^32 chance of hitting the exact boundary integer in 256 cases. **Fix in follow-up:** added T20c (`score_to_tt_boundary_at_mate_in_max_ply_is_no_op`, `score_from_tt_boundary_at_mate_in_max_ply_is_no_op`, `score_to_tt_just_above_mate_in_max_ply_does_adjust`) — explicit deterministic assertions at `±MATE_IN_MAX_PLY` and `±(MATE_IN_MAX_PLY + 1)`. Verified via manual mutation: original passes; mutated fails on the boundary case.

Three timeouts (`search.rs:551 delete -`, `search.rs:562 delete -`, `tt.rs:265 / → *`) are caught-via-hang — the mutated code allocates 256× the intended memory or causes an infinite recursion that the test suite traps via timeout. No follow-up needed.

Six unviable mutations are compile failures (cargo-mutants generated a syntactically-valid mutation that doesn't typecheck). No action.

## M4.B (2026-04-29) — Killer moves

Second M4 phase. Adds two killer slots per ply, updated on quiet-move beta cutoffs and folded into negamax move ordering between captures/promos and remaining quiets. Builds on M4.A's TT-move-first ordering; does not touch qsearch.
