## M4.A (2026-04-29) — Transposition table

First M4 phase. Adds a Zobrist-keyed transposition table layered over M3.E's iterative-deepening alpha-beta. Depth-preferred + age-bias replacement; bound-aware probe with cutoffs at non-PV nodes only; mate-score depth-adjustment on store/probe; `Hash` UCI option (default 16 MiB, range 1–4096); `Engine::reset_for_new_game()` consolidated for both `ucinewgame` and per-bench-position lifecycle. `prior_root_move` (M3.E) removed — TT subsumes the M3.E ordering hint.

ADR-0018 codifies the TT layout, replacement scheme, mate-score discipline, GHI stance, and per-game state inventory.

### Mutation-survivor analysis

`cargo mutants --in-diff /tmp/m4.a.diff` against the M4.A primary commit produced 140 mutations: **127 caught + 3 timeout (caught-via-hang) + 6 unviable + 3 initially missed**. The three survivors (per workflow §"Triaging a single survivor"):

1. **`src/search.rs:568:42` `==` → `!=` in `child_is_pv = is_pv && i == 0`.** Real coverage gap. S13 (`negamax_is_pv_only_first_recursion_index_propagates`) used a node-count differential assertion (`nodes_with_tt < nodes_ref` + `savings >= n_children - 1`) that the mutation passed because under `i != 0`, savings still exceed `n_children - 1` by far (a single TT cutoff saves an entire subtree). **Fix in follow-up:** tightened the assertion to `nodes_with_tt < nodes_ref / 2` — under correct behavior savings are ≥95% of `nodes_ref`; under the mutation savings are ~5%. The /2 threshold cleanly separates the two regimes. Verified via manual mutation: original passes (`238 < 1089`); mutated fails (`2045 > 1089`).

2. **`src/tt.rs:96:27` `|` → `^` in `TtEntry::pack_age_bound`.** Equivalent mutant. The expression `(age & 0x3F) << 2 | bound as u8` has disjoint operand bit positions: left operand lives in bits [7..2], right operand in bits [1..0]. For disjoint operands, `|` and `^` produce identical results for every input. **Fix in follow-up:** documented and excluded via `.cargo/mutants.toml`.

3. **`src/tt.rs:297:14` `>` → `>=` in `score_from_tt`.** Boundary case at `score == MATE_IN_MAX_PLY = 29936` exactly. The mutated predicate fires at the boundary (where the original does not), causing a ply adjustment on a non-mate centipawn score. T17/T18/T20/T20b use mate scores strictly above the boundary; T19 proptest's i32 sampling has ~1/2^32 chance of hitting the exact boundary integer in 256 cases. **Fix in follow-up:** added T20c (`score_to_tt_boundary_at_mate_in_max_ply_is_no_op`, `score_from_tt_boundary_at_mate_in_max_ply_is_no_op`, `score_to_tt_just_above_mate_in_max_ply_does_adjust`) — explicit deterministic assertions at `±MATE_IN_MAX_PLY` and `±(MATE_IN_MAX_PLY + 1)`. Verified via manual mutation: original passes; mutated fails on the boundary case.

Three timeouts (`search.rs:551 delete -`, `search.rs:562 delete -`, `tt.rs:265 / → *`) are caught-via-hang — the mutated code allocates 256× the intended memory or causes an infinite recursion that the test suite traps via timeout. No follow-up needed.

Six unviable mutations are compile failures (cargo-mutants generated a syntactically-valid mutation that doesn't typecheck). No action.

## M4.C (2026-04-30) — History heuristic

Third M4 phase. Adds a butterfly-indexed history table (`[side][from][to]` i16, 16 KiB) updated with `+= depth*depth` bonus on quiet beta-cutoff and matching `-= depth*depth` malus on quiets searched-but-failed. Layered into M4.B's `negamax_move_order_score` as the score for non-killer quiets in `[-MAX_HISTORY, MAX_HISTORY] = [-16384, 16384]` (literature standard).

To preserve the captures > killers > history-quiets hierarchy with the literature-standard MAX_HISTORY range, M4.B's `KILLER0_SCORE = 200` and `KILLER1_SCORE = 100` were bumped at M4.C-rebase to `100_001` / `100_000`, and `negamax_move_order_score`'s non-quiet branch now adds `CAPTURE_OFFSET = 1_000_000` to `mvv_lva_score`. Compile-time `_SCORE_TIER_INVARIANTS` const-assert pins the four tunables; runtime tests S23 + HS12 re-pin the discipline against drift. Relative orderings within tiers (e.g., between captures, between promos and captures) are unchanged from M4.B.

ADR-0019 codifies indexing (butterfly + side dim), bonus/malus formula, saturation policy, reset boundary (joins M4.A's `Engine::reset_for_new_game()`), and pipeline placement (TT-bubble → captures → killer0 → killer1 → history-scored quiets).

The CAPTURE_OFFSET concept from the parallel branch is no longer needed — captures already sort above killers via the existing `mvv_lva_score ≥ 287 > KILLER0_SCORE = 200` discipline, and killers above quiets via `KILLER1_SCORE = 100 > MAX_HISTORY = 99`.
- **`Move::is_quiet` from the parallel branch** was dropped — M4.B already lands `is_quiet` as a free function in `src/search.rs`. M4.C call sites (cutoff dispatch, malus loop, push site) use the M4.B free function.

## M4.D (2026-04-30) — Aspiration windows

Fourth and final M4 phase. Wraps M3.E's iterative-deepening outer loop with two-tier asymmetric aspiration windows: at depth ≥ `ASPIRATION_MIN_DEPTH`, the next-iteration window is centered on the prior iteration's score with half-width ±50 cp; on fail-high or fail-low, exactly one re-search runs with the proved fail-soft bound preserved on the unfailed side and `±INF` on the failed side. No third tier (deferred to M5). No PVS / negascout (M5+). No mate-score special-casing (research §7.2: asymmetric widening handles correctly).

**Threshold tuning at landing**: ASPIRATION_MIN_DEPTH was raised from 4 to **6** after the initial fast-TC SPRT showed threshold=4 regressed by 22 Elo at tc=10+0.1. Threshold=6 produced +65.92 Elo at the same TC vs the same baseline (LOS 100%). At fast TC the engine reaches ~depth 7, so threshold=4 exposed too many shallow iterations to aspiration's re-search overhead; threshold=6 limits exposure to iterations 6–7 where prior-iteration scores are stable enough for first-try success to dominate the EV.

Plan: [`docs/plans/m4.d.md`](../docs/plans/m4.d.md). Research: [`docs/research/m4-aspiration-windows.md`](../docs/research/m4-aspiration-windows.md). No new ADR — parameter-level addition documented by plan + research. ADR-0018 §11 stale "M4.D = PVS" text corrected at landing.

### Qualitative behavior shift from M4.C

| Feature | M4.C (TT + killers + history) | M4.D (TT + killers + history + aspiration) |
|---|---|---|
| ID outer loop | One negamax call per iteration with `(-INF, INF)` window | Up to two negamax calls per iteration; first try at `(prior - 50, prior + 50)` for depth ≥ 6; asymmetric re-search on fail |
| Per-iteration overhead | clear_killers + negamax | clear_killers + aspiration loop (per-try reset of aborted/root_score/pv.lengths) + 0–1 re-search |
| Window-contained iterations | n/a | typical (~70% per literature) — single negamax call |
| Fail-high / fail-low iterations | n/a | re-search at `(L, +INF)` or `(-INF, L')` — exactly two calls |
| Mate-score iterations | full window | centered on mate-score (not special-cased; asymmetric widening handles via fail-high re-search) |
| Empty-PV recovery | n/a | `extract_bestmove_or_tt_fallback` falls back to root TT entry's `best_move` (preserved via ADR-0018 §7's overwrite rule) |
| Test instrumentation | n/a | `info string aspiration_re_search depth=N alpha=A beta=B` line emitted on each re-search |
| New helpers in `src/search.rs` | n/a | `aspiration_window`, `widen_after_fail`, `extract_bestmove_or_tt_fallback` (M3.D `negate_window` precedent — direct unit-testable) |
| New constructor in `src/mov.rs` | n/a | `Move::from_bits(u16) -> Move` (`pub(crate) const fn`) |

### Plumbing / process highlights

- **Three review loops** converged. Plan-review pass 3: `no further substantive issues` (1 must-fix + 6 should-fix in pass 1, all addressed; pass 2 must-fix on `Move::from_bits` API gap addressed). Test-suite reviewed jointly with impl per project precedent. Final-review pass 2: `no further substantive issues` (2 should-fix in pass 1: AS23 weak-pin documented as anticipated possibly-surviving, ADR-0018 §11 stale text fixed; 3 nits addressed including `Move::from_bits` invariant docstring).
- **Helper extractions follow the M3.D `negate_window` / M3.E `aborted_fallback_result` / M3.F `compute_bench_nps` precedent** — direct unit-testability for mutation-test surface; AS24a–d cover the empty-PV TT-fallback's four branches with synthetic state.
- **Mate-score special-casing dropped at v2** — plan v1 had `prior.abs() > MATE_IN_MAX_PLY → full window` skip; revised v2 to no skip per research §7.2's "do not special-case mate detection in the aspiration loop" recommendation. AS5b inverted to anti-stub against re-introduction.
- **Stop-flag check between aspiration tries dropped at v2** — plan v1 had a defensive between-tries `ctx.stop.load()` probe; revised v2 to drop per research §12.4's "no additional code needed" recommendation. The existing post-call `self.aborted` check + the re-search's first 4096-cadence poll cover the cancellation contract.
- **Re-search window form: `(L, +INF)` / `(-INF, L')`** matches CPW / Beowulf / TalkChess literature consensus exactly. Plan v1's `(L-1, +INF)` / `(-INF, L'+1)` deviation (originally motivated as a structural fix for an empty-PV edge case) was reverted; the empty-PV case is handled via the TT-fallback helper instead. The TT preservation only applies to the fail-high path; fail-low always populates PV[0] (any finite score > -INF improves alpha at the root).
- **Killer persistence across aspiration tries** — preserved within a depth step (research §12.7); cleared only between depth steps via the existing M4.B per-iteration `clear_killers`. AS23 is a weak pin (asserts only "any populated post-go"); the targeted mutation (between-tries-clear) is anticipated possibly-surviving in the joint mutation campaign and will be triaged at campaign time.
